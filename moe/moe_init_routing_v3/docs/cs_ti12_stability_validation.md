## 3. 稳定性分析

### 3.1 基线对照（ti=0）

ti=0（与原 ti=12 同参数）重测 Δ%=-1.7%，与 v1.1 报告 -4.0% 同方向但幅度更小。结合 v1.0（-2.8%）/ v1.1（-4.0%）/ 本次（-1.7%），优化幅度本身在 **-1.7% ~ -4.0%** 区间波动，**接近 1% 阈值边缘，稳定性差**。

### 3.2 cols 维度（ti=0/1/2/3/4）

| cols | Δ% | 判定 |
|------|-----|------|
| 2048 | +12.2% | ❌ 严重劣化 |
| 4096 | +3.7% | ❌ 劣化 |
| **7168** | **-1.7%** | ✅ 优化 |
| 16384 | +3.9% | ❌ 劣化 |
| 32768 | +0.4%（CS 关闭回落）| ⚪ 持平 |

**cols=7168 是唯一优化点**，cols 变大或变小都劣化。cols=2048 最严重（+12.2%）。
cols=32768 时 CS 主动关闭回落（TK=11000000），与 builtin 同路径。

### 3.3 N 维度（ti=0/5/6）

| N | Δ% | 判定 |
|---|-----|------|
| 4096 | +0.1% | ⚪ 持平 |
| **9000** | **-1.7%** | ✅ 优化 |
| 16384 | +0.0% | ⚪ 持平 |

N 变化时优化消失，仅 N=9000 触发轻微优化。**说明优化与具体 N 有关，不是结构性收益**。

### 3.4 expertNum / AER 维度（ti=0/7/8/9）

| expertNum | AER | Δ% | 判定 |
|-----------|-----|-----|------|
| 256 | [0,256] | -1.7% | ✅ 优化 |
| 128 | [0,128] | -2.1% | ✅ 优化 |
| 64 | [0,64] | -4.8% | ✅ 优化 |
| 256 | [0,128]（LE 窄 range）| — | ⚠️ tiling 失败 |

**expertNum 缩小，优化幅度增大**（-1.7% → -4.8%）。LE 窄 range（AER<expertNum）触发 tiling 失败，**该组合 builtin 也不支持**（两侧 OPTILING_FAILURE），非 CS 问题。

### 3.5 dtype 对照（ti=0/10/11，同 cols=7168 / N=9000 / e256）

| dtype | Δ% | 判定 |
|-------|-----|------|
| **fp32** | **-1.7%** | ✅ 优化 |
| fp16 | +4.1% | ❌ 劣化 |
| bf16 | +5.9% | ❌ 劣化 |

**优化是 fp32 特有的**，同条件 fp16/bf16 都劣化 4-6%。推测原因：fp32 数据量是 fp16/bf16 的两倍（4B vs 2B），CS 的 Phase C 双缓冲在大数据量下能更好隐藏 DMA 延迟；fp16/bf16 数据量小，CS 三相流水线的固定开销（SyncAll、workspace 读写）无法摊薄，反而拖累。

## 4. 结论

### 4.1 ti=12 的优化不稳定

ti=12（CO unquant fp32 GATHER COUNT dropless）的优化信号 **不稳定、不通用**：

- **窄区间**：仅 cols=7168 + fp32 + AER=[0,expertNum]（全通过）组合有轻微优化（-1.7% ~ -4.8%）
- **接近阈值边缘**：基线用例 v1.0/v1.1/本次三次测量 Δ% 在 -1.7% ~ -4.0% 波动，单次测量抖动可能翻向持平
- **dtype 强相关**：fp32 优化、fp16/bf16 同条件劣化（+4% ~ +6%），不是 GATHER/COUNT 算法本身的通用优化
- **cols 强相关**：cols 偏离 7168（4096/16384）即劣化，cols=2048 劣化最严重（+12.2%）

### 4.2 与 dropPad 优化对比

| 场景 | 优化稳定性 | 优化区间 | 用例覆盖 |
|------|-----------|---------|---------|
| **dropPad**（13/13 全复现）| **稳定** | -5% ~ -33% | 全 dtype / cols / N / cap |
| **ti=12 fp32 GATHER COUNT**（本次）| **不稳定** | -1.7% ~ -4.8% | 仅 fp32 + cols=7168 |

dropPad 是 CS 模板的**结构性稳定优化**；ti=12 的优化是 **fp32 数据量与 cols=7168 巧合对齐**的边缘现象，接近测量噪声。

### 4.3 建议

- **不要把 ti=12 的 -4.0% 当作稳定优化信号**用于 tiling 启用条件决策
- 与 `cs_vs_builtin_perf.md` 的整体结论一致：除 dropPad 外，**dropless + GATHER + 大列场景没有稳定的 CS 优化**，建议在这些场景考虑收紧 `IsCountingSortApplicable` 启用门槛
- 若需要进一步排查 fp32 特有的轻微优化根因，可 profiling 对比 fp32 vs fp16 在 cols=7168 下的 Phase A/B/C 耗时分布
