# A3 1200000 / A5 400000 共通 FullLoad 用例 A/B 性能对比

## 0. 摘要

构造 15 个 dropless 部分专家范围（ep\_=1, LE\<E）用例，同时满足 A3 CS FullLoad（TilingKey 1200000）和 A5 CS FullLoad（TilingKey 400000）启用条件。在 A3（Ascend910B2, 48核, 192KB UB）和 A5（Ascend950DT, 64核, 248KB UB）上分别跑 CS 侧，在 A5 上卸包跑 builtin baseline。

**结论**：A3/A5 双方 15/15 全部进入预期 TilingKey，A5 CS 对比 Builtin **15/15 全优化**（-0.2% ~ -24.6%），无劣化。与先前 fl\_k8（全专家范围 LE=256=E）劣化 +65.9% 形成完美对照——**dropless FullLoad 在部分专家范围是合法优化路径，劣化仅出现在 A5 例外放行引入的全专家范围场景**。

## 5. 优化规律分析

### 5.1 LE 越小优化越显著

| LE | 用例 | A5 Δ% |
|----|------|-------|
| 32 | t1024\_h128\_le32 | -22.9% |
| 32 | t4096\_h256\_le32 | -24.6% |
| 64 | t1024\_h128\_le64 | -14.1% |
| 64 | t4096\_h512\_le64 | -3.9% |
| 128 | t1024\_h128\_le128 | -0.2% |
| 128 | t4096\_h256\_le128\_e512 | -7.4% |

LE 越小，filteredCount = active\_num × (LE/E) 越小，Phase C 逐 pair 串行循环次数越少，CS 相对 builtin 优势越大。

### 5.2 小 T 优化更明显

| T | 用例 | A5 Δ% |
|---|------|-------|
| 1024 | t1024\_h128\_le64 | -14.1% |
| 4096 | t4096\_h128\_le64 | -7.2% |
| 8192 | t8192\_h128\_le64 | -3.7% |
| 16384 | t16384\_h128\_le64 | -5.4% |

小 T 下 builtin 的 sort+gather 固定开销占比较高，CS 计数排序更高效。

### 5.3 H 对优化幅度影响较小

H=128/512/2048 下优化幅度稳定在 -3% ~ -14%，说明 FullLoad UB 全载模式下 H 不是主要瓶颈。

| fl\_k8\_aer64（部分范围）| 64 | 256 | ❌ | 1 | 400000 | 128.779 | 134.842 | **-4.5%** |

**核心结论**：dropless FullLoad 在部分专家范围（A3 合法启用区）全面优化；劣化仅出现在 A5 例外放行（line 2309-2312 `actualExpertNum != expertNum_` 短路）引入的全专家范围场景。

详见 `cs_fullload_k8_degradation_analysis.md` §3.5 和 `cs_a3_fullload_entry_conditions.md` §9.4。
