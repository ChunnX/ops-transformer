1mxfp8 是什么（字节级）

一个 token 的 h 个元素，不再用 bf16(2 字节/个)，而是 mxfp8：每元素 1 字节 fp8(e4m3fn)，外加每 32 个元素共享 1 个 e8m0 缩放因子(1 字节，纯指数，表示 2 的整数幂)。

x₆₃
… h 个
scale (e8m0, 每 32 共享)
s₀管 x₀₋₃₁
s₁管 x₃₂₋₆₃
… h/32 个
真实值 ≈ fp8(xᵢ) × 2^(e8m0[i/32] − 127)

真实场景 h=7168 → 一个 token = 7168 字节 fp8 payload + 224 字节 e8m0 scale。payload 与 scale 在算子里是两个分开的 GM tensor（token_data / token_scale）。e8m0 字节 E 直接就是 fp32 的偏置指数：2^(E−127) 的 fp32 位型 = E<<23，反量化时一个移位即得缩放因子。

topk=8 = 全局专家数 GE=8 → 每个 token 路由到全部 8 个专家，这是全密退化场景：

wish_cnt[8][8,8,8,8,8,8,8,8] — 每块都收满 bs=8 个 token，没有空洞（"去空洞"在此是 no-op，expand_x = 数据区原样） send_counts[8][8,16,24,32,40,48,56,64]（前缀和） expert_token_nums[4][16,16,16,16]（每本地专家从 2 卡各收 8） expand_idx[8,8]第 i 行全是 i → [[0×8],[1×8],…,[7×8]]（每专家每行出现一次，行 i 时已出现 i 次） A= R·bs·min(topk,E) = 2·8·4 = 64 = Σwish，完全填满

4combine teardown：gather + 反量化 + 加权和

combine 数据区每个全局专家一块(GE=8 块×bs=8 槽)，mxfp8 存储。一个 token 发给 k 个专家就有 k 份复制体散在 k 个专家块里。

复制体行号 = expert_ids[i][j] · bs + expand_idx[i][j]

专家 id 定位"哪一块"(块起点 ge·bs)，expand_idx 定位"块内第几行"。

还原 token0 逐步 （沿用 §3② 稀疏示意 expert_ids=[0,2], expand_idx=[0,0]；真实主场景 topk=8 → 每 token gather 8 份复制体）

定位j=0→专家0 行 0·8+0=row0；j=1→专家2 行 2·8+0=row16 反量化每行：fp8 payload → fp32(Cast)；每 32 元素 × 2^(e8m0−127)（位型 E<<23 构造） 加权和× expert_scales[0][j]，fp32 累加 k 份 回写fp32 → bf16(四舍五入) → x[0]
x[0] = Σ_j expert_scales[0][j] · ( fp8(combine_data[row]) × 2^(combine_scale[row]−127) )

对 8 个 token 各做一遍 → x [8,7168] bf16。fp32 累加保证精度，末位 cast bf16。

5多核并行（无 SyncAll、无跨核依赖）

dispatch：按输出行切

所有核都算出每块 {起点,数量} 与总有效行 N=ΣwishCnt；把 [0,N) 行均分给 aivNum 个核，每核搬自己那段 expandX 行(payload+scale)。各核写不相交的行 → 无需同步。仅 core0 额外产 3 个 int 输出(很小)。

combine：按 (token,chunk) 切

h 切成 1024 元素的 chunk(7168→7 chunk)，工作项 = bs×chunk 数 = 8×7=56，均分给各核。每核处理若干 (token,chunk)，写 x 的不相交列段 → 无需同步。

blockDim 由 host tiling 从平台 AIV 核数推得(GetCoreNumAiv())，与工作量取 min。真实场景 dispatch 64 行 / combine 56 项分到数十核并行。

  Duplicate acc=0
