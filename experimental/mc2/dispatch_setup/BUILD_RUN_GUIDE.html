工程目录 ops-transformer/experimental/mc2/dispatch_setup · 最终目标：在 a6 上编译跑通

a5 结构编译门禁 全绿 2 die / 2 rank (MPI) a6 运行待核实（见末表）
一句话：把 dispatch_setup(CCU 语义，写状态位) 与 dispatch_teardown(AIV，等状态位) 两个算子， 集成在同一工程里、一起编译、串行跑——两条流靠"写状态位 / 等状态位"同步。本机为 a5（权宜工作台）， a6-only 代码用 #ifdef DISPATCH_CCU_A6 隔离；所有代码以 a6 视角写，a6 真值靠上板 + 实测校准。
⚠ 重大变更（2026-06-24）：CCU 写端 本地 LocalCopyNb → 跨卡 WriteNbWithArriveNotify
a6 上板诊断坐实：旧的"本卡 CCU 用 6 参 LocalCopyNb 写自己状态区"——CCU 跑完无 fault、但 statusGm 全 0 （[DIAG] statusGm[0..3]=0,0,0,0），即 a6 那个新开发、未验证的 6 参 LocalCopyNb 静默失效。 改用 a6 已验证功能正常的 0.5RTT 跨卡写：卡0 的状态区由卡1 写、卡1 的由卡0 写（WriteNbWithArriveNotify）。 kernel 基类改继承 Mc2CcuKernelBase（新增 dispatch_setup_ccu_api.h facade），裁剪自已验证参考 moe_distribute_dispatch_ccu_setup.cpp。下文 §1/§3/§6/§8 已据此更新。

1 · 架构与数据流

dispatch_setup(CCU) = 独立 host 驱动 dispatch_min_driver（registry build 里 if(BUILD_OPEN_PROJECT) return() 自跳过，单独 cmake 构建）：自建 2-rank CCU comm → 注册/拉起 CCU kernel（跨卡 WriteNbWithArriveNotify 把就绪值写进对端状态区）。
dispatch_teardown(AIV) = 标准 registry aclnn 算子（build.sh --pkg 编）：blockDim=1 忙等轮询本卡状态位（现由对端写）→ 写 done。

1 · MPI
mpirun -n 2，每进程一个 rank（dev=rank）
2 · 建链
root 取 RootInfo → MPI_Bcast → HcclCommInitRootInfoConfig(rank=2, hcclOpExpansionMode=CCU) → 建出 ccuContainer
3 · 流1 CCU（0.5RTT 跨卡写）
建 channel → clear → PreSync 换对端 status 地址/token → RecordExpectCount → 跨卡 WriteNbWithArriveNotify 写对端 status → Waitallpeersarrive(R-1) 等本卡被对端写好
4 · 流2 AIV
aclnn teardown 忙等本卡 statusGm[0]==1（对端写的）→ 写 doneGm[0]=1
5 · 校验
同步两流 → host 读 done==1 → 两 rank 各自 PASS

teardown 的忙等轮询本身就是跨流同步。两 rank 对称：各自把就绪值跨卡写给对端、各自等对端写好本卡 status，再由本卡 teardown 轮询 slot0。状态写是真跨卡（0.5RTT），但 payload 极小（仅就绪标志 32B）。不死锁：先各自非阻塞 Write 再各自 Wait，两写都已发射→两等都能解。

2 · 为什么必须 2 die

a6 报 [HcclCcuKernelRegister] ptr [ccuContainer] is nullptr 的根因：CCU 容器不是 new 出来的，是 HCCL/HCOMM 库在【CCU 扩展模式 + rank_size≥2】下建 comm 时副作用式创建的（基线 hccl_test_common.cc:861-941 即此路径，mpirun -n 2 跑通）。单 rank 不建容器（a5 实测 1-rank CCU 实例不可用）→ 故最小验证也必须 2 die。

9 · a6 上手核验三步（编过 + 链上）

① 核 CCU API 签名（跨卡写的 4 数据面 API + PreSync；a5 已核 CcuKernel 侧存在，4 数据面 API impl 由 SE 在 a6 libhcomm 补全）：

grep -n "RecordExpectCount\|WriteNbWithArriveNotify\|Waitallpeersarrive\|clearallpeersarrive" <a6>/.../moe_dispatch_ccu_api.h
grep -n "NotifyRecord\|NotifyWait\|CreateRemoteAddr\|CreateVariable" <a6>/.../hcomm/ccu/ccu_kernel.h

facade dispatch_setup_ccu_api.h 的 Mc2CcuKernelBase 4 个签名须与参考逐字一致（否则链不到 SE 实现）；其它别动。

② build 顺序（驱动要链 teardown 的 libcust_opapi，先算子后驱动）：

bash build.sh --pkg --experimental --soc=<a6 token> --ops=dispatch_teardown -j16
cd experimental/mc2/dispatch_setup && cmake -B build -DDISPATCH_CCU_A6=ON \
  -DASCEND_CANN_PACKAGE_PATH=<a6 CANN> ... && cmake --build build -j16

③ nm 核 CCU 符号导出（a6 libhcomm 须导出，a5 为空才链不了）：

nm -D <a6>/.../libhcomm.so | grep -iE "HcclCcuKernelLaunch|HcclCcuKernelRegister|HcclThreadAcquireWithStream|CcuKernel"

非空 → 能链；空 → 该 a6 libhcomm 没编出 CCU 符号（换库 / 确认 CCU 特性已开），非改码能解决。
