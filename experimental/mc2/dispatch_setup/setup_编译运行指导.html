1算子原型（4 算子 I/O · docx 真值 ↔ 本实现）

完整逐字段对齐表见「端到端手把手讲解」§1；此处给编译 / 联调需要的 I/O 契约与硬件强制偏离摘要。

算子输入输出
dispatch setup
(CCU)		x = xData[bs,h] fp8 + xScale[bs,h/32] e8m0 · routeTable[bs*topk,3] int64(host预算) · 本卡 dataRegion/scaleRegion 接收区(PreSync 换址) · commCmdInfo/oneBuf写对端 dataRegion[R*E*bs,h] fp8 + scaleRegion[R*E*bs,h/32] e8m0(expert-major) · 本卡 ready[0..R)=1
dispatch teardown
(AIV)		token_data[R*E*bs,h] + token_scale · wish_cnt[R*E] · expert_ids[bs,topk]expand_x[A,h] + expand_scale · send_counts[R*E] 前缀和 · expand_idx[bs,topk] · expert_token_nums[E]
combine setup
(CCU)		expandXData[A,h] fp8 + expandXScale · assistTable[A,3] int64(host预算) · 本卡 combineData/combineScale 接收区 · commCmdInfo/oneBuf写对端 combineData[R*E*bs,h] fp8 + combineScale[R*E*bs,h/32] e8m0
combine teardown
(AIV)		combine_data[R*E*bs,h] + combine_scale · expert_scales[bs,topk] · expand_idx[bs,topk] · expert_ids[bs,topk]x[bs,h] bf16

A = R·bs·min(topk,E)。真实场景 R=2/E=4/bs=8/topk=8/h=7168 → A=64，数据区 [R*E*bs,h]=[64,7168]。

setup 侧因 CCU 硬件/API 无法直译 docx 原型的偏离（等价实现、数据布局零偏离，详见手把手 §1）：
  • wishCnt 输出：docx 是 dispatch setup 的输出；实现由 driver host 预算（CCU 无 StoreVariableAt、不能动态标量 GM 写累加）。shape / 语义 [R*E] 不变。
  • expert_id_2_dst_va_map → PreSync 换基址 + token + host 预算 routeTable（CCU 访存是 (VA, token) 对，token 须运行时 PreSync 换来，纯 host VA 不可寻址）。
  • expert_id_2_dst_notify_va_map → per-channel/tag arrive-notify（RecordExpectCount + WriteNbWithArriveNotify + WaitallpeersarriveNotify），非 per-expert Xn 地址。
  • mxfp8：每数据区拆 payload(fp8_e4m3fn) + scale(e8m0, h/32) 两个 GM——docx「mxfp8 量化后面加」要求，非偏离。
  • combine 数据区 [R*E*bs,h]：docx 已修正含 *bs，与实现完全一致。

2A5 上能做的：地址 math 端到端自检

CCU 本体跑不了，但 CCU 执行的地址逻辑（host 预算的 expert-major 落点）是纯 C++、可在 a5 完整验证——用一个 host 侧模型模拟整条数据流，检查每个 token 精确往返。

3A6 上编译（CCU 本体 + 驱动）

每个 setup 是独立 standalone cmake 工程（不走 ops-transformer 注册框架），产出 host 驱动 exe。A6 上开 *_CCU_A6=ON 才编入 CCU kernel。

# A6（ssh 上去；CANN/hcomm 为 a6 版）
cd /home/developer/ops-transformer/experimental/mc2/dispatch_setup
cmake -B build_a6 -DDISPATCH_CCU_A6=ON -DSOC_VERSION=<a6 soc> \
      -DASCEND_CANN_PACKAGE_PATH=<a6 CANN> -DMPI_HOME=<mpi 根>
cmake --build build_a6 -j
# combine 同理
cd ../combine_setup && cmake -B build_a6 -DCOMBINE_CCU_A6=ON ... && cmake --build build_a6 -j
为什么 A5 编不了 CCU（实测铁证）：a5 缺 ccu_kernel_arg.h/ccu_types.h；channels_ 是 private unordered_set（a6 可索引）；CompletedEvent 无 SetMask。A6-proven 真实参考在 a5 上同样编不过 → 不是代码问题，是 a5 CCU 头/库与 a6 不同代。故 DISPATCH_CCU_A6=OFF（a5 默认）只编驱动本体、不编 ccu.cpp。

4A6 上运行（chain_e2e 四算子链，2-rank MPI）

# 一键：编两 teardown 包 + 装包 + 编链驱动（CCU 开）+ 运行提示
cd experimental/mc2/chain_e2e && TARGET=a6 ./run.sh
# 清场后（run.sh 末尾也会给出以下提示）：
npu-smi info; pkill -9 chain_e2e_driver; pkill -9 python; sleep 3
source <a6 CANN>/set_env.sh
export ASCEND_CUSTOM_OPP_PATH=${ASCEND_OPP_PATH}/vendors/custom_transformer   # teardown aclnn 需要
export LD_LIBRARY_PATH=<CANN>/lib64:<ops-transformer>/build:$LD_LIBRARY_PATH
mpirun --allow-run-as-root -n 2 ./build/chain_e2e_driver   # 可传 [bs topk h E [seed]]，默认 8/8/7168/4
# 期望：每 rank 打印 ①②③④ 各段 launched + [rank r] PASS: 链端到端 golden bad=0

链驱动职责：① host 预算 routeTable/wishCnt/assistTable/expandIdx（setup_host_precompute.h）；② 分配全部 GM 区（x mxfp8 / data·scale 区 / expandX / combine 区 / commCmdInfo）；③ 建 CCU container（rank≥2）+ channel（UBC_CTP）；④ 单进程顺序 launch ①dispatch_setup(CCU)→②dispatch_teardown(aclnn)→③combine_setup(CCU)→④combine_teardown(aclnn)，段间 aclrtSynchronizeStream + MPI_Barrier 定序（非 ready 位轮询——teardown 本链不读 ready）；⑤ host mxfp8 golden 比对。
注：旧 dispatch_min_driver 是 2 算子 status 位握手原型（4 参 TaskArg，与当前 14 参 kernel 不兼容），仅留作 CCU 拉起机制母体参考，不用于真数据面。

5常见坑速查

现象根因解
链接 undefined: WriteNbWithArriveNotify / CcuKernel*SE 实现 a6-only；或类名/签名/大小写没逐字对齐A6 libhcomm 才有；Waitallpeers大W/clearallpeers小c 一字不差
a5 编 ccu.cpp 报 ccu_kernel_arg.h 缺a5 CCU 头与 a6 不同代a5 用 *_CCU_A6=OFF（不编 CCU）；CCU 编译只在 a6
ccuContainer is nullptrrank<2（CCU 容器须 rank≥2）必须 mpirun -n 2
107003 stream not in current context用了 aclrtCreateContext用 aclrtSetDevice 隐式默认 context，别显式建
teardown 读到旧/错数据上板静默错：Variable 非 int64 排布 / token 没两端设 / dstByteOff 算错routeTable int64 步进 8；LocalAddr/RemoteAddr .token 必设；先跑 §1 地址自检
arrive-notify 不满足挂住某对端发 0 token 时 target 语义SE 确认（见手把手 §7 边界）；host 按实际发≥1 的对端数调 target
