# kv_quant_sparse_attn_sharedkv — N=64 / N=128 v0preload 性能验证报告

> 仅测性能(skip-golden)；真实内核耗时按算子名 `KvQuantSparseAttnSharedkv` 从 msprof `op_summary` 取，每配置多轮 IQR 中位数。Δ%<0 表示 after(v0preload)更快。

---

## 1. 背景：v0preload 做了什么，以及为什么 N=64 需要"出核(GM)"

**数据流背景**：该算子 K/V 共享(sharedkv)。每个 S2 基本块的右矩阵 **V0**(去量化后的 KV，`s2BaseSize=128 × D=512` bf16 = **128KB**)由 **AIV(向量核)** 算出，既作 `bmm1` 的右矩阵(当 K，算 Q·Kᵀ)又作 `bmm2` 的右矩阵(当 V，算 P·V)——一份 V0 要从 load 一直存活到 bmm2。

**v0preload 的本质**：加深软件流水(**3 级 → 4 级**)。让 AIV 提前产出 V0、AIC 提前预取(`IterateLoadQK`)，把"V0 生产 + 跨核交付"的延迟掩盖到**前序 tile 的 cube 计算**之后，减少 cube 空等。任务错位为 `vec0(t) / load(t-1) / bmm1(t-2) / bmm2(t-3)`(`runInfo[4]`)。

**为什么 N=64 必须"出核(GM)"**：4 级流水需要 **4 份在飞的 V0**。但 L1 装不下第 4 份——L1 总计 512KB = **416KB(P+Right)** + 96KB(Q)，其中 Right 区 = `3 × 128KB = 384KB` 已占满；第 4 个 128KB 的 V0 right buffer 放不进。于是把 V0 经 **GM(`v0ResGm`)** 中转(GM 充裕)：第 4 份(预取份)暂存 GM，AIC 用时再 `DataCopy` 回 L1。这就是"N=64 需要出核"的根本原因——**用 GM 换取 L1 放不下的那一级流水深度**。

**N=128 对比**：G=128 跨 **2 个 AIC** 拆分(各算 64 头)，V0 本就经 GM 跨核交付，故 commit `d9d483c` 直接把它从 3 级加深到 4 级。

**前后对照**：

| | N=64 | N=128 |
|---|---|---|
| before | V0 **直写 L1**(`CopyOutKvUb2L1`)，**3 级**(`runInfo[3]`)，无 GM 往返 | V0 经 **GM**，**3 级** |
| after(`753c1ba0`/`c632c8f2a`、`d9d483c`) | V0 经 **GM**(`CopyOutKvUb2Gm` + `IterateLoadQK` GM→L1)，**4 级**(`runInfo[4]`) | V0 经 **GM**，**4 级** |


## 2. 前后同步的变化（确有简化）

**N=64：跨核同步从 "L1 跨核" 改为 "GM 跨核"。**
- **before**：`ProcessVec0` 末尾 `outputL1.SetCrossCore()`(L1 `CROSS_CORE_SYNC_FORWARD`：AIV 在 `MTE3` 写完 L1 后置位，AIC 在读 L1 做 bmm1 前以 `MTE1` 等待)。V0 已在 L1，AIC 无需任何 GM 搬运。
- **after**：改为 `v0ResGm.SetCrossCore()`(GM `CROSS_CORE_SYNC_BACKWARD`：AIV `MTE3` 写完 GM 后置位，AIC 在 `IterateLoadQK` 内 `WaitCrossCore` 以 `MTE2` 等待、再 `DataCopy` GM→L1)。即**屏障从"L1 就绪(MTE1)"前移到"AIC 预取(MTE2)"处**，使 AIC 能提前发起 GM→L1 预取并与前序 cube 计算重叠。

**简化点（代码层面确实合并/精简了）**：
1. **删除双路分支**：`ProcessVec0` / `ProcessNotSparseKv` / `ProcessSparseKv` 中原有的 `if constexpr (IS_SPLIT_G) { v0ResGm.SetCrossCore()/CopyOutKvUb2Gm } else { outputL1.SetCrossCore()/CopyOutKvUb2L1 }` 双分支被删除 → **N=64 与 N=128 统一走 GM 一条路径**。
2. **合并主循环**：`ProcessMainLoopN64` + `ProcessMainLoopN128` 合并为单一 `ProcessMainLoop`，`PRELOAD_NUM` 统一为 3、统一 `runInfo[4]`。
3. **N=128 标志位前移**：旧版在 AIV 侧 `CrossCoreSetFlag<MTE3>` 处置位，新版移到 AIC 侧 `IterateLoadQK` 的 `CrossCoreSetFlag<MTE2>(10)`(对齐到预取流水)。

**代价**：N=64 运行期多了一段 GM→L1 预取(`MTE2`)——但这正是 4 级流水要掩盖的延迟；换来的是"双路合一 + 双主循环合一"的代码简化与更深的流水。

**Buffer 分配不变**：`l1Right` 仍 3×128KB、`l1P` 2×16KB(DB)、`l1Q` 96KB；4 级流水靠 `runInfo[4]` 的任务错位**复用同样的 3 个物理 L1 buffer** + GM 暂存(每份 V0 在某个 L1 槽的存活期仍 ≤3 轮 load→bmm1→bmm2)。
