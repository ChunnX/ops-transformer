# KCTQ 自验证步骤说明

> 对应任务书 §4 交付件之「自验证步骤说明」。本文件描述**在昇腾 NPU 环境上从零复现**本算子
> 自验证结果的完整步骤；所有脚本均在仓库内，命令可直接复制执行。
> 算子仓：`ops-transformer`（个人 fork `jingkai-2026/ops-transformer`），分支 `kv_cache_turbo_quant`，
> 目录 `experimental/attention/kv_cache_turbo_quant/`。

## 0. 环境要求

| 项 | 要求 |
|---|---|
| NPU | Atlas 800T A2 / 910B3（本自验证在 910B3 上完成） |
| CANN | **9.1.0**（任务书 §3.1 要求 ≥ 9.1.0）；需 **toolkit + 910b 算子包** 两件（见下方说明） |
| Python | 3.11（本容器 `/usr/local/bin/python3` = 3.11.4，下称 `PY`） |
| 依赖 | torch / torch_npu、numpy 1.26.4（环境锁）、ml_dtypes（golden.py 需要） |
| 说明 | **不要设置** `ASCEND_RT_VISIBLE_DEVICES`（容器内设备已直接可见） |

> 本轮（交付件 `2.2` / `3.2` 日志）实测环境：**CANN 9.1.0**、torch 2.7.1 / torch_npu 2.7.1.post4、
> Python 3.11.4。原始记录与复现命令见 `docs/evidence/repro/2026-09-30_kctq_bitexact_reverse/`
> （9.1.0 轮证据在其 `cann910/` 子目录，含环境留痕 `env.log` 与安装脚本）。
>
> **重要（安装包清单）**：CANN 9.1.0 的 toolkit 包**不含** 910b 内置算子与 `libhccl.so`，
> 只装 toolkit 会导致 `import torch_npu` 报 `libhccl.so: cannot open shared object file`。
> 需同时安装：
> 1) `Ascend-cann-toolkit_9.1.0_linux-aarch64.run`
> 2) `Ascend-cann-910b-ops_9.1.0_linux-aarch64.run`（提供 `libhccl/libhixl/libdvpp` 与
>    `ops_math/nn/cv/transformer/legacy/ras` 内置算子）
>
> 同一份内核亦已在 CANN 9.0.0 上复验（精度结果逐位一致、耗时在噪声内），
> 行归约结构在 9.0.0/9.1.0 上实测相同（`tools/verify_structure.py` 可直接在评测机复跑）。

环境自检（可选，先跑一遍确认工具链与 NPU 可用）：

```bash
npu-smi info | head -12          # 应看到 910B 设备
python3 -c \
  "import torch, torch_npu, ml_dtypes; print('npu devices:', torch.npu.device_count())"
```

与 `golden.py` 使用同一份文件。）

> 数据来源说明：交付轮的矩阵与输入取**任务包官方** `generate_data.py`（master_seed 20260928）的输出
> （`rotation_matrix` seed=42、`qjl_matrix` seed=137、各 case 的 `kv_vectors`），文件 sha256 逐行记在

> 统计等价兜底（任务包未随附矩阵时使用）。

## 2. 编译算子并安装

```bash
cd ops-transformer
bash build.sh --pkg --experimental --soc=ascend910b --ops=kv_cache_turbo_quant
cd build_out
./cann-ops-transformer-custom_linux-aarch64.run --quiet \
  --install-path=<CANN 根目录>/opp
```

> 说明：生成物为 `cann-ops-transformer-custom_linux-aarch64.run` 与 aclnn 头文件，
> 安装后可用同目录 `uninstall.sh` 回滚。构建/安装均需**先把环境指向目标 CANN**（见第 3 节），
> 否则会链到另一版本。
> （2026-09-23 轮在旧环境需 `PATH=/usr/local/python3.11.15/bin:$PATH` 以补齐 `packaging`；
> 本容器 `python3` 自带该依赖，无需前缀。若系统 `python3` 缺依赖，可显式指定
> `PATH=<你的 python 目录>/bin:$PATH`。）

编译自测用的 aclnn 示例驱动（`tests/run_all.sh` 需要它）：

```bash
cd ops-transformer/build_out
./cann-ops-transformer-custom_linux-aarch64.run --extract=/tmp/kctq_pkg --noexec
cd ../experimental/attention/kv_cache_turbo_quant
ASCEND_HOME_PATH=<CANN 根目录> \
  bash examples/build_and_run.sh /tmp/kctq_pkg/packages /tmp/kctq_example
```

## 4. 精度自验证（V1 契约 / V2 逐位对拍 / V3 指标）

```bash
cd ops-transformer/experimental/attention/kv_cache_turbo_quant
export KCTQ_BIN=/tmp/kctq_example/test_aclnn_kv_cache_turbo_quant
export KCTQ_MATERIAL=<含 golden.py 的任务包目录>
export KCTQ_GOLDEN=$KCTQ_MATERIAL/golden.py
export KCTQ_WORK=/tmp/kctq_selftest PYTHON=python3

# 【推荐】使用官方件的「每个 case 各自的输入」（含内积口径所需的 ip_query）：
#   KCTQ_OFFICIAL_DATA = 官方 generate_data.py 的输出根目录（其下每个 case 一个子目录）
export KCTQ_OFFICIAL_DATA=<官方生成器输出根，例如 .../.runtime/gen/v1>

# 一条命令跑完 5 个 case 的：计时 → V1 契约/V2 逐位对拍 → V3 精度 → 生态标准层
bash tests/run_all.sh 2>&1 | tee runall_final.log
```

> 这条单轮 stdout 就是交付件 `2.2 精度自验证日志.log`（其计时段落即 `3.2 性能自验证日志.log`）；
> `gqa_decode_b1` 的 bits=2/4 交叉档位见该日志末尾附录。
>
> **输入解析优先级**（`run_all.sh`）：`KCTQ_OFFICIAL_DATA/<case_name>/{kv_vectors,ip_query}.bin`
> → `$KCTQ_WORK/inputs/<case_name>/` → 旧布局 `inputs/t{tokens}_h{heads}/` → 由
> `tests/gen_case_input.py` 生成（固定 seed，统计等价）。日志逐行给出 `input=` / `ip_query=` 的 sha256。
> 注意：`gqa_mse2_t2048` / `gqa_mse4_t2048` 与 `gqa_prefill_t2048` 形状相同但**官方件各有一份输入**，
> 不要用一份输入跑三档。
>
**V3 指标口径（任务书 §3.2 字面式）**：`relMSE = Σ‖x−x̂‖²/Σ‖x‖²`（主量化 + 1-bit QJL **完整重构**
> `x̂ = (‖x‖·centroid[idx] + γ·√(π/2)/d·(sign@S)) @ H`）；内积 p95 用**字面分母** `max(|<q,x>|,1e-6)`，
> q 取官方 `ip_query`（与 x 相关）；另报逐向量 NMSE max/P95（2-bit 阈值 max<0.10、P95<0.06，
> 3/4-bit max<0.05）。工具：`tests/kctq_v3_precision.py`（`--ip-query` 指定官方 q；缺省按
> `BF16(x+0.5·N(0,1))` 自采）。

- 单 case 手跑（示例：t2048 bits=3；需已执行上面第 1 步生成数据）：

```bash
cd ops-transformer/experimental/attention/kv_cache_turbo_quant
W=/tmp/kctq_selftest; O=$W/out/gqa_prefill_t2048_b3; mkdir -p $O
$KCTQ_BIN --kv $W/inputs/t2048_h8/kv_vectors.bin --rot $W/data/rotation_matrix.bin \
  --qjl $W/data/qjl_matrix.bin --out $O --tokens 2048 --heads 8 --bits 3 --warmup 3 --repeat 10
$PYTHON tests/kctq_compare.py      --workdir $O --kv $W/inputs/t2048_h8/kv_vectors.bin \
  --rot $W/data/rotation_matrix.bin --qjl $W/data/qjl_matrix.bin --tokens 2048 --heads 8 --bits 3 \
  --material "$KCTQ_MATERIAL"
$PYTHON tests/kctq_v3_precision.py  --workdir $O --kv $W/inputs/t2048_h8/kv_vectors.bin \
  --rot $W/data/rotation_matrix.bin --qjl $W/data/qjl_matrix.bin --tokens 2048 --heads 8 --bits 3 \
  --golden "$KCTQ_GOLDEN"
```

## 8. 附加套件（边界用例 / 非法输入拒绝）

交付的算子目录自带两套附加自测，与上面的 5 个指定 case **共用同一 aclnn 驱动器**，评审可一键复跑
（用法见算子仓 `experimental/attention/kv_cache_turbo_quant/tests/README.md`）：

```bash
cd <算子目录>/tests
export KCTQ_MATERIAL=<含 golden.py 的任务包目录> KCTQ_GOLDEN=$KCTQ_MATERIAL/golden.py
export KCTQ_BIN=<算子包>/examples 编译出的 test_aclnn_kv_cache_turbo_quant
python invalid_cases.py --json invalid_cases.json   # 11 个非法输入必须被拒绝 + 合法基准被接受
bash run_edge_cases.sh                              # 10 个边界 case 与 golden.py 逐字节对拍
```

- **边界用例（10 例）**：`num_kv_heads` 上下界 4/32、`tokens=1`、对齐尾块 t3/t9/t17、
  多轮调度临界 t2081、行内容边界（全 0 行 / 次正规行 / 正负抵消行 × bits 2/3/4）、
  非有限输入行（inf / -inf / NaN / 1e4）。
  实测 **10/10 对拍通过**（恒定输入行逐字节 0 不一致；非有限行按声明域处理，NaN 不参与相等比较，
  见算子仓 `tests/README.md` §4.2 与 `tests/edge_cases.json`）。
- **非法输入（11 例）**：`mse_bits ∉ {2,3,4}`、`kv_vectors` rank≠3、`head_dim≠128`、
  head 数 <4 或 >32、dtype 非声明类型、矩阵形状 ≠[128,128]、空 tensor。
  实测 **11/11 被 `GetWorkspaceSize` 拒绝**（tiling 校验 9 例 + OpDef 原型 dtype 3 例）。
- 两套件的实测输出与结果 JSON 由上述命令落在 `tests/_out/` 下；套件入口、判据与已知限制见 `tests/README.md`。
