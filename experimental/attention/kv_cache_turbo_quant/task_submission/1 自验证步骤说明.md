# KCTQ 自验证步骤说明

> 对应任务书 §4 交付件之「自验证步骤说明」。本文件描述**在昇腾 NPU 环境上从零复现**本算子
> 自验证结果的完整步骤；所有脚本均在仓库内，命令可直接复制执行。
> 算子仓：`ops-transformer`（个人 fork `jingkai-2026/ops-transformer`），分支 `kv_cache_turbo_quant`，
> 目录 `experimental/attention/kv_cache_turbo_quant/`。

## 0. 环境要求

| 项 | 要求 |
|---|---|
| NPU | Atlas 800T A2 / 910B3（本自验证在 910B3，CANN 9.1.0 上完成） |
| CANN | ≥ 9.1.0（含 msopgen / bisheng 工具链） |
| Python | 3.11（本仓库统一用 `/usr/local/python3.11.15/bin/python`） |
| 依赖 | torch / torch_npu、numpy 1.26.4（环境锁）、ml_dtypes（golden.py 需要） |
| 说明 | **不要设置** `ASCEND_RT_VISIBLE_DEVICES`（容器内设备已直接可见） |

环境自检（可选，先跑一遍确认工具链与 NPU 可用）：

```bash
npu-smi info | head -12          # 应看到 910B 设备
/usr/local/python3.11.15/bin/python -c \
  "import torch, torch_npu, ml_dtypes; print('npu devices:', torch.npu.device_count())"
```

## 1. 生成测试数据与用例输入

```bash
cd ops-transformer/experimental/attention/kv_cache_turbo_quant/tests
PY=/usr/local/python3.11.15/bin/python
$PY gen_test_data.py  --out /tmp/kctq_selftest/data                      # rotation_matrix.bin / qjl_matrix.bin
$PY gen_case_input.py --out /tmp/kctq_selftest/inputs/t2048_h8 --tokens 2048 --heads 8
```

（`tests/run_all.sh` 会按 `case.json` 自动生成/复用上述数据，此步仅为单跑准备；两个矩阵为固定 seed 生成，
与 `golden.py` 使用同一份文件。）

## 2. 编译算子并安装

```bash
cd ops-transformer
PATH=/usr/local/python3.11.15/bin:$PATH \
  bash build.sh --pkg --experimental --soc=ascend910b --ops=kv_cache_turbo_quant
cd build
./cann-ops-transformer-custom_linux-aarch64.run --quiet \
  --install-path=/usr/local/Ascend/cann-9.1.0/opp
```

> 说明：`PATH=...` 是必须的（系统 python3.12 缺 `packaging`）；生成物为 `cann-ops-transformer-custom_linux-aarch64.run`
> 与 aclnn 头文件，安装后可用同目录 `uninstall.sh` 回滚。

## 3. 设置运行环境

```bash
source /usr/local/Ascend/cann-9.1.0/opp/vendors/custom_transformer/bin/set_env.bash
```

## 4. 精度自验证（V1 契约 / V2 逐位对拍 / V3 指标）

```bash
cd ops-transformer/experimental/attention/kv_cache_turbo_quant
export KCTQ_BIN=/tmp/kctq_example/test_aclnn_kv_cache_turbo_quant
export KCTQ_MATERIAL=<含 golden.py 的任务包目录>
export KCTQ_GOLDEN=$KCTQ_MATERIAL/golden.py
export KCTQ_WORK=/tmp/kctq_selftest PYTHON=/usr/local/python3.11.15/bin/python

# 一条命令跑完 5 个 case 的：计时 → V1 契约/V2 逐位对拍 → V3 双口径 → 生态标准层
bash tests/run_all.sh 2>&1 | tee runall_final.log
```

> 这条单轮 stdout 就是交付件 `2.2 精度自验证日志.log`（其计时段落即 `3.2 性能自验证日志.log`）；
> `gqa_decode_b1` 的 bits=2/4 交叉档位见该日志末尾附录。

- 单 case 手跑（示例：t2048 bits=3；需已执行上面第 1 步生成数据）：

```bash
cd ops-transformer/experimental/attention/kv_cache_turbo_quant
W=/tmp/kctq_selftest; O=$W/out/gqa_prefill_t2048_b3; mkdir -p $O
$KCTQ_BIN --kv $W/inputs/t2048_h8/kv_vectors.bin --rot $W/data/rotation_matrix.bin \
  --qjl $W/data/qjl_matrix.bin --out $O --tokens 2048 --heads 8 --bits 3 --warmup 3 --repeat 10
$PYTHON tests/kctq_compare.py      --workdir $O --kv $W/inputs/t2048_h8/kv_vectors.bin \
  --rot $W/data/rotation_matrix.bin --qjl $W/data/qjl_matrix.bin --tokens 2048 --heads 8 --bits 3 \
  --material "$KCTQ_MATERIAL"
$PYTHON tests/kctq_v3_precision.py  --workdir $O --kv $W/inputs/t2048_h8/kv_vectors.bin \
  --rot $W/data/rotation_matrix.bin --qjl $W/data/qjl_matrix.bin --tokens 2048 --heads 8 --bits 3 \
  --golden "$KCTQ_GOLDEN"
```

## 8. 附加套件（边界用例 / 非法输入拒绝）

交付的算子目录自带两套附加自测，与上面的 5 个指定 case **共用同一 aclnn 驱动器**，评审可一键复跑
（用法见算子仓 `experimental/attention/kv_cache_turbo_quant/tests/README.md`）：

```bash
cd <算子目录>/tests
export KCTQ_MATERIAL=<含 golden.py 的任务包目录> KCTQ_GOLDEN=$KCTQ_MATERIAL/golden.py
export KCTQ_BIN=<算子包>/examples 编译出的 test_aclnn_kv_cache_turbo_quant
python invalid_cases.py --json invalid_cases.json   # 11 个非法输入必须被拒绝 + 合法基准被接受
bash run_edge_cases.sh                              # 10 个边界 case 与 golden.py 逐字节对拍
```

- **边界用例（10 例）**：`num_kv_heads` 上下界 4/32、`tokens=1`、对齐尾块 t3/t9/t17、
  多轮调度临界 t2081、行内容边界（全 0 行 / 次正规行 / 正负抵消行 × bits 2/3/4）、
  非有限输入行（inf / -inf / NaN / 1e4）。
  实测 **10/10 对拍通过**（恒定输入行逐字节 0 不一致；非有限行按声明域处理，NaN 不参与相等比较，
  见算子仓 `tests/README.md` §4.2 与 `tests/edge_cases.json`）。
- **非法输入（11 例）**：`mse_bits ∉ {2,3,4}`、`kv_vectors` rank≠3、`head_dim≠128`、
  head 数 <4 或 >32、dtype 非声明类型、矩阵形状 ≠[128,128]、空 tensor。
  实测 **11/11 被 `GetWorkspaceSize` 拒绝**（tiling 校验 9 例 + OpDef 原型 dtype 3 例）。
- 两套件的实测输出与结果 JSON 由上述命令落在 `tests/_out/` 下；套件入口、判据与已知限制见 `tests/README.md`。
