# QAR/QRS 算子性能指标体系

> 基于 2026-05-13/14 实测数据，int8 量化，56 GB/s MTE 单口带宽上限

---

## 1. 综合带宽定义

```
V_data  = 算子每 rank 有效载荷
          QAR: bs × h × 1B
          QRS: bs × h / world_size × 1B

BW      = V_data / T_kernel      (GB/s)
Util    = BW / 56 GB/s × 100%
```

### 规律

**规律 1：8 卡比 4 卡整体低 3-5%（正常）**

8 卡需同步 8 个 rank 的 Win 区状态位，ReadStatus 忙等开销更大，T_latency 天然偏高。这个差距在所有 V 下稳定存在。

**规律 2：QAR 在 8 卡下表现健康**

4 卡→8 卡 QAR 大部分 V 降 3-4%，在 V ≥ 6 MB 后甚至追平（44.5% vs 43.8%）。QAR 的 CopyDataToWin 只写自己 Win 区，不随卡数线性放大。

**规律 3：QRS 在 8 卡 V ≥ 9 MB 急剧退化（异常）**

| V=9 MB | QAR 8卡 | QRS 8卡 | 说明 |
|--------|---------|---------|------|
| 每 rank 输入 | 72 MB | 72 MB | 相同 |
| CopyDataToWin 写入量 | 72 MB × 1 区 | 72 MB × **8 区** = **576 MB** | QRS 是 8 倍 |
| T_kernel | 358 us | 478 us | QRS 慢 34% |

QRS 的 all2all 模式导致 MTE 写带宽成为次瓶颈：576 MB / 478 us ≈ 1205 GB/s 聚合写带宽需求，远超单 MTE 口写入能力。即使多 AIV 核并发写，总带宽上限也是有限的。

## 8. 总结

```
            ┌─────────┬──────────────┬──────────────┐
            │  4 卡    │   8 卡 QAR   │  8 卡 QRS    │
┌───────────┼─────────┼──────────────┼──────────────┤
│ QAR/QRS差 │ < 3%    │  < 4% (V≤6)  │  需拆分       │
│ 平台 Util  │ ~43%    │  ~44%       │  ~33% (V≥9)  │
│ 最高档阈值 │ > 34%   │  > 32%      │  > 26%       │
│ 标准       │ 共用    │  独立       │  独立         │
└───────────┴─────────┴──────────────┴──────────────┘
```

**QRS 8 卡 V ≥ 9 MB 是唯一需要特殊对待的场景**，all2all CopyDataToWin 导致 MTE 写带宽成为瓶颈，Util 天花板仅 33%。其余场景 QAR/QRS 差异 < 5%，可共用标准。
