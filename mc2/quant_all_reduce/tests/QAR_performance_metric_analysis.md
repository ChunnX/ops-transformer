# QAR/QRS 算子性能指标体系

> 基于 2026-05-13/14 实测数据（2/4/8 卡，EVB + 标卡 + POD + Server 四环境），统一线性模型，R² > 0.99

---

## 1. 指标定义

```
V_data  = 每 rank 有效载荷
          QAR: bs × h × 1B
          QRS: bs × h / world_size × 1B

BW      = V_data / T_kernel      (GB/s)
Util    = BW / 56 GB/s × 100%
```

---

## 2. 数学模型

Kernel 时间建模为：

```
T(V, N, env, op) = T_base(N, env, op) + V / BW_eff(N, env, op)
                   └──固定开销──┘       └──每 MB 时间成本──┘
```

- `T_base` — ReadStatus 软同步 + kernel 启动
- `BW_eff` — 等效带宽（含 MTE 读带宽 + 反量化计算 + 流水线开销 + 环境 MTE 延迟差异）

### 2.1 环境差异

| 环境 | 卡数 | 特点 | 验收角色 |
|------|------|------|---------|
| **EVB 2p** | 2 | 开发板 | 早期验证 |
| **标卡 4p** | 4 | 标准卡 | 开发调试 |
| **POD 8p** | 8 | 单机 8 卡，高速互联 | 开发调试 |
| **Server 8p** | 8 | 多节点/跨 socket | **正式验收** |

Server 比 POD 整体慢 ~22%（每 MB 时间成本 +26%），根源在 Server 多 socket 拓扑下 MTE 跨 socket 访问 Win 区延迟较高，非算子代码。

## 3. EVB 2p + 标卡 4p + POD 8p 模型

### 3.1 QAR

| N | T_base | slope | BW_eff | Util_max | R² |
|---|--------|-------|--------|----------|-----|
| 2 | 4.6 us | 34.4 us/MB | 29.1 GB/s | 52.0% | 0.9995 |
| 4 | 6.1 us | 40.3 us/MB | 24.8 GB/s | 44.3% | 0.9949 |
| 8 | 21.3 us | 37.9 us/MB | 26.4 GB/s | 47.1% | 0.9971 |

```
T(V, N) = (-3.0 + 2.9N) + V × (35.6 + 0.4N) / 1000
```

slope 几乎不随 N 变化（0.4 us/MB/rank），CopyDataToWin 只写自己 Win 区。

### 3.2 QRS

| N | T_base | slope | BW_eff | Util_max | R² |
|---|--------|-------|--------|----------|-----|
| 2 | 4.6 us | 34.4 us/MB | 29.1 GB/s | 52.0% | 0.9995 |
| 4 | 6.1 us | 40.3 us/MB | 24.8 GB/s | 44.3% | 0.9949 |
| 8 (V≤6) | 11.5 us | 44.8 us/MB | 22.3 GB/s | 39.9% | 0.9975 |
| 8 (V>6) | −63.3 us | 58.9 us/MB | 17.0 GB/s | 30.3% | 0.9971 |

```
T(V, N) = (1.9 + 1.2N) + V × (32.1 + 1.7N) / 1000
          + 14.1 × max(0, V − 6) / 1000      [N ≥ 8]
```

slope 随 N 线性增长（1.7 us/MB/rank，是 QAR 的 4×），根源在 all2all CopyDataToWin 写入量放大 N 倍。N=8 大 V 时额外 +14.1 us/MB（MTE 写带宽饱和）。

## 4. Server 环境模型（正式验收标准）

Server 8p 是验收主环境。EVB 2p + 标卡 4p 数据表明 N ≤ 4 时 QAR/QRS 无差异，Server 2p/4p 可沿用同比例折算（待实测验证）。

### 4.1 QAR

```
T(V) = 18.4 + V / 21.0        (R² = 0.9979)
```

| 参数 | 值 | vs POD 8p |
|------|---|-----------|
| T_base | 18.4 us | 21.3 (−14%) |
| slope | 47.7 us/MB | 37.9 (+26%) |
| BW_eff | 21.0 GB/s | 26.4 (−20%) |
| Util_max | 37.4% | 47.1% (−10pp) |

### 4.2 QRS

```
T(V) = -8.2 + V / 15.6        (R² = 0.9983, V ≤ 6 MB 尾段主导)
```

两段拟合：

| 段 | 公式 | BW_eff | Util_max |
|----|------|--------|----------|
| V ≤ 6 | T = 2.3 + V / 16.9 | 16.9 GB/s | 30.2% |
| V > 6 | T = −41.3 + V / 14.8 | 14.8 GB/s | 26.5% |

```
T(V) = 2.3 + 59.1 × V              [V ≤ 6 MB]
T(V) = −41.3 + 67.5 × V           [V > 6 MB]
```

| 参数 | 值 | vs POD 8p |
|------|---|-----------|
| slope lo-V | 59.1 us/MB | 44.8 (+32%) |
| slope hi-V | 67.5 us/MB | 58.9 (+15%) |
| lo→hi 跳变 | +14% | +31% |

Server 上 all2all 退化比例更小（14% vs 31%），因为基线传输已慢，all2all 额外写开销被「淹没」。

## 5. 判定标准

```
T_actual ≤ T_expected(V, N, env, op) × 1.10   →  PASS
T_actual  > T_expected(V, N, env, op) × 1.10   →  FAIL（性能退化 > 10%）
```

### 5.1 EVB + 标卡 + POD 环境 T_expected

```
QAR:  T_exp = (-3.0 + 2.9N) + V × (35.6 + 0.4N) / 1000
QRS:  T_exp = (1.9 + 1.2N) + V × (32.1 + 1.7N) / 1000
             + 14.1 × max(0, V − 6) / 1000      [N ≥ 8]
```

### 5.2 Server 8p T_expected（正式验收）

```
QAR:  T_exp = 18.4 + 47.7 × V
QRS:  T_exp = 2.3 + 59.1 × V                  [V ≤ 6]
             −41.3 + 67.5 × V                  [V > 6]
```

## 6. all2all 放大原理（QRS 专项）

同一份 `mte_comm.h`，QAR 和 QRS 走不同分支：

```cpp
// mte_comm.h CopyDataToWin()
if constexpr (isReduceScatter) {
    // === QRS 路径 ===
    for (curRank = 0; curRank < rankDim; ++curRank) {
        CopyDataBlock(offset + curRank * slice, ...);  // 写到第 curRank 个 Win 区
    }
} else {
    // === QAR 路径 ===
    CopyDataBlock(offset, ...);  // 只写自己 Win 区
}
```

```
QAR:  每 rank 写 自己 Win 区 × 1    →  V_data 写入
QRS:  每 rank 写 所有 N 个 Win 区    →  V_data × N 写入（all2all 放大）
```

这就是 QRS slope 随 N 线性增长、大 V 下 MTE 写带宽饱和的根本原因。
