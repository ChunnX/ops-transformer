# A5 dispatch/combine 优化移植到 A3

已移植可复用的发送、计数合并、打包通知、接收轮转和收发重叠逻辑。A3 EP16
最终 55 个精度用例全部通过；dispatch 耗时下降 2.74%～26.41%，combine 的
7 个性能形状下降 4.01%～23.27%，另 1 个形状回退 0.72%。

## 基线与范围

开发基线为 `dispatch-perf-opt` 分支 `093c31e5cce3f44b69dd3480488608c9765b3bed`。
移植参考为 youhua 分支 `68c5f8ded246738cd42c77e63c78bf051395a0e0`，并进一步对照
开发基线中的 A5 MTE/fullmesh 实现。结果不以目录名为版本依据。

主要修改 A3 fullmesh 的 dispatch/combine。V3 复用 V2 内核，因此同步调整 V3 的
tiling info 读取。A3 hierarchy 的更改仅为 tiling 参数传递；保留其原通信算法。

## 优化来源与实现

| 内容 | 来源 | A3 实现 |
|---|---|---|
| Dispatch token 分核、多槽发送 | A5 PR5732；youhua `d20ba6952` | 普通发送按 token×topK 连续区间分核；保留 BS 路径同 token 的读取/量化复用；发送槽最多 8 个，独立事件保护复用 |
| Dispatch 计数发送合并 | A5 PR6074；youhua `87c2ca405` | 发送核先发布专家计数，同目的 rank 内连续专家合并 DataCopy；前缀和核上限 8，保留 A3 状态区布局 |
| Combine data-as-flag、接收轮转 | A5 PR6074；youhua `180cd9435` | 每块 480B 数据与 32B 完成标志同时发送；按连续就绪 slot 处理；两个 token 累加缓冲轮转；消费完后清除标志 |
| Combine 收发分核并行 | A5 PR10725，`7e379a195` | 部分核从首批 token 开始接收，发送核完成后参与剩余 token 接收；按接收轮次优先发送对应 token |
| Combine 发送预取 | A5 PR11528，`fb2ea1870` | 提前搬入 token t，再打包、发送 token t−1；单槽退化为串行；收尾补发最后一个 token 并消费全部残留事件 |
| Combine 缓冲初始化与索引分片 | 当前 A5 MTE 实现 | 一次初始化打包标志；按实际 UB 对发送三元组分片；按剩余 UB 分配输入/输出槽 |
| 小 tiling info 读取 | youhua `d0f248e96` / `68c5f8ded` | A3 入口只读取 info 成员；为已有完整 tiling 调用者保留转发重载 |

当前分支已有的 dispatch expertScales 分支外提予以保留。实现没有引入 A5 的
CCU、TP 通信协议、MXFP8/MXFP4 类型或特定硬件寄存器操作。

## 必须保留的产品差异

A3 继续使用其 HCCL/显式通信上下文适配器和窗口状态管理。A5 的 TP 路径及低精
类型支持不适用于此次 A3 fullmesh 移植。A5 权重搬运使用 Compact padding，
A3 不支持该接口，因此使用逐行 32B 对齐布局，同步调整权重索引及 UB 预算，
确保 K=1 等非对齐形状仍正确。行偏移在 token 初始化时计算，专家循环继续线性
访问权重，避免逐专家执行除法/取余。A3 INT8 反量化之后仍按原有精度顺序执行
Cast、可选加权和累加，不能直接替换为 A5 融合反量化实现。

Combine 的数据面协议在同一通信组所有 rank 上必须一致；不能将旧的独立通知协议
与 data-as-flag 协议混用。计算顺序仍为原 topK 顺序；并行调度改变 token 处理顺序，
不改变同一 token 的专家归并顺序。

## 配套资源与兼容性修正

1. A3 fullmesh tiling 复用 A5 的通信缓冲预算、发送最低预算和提前接收的权重/计时
   缓冲预算，先检查单缓冲能否容纳，再决定是否双缓冲。A2/hierarchy 保留原预算。
2. A3 combine 窗口检查按 `ceil(H×最大元素字节数/480)×512` 计入标志开销；标记
   默认关闭，因此不会无条件改变其他算子的窗口布局判断。
3. 发送阶段使用分槽事件，所有输入、输出槽在结束前配平，再允许 TPipe reset。
4. 空闲发送核不设置发送事件；实际发送数为零时不等待不存在的事件。
5. 保留完整 tiling 参数的 Init 重载，避免已有 A5 普通 dispatch 和 A3 融合调用方
   因接口精简而无法编译。

## 回归方法

以 `ep_test_mega_moe_T` Stage v2 为基础，在独立副本运行，原目录的用户改动保留。
原框架使用旧 fullmesh assist 索引，需要应用随用例提供的 `ep_test_current_abi.patch`：

- 构造当前 `A×128` 容量的辅助信息，有效区按每个接收 token 三个 int32 编排。
- Dispatch 校验全部有效三元组及对应 expandScales，同时沿用 payload、动态 scale、
  expertTokenNums、epRecvCounts 的原校验。
- 不再将 fullmesh 的 comm_quant_mode 强制覆盖为 0，确保 INT8 用例实际执行量化。
- 为 A3 INT8 combine 补充八元素分块量化/反量化的 CPU benchmark，保留 FP64 数学
  Golden 和原双标杆阈值；不通过放宽容差规避失败。

用例生成器、适配补丁及复现步骤见 `../tests/a3_fullmesh_regression/`。
基线与优化包使用不同 vendor、安装目录和编译缓存；使用相同输入 seed 和配置。
精度用例重复 10 次，检查窗口交替与清理；性能用例沿用框架 profiler，100 次执行，
统计稳态设备任务耗时。NPU 预检和 worker/HCCL 回收由框架负责。

### 环境来源与重复调用约束

早期 `--jit` 包没有设备二进制，运行时可能混用系统内核；该批精度和性能结果
全部作废，不纳入本报告结论。正式回归使用包含设备二进制的包、独立 OPP 目录
及明确的内核路径/哈希来源证明，不修改系统已安装 vendor。

精度循环在每次调用后执行相同的 rank barrier，限定 rank 进度差并重复使用窗口；
性能循环独立测量，不包含该 barrier。本报告不据此宣称任意 rank 进度差下的
稀疏连续调用均可工作。早期混用系统内核时的挂起现象也不能归因于本次源码。

## 实测结果

测试日期：2026-09-14。硬件为一台 A3，8 张物理卡、16 个逻辑 NPU，EP=16；
CANN 9.1.0，driver 25.5.1，torch 2.8.0+cpu，torch_npu 2.8.0.post4。
测试框架版本 `dc6f88ee893e509cad8f1464c2bb24383e8e79f6` 加随附适配补丁。

基线设备二进制的 dispatch 27 个、combine 26 个精度用例均通过。
优化版 dispatch 27 个、combine 26 个、dispatch→combine 往返 2 个精度用例
全部通过，共 55 个用例配置 × 16 个 rank。每个配置执行 10 次，校验末次输出。
Dispatch INT8 确认 quant_mode=2、combine INT8 确认 comm_quant_mode=2
实际传入，保留原双标杆阈值。

| dispatch | 32 | INT8 | 43.639 | 36.722 | 15.85% | 1 |

Dispatch 的 8 个形状均有收益，耗时下降 2.74%～26.41%。Combine 的 7 个形状
下降 4.01%～23.27%；B256 非量化形状两次测量的均值仍回退 0.72%，不算正收益。
这不是所有形状都等比例提速的优化。

较大非量化形状可能更受数据搬运开销限制：H=3584、BF16 的每 token 有效数据
为 7168B，data-as-flag 打包后为 7680B；新增包内开销可能抵消部分流水收益。
旧协议也有独立通知，不能把该比值直接当成总线上流量增幅。此处为基于代码和
核时延的解释，未进行分阶段耗时/链路计数器归因。

性能固定 H=3584、topK=8、256 个专家、BF16 输入，分别测量无通信量化与 INT8。
B=128/256 的非量化 combine 每版另复测一次，按两次独立采集的均值统计；
其他形状每版采集一次。每个 rank 每次执行 100 次，筛选 `MoeDistributeDispatchV2` 或 `MoeDistributeCombineV2`
设备任务，保留最后 50 次，再对 16 个 rank 的均值取平均。收益定义为
`(基线耗时−优化耗时)/基线耗时`，不将启动、编译或 CPU 校验耗时计入。
本轮采用 eager 模式；沿用框架的大张量 exp 预热，结果不等同于图模式或端到端 MoE。

### 覆盖边界

本轮硬件验证覆盖普通 A3 fullmesh V2 接口。V3 设备内核随包编译，但未直接运行
V3 接口；A2、A5、hierarchy、共享专家 rank、弹性缩容及融合 AddRmsNorm 未完成
硬件回归。单机 EP16 收益不能直接外推到 EP64/EP128。
