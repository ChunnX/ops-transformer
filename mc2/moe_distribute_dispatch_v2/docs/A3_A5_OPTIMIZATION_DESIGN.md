# A3 dispatch/combine 优化设计

最近完成完整回归的 rawmanual 已通过 EP16 全部 293 项主精度、15 项补充边界和 2 项 INT8 连续检查，并完成 64 项模型性能配对。Dispatch/Combine 几何平均耗时分别下降 19.11%/9.73%；两项 dispatch 小幅回退尚在处理。下面描述 rawmanual 的设计；rangeinit 只作为诊断补丁保存，8 项 BF16 精度通过，但性能受并发占用干扰，未合入业务代码。结果见 [EP16 泛化报告](A3_EP16_GENERALIZATION_REPORT.md)。

这次移植保留 A3 的通信上下文、窗口状态和数值计算方式，复用 A5 的任务分配、计数发送合并、发送预取及每槽事件管理。Combine 在 A3 上继续使用连续数据区和独立完成标志：泛化测试发现直接移植 packed data-as-flag 与提前接收的组合会使部分大 BF16 用例回退，最终候选撤回了这部分数据面改动。

## Dispatch

主要优化位于 `op_kernel/arch22/moe_distribute_dispatch_v2_full_mesh.h`，需要显式选择 `comm_alg="fullmesh_v2"`。默认算法的兼容测试单列，不能用默认路径结果证明该分支收益。

发送任务按 token×topK 连续区间分配，BS 路径继续复用同一 token 的读取和量化结果。发送核发布专家计数，同一目的 rank 的连续专家计数合并搬运。计数核默认上限为 8；对 EP≤16、非量化、B≥128、H≥4096、没有共享专家 rank 且专家数不是 2 的幂的形状，上限收敛为 4。条件来自 Kimi/DeepSeek-V2 等实测，保留 2 的幂专家数原分配，避免扩大适用范围造成回退。

精度回归补充了三项必要修复：BS 发送按正确偏移写入专家权重；发送阶段复用已申请的路由与计数/量化 scratch，消除重复 UB 分配；打包源缓冲覆盖完整 480B 块及元数据尾部。同步按实际读写流水保护槽复用，没有改变量化规则或精度阈值。

Host 保留 A3 非 hierarchy 的 packed 槽容量预留校验，覆盖 fullmesh_v2 dispatch 的窗口前缀预留。Combine 恢复原数据协议后仍使用这一保守容量检查，没有因性能分支切换改变通信窗口地址。

## Combine

主要实现位于 `op_kernel/arch22/moe_distribute_combine_v2.h`。所有 A3 形状始终使用同一种原有协议：先写连续 token 数据，每批数据发送排空后再写独立完成标志，接收方按原 topK 顺序做反量化、加权和累加。

每批先预取第一个 token；循环先搬入下一项，再发送或量化当前项。非量化复用原有发送槽数，使用 MTE3→MTE2 事件保护槽再次写入，使用 MTE2→MTE3 事件保护数据发送。量化输入保持双缓冲，使用 V→MTE2 和 MTE2→V 事件保护搬入与量化；输出继续使用原发送队列。缓冲容量沿用 A3 原预算，未额外增加通信窗口。

最后一项不再预取不存在的后继。批尾仍保留 MTE3 排空和完成标志发送；发送结束消费所有剩余可复用事件，包括未使用槽的初始化事件，然后才允许 TPipe 重置。零发送任务不初始化这些事件，也不执行对应等待。

最初把输入队列深度直接增加到 2 的实现引入很大标量开销。Qwen3-30B/B256/BF16 探针中，Scalar 时间从参考约 22.96 μs 增至 143.10 μs；改用每槽事件后降至 16.79 μs，目标耗时从参考约 85.18 μs 降至 82.49 μs。该数据是定位对照，最终收益须查看完整配对矩阵；并行流水时间不能相加。

不按 token 数或量化模式混用 raw 与 packed 两种数据布局，避免一类调用写入的数据成为另一类调用的残留完成标志。此前切换方案的精度失败及其他未改善性能的方案均归档，未保留为业务分支。

## 产品隔离与兼容

保留 A3 的 HCCL/显式上下文适配器、原窗口状态区、INT8 反量化和累加方式。没有引入 A5 的 CCU、TP 协议、MXFP8/MXFP4 或特定寄存器行为。A5 源码未修改。

V3 与融合 RMSNorm 共享 A3 combine 头文件，因此保留原完整 tiling 参数重载。V2/V3 二进制随包编译；本轮硬件验收针对 A3 EP16 V2，不能将其等同于 V3、融合 RMSNorm、hierarchy、共享/弹性或跨机 EP64/128 的硬件覆盖。

## 回归与交付

测试使用 `ep_test_mega_moe_T` 的独立副本，原目录未改动。补丁适配当前 assist ABI、有效三元组和专家权重校验、INT8 CPU 双标杆，以及逐用例结果、逐 rank 窗口/精度记录和 rank 0 库加载来源；不放宽精度阈值。

主矩阵包含 293 个精度用例和 64 个性能形状；另有同通信域切换、每 rank 32 次连续变输入、15 个边界用例和 2 个 H3584 旧规格性能形状。八个模型的 H/E/K 来自固定版本官方配置，B、通信 dtype 和量化模式为测试选择。生成器、配置快照、SHA-256 和复现步骤见 [泛化测试目录](../tests/a3_fullmesh_regression/generalization/README.md)。

精度重复 10 次并校验有效输出；性能沿用原 AllReduce/Exp 预热，每 rank 调用 100 次，取最后 50 个目标 kernel，汇总完整 16 rank。参考与候选使用独立 vendor、缓存和来源记录，以及相同输入和 8 GiB 窗口；最高边界形状单独用 9 GiB 验证。缺少 rank、初始化失败或精度失败的数据不计收益。

早期移植和所有性能定位实验保存在 [阶段与回归报告](A3_EP16_GENERALIZATION_REPORT.md)。最终报告将明确实测包、提交、通过数量、性能回退与未覆盖范围。
