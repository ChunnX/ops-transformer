新增行数来源:
  - 每个 module 文件需要 copyright/header guard/include 块

设计原则（与首次 modules/ 版本的区别）:
  - class MegaMoe 保留所有成员变量和 buffer 所有权，不做拆分
  - module 文件只包含纯计算逻辑（namespace 内自由函数或 struct/class 的 static 方法）
  - 通过显式参数传入 buffer 引用 + TileInfo，避免 buffer 定义重复
  - orchestrator Process() 在入口处从硬件 API 计算 TileInfo，然后传给所有 module 调用

四、模板参数传递方式
─────────────────────────────────────────────────────────────────────────────────

  原始: class MegaMoe<XType, OutputType, TopkWeightsType, Weight1Type, QuantMode, CombineQuantMode>
        所有方法共享同一模板参数列表，内部类型 (QuantOutType 等) 作为类 typedef 自动可用。

  拆分后:
    - orchestrator mega_moe.h: 保留原始完整模板参数列表，计算所有派生类型
    - 各 module 文件: 只接收自己需要的类型参数子集:

      topk_gather.h:    无模板参数（纯运行时参数）
      token_dispatch.h: <ActivationType, QuantOutType, QuantScaleOutType, QuantMode, ENABLE_A8W4>
      gmm1.h:           struct Gmm1Module<QuantOutType, Weight1Type, SwigluQuantOutType, QuantScaleOutType, QuantMode, ENABLE_A8W4, ENABLE_A4W4>
      swiglu_quant.h:   <SwigluQuantOutType, QuantScaleOutType>
      gmm2.h:           class Gmm2Module<QuantOutType, Weight1Type, SwigluQuantOutType, QuantScaleOutType, QuantMode, CombineQuantMode, ENABLE_A8W4, ENABLE_A4W4>
      combine_send.h:   <ElementMMadOut2> 或 <QuantMode, ElementMMadOut2>
      combine_reduce.h: <CombineQuantMode> + BuffInit 额外需要 <TopkWeightsType>

    - orchestrator 通过 using typedef 将 module 类型与自身模板绑定:
        using Gmm1Module = MegaMoeModules::GMM1::Gmm1Module<QuantOutType, Weight1Type, ...>;
        using Gmm2Module = GMM2::Gmm2Module<QuantOutType, Weight1Type, ...>;

    - constexpr bool (ENABLE_A8W4, CombineQuantMode != COMBINE_NO_QUANT) 的传递:
      部分模块接收为模板参数 (gmm1.h, gmm2.h)
      部分模块接收为运行时 bool 参数 (topk_gather.h 的 combineQuantEnabled / enableA8W4)
      原因: namespace 自由函数无法接收 constexpr bool 作为模板参数同时又保持签名简洁，
            故 TopKGather 的 ResetFlagList/SendCntCal 改用运行时 bool；
            GMM1/GMM2 的 struct/class 可以在模板参数中保留 constexpr bool 用于 if constexpr 分支。

五、与首次 modules/ 版本的设计差异
─────────────────────────────────────────────────────────────────────────────────

  | 维度               | 首次 modules/ 版本                    | redo single_core/ 版本                |
  |────────────────────|───────────────────────────────────────|───────────────────────────────────────|
  | buffer 所有权       | 每个模块 State struct 复制 buffer 声明  | orchestrator class 独占所有 buffer     |
  |                    | → 定义重复, 所有权模糊                  | → module 通过引用参数接收              |
  | 函数形式            | namespace 自由函数                     | namespace 自由函数 / struct 静态方法   |
  |                    |                                        | / class 成员方法 (gmm1/gmm2 需要       |
  |                    |                                        |   constexpr typedef)                   |
  | TileInfo            | 无独立文件, 内嵌在各模块               | 独立 mega_moe_tile_info.h             |
  | ExpertLoopState     | 各模块自定义                           | 统一在 mega_moe_tile_info.h            |
  | TupleShape/BlockOffset | 各模块自定义                       | 统一在 mega_moe_tile_info.h            |
  | orchestrator        | 独立 orchestrator 文件调用模块         | mega_moe.h 即 orchestrator             |
  |                    | class 仍持有 buffer 但更薄             | class 保留原始结构 + Process 组装调用   |

六、已知问题与未来重构范围
─────────────────────────────────────────────────────────────────────────────────

  6.1 深层依赖仍使用 GetBlockIdx
    - mega_moe_impl.h: GroupMatmulSwigluQuant / GroupMatmul2 / GroupMatmul2CombineA8W4
      内部调用 ComputeCoreGrouping(aivCoreIdx_, ...) → 未提取
    - mega_moe_combine_send.h: CombineSendTokenToRemote
      内部调用 GetBlockIdx()/GetBlockNum() → combine_send.h 已注释标记
    - block_epilogue_swiglu_mx_quant.h: 内部可能有 GetSubBlockIdx() → 未验证

    这些文件不在本次拆分范围内（约束: 保持原始依赖文件不动），
    未来需逐层下沉提取。

  6.2 constexpr bool 运行时化
    TopKGather::SendCntCal 的 enableA8W4 参数从 constexpr → bool，
    导致 if constexpr (ENABLE_A8W4) 变为 if (enableA8W4)，
    编译器无法在 false 分支做类型检查消除。
    当前不影响功能（运行时分支选择正确），
    但理想做法是将 SendCntCal 也改为模板参数传入 ENABLE_A8W4。

  6.3 EVENT_ID 宏
    combine_reduce.h Unpermute 中 EVENT_ID0/1 改为硬编码 0/1，
    因 AscendC::EVENT_ID0 在 include 链中未定义。
    原始代码使用 EVENT_ID0 = 0, EVENT_ID1 = 1，数值一致，
    但建议未来确认宏定义来源并统一。

  6.4 winRankAddr_ 全局变量
    combine_reduce.h CrossRankSyncInWorldSize 使用 winRankAddr_[i]，
    此全局变量定义在 mega_moe_base.h (inline GM_ADDR winRankAddr_[HCCL_MAX_RANK_SIZE])。
    orchestrator Init() 中已初始化 winRankAddr_[]，
    但 module 文件依赖全局变量的链接正确性。
    未来可考虑将 winRankAddr_ 也作为参数传入。

  6.5 orchestrator 保留的 BuffInit 函数
    DispatchBuffInit() / SendAndQuantBuffInit() 仍为 orchestrator 类方法，
    因为它们负责 UB tensor 地址分配，与 buffer 所有权绑定。
    未来可考虑将 BuffInit 也提取为 module 函数（传入 buffer 结构体引用），
    但需注意 UB 地址分配必须与 buffer 使用在同一 class 生命周期内。
