MegaMoe · AIC rolling scheduler audit

热点核为何跨 wave 固定，以及当前 cursor 修复如何打散它

这是 owner-level 调度模型：严格复现 startBlockIdx 的模 36 推进和当前 exact-resonance 条件， 用来观察每个 stage 的“余数 tile”落在哪些 AIC 上。它不是 cycle-accurate 性能 trace。

输入与预设

默认例子故意构造 GMM1=60 tiles、GMM2=120 tiles：两段合计正好回到 wave 起点， 但 GMM1 自己有 24 个余数 tile。

最容易误判的一点： exact-resonance 例子里，每颗核每个 wave 的“总 tile 数”甚至可以完全一样； 热点来自 GMM1/GMM2 的额外任务角色固定，而两类 tile 的真实耗时、依赖等待和访存代价并不相同。

Cursor 推进：修复只改下一 wave 的起点

当前 wave 内 GMM1 和 GMM2 的 owner 完全不变；补丁在 GMM2 全部结束并 publish ready 后， 才可能把下一 wave 的起点从 S2 改为 S1。

当前代码实际做了什么

它解决的范围

  • 检测整 wave 的自然结束 cursor 是否精确回到 wave 起点。
  • 同时要求 GMM1 自己有非零余数，排除 GMM1 已经完全均分的情况。
  • 命中时使用 GMM1 end cursor 作为下一 wave 起点，让较重 stage 的余数 owner 跨 wave 轮转。
  • 只发生在仍有下一 wave 时；最后一波不做无意义改写。

安全边界

  • 不改变当前 wave 的 tile、地址、同步或 ready 粒度。
  • AIC、AIV0、AIV1 各自维护本地 cursor，但必须用相同 tileNum 做完全一致的虚拟推进。
  • 当前逻辑仅位于 direct-GM rebuild 的 ProcessGmm2GmWaves 路径，不覆盖 legacy/layered 调度。
  • 收益假设是“重复 stage 角色”确实主导关键路径，仍需宏开关 A/B 上板证明。
gmm1End = (waveBegin + gmm1Tiles) % aicNum
gmm2End = (gmm1End + gmm2Tiles) % aicNum

fixedRoleResonance =
    (gmm2End == waveBegin) &&
    (gmm1End != waveBegin)

nextWaveBegin = fixedRoleResonance ? gmm1End : gmm2End

需要警惕的陷阱

  1. 只抓 exact resonance。 若整 wave 每次只前移 1 核，角色在有限 wave 内仍高度重叠，但当前条件不会触发。点击“每 wave 只漂 1 核”可见。
  2. tile 数不等于耗时。 GMM1/GMM2 的 K、访存、等待和尾 tile 成本不同；上面的成本权重只是观察假设，不是硬件测量。
  3. 不均匀 token 可能天然抵消，也可能反向。 某个 exact wave 的强制旋转，可能破坏后续不规则 wave 原本更好的自然去相关；“不均匀 wave 反例”展示一个合成反例。
  4. 均衡需要足够多 wave。 固定步长 r1 只访问 C/gcd(C,r1) 个 phase；通常一整个周期后才完全均摊，短序列仍可能偏斜。
  5. 最后一波不会被 cursor 修复。 hasNextWave=false 是合理的；默认 small-tail 策略会把 5+5+5+1 改成 5+5+6，但最后 6 专家的 terminal Combine 和 wave 内余数仍需独立评估。
  6. 慢核与 locality 不在模型内。 轮转可能把额外任务交给物理慢核，也会改变每核访问的 tile 区域；平均更均匀不保证单次 latency 必然更低。
  7. interleave 会改变 GMM1 tileNum。 开关变化后是否命中 exact resonance 也会变化；当前默认关闭，比较时必须固定权重布局和编译宏。
  8. cursor lockstep 是正确性前提。 未来若某种 dtype/空专家分支让 AIC 与 AIV 的 startBlockIdx 推进不一致，可能造成 epilogue 配对错误甚至等待挂死。

建议怎样验证

必须做的 A/B

  • 同一编译、同一权重布局，只切换 MEGA_MOE_BREAK_FIXED_CORE_RESONANCE=0/1。
  • 分别测：exact、多 wave；shift=1 的 near resonance；随机不均匀 M；5+5+5+1 与 5+5+6 A/B。
  • 至少看 P50/P90 和多次方差，不能只看一个最优点。

最有判别力的 trace

  • 每 wave 记录 waveBegin、gmm1End、gmm2End，先确认实际命中次数。
  • 按 AIC 记录 GMM1/GMM2 首尾，观察 stage 尾部是否从固定核组轮转。
  • 同时记录算子总耗时；热点图变均匀但总耗时不变，说明瓶颈不在 AIC 余数 owner。
