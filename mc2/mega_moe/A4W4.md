# MegaMoe 算子 MXFP4 (E2M1) 量化支持设计文档

## 1. 概述

### 1.1 变更目的

本次变更为 MegaMoe 算子新增 **MXFP4 (E2M1)** 量化模式支持（`QuantMode = 5`），使算子能够在 MoE 路由阶段将激活值量化为 4-bit 浮点格式（`fp4x2_e2m1_t`），从而降低显存占用和跨 Rank 通信带宽，提升整体 MoE 推理/训练性能。

### 1.2 量化模式总览

| QuantMode | 常量名 | 量化输出类型 | Scale 类型 | 存储类型 (ActivationType) | 每元素位宽 |
|-----------|--------|-------------|-----------|--------------------------|-----------|
| < 3 | — | `fp8_e4m3fn_t` | `float` | `fp8_e4m3fn_t` | 8-bit |
| 3 (`E5M2_QUANT`) | `E5M2_QUANT` | `fp8_e5m2_t` | `fp8_e8m0_t` | `fp8_e5m2_t` | 8-bit |
| 5 (`E2M1_QUANT`) | `E2M1_QUANT` | `fp4x2_e2m1_t` | `fp8_e8m0_t` | `uint8_t` | 4-bit (两元素打包) |

### 1.3 涉及文件

| 文件 | 变更类型 | 说明 |
|------|---------|------|
| `mega_moe_workspace_info.h` | 修改 | 新增常量定义 |
| `mega_moe.h` | 修改 | 类型系统重构 + FP4 偏移适配 |
| `moe_v3_common.h` | 修改 | 常量上提 + 新增 FP4 常量 |
| `moe_v3_gather_mxfp4_quant.h` | **新增** | MXFP4 Gather+量化 Kernel |
| `moe_v3_gather_mxfp8_quant.h` | 修改 | 常量迁移至 common |
| `moe_init_routing_v3_apt.h` | 修改 | 分发逻辑新增 FP4 分支 |

## 2. 类型系统设计

### 2.1 QuantTraits 模板特化

**变更前**：使用 `std::conditional` 的二分支逻辑，仅支持 E4M3 和 E5M2：

```cpp
using QuantOutType = typename std::conditional<
    ((QuantMode >= 3) && (QuantMode != 4)),
    fp8_e5m2_t, fp8_e4m3fn_t>::type;
```

**变更后**：引入 `QuantTraits` 模板特化，支持三种量化模式的可扩展设计：

```cpp
template<int32_t QuantMode>
struct QuantTraits {
    using OutType = fp8_e4m3fn_t;  // 默认 E4M3
};
template<>
struct QuantTraits<E5M2_QUANT> {   // QuantMode == 3
    using OutType = fp8_e5m2_t;
};
template<>
struct QuantTraits<E2M1_QUANT> {   // QuantMode == 5
    using OutType = fp4x2_e2m1_t;
};
```

### 2.2 ActivationType 引入

FP4 量化输出类型 `fp4x2_e2m1_t` 为 4-bit 类型，两个元素打包存储在一个 `uint8_t` 中。在 Global Memory 搬运和 Buffer 分配时，需要使用 `uint8_t` 作为实际存储类型：

```cpp
using ActivationType = typename std::conditional<
    Std::IsSame<QuantOutType, fp4x2_e2m1_t>::value,
    uint8_t,           // FP4: 存储粒度为 uint8_t（2个FP4元素打包）
    QuantOutType       // FP8: 存储粒度即量化类型本身
>::type;
```

**设计意图**：`QuantOutType` 保留语义（量化目标类型），`ActivationType` 用于所有涉及内存操作的场景（GlobalTensor、LocalTensor、Buffer 分配、指针偏移计算）。

### 2.3 QuantScaleOutType 保持不变

```cpp
using QuantScaleOutType = typename std::conditional<
    (QuantMode >= E5M2_QUANT), fp8_e8m0_t, float>::type;
```

E2M1_QUANT (5) >= E5M2_QUANT (3)，因此 Scale 类型为 `fp8_e8m0_t`，与 E5M2 模式一致。

## 4. MegaMoe 主类适配

### 4.1 CopyGMToGMPerToken

函数签名中所有 `QuantOutType` 替换为 `ActivationType`：

```cpp
__aicore__ inline void CopyGMToGMPerToken(
    GlobalTensor<ActivationType> dst,
    GlobalTensor<QuantScaleOutType> dstScale,
    GlobalTensor<ActivationType> src,
    int32_t rows, int32_t hiddenSize, int32_t& pingpongId);
```

内部 LocalTensor 同步更新为 `ActivationType`，保证 GM→UB→GM 搬运链路类型一致。

**关键变化**：`scaleLen` 的计算改为基于 `k_`（原始 hidden 维度）而非 `hiddenSize`（可能已经除以 FP4_NUM 的存储宽度），确保 scale 长度始终按原始元素数量计算：

```cpp
uint32_t scaleLen = Ops::Base::CeilDiv(static_cast<int32_t>(k_),
    static_cast<int32_t>(MXFP_DIVISOR_SIZE)) * MXFP_MULTI_BASE_SIZE;
```

### 4.2 DispatchTokens

FP4 模式下，`widthA`（数据宽度）需除以 `FP4_NUM`（因为两个 FP4 元素打包在一个 uint8_t 中），但 `widthAScale` 仍基于原始 K 值计算：

```cpp
int64_t widthA;
if constexpr(QuantMode == E2M1_QUANT) {
    widthA = Get<K_VALUE>(problemShape_) / FP4_NUM;  // 存储宽度减半
} else {
    widthA = Get<K_VALUE>(problemShape_);
}
int64_t widthAScale = Ops::Base::CeilDiv(Get<K_VALUE>(problemShape_),
                        static_cast<int64_t>(MXFP_DIVISOR_SIZE)) * MXFP_MULTI_BASE_SIZE;
```

所有 GlobalTensor 声明从 `QuantOutType` 改为 `ActivationType`。

### 4.3 UpdateGroupParams

FP4 模式下，Activation 数据的偏移量计算需除以 `FP4_NUM`：

```cpp
if constexpr (QuantMode == E2M1_QUANT) {
    Get<IDX_A_OFFSET>(baseOffset_) += (m * k) / FP4_NUM;
    Get<IDX_B_OFFSET>(baseOffset_) += (n * k) / FP4_NUM;
} else {
    Get<IDX_A_OFFSET>(baseOffset_) += (m * k);
    Get<IDX_B_OFFSET>(baseOffset_) += (n * k);
}
```

同理，`IDX_B2_OFFSET` 也做了 FP4 适配：

```cpp
if constexpr (QuantMode == E2M1_QUANT) {
    Get<IDX_B2_OFFSET>(baseOffset_) += (k * n / SWIGLU_N_HALF) / FP4_NUM;
} else {
    Get<IDX_B2_OFFSET>(baseOffset_) += (k * n / SWIGLU_N_HALF);
}
```

**注意**：Scale 偏移（`IDX_A_SCALE_OFFSET`, `IDX_B_SCALE_OFFSET`, `IDX_C_SCALE_OFFSET`, `IDX_B2_SCALE_OFFSET`）不受 FP4 影响，因为 Scale 始终按原始元素数量计算（每 32 个原始元素一个 scale）。

### 4.4 UpdateGlobalBuffer

所有 `sizeof(QuantOutType)` 替换为 `sizeof(ActivationType)`，确保指针偏移按实际存储类型计算：

- `ptrA` / `ptrA2` 偏移：`sizeof(ActivationType)`
- `bGlobal` / `b2Global` 偏移：`sizeof(ActivationType)`
- Scale 偏移保持 `sizeof(QuantScaleOutType)` 不变

### 4.5 FirstBuffInit

CopyTempBuf 的 Buffer 分配按 `ActivationType` 大小：

```cpp
tPipe->InitBuffer(CopyTempBuf_, BUFFER_ALIGN * sizeof(ActivationType));
```

## 5. MXFP4 Gather+量化 Kernel（新增文件）

### 5.1 文件：`moe_v3_gather_mxfp4_quant.h`

新增 `MoeV3GatherMxfp4Quant<T, U>` 类，实现 Gather（按 expert 路由搬运 token）与 MXFP4 量化的融合操作。

**模板参数**：
- `T`：输入数据类型（`half` / `bfloat16_t`）
- `U`：量化目标类型（`fp4x2_e2m1_t`）

### 5.2 整体处理流程

```
Process()
  ├── for each rowLoop:
  │     ├── CopyInExpandedExpertIdx()   // GM→UB: 加载排序后的行索引
  │     └── CopyExpandedXandMXQuant()   // 对每行每列块执行:
  │           ├── CopyIn()              // GM→UB: 加载原始 x 数据
  │           ├── Compute()             // VF 调用三步量化流水线
  │           │     ├── vfMxfp4ComputeMaxExp()   // Step1: 计算块内最大指数
  │           │     ├── vfMxfp4ComputeScale()    // Step2: 计算 MX Scale + invScale
  │           │     └── vfMxfp4ComputeData()     // Step3: 量化数据 x*invScale→FP4
  │           └── CopyOut()             // UB→GM: 写出量化数据 + Scale
```

### 5.3 三步量化流水线（VF 函数）

#### Step 1: `vfMxfp4ComputeMaxExp` — 计算块内最大指数

**目标**：对每 32 个元素（一个 MX 块）计算最大绝对值对应的指数（以 BF16 格式表示）。

**核心算法**：
1. **双搬入**（`DIST_DINTLV_B16`）：将 x 数据按奇偶位分离到 x0、x1 两个 RegTensor
2. **FP16 特殊处理**：若输入为 FP16，先检测 NaN/Inf，再转为 BF16 统一处理指数提取
3. **指数提取**：通过 `And` 操作提取 BF16 的指数位（`BF16_EMASK_AND_INF_VAL`）
4. **块内归约**：先 `Max(exp0, exp1)` 计算奇偶位两两最大值，再 `ReduceMaxWithDataBlock` 每 32B 归约
5. **非对齐搬出**：通过 `DataCopyUnAlign` 将归约结果紧凑写出到 maxExpBuffer

**与 MXFP8 版本差异**：算法逻辑相同，但函数名独立以避免符号冲突，且增加了 FP32 相关的 CastTrait 定义（供 Step3 使用）。

#### Step 2: `vfMxfp4ComputeScale` — 计算 MX Scale 和逆 Scale

**目标**：基于 maxExp 计算两个输出：
- `mxScale`（`float8_e8m0_t`）：写出到 expandedScale 输出
- `invScale`（`bfloat16_t`）：用于 Step3 量化 `xQuant = x * invScale`

**核心算法**：
1. **下限保护**：`maxExp < expLowerBound` 的位置替换为 `expLowerBound`（E2M1 对应 `0x0100`）
2. **共享指数计算**：`sharedExp = maxExp - expLowerBound`
3. **mxScale 生成**：`mxScale = sharedExp >> BF16_EXP_SHR_BITS`，右移 7 位取低 8 位存入 E8M0
4. **特殊值处理**：
   - `maxExp == INF` → `mxScale = FP8_E8M0_NAN_VAL (0xFF)`
   - `maxExp == 0` → `mxScale = 0`
5. **invScale 生成**：`invScale = BF16_EXP_INVSUB - sharedExp`，等价于 `1/realScale`
6. **特殊值处理**：
   - `maxExp == INF` → `invScale = BF16_NAN_VAL`
   - `maxExp == 0` → `invScale = 0`
   - `invScale == 0`（即 sharedExp == invSub）→ `invScale = FP8_E8M0_SPECIAL_MIN`

**输出格式**：
- `mxScale` 以 `DIST_PACK_B16` 方式写出（每 uint16 只取低 8 位，即 E8M0 格式）
- `invScale` 以 uint16 写出（实际存储 BF16 二进制值）

#### Step 3: `vfMxfp4ComputeData` — 量化数据为 FP4

**目标**：将原始 x 乘以 invScale 后量化为 FP4 (E2M1) 格式。

**FP16 输入路径**（复杂，需经 FP32 中间精度）：

```
FP16 x → FP32 → (× invScale_FP32) → ComputeFP4FromHalf → BF16 → Pack → Interleave → Cast → FP4
```

详细步骤：
1. **invScale 转 FP32**：BF16 → FP32 广播
2. **x 分离奇偶 + 转 FP32**：使用两种 RegLayout（ZERO/ONE）分别处理
3. **FP32 乘法量化**：`x_FP32 * invScale_FP32`
4. **ComputeFP4FromHalf**（核心 FP4 转换逻辑，在 FP32 域完成）：
   - 检测负零（`NEG_ZERO = 0x80000000`）
   - 提取 FP32 指数位，计算 `exp0 = max(exponent - 127 - 1, 0)`
   - 构造缩放因子 `exp1 = 2^(bias - exp0)` 和 `exp0 = 2^(exp0 + bias)`
   - 先乘以缩小因子，做 RINT 截断，再乘以放大因子
   - 处理负零和特殊值（合并 negInfMask 和 zeroMask）
5. **FP32 → BF16**（RINT 舍入）
6. **Pack**：将 BF16 低 16 位打包到 32 位空间
7. **Interleave**：恢复奇偶分离前的原始顺序
8. **BF16 → FP4**：通过 `Cast<U, bfloat16_t, traitB16ToB4>` 完成最终转换

**BF16 输入路径**（简化）：

```
BF16 x → (× invScale_BF16) → Interleave → Cast → FP4
```

1. 直接在 BF16 精度下乘以 invScale
2. Interleave 恢复顺序
3. Cast 到 FP4

**输出**：以 `DIST_PACK4_B32` 方式写出，每 64 个 FP4 元素（即 32 字节）一次写出。

### 5.4 Tiling 策略

#### 多核切分

```
expertTotalCount → perCoreRow = Ceil(total / coreNum)
                 → needCoreNum = Ceil(total / perCoreRow)
```

每个 Core 处理 `perCoreRow` 行（最后一个 Core 处理剩余行）。

#### 行内循环

```
coreRows → perLoopRows (由 Tiling 参数决定)
         → rowLoops = Ceil(coreRows / perLoopRows)
```

#### 列切分

```
cols (hiddenDim) → perLoopCols (32 的整数倍，由 Tiling 决定)
                → colLoops = Ceil(cols / perLoopCols)
```

#### FP4 特有参数

```
colsQuant = (cols + 1) / FP4_NUMBER           // FP4 打包后的列数
perLoopColsQuant = (perLoopCols + 1) / FP4_NUMBER
perLoopScaleCols = perLoopCols / MX_BLOCK_SIZE // 每循环的 scale 列数
```

### 5.5 Buffer 规划

| Buffer | Queue/Buf 类型 | 大小 | 说明 |
|--------|---------------|------|------|
| `sortedRowIdxInQueue_` | TQue VECIN | `AlignBytes(perLoopRows, 4)` | 排序行索引 |
| `xInQueue_` | TQue VECIN | `AlignBytes(perLoopCols, sizeof(T))` | 输入 x 数据 |
| `xQuantOutQueue_` | TQue VECOUT | `AlignBytes(perLoopCols/4, 1) * 4` | FP4 量化输出 |
| `mxScaleOutQueue_` | TQue VECOUT | `AlignBytes(perLoopScaleCols, 1)` | MX Scale 输出 |
| `maxExpBuffer_` | TBuf VECCALC | `AlignBytes(perLoopScaleCols, sizeof(T))` | 中间结果：最大指数 |
| `invScaleBuffer_` | TBuf VECCALC | `AlignBytes(perLoopScaleCols, sizeof(T))` | 中间结果：逆 Scale |

### 5.6 输出内存布局

量化后的数据与 Scale 在同一 Global Buffer 中按行交织存储：

```
每行布局: [xQuant (colsQuant 字节)] [mxScale (scaleCols 字节)]
行偏移: dstIdx * (colsQuant + scaleCols)
```

- `xQuant` 区域：`colsQuant = (cols + 1) / 2` 字节（每字节存 2 个 FP4 元素）
- `mxScale` 区域：`scaleCols = CeilAlign(CeilDiv(cols, 32), 2)` 字节（E8M0 格式）

## 7. 关键设计决策

### 7.1 为什么引入 ActivationType 而非直接复用 QuantOutType？

`fp4x2_e2m1_t` 是 4-bit 类型，在 Ascend C 框架下不能直接用于 `GlobalTensor<>`、`LocalTensor<>` 的模板参数进行内存操作。需要 `uint8_t` 作为"存储代理类型"，一个 uint8_t 承载两个 FP4 元素。引入 `ActivationType` 将"语义类型"与"存储类型"解耦。

### 7.2 为什么 FP4 模式下偏移计算要除以 FP4_NUM？

FP4 量化后每两个元素打包在一个字节中，因此：
- Activation 数据的总字节数 = `(元素数) / 2`
- 所有基于元素数计算的 GM 偏移（A/B/B2 矩阵）需额外除以 `FP4_NUM = 2`
- Scale 数据不受影响，因为 Scale 是按原始元素数量（每 32 个元素一个 scale）计算的

### 7.3 为什么 FP16 输入路径需要 FP32 中间精度？

FP16 的动态范围和精度不足以支撑 `x * invScale` 的乘法运算后再做 FP4 转换。在 FP32 域完成乘法和 ComputeFP4FromHalf（指数调整 + RINT 截断）可以保证量化精度，最终再降级到 BF16 → FP4。

BF16 输入路径由于 invScale 本身就是 BF16 格式，且 BF16 的指数范围足够，可以直接在 BF16 精度下完成乘法后转 FP4。

### 7.4 为什么常量要从 mxfp8_quant.h 上提到 common.h？

MXFP4 和 MXFP8 共享大量 MX 量化相关常量（块大小、指数 Mask、特殊值等）。上提到 `moe_v3_common.h` 避免重复定义和潜在的 ODR 违规，同时使新增 FP4 模块可以复用这些常量。

## 8. 兼容性

### 8.1 向后兼容

- 原有 `QuantMode < 3`（非 MX 量化）和 `QuantMode == 3`（E5M2 MXFP8 量化）路径行为不变
- `QuantTraits` 默认特化仍为 `fp8_e4m3fn_t`，保持原有默认行为
- `moe_v3_gather_mxfp8_quant.h` 功能不变，仅常量定义位置迁移

### 8.2 架构支持

- MXFP4 量化 Kernel 使用 RegBase 微指令编程（`__simd_vf__`、`RegTensor`、MicroAPI），目标架构为 Arch35（`__NPU_ARCH__ == 3510`）
- `moe_init_routing_v3_apt.h` 位于 `arch35/` 目录下，仅影响 Arch35 路径

## 9. 风险与注意事项

| 风险项 | 说明 | 缓解措施 |
|--------|------|---------|
| FP4 打包对齐 | `colsQuant = (cols + 1) / 2`，奇数列场景需注意边界 | CopyOut 中 `loopColsQuant` 按实际列数计算 |
| FP16→FP32→BF16→FP4 精度链 | 多级精度转换可能累积误差 | ComputeFP4FromHalf 在 FP32 域完成核心计算，RINT 舍入控制误差 |
| Scale 计算中 `k_` vs `hiddenSize` | CopyGMToGMPerToken 中 scaleLen 改用 `k_` 计算 | 确保 FP4 模式下 scaleLen 基于原始维度，不受存储宽度影响 |
| FP4 偏移整除 | `(m*k) / FP4_NUM` 要求 `m*k` 为偶数 | 实际模型 hiddenDim 通常为 2 的幂次，m 为 token 数，乘积为偶数 |
| ComputeFP4FromHalf 代码重复 | FP16 路径中 4 段 ComputeFP4FromHalf 逻辑高度相似 | 当前为内联展开以适配不同 RegTensor 变量，后续可考虑宏或模板抽取 |
