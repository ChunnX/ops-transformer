## 一、现状调研报告

### 1. 代码结构分析

#### 目录结构对比

| 层级 | all_gather_matmul (V1) | all_gather_matmul_v2 (V2) | 共享代码位置 |
|------|------------------------|---------------------------|-------------|

#### 共享代码和独立代码的位置

**独立代码：**
- V1：简单的 gentask 实现（只支持 AICPU KFC）

### 2. 复用方式总结

#### aclnn 接口的复用方式（详细代码示例）

**V1 在 A5 架构下直接调用 V2 的 aclnn 接口：**

```cpp
// aclnn_all_gather_matmul.cpp (V1) - line 203-207
if (IsAscend910A5()) {
    const char *commMode = "ccu";  // 构造默认参数

        x1, x2, bias,

        group, gatherIndex, commTurn, streamMode, 
        0,                          // groupSize 默认值

        const_cast<aclTensor *>(gatherOut),

```

**关键点：**
1. **架构判断**：V1 根据架构决定是否调用 V2

3. **参数传递**：所有 V1 参数直接传递给 V2，新增参数根据架构构造
4. **Execute 调用**：V1 的 Execute 直接调用 V2 的 Execute

  // ...
}

**all_gather_matmul_v2 V2 的 gentask：**

```cpp
// all_gather_matmul_v2_gen_task.cpp (V2)
static ge::Status AllGatherMatmulV2CalcOpParam(gert::ExeResGenerationContext *context)
{
    if (IsTargetPlatformNpuArch(context->GetNodeName(), NPUARCH_A5)) {
        uint8_t commMode = Mc2Comm::GetCommModeFromEnv();  // 从环境变量读取
        if (commMode == Mc2Comm::COMM_MODE_AICPU) {
            OPS_LOG_D(context->GetNodeName(), "Do A5 AICPU GenTask CalcOpParam");
            return Mc2GenTaskOpsUtils::CommonKFCMc2CalcParamFunc(context, 
                                                                 "aicpu kfc server", 
                                                                 "kfc_stream");
        } else {
            OPS_LOG_D(context->GetNodeName(), "Do A5 CCU GenTask CalcOpParam");
            return Mc2GenTaskOpsUtils::CommonKFCMc2CalcParamFunc(context, 
                                                                 "ccu server", 
                                                                 "ccu_stream");
        }
    }
    OPS_LOG_D(context->GetNodeName(), "AICPU GenTask CalcOpParam");
    return Mc2GenTaskOpsUtils::CommonKFCMc2CalcParamFunc(context, 
                                                         "aicpu kfc server", 
                                                         "kfc_stream");
}

static ge::Status AllGatherMatmulV2GenTask(const gert::ExeResGenerationContext *context,
                                            std::vector<std::vector<uint8_t>> &tasks)
{
    if (IsTargetPlatformNpuArch(context->GetNodeName(), NPUARCH_A5)) {
        uint8_t commMode = Mc2Comm::GetCommModeFromEnv();
        if (commMode == Mc2Comm::COMM_MODE_AICPU) {
            OPS_LOG_D(context->GetNodeName(), "Do A5 AICPU GenTaskFunc");
            return Mc2GenTaskOpsUtils::CommonKFCMc2GenTask(context, tasks);  // 与 V1 相同
        } else {
            OPS_LOG_D(context->GetNodeName(), "Do A5 CCU GenTaskFunc");
            return Mc2Arch35GenTaskOpsUtils::Mc2Arch35GenTaskCallBack(context, tasks);  // V2 专用
        }
    }
    OPS_LOG_D(context->GetNodeName(), "AICPU GenTaskFunc");
    return Mc2GenTaskOpsUtils::CommonKFCMc2GenTask(context, tasks);  // 与 V1 相同
}
```

**特点：**
- 有架构判断（A5 vs 其他）
- 有通信模式判断（AICPU vs CCU）
- A5 AICPU 模式：使用与 V1 **完全相同** 的回调函数
- A5 CCU 模式：使用 CCU 专用回调函数
- 其他架构：使用与 V1 **完全相同** 的回调函数

**关键复用点：**
- **V1 和 V2 在 AICPU 模式下使用相同的公共回调函数**
- **V2 通过架构和通信模式判断选择不同的回调路径**
- **CalcOpParam 和 GenTaskFunc 两个回调函数都根据模式选择不同实现**

#### 新增参数的获取和传递方式

**V1 调用 V2 时的参数处理：**

```cpp
// aclnn_all_gather_matmul.cpp (V1)
if (IsAscend910A5()) {
    const char *commMode = "ccu";  // V1 根据架构构造默认值
    return aclnnAllGatherMatmulV2GetWorkspaceSize(
        x1, x2, bias,
        nullptr, nullptr, nullptr,  // x1Scale, x2Scale, quantScale 填 nullptr
        0,                          // blockSize 默认值
        group, gatherIndex, commTurn, streamMode,
        0,                          // groupSize 默认值
        commMode,                   // 构造的参数
        const_cast<aclTensor *>(output),
        const_cast<aclTensor *>(gatherOut),
        nullptr,                    // amaxOut 填 nullptr
        workspaceSize, executor);
}
```

**关键处理方式：**
1. **默认值填充**：V1 不支持的参数（量化相关）填 nullptr 或 0
2. **参数构造**：commMode 根据架构构造（A5 使用 "ccu"，其他架构不调用 V2）
3. **参数顺序**：严格按照 V2 的参数顺序传递
4. **无判断逻辑**：V1 不需要复杂的条件判断，直接填充默认值

---

#### 参数顺序的处理方式

**V1 的参数顺序（简化版）：**
```
x1, x2, bias, group, gatherIndex, commTurn, streamMode, output, gatherOut
```

**V2 的参数顺序（完整版）：**
```
x1, x2, bias, x1Scale, x2Scale, quantScale, blockSize, group, gatherIndex, 
commTurn, streamMode, groupSize, commMode, output, gatherOut, amaxOut
```

**处理方式：**
- V1 在调用 V2 时，严格按照 V2 的参数顺序
- V1 的原有参数保持相对位置不变
- V2 新增参数插入到合适位置（量化参数在 bias 后，通信参数在 streamMode 后）
- V1 填充默认值时不影响原有参数的传递

## 二、架构设计模式

### 1. 模式识别

#### all_gather_matmul 采用的复用模式

**核心模式：模式 A + 模式 C 的组合**

| 层级 | 复用模式 | 具体实现 |
|------|---------|---------|
| **aclnn 层** | **模式 A** | V1 在 A5 架构下调用 V2 的 aclnn 接口 |
| **gentask 层** | **模式 C** | V1 和 V2 在 AICPU 模式下共用相同回调函数 |

---

#### 模式 A（aclnn 层 V1 调用 V2）

**实现细节：**
- **触发条件**：`IsAscend910A5()` 架构判断
- **调用方式**：
  - GetWorkspaceSize：V1 调用 V2 GetWorkspaceSize
  - Execute：V1 调用 V2 Execute
- **参数处理**：V1 填充默认参数传递给 V2
- **其他架构**：V1 使用独立的 inner 接口（不调用 V2）

**优点：**
- 避免代码重复，V1 直接复用 V2 的完整逻辑
- 维护成本低，只需维护 V2 的核心逻辑
- 向后兼容性好，V1 接口保持不变

**缺点：**
- V1 必须为 V2 新增参数填充默认值
- 如果 V2 参数变化，V1 需要同步修改
- V1 和 V2 的耦合度较高

---

#### 模式 C（gentask 层共用回调函数）

**实现细节：**
- **公共回调**：`CommonKFCMc2CalcParamFunc` 和 `CommonKFCMc2GenTask`
- **V1 实现**：无条件使用公共回调（AICPU KFC 模式）
- **V2 实现**：
  - A5 AICPU 模式：使用公共回调（与 V1 相同）
  - A5 CCU 模式：使用 CCU 专用回调（`Mc2Arch35GenTaskCallBack`）
  - 其他架构：使用公共回调（与 V1 相同）

**优点：**
- 公共回调函数可被多个算子复用
- V1 和 V2 在相同模式下行为完全一致
- 新增算子只需调用公共回调，无需重复实现

**缺点：**
- 公共回调函数的修改会影响所有使用它的算子
- 需要维护公共函数库的兼容性

---
