## Round 4 优化核心思路

在 per-tile 流水路径（方案 D, T>1）中，为子问题（m=headMSize, n=N, k=K）生成独立 tiling。
SWAT 为 m=512 生成的 baseM=256（与全量 m=2048 相同），未触发 AdjustBasicBlock。
因此在 Host 侧后处理：将 subMmTiling.baseM 从 256 减半为 128，产生更多 tiles 提升核间负载均衡。

```
Round 3 (baseM=256):                    Round 4 (baseM=128):
  mBlockCnt = 512/256 = 2                 mBlockCnt = 512/128 = 4
  nBlockCnt = 4096/256 = 16               nBlockCnt = 4096/256 = 16
  totalBlockCnt = 2 × 16 = 32             totalBlockCnt = 4 × 16 = 64
  28 cores → 1.14 tiles/core              28 cores → 2.29 tiles/core
```

关键设计:
- subMmTilingData 新增到 TilingData 结构体，由 Host 侧 SWAT 生成后传入 kernel
- T=1 退化路径不受影响（仍用全量 mmTilingData）
- tail tile 仍用全量 tiling（tail M 大小不固定）
- blockDim 固定使用 mmTilingData.usedCoreNum（kernel launch 时确定）
- L1 安全性: baseM 减半 → A buffer 减半, L1 用量减少, stepK/scaleKL1/nBufferNum 不变仍有效
- 对齐安全性: baseM=128 是 CUBE_BLOCK(16) 的整数倍

## 与 Round 3 对比分析

### basic_rank2 (tileCnt=2): 1.116ms → 1.098ms (-1.7%)
- Task Duration 降低 1.7%（18.4 us 绝对减少）
- AIC CUBE: 997.7 → 939.8 us (-5.8%) ← baseM=128 产生更多 tiles, cube 计算更高效
- AIC MTE2: 918.5 → 1027.5 us (+11.9%) ← 更多 tiles 导致更多数据加载
- AIC FIXP: 309.8 → 294.3 us (-5.0%) ← 更小 tile 的 fixpipe 开销降低
- cube_util: 7.98% → 9.00% (+1.02pp, +12.8% 相对提升)

### largeM_rank2 (tileCnt=4): 2.224ms → 2.208ms (-0.7%)
- Task Duration 降低 0.7%（16.0 us 绝对减少）
- AIC CUBE: 2028.1 → 1975.6 us (-2.6%) ← cube 计算时间减少
- AIC MTE2: 1905.4 → 2118.2 us (+11.2%) ← 更多 tiles 导致更多数据加载
- AIC FIXP: 648.0 → 613.4 us (-5.3%) ← fixpipe 开销降低
- cube_util: 7.91% → 8.52% (+0.62pp, +7.8% 相对提升)

### 性能提升根因分析

1. **cube_utilization 提升**（核心收益）:
   - baseM 从 256 减半为 128, tiles 从 32 增至 64
   - 每核 tiles 从 1.14 增至 2.29, 负载更均衡
   - cube 计算时间降低 2.6%~5.8%
   - cube_util 提升 7.8%~12.8%（相对）

2. **AIC CUBE mac 时间降低**:
   - 更小 baseM → 更小 tile → 更好的 L1/L0 局部性
   - BlockScheduler 对 64 tiles 的分配比 32 tiles 更均匀
   - 尾核（仅处理 1 tile 的核）数量减少

3. **AIC MTE2 时间增加**（副作用）:
   - 更多 tiles → 更多 DMA 加载次数 → MTE2 占比增加
   - baseM=128 的 A 数据加载量不变, 但加载次数翻倍
   - MTE2 占比从 82.4%→93.7%（basic）/ 85.7%→96.0%（largeM）
   - 这是 cube_util 提升但 Task Duration 仅小幅降低的原因：MTE2 成为新瓶颈

4. **AIV 通信仍被完全掩盖**:
   - AIV VEC + MTE2 时间基本不变（~23 us / ~28 us）
   - per-tile 流水重叠继续有效

### 达标判定
