## 优化方案 D 核心思路

将 AIC 的单次全量 matmul 改为 T×R 次子调用（T=commTurn, R=rankSize），每次只计算一个 tile 的 M 范围。
每轮 T 完成后 SetFlag 通知 AIV，AIV WaitFlag 后执行该 tile 的 AllToAll + reduceSum。

```
AIC: [tile0 R段mm] SetFlag [tile1 R段mm] SetFlag [tile2 R段mm] SetFlag ...
AIV:                WaitFlag [comm0+rs0]  WaitFlag [comm1+rs1]  WaitFlag [comm2+rs2]
```

关键设计:
- T=1 退化路径: 保持原行为（单次全量 mm + 单次 SetFlag）
- T>1 per-tile 流水路径: T×R 次子调用, flag 计数式（T 次 Set ↔ T 次 Wait, flagId=0）
- CrossCore flag flagId=0 计数式: 峰值 T ≤ 15
- 零 tile 核: SetFlag 在 R-loop 外, 所有 AIC 核都执行（flag 计数平衡）
- reduceSum per-tile 分块: RunReduceSumTile(t) 处理单个 tile

## 与 Round 2 对比分析

### basic_rank2 (tileCnt=2): 1.110ms → 1.116ms (+0.5%)
- Task Duration 基本持平（+0.5% 在噪声范围内）
- AIV VEC: 51.2 → 23.1 us (-55%) ← reduceSum 被 AIC 计算掩盖
- AIV MTE2: 63.3 → 28.2 us (-55%) ← 数据搬移被 AIC 计算掩盖
- AIC CUBE: 1063.4 → 997.7 us (-6.2%) ← per-tile 调用可能改善 L1 局部性
- cube_util: 7.52% → 7.98% (+0.46%)

### largeM_rank2 (tileCnt=4): 2.392ms → 2.224ms (-7.0%) ← 显著提升
- Task Duration 降低 7.0%（168 us 绝对减少）
- AIV VEC: 112.2 → 36.3 us (-68%) ← per-tile reduceSum 与 AIC matmul 重叠
- AIV MTE2: 155.9 → 47.4 us (-70%) ← per-tile AllToAll PUT 与 AIC matmul 重叠
- AIC CUBE: 2335.0 → 2028.1 us (-13.1%) ← per-tile 调用改善 L1/L0 局部性或负载均衡
- cube_util: 6.91% → 7.91% (+1.00%)

### 性能提升根因分析

1. **AIV 通信被 AIC 计算掩盖**（核心收益）:
   - 方案 D 实现 AIC tile N matmul || AIV tile N-1 comm 的真正流水重叠
   - AIV VEC + MTE2 时间大幅降低（-55%~-70%），被 AIC CUBE 计算掩盖
   - tileCnt 越大，可重叠的 AIV 工作越多，收益越大（tileCnt=4 收益 7% > tileCnt=2 收益 0.5%）

2. **AIC CUBE mac 时间降低**（额外收益）:
   - per-tile 调用将大 matmul 拆分为小 matmul，可能改善 L1 cache 局部性
   - 小 tile 的 M 维度更小，A 数据在 L1 中的复用率更高
   - BlockScheduler 对小 M 的负载分配可能更均匀

3. **AIV 流水占比降低**:
   - AIV VEC 从 4.6-4.7% 降至 1.6-2.1%（reduceSum 被完全掩盖）
   - AIV MTE2 从 5.7-6.5% 降至 2.1-2.5%（AllToAll PUT 被完全掩盖）
   - 说明 per-tile 流水成功将 AIV 工作隐藏在 AIC 计算之后
