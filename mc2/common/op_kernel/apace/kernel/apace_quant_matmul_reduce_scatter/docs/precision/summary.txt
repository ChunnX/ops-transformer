## 四、与 v1 精度对比

v1 数据来源：git 分支 feat/apace-quant-matmul-reduce-scatter:
operators/apace_quant_matmul_reduce_scatter/docs/precision/summary.txt（2026-08-11 Step 6a），
以及 v2 验收时 Reviewer 本地实测的 v1 数据（accept_v1_compare.log，同数据同判定）。

| shape (M,K,N) | dtype | v1 max_rel_err | v3 max_rel_err（本轮实测） | 对比 |
|---------------|-------|---------------|--------------------------|------|
| 2048,4096,2048 | E4M3×E4M3 | 7.41e-3 | 6.06e-3 | ✅ v3 更优 |
| 2048,4096,2048 | E5M2×E5M2 | 7.41e-3 | 0（bit 级一致） | ✅ v3 明显更优 |
| 2048,4096,2048 | E4M3×E5M2 | 7.41e-3 | 5.62e-3 | ✅ v3 更优 |
| 2048,4096,2048 | E5M2×E4M3 | 7.30e-3 | 5.68e-3 | ✅ v3 更优 |
| 512,1024,512 | E4M3×E4M3 | 7.75e-3 | 0（bit 级一致） | ✅ v3 明显更优 |
| 1120,2048,1024 | 各 dtype | 7.75e-3 | 0 ~ 4.90e-3 | ✅ v3 明显更优 |

**分析**：v3 相对误差全面低于 v1，与 v2 原因相同——v1 采用 localMatmul=1 + BF16 AtomicAdd
跨 rank 累加路径（AtomicAdd 引入 ~0.79% 精度损失）；v3 继承 v2 的 REMOTE-only（localMatmul=0）
架构，跨 rank 累加在 L0C（FP32）由硬件完成后一次性 fixpipe 写出，reduceSum 阶段仅普通
DataCopyPad 搬运、无 AtomicAdd，消除了 BF16 原子累加的精度损失。v3 实测误差（≤6.49e-3）
即 FP8 量化本身 + BF16 输出舍入的固有误差，距 1e-2 阈值余量 >35%。

## 五、验收结论

### 5.1 精度达标判定

**全部 4 种 dtype 变体 × 13 个 cases.csv 用例 + T13-b 边界用例全部 PASS（14/14）；T13-a 超界用例被 host 正确拒绝。**

- max_rel_err 范围：0 ~ 6.49e-3，全部低于 1e-2 阈值（余量 >35%）
- 无全 0 / NaN / 单核异常 / padding 污染等代码 bug 特征
- 尾块（mLocal=280、M=2252 尾块拆分）、K 对齐边界（K=4608）、大 shape（T=5/10/15 多档
  maxTilesPerCore）精度与常规 shape 一致，边界处理正确
- 误差不随数据规模增长（16384×4096×4096 与 2048×4096×2048 同量级），无累积误差问题
- C8 host 校验双向生效：T=37 正确拒绝（报错清晰并提示回退 v2），T=15 边界恰好放行且精度达标

### 5.2 精度标准说明

| 标准 | rtol | atol | 来源 |
|------|------|------|------|
| 本算子采用 | 1e-2 | 1e-2 | DESIGN.md，与 v1/v2 及 all_to_all_quant_matmul ST 一致 |
| 官方 BF16 标准 | 1.56e-2 | 1.56e-2 | ops-precision-standard/references/float_compute.md |

本算子输出 dtype 仅 BF16（输入为 FP8 量化），无 FP32/FP16 输出，统一按 BF16 标准应用；
且采用比官方 BF16 标准更严格的 1e-2 阈值，所有用例均以充足余量通过。

### 5.3 测试覆盖说明

| 覆盖维度 | 覆盖情况 |
|---------|---------|
| dtype 覆盖 | ✅ 全部 4 种 dtype 变体（E4M3×E4M3, E5M2×E5M2, E4M3×E5M2, E5M2×E4M3） |
| shape 覆盖 | ✅ 常规（2048×4096×2048）+ 小（512×1024×512）+ 尾块（1120×2048×1024、2252×2048×1024）+ 大 shape（16384×4096×2048、16384×4096×4096、10240×4096×10752） |
| 边界覆盖 | ✅ 尾块 + K 对齐边界（K=4608）+ maxTilesPerCore=5/10/15 多档 + T=37 超界拒绝 |
| v3 特性覆盖 | ✅ T12（tiles/core=10>4，取消轮转回压核心场景）精度达标；T13 双向校验通过 |
| 可复现性 | ✅ 与 Round 0 独立运行结果逐用例一致（seed=42 确定性数据）；与 v2 同 shape 逐位一致 |

### 5.4 运行时备注（透明记录）

- 本轮首轮运行中 row 1、row 12、T13-b 各出现 1 次 `connect peers failed` + 600s 超时失败，
  经排查为多用户共用 NPU 环境下 HCCL 建链（port 8998）与其他用户任务冲突所致（环境性、非算子问题；
  失败发生时算子尚未进入 kernel 执行，无精度数据产生）。通过 qrun 重新排队后 3 个用例全部一次通过，
  精度数据与 Round 0 同 shape 结果一致。Reviewer 判定这些失败不构成算子精度问题。
- 部分用例 `count(|abs_err| > 0.01)` 非零，属 BF16 输出固有量化噪声（输出量级 ~1e5-7e5，
  BF16 ULP 远大于 atol=0.01）；混合容差公式 `|actual-golden| ≤ atol + rtol×|golden|`
  通过 rtol 分量正确判定，全部用例 allclose 通过。
