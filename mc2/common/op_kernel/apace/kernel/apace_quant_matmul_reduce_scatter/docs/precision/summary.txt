## 8. 误差分析

### 8.1 误差来源

本算子误差来自 MXFP8 量化 MatMul 的 BF16 累加精度差异:
- **CPU golden**: 反量化后在 FP32 中完成 MatMul + reduceSum 累加, 最后转 BF16
- **NPU kernel**: AIC 侧 Cube 引擎在 L0C 中以 BF16/FP32 混合精度累加, AIV 侧 reduceSum 在 BF16 下逐元素求和

### 8.2 abs_err max 分析

abs_err max 随 rank 数和 K 维度增长:
- rank=2, K=3584: max abs_err = 8192 (输出值范围 ~1.2M, BF16 ULP ~512, ~16 ULP)
- rank=4, K=3584: max abs_err = 16384 (输出值范围 ~2.5M, BF16 ULP ~1024, ~16 ULP)
- rank=4, K=8192: max abs_err = 32768 (输出值范围 ~6M, BF16 ULP ~4096, ~8 ULP)

这些是 BF16 舍入的固有精度特征, torch.allclose 的混合容差公式 |a-b| <= atol + rtol*|b| 对大值元素允许更大的绝对误差:
- 对于值 ~6M 的元素: 允许误差 = 0.01 + 0.01*6M = 60000 >> 32768

### 8.3 rel_err 分析

所有用例的 max rel_err 均在 5.88e-3 ~ 7.19e-3 范围内, 远低于 rtol=1e-2 阈值.
- 最大 rel_err: 7.194e-3 (Case 3, Rank 0)
- 最小 rel_err: 5.882e-3 (Case 6, Rank 0)
- 误差分布均匀, 无异常模式

### 8.4 超差计数分析

超差计数 (|abs_err| > atol=0.01) 极低:
- Case 1-5,7: 7~50 / 数百万元素 (<0.001%)
- Case 6 (大K): 241~252 / 4M 元素 (~0.006%)
- 超差元素均通过 torch.allclose 的 rtol 项验证 (大值元素的 rtol 容差覆盖了 atol 不足)

### 8.5 结论

误差特征正常, 无代码 bug 迹象:
- 无全 0 / NaN 输出
- 无特定 rank 数据错误
- 无 padding 区域参与计算
- 误差随数据规模线性增长 (BF16 舍入特征), 非累积发散
- 所有 dtype (BF16 输出) 均匀达标
