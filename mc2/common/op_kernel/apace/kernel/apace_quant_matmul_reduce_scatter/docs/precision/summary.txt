## 三、与 v1 精度对比（本轮 Reviewer 本地实测）

v1 对比数据来源：本轮 Reviewer 通过 qrun 排队本地运行 v1 二进制
（operators/apace_quant_matmul_reduce_scatter/st/build/apace_quant_matmul_reduce_scatter，PUT 串行模式），
输入与 golden 由 v2 的 gen_data.py 生成（同一数学语义，seed=42，与 v2 用例完全同数据），
验证脚本同为 verify_result.py（rtol=atol=1e-2）。原始日志：accept_v1_compare.log。

### 3.1 同 shape 同数据逐点对比

| shape (M,K,N) | dtype | v1 max_rel_err | v2 max_rel_err | 对比 |
|---------------|-------|---------------|---------------|------|
| 2048,4096,2048 | E4M3×E4M3 | 7.41e-3 | 6.06e-3 | ✅ v2 更优 |
| 2048,4096,2048 | E5M2×E5M2 | 7.41e-3 | 0（bit 级一致） | ✅ v2 明显更优 |
| 2048,4096,2048 | E4M3×E5M2 | 7.41e-3 | 5.62e-3 | ✅ v2 更优 |
| 2048,4096,2048 | E5M2×E4M3 | 7.30e-3 | 5.68e-3 | ✅ v2 更优 |
| 512,1024,512 | E4M3×E4M3 | 7.81e-3 | 0（bit 级一致） | ✅ v2 明显更优 |

v1 本轮 5 个用例全部 PASS（max_rel_err 7.30e-3 ~ 7.81e-3，均 < 1e-2），
与 v1 开发分支历史精度报告区间（6.21e-3 ~ 7.75e-3）一致，交叉印证有效。

### 3.2 对比结论

| 维度 | v1 | v2 | 结论 |
|------|----|----|------|
| dtype 覆盖 | 4 种变体 | 4 种变体 | ✅ 一致 |
| 精度标准 | rtol=atol=1e-2 | rtol=atol=1e-2 | ✅ 相同 |
| max_rel_err 范围（本轮实测） | 7.30e-3 ~ 7.81e-3 | 0 ~ 6.41e-3 | ✅ v2 全面更优 |
| 小/尾块 shape | 全部存在 AtomicAdd 累加误差 | 6/12 用例 bit 级一致 | ✅ v2 明显更优 |

**分析**：v2 相对误差全面低于 v1，且一半用例达到 bit 级一致。这与架构差异一致——
v1 采用 localMatmul=1 + BF16 AtomicAdd 跨 rank 累加路径（AtomicAdd 引入 ~0.79% 精度损失）；
v2 改为 REMOTE-only（localMatmul=0），跨 rank 累加在 L0C（FP32）由硬件完成后一次性 fixpipe 写出，
reduceSum 阶段仅普通 DataCopyPad 搬运、无 AtomicAdd，消除了 BF16 原子累加的精度损失。
v2 实测误差（≤6.41e-3）即 FP8 量化本身 + BF16 输出舍入的固有误差，距阈值余量 >35%。

## 四、验收结论

### 4.1 精度达标判定

**全部 4 种 dtype 变体（E4M3×E4M3, E5M2×E5M2, E4M3×E5M2, E5M2×E4M3）× 12 个用例全部 PASS。**

- max_rel_err 范围：0 ~ 6.41e-3，全部低于 1e-2 阈值（余量 >35%）
- 无全 0 / NaN / 单核异常 / padding 污染等代码 bug 特征
- 尾块 shape（mLocal=280）、K 对齐边界（K=4608）、大 shape（tileCnt=2/4 多轮通信）精度与常规 shape 一致，边界处理正确
- 误差不随数据规模增长（16384×4096×2048 与 2048×4096×2048 同量级），无累积误差问题

### 4.2 精度标准说明

| 标准 | rtol | atol | 来源 |
|------|------|------|------|
| 本算子采用 | 1e-2 | 1e-2 | DESIGN.md §2.13，与 v1 及 all_to_all_quant_matmul ST 一致 |
| 官方 BF16 标准 | 1.56e-2 | 1.56e-2 | ops-precision-standard/references/float_compute.md |

本算子采用比官方 BF16 标准更严格的 1e-2 阈值，所有用例均以充足余量通过。

### 4.3 测试覆盖说明

| 覆盖维度 | 覆盖情况 |
|---------|---------|
| dtype 覆盖 | ✅ 全部 4 种 dtype 变体（E4M3×E4M3, E5M2×E5M2, E4M3×E5M2, E5M2×E4M3） |
| shape 覆盖 | ✅ 常规（2048×4096×2048）+ 小（512×1024×512）+ 尾块（1120×2048×1024，mLocal=280）+ 大 shape（4096×8192×4096、16384×4096×2048） |
| 边界覆盖 | ✅ 尾块 + K 对齐边界（K=4608）+ tileCnt=4 workspace 轮转全占用 |
| 通信轮次覆盖 | ✅ tileCnt=1/2/4 三档，覆盖 PIPELINE_NUM=4 slot 轮转的单轮/多轮场景 |
| 可复现性 | ✅ 两轮独立 qrun 运行结果逐用例一致（seed=42 确定性数据） |

### 4.4 运行时备注

- 本轮 12 用例**零重试一次通过**，未复现 Round 0 审查时遇到的 `CreateDeviceContext failed` HCCL 建链抖动（环境性、非算子问题）。
- 部分用例 `count(|abs_err| > 0.01)` 非零，属 BF16 输出固有量化噪声（输出量级 ~7e5，BF16 ULP 远大于 atol=0.01）；混合容差公式 `|actual-golden| ≤ atol + rtol×|golden|` 通过 rtol 分量正确判定，全部用例 allclose 通过。
