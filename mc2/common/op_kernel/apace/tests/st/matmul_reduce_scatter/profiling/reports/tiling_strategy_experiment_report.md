# tileM 公式与 scope 顺序策略实验全记录

- **日期**: 2026-09-28 ~ 2026-09-29
- **代码基线**: ops-transformer upstream-apace（v8 + L1 排空条件化之上，工作区演进）
- **环境**: Ascend950PR ×4, CANN 9.2.0（Ascend915 安装路径）, bisheng dav-3510, msprof task-based
- **定位**: 完整实验记录（含过程事件与数据修正），结论性文档见
  [formula_tiling_scenario_report.md](formula_tiling_scenario_report.md)

## 1. 背景与目标

- **起点**: tileM（headMSize）为逐 case 手工配置（cases.csv 第 5 列），源自早期 rank 粗分经验
  （rank2→512 / rank4→128/256）+ P1-b 对 row16/17/47 三族的手工穷举扫描
- **提议一（tileM 公式化）**: `tileM = ceil(blockNum / (N/256)) * 256`——N 方向 256 宽 slab 数
  `(N/256)` 能分满核（≥ blockNum=usedCoreNum=28）则 tileM=256，否则 512 甚至更大；
  语义 = 每 tile base-tile 网格覆盖全部 AIC 核（逐 tile 全核占用）
- **提议二（scope 顺序开关）**: LOCAL 后置（localScopeLast）做成可配置项——v2 时代曾有
  localLast 双 flag 设计，v5 重构后固定为 LOCAL 先；单 flag 语义下理论时序中性，需实测裁决
- **目标**: 判定两种策略的收益场景，能否结合，落地最优配置

## 3. 实验一：tileM 公式场景（localLast=0）

### 3.1 实现与触发

- `FormulaHeadMSize(n, chunkM, blockNum)`：ceil(blockNum/max(1,n/256))*256，约束链
  tileM≤chunkM 钳制 + T≤14 倍增修复（flagid 上限）
- 触发：`headMSize<=0` 显式传入；缺省仍 512；101 case 中 45 case 公式值与现值一致（免测）

### 3.2 精度

**56/56 变化 case 全 PASS**（公式 tiling 生效）+ 默认路径冒烟 10/10 PASS。

### 3.3 性能（56 case 全量 A/B）

| 变化组 | case 数 | 改善>1% / 回退>1% | 组 geomean | 判读 |
|---|---|---|---|---|
| 128→256（rank4 大 N） | 25 | 13 / 7 | **−5.67%** | 公式显著更优 |
| 128→512（N=4096/5120 r4） | 4 | 1 / 3 | **+10.69%** | 公式显著更差（row10 +34.0%） |
| 512→256（rank2 大 N） | 27 | 7 / 16 | **+2.95%** | 公式偏差，族内 ±28% 分化 |
| **全量** | **56** | 21 / 26 | **−0.48%** | 净中性略优 |

关键判读：同为 512→256 组的 rank2 族内部剧烈分化（row57 −26.2% vs row52 +28.4%）——
该族性能由 **matmul tiling 随 scope m 的联动效率**主导，通信级占用率公式无法建模；
小 N r4 族最优由 PUT/compute 重叠粒度主导（轮次越多越好），与占用率准则方向相反。

|---|---|---|

| 掩盖率（修正） | 中位 0.56（min 0.12 / max 0.91） | 中位 0.68 |
| 通信 Bound 族 | 1.36x / 0.88 | 1.36x / 0.83 |

row10 0.57→0.29（小 N r4 族 T 骤降压缩重叠窗口）。

## 7. 收益场景分布与机制

| 场景 | case 数 | 收益 | 机制 |
|---|---|---|---|
| **主力：大 K(≥4096) × 大 N(≥16384) × r4** | 10 | −8% ~ −28% | tileM 128→256 使 matmul scope 变大——隔离数据佐证：row67 纯 matmul 分量 T_mm 2680→2139us（**−20%**），通信分量不变；计算/均衡 Bound 族小 tileM 逐 tile matmul 效率低 |
| 次要：M=2048 × 大 N × r2 | 5 | −2.5% ~ −9.5% | tileM 512→256、T 翻倍——通信 Bound 重叠粒度细化 |
| 特例：row27（128 + localLast=1） | 1 | −8.2% | 顺序收益与 tileM=128 绑定，AIC 侧二阶效应（机制未闭合） |
| 边际：小 N r4（row10/12/17） | 3 | −1.9% ~ +0.7% | 噪声级 |

## 8. 过程记录与数据完整性

1. **方向批样本偏差教训**：首轮 11 case 方向批 geomean +4.1%（恰抽中偏负样本），全量 56 case
   复测后为 −0.48%——小样本方向批不可作为全局结论，全量数据裁决
2. **环境事件**：机器重启一次（队列任务丢失重提）；qrun 队列服务两次静默吞任务（以结果文件
   断点续跑恢复）；rootInfo TCP 端口竞态两次（run.sh 内建重试通过）；按共享队列要求中途暂停
   让出 NPU（孤儿进程已清理，续跑批恢复）
3. **数据修正记录**：续跑批脚本 eval 存在 int/str 比较缺陷（headM 传空 → 二进制按公式 tiling
   执行），产生 5 条无效 old 侧数据（表现为"收益消失"假象）——已识别剔除并以显式参数重测，
   修正后 5 case 收益全部复现（−2.7% ~ −28.2%，与原测吻合）
4. 全部 A/B 为同日同二进制交替测量，消除跨日漂移（历史跨日漂移实测达 29%）

## 9. 结论与遗留方向

1. **组合表为新的正式配置**（cases.csv 逐 case tiling + localScopeLast），全新复测确认
   变更 case geomean −9.65%（101 全集 ≈ −2.0%），精度零回退
2. 公式与顺序**不可叠加但可分 case 组合**；公式缺省不启用（`headMSize<=0` 实验入口），
   localScopeLast 缺省 0
3. **遗留机制问题**：row27 顺序收益的量级特异性（vs 同构 row47 中性）与顺序效应的 tile 粒度
   依赖未闭合——候选解释为 fixpipe 尾部暴露差异，需 op_summary pipe 利用率分析定论
4. 后续可评估：oracle 上界 −3.98% vs 落地 −9.65%/21case 的差距源于 −2% 防过拟合阈值与
   顺序数据覆盖面（仅 11 case 抽样）——顺序开关全量扫描可进一步挖掘
