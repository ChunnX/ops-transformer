# tileM 公式化场景验证报告（localScopeLast=0 + 公式 tileM）

- **日期**: 2026-09-28
- **场景**: `tileM = ceil(blockNum / (N/256)) * 256`，scope 顺序 LOCAL 先（不使能 local 后置）
  - 语义：N 方向 256 宽 slab 数 `(N/256)` 能分满核（≥ blockNum）→ tileM=256；否则 512 甚至更大
  - `blockNum = mmTilingData.usedCoreNum`（tiling 引擎输出 AIC 核数，本平台 28）
  - 约束链：tileM ≤ chunkM 钳制；T = ceil(chunkM/tileM) ≤ 14（flagid 上限，超限倍增）
- **触发方式**: `headMSize <= 0`（实验入口；缺省仍为 512，cases.csv 显式值为正式生效配置）
- **环境**: Ascend950PR ×4, CANN 9.2.0, 同日同二进制交替 A/B（性能）/ probe 四模式自采（掩盖率）

## 一、精度

- **56 个 tiling 变化 case 全部 PASS**（公式 tiling 生效，precision 模式逐 case 比对）
- 默认路径（cases.csv 显式值 + localLast=0）冒烟 10/10 PASS（含 3 tail / T=1 / rank2/4 结构覆盖）

### 关键判读

1. **单一占用率准则无法统一最优**：同为 512→256 组的 rank2 大 N 族内部 ±28% 分化（row57 −26.2% vs
   row52 +28.4%），说明该族性能由 **matmul tiling 随 scope m 的联动效率**主导，通信级占用率公式无法建模
2. **rank4 大 N 族（tileM 128→256）是公式的明确受益族**（−5.67%，25 case，与 row47 P1-b 扫描方向一致）
3. **小 N r4 族（tileM 128→512）方向相反**：公式减少轮次（T=8→2/1），但该族最优由 PUT/compute
   重叠粒度主导（轮次越多重叠越充分），占用率准则给出相反建议
4. row10 结论与 v7 时代 P1-b 扫描一致（T=1 比 T=4 慢 ~34%），v8 尾声批量 RS 未改变该结论

## 六、结论

1. **组合表为新的正式配置**：cases.csv 逐 case 组合（tiling + localScopeLast），全新复测确认
   变更 case geomean −9.65%（101 全集 ≈ −2.0%），精度零回退
2. 公式与顺序**不可叠加但可分 case 组合**：公式收益 order 无关（rank4 大 N 族为主），
   顺序收益 tiling 绑定（row27 @128 独有 −8.5%）
3. 机制遗留：row27 顺序收益的量级特异性（vs 同构 row47 中性）与顺序效应的 tile 粒度依赖
   未闭合，需 op_summary pipe 利用率分析（后续方向）
4. 默认 headM 缺省仍为 512（公式保留为 `headMSize<=0` 实验入口），localScopeLast 缺省 0
