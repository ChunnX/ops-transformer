## 一、P2-RS: reduceSum 批量加载（三轮迭代收敛）

### 迭代过程（完整的失败-定位-收敛链）

**v8.0 全量批量**（rankDim 份输入背靠背 DataCopy + 单次等待）:
- 精度 10/10 FAIL → 定位①: 缺 V→MTE2 排序（跨行/跨段 Cast 读 vs 批量 MTE2 写），补段首
  `SetFlag/WaitFlag<V_MTE2>` 对 → 修复大规模损坏（75% → 0.004% 元素）
- 剩余散点损坏（列 128~135 = UB 字节 512~543）→ 定位②: **v7 引入的 fence 轮询 buffer
  (offset 512) 落在 RS 累加器 slot#0 内**，轮询 MTE2 写与上一轮 RS 输出 Cast 的 V 读无排序
  （v7 潜伏竞态，v8 RS 加速使窗口张开）→ **UB 分区修复**: RsParams.ubReservedBytes，RS slot
  布局整体上移 544B → 精度 10/10 PASS
- 性能: row17 **-28%** / row16 -4.8% / row10 -4.2%，但 row47/87/89 **+2.6~+5.7% 回退**

**v8.1 配对批量**（每批 2 份，突发减半）: 回退仍在 → 排除"突发大小"因素

**v8.2 在途串行**（batchRank=1）: 回退仍在 → 排除"批量加载"本身

**根因定论**: 回退与加载批量无关，而是 **移除逐 rank V_MTE2 排空后 load(r+1) 与 compute(r)
重叠，在途 RS 的 GM 读流变连续，与并发 PUT 争抢带宽**（v7 的 load→wait→compute→V排空
严格交替节奏恰好为 PUT 留出带宽间隙；尾声 RS 无并发 PUT 故批量纯赚）

**v8 最终结构**:
```
在途 RS (与 PUT(t) 并发): 逐 rank 串行 + 逐 rank V_MTE2 排空   ← v7 节奏, 零回退
尾声 RS (PUT 已 drain):   rankDim 份全量批量 + 单次等待         ← 延迟交叠, 纯收益
```

## 二、P3 复评: 残余同步占比

v8 最终 op_summary: AIV idle 30~67%（v5 时代 42~69%），其中:
- 通信 bound case（row1/86: idle 60~67%）: 关键路径 = 单通道 ~40GB/s 链路带宽（P0 已证
  jetty 物理上限），fence RTT 已被 v7 重叠化，**进一步压缩同步无收益 — P3 不再值得投入**
- 均衡 case（row87/89/93: idle 30~37%）: idle 主要为 WaitFlag(AIC 生产) + #1 barrier 汇合，
  属流水固有节奏，非 fence 残值
- **P3 结论: 关闭**。fence 本地化（数据内嵌序列号）仅在未来多 link 拓扑（跨机）上有意义

## 三、P2-AIC: 递延（未实施）

- 安全可调旋钮仅 `SetMaxBaseM` / `EnableBaseMHalving`（baseK/stepK/scaleKL1 与 L1 深度强
  耦合，不可后补丁）
- 收益目标 case（K=5472/6144 计算 bound, row67/81/97）不在当前 10 case 典型集，且经 v7+v8
  优化后当前集内已无 AIC bound case
- 建议后续: 在 aiss-tiling-solver / Blaze tiling 专家流程下针对大 K 族专项调优
