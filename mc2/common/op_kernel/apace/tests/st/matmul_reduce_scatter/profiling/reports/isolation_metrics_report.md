# apace ST 隔离测试指标核算报告 v2（加速比与掩盖率，四分量分解）

- **方法论**: ascendc-perf-optimize skill / comm-compute，针对 AIC/AIV 三方流水架构修正口径
- **采集**: msprof task-based, 10 iter / 丢弃前 5 warm-up / 后 5 均值 / 跨 rank 取 max

## 指标定义

```
四分量隔离: T_mm(compute_only) | T_a2a(comm_only 纯AllToAll) | T_rs(reduce_only)
T_before = serial 模式实测（三方串行）
T_after  = 融合模式实测（三方流水: matmul ∥ AllToAll(t) ∥ reduceSum(t-1)）

加速比 = T_before / T_after

T_floor = max(T_mm, T_a2a, T_rs)                # 三方完美流水理论下界
掩盖率(修正) = (T_before - T_after) / (T_before - T_floor)   # 恒 ≤ 1
```

> **v1 口径修正说明**: v1 的 T_comm(comm_only) 混入了 reduceSum（AIV 计算分量），
> 而融合模式下 AllToAll(t) 与 reduceSum(t-1) 在不同 AIV 核组并行，通信阶段内部被流水压缩，
> 致 (T_before-T_after) 超过 min(T_mm, T_comm)，两阶段公式掩盖率 >1（row87 达 3.51）。
> v2 拆分为纯 AllToAll / 纯 reduceSum，分母改为三方完美流水的理论最大可节省量，
> 物理含义 = 「实际流水达到理论流水收益的程度」，恒 ≤ 1。

## 负掩盖率验证（同一二进制背靠背复测）

对 2 个负值用例，用**同一 probe 二进制**背靠背跑 serial 与 perf 各 2 轮（消除跨二进制噪声）：

| 用例 | 轮次 | serial(us) | perf(us) | 差值 | 判定 |
|---|---|---|---|---|---|
| row17 (4096/5120/640/r4) | #1 | 221.7 | 231.5 | +9.8 | **融合更慢（真实，复现）** |
| row17 | #2 | 221.0 | 229.8 | +8.8 | **融合更慢（真实，复现）** |
| row81 (8192/5472/16384/r4) | #1 | 4424.4 | 4179.4 | -245.1 | 融合更快 |
| row81 | #2 | 4166.0 | 4181.4 | +15.4 | 持平（噪声） |

### 负值结论

1. **row17（-0.63）— 真实的融合开销回退**：
   - 4 次复测一致：融合模式稳定慢 ~9us（4%）
   - 该 shape 为 commTurn=8 的小 tile 快速通信/计算（T_a2a=103.6, T_rs=46.5），理论收益窗口仅 7.5us，**每 tile 的 SyncAll/CrossDevice 同步开销（8 tile × 3 次）超过重叠收益** —— 小分母将 9us 差值放大为 -0.63
   - 性质：架构性 trade-off（与 vs 级联基线 0.63x 劣势结论相互印证），属已知小 N 场景限制，非流水实现缺陷

2. **row81（-0.03）— 测量噪声，实际持平**：
   - serial 模式自身跨轮波动 6%（4424 vs 4166），融合模式非常稳定（4179.4/4181.4，偏差 0.05%）
   - 该用例 R=1.50 计算 Bound 边缘，通信掩盖空间本就趋近于 0，真实状态为**收支平衡**，-0.03 应读作 0

### 口径说明

负掩盖率在以下情形属正常物理现象，不代表公式错误：
- **小幅负值（|cover| < 0.1）**：计算 Bound 用例的噪声级持平，读作 0（无收益）
- **大幅负值（如 -0.63）**：小 tile 快速场景下融合同步开销 > 重叠收益的真实回退信号，应标注为架构限制场景
