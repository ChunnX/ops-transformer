1. 先建立心智模型

这个文件是 V2 的“调度中枢”。同一个 MIX kernel 中，AIV 先把各 rank 的输入重排到本地 recvBuffer，AIC 再把每个专家的连续片段交给 CATLASS。点击文中的紫色、蓝色、绿色变量，可以在弹窗里查看声明/使用位置，并跳到下方完整源码。

当前边界：只讲 BF16 + AIV + 910C 最终实现；外层循环粒度是 expert，不含 chunk，也不宣称当前已有专家级通算重叠。
参与者职责关键对象
AIV把本卡输入发布到窗口；从每个 peer 拉取当前 expertcontext、layout、copyBuffer
AIC等待完整数据，然后逐 expert GEMMgmmweight、gmmy
控制面区分不同调用轮次并做 publish/release barrierepoch、flagBuffer

2. 先分清三种排列

源 rank 的 gmm_x/send_counts: destination-major, expert-minor
目标 rank 的 recv_counts:    source-major, expert-minor
目标 recvBuffer:              expert-major, source-minor

BuildExpertMetaForIndex 计算某个专家的总起点和总量；GetDestinationSourceTokenOffset 再在该专家内按 source 前缀和定位。远端源窗口中的起点由 GetPeerSourceTokenOffset 按 destination 前缀和计算。

最常见的精度错误不是 CATLASS，而是把 source*E+expert 与 destination*E+expert 混用。

3. Run 总入口：先决定接收区，再分 AIV/AIC

1
选择接收缓冲若用户需要 permuteOut，它本身就是 recvBuffer；否则使用 userWorkspace 加 recvTokenOffset。这样不会为可选输出重复复制。
2
AIV 初始化通信上下文context 取得 rank/window；校验其 rankSize 与 tiling 一致。
3
求窗口布局累计 sendCounts 得 inputTokens，交给 BuildDeviceWindowLayout。
4
建立 UB bufferGetCopyQueueBytes 给出 queueBytes，分配 copyBuffer 与 flagBuffer。
5
两条核路径AIV 调 ProcessAiv；AIC 调 ProcessAic。入口函数本身是 Run。

4. ProcessAiv：20 步看懂一轮通信

6
识别 worker读取 taskIdx、subBlockIdx 和 taskRatio，计算 blockIdx。
7
产生本轮 epoch只有 task0 修改 epoch；本 rank AIV `SyncAll` 后用 LoadInvocationEpoch 读取统一值。
8
发布本卡输入CopyInitialWindowPayload 把 gmmx 和 sendCounts 放进本卡窗口。
9
输入分核PartitionElements 返回每个 worker 的 range，依据总 inputElements 均匀切分。
10
publish barrier每个 rank 发布当前 epoch；task0 等全部 peer。控制地址来自 layout，读写借助 flagBuffer。
11
进入 expert 外循环expertIdx 从 0 到 expertPerRank-1；本版没有 chunk。
12
把 block 映射到 sourcesourceRank 取 blockIdx；IsSourceWorker 保证仅 subBlock0 且一 block 对一 source。
13
拉当前 expert 的一个源片段CopyExpertFromSource 同时计算 sourceTokenOffset 与 destinationTokenOffset。
14
交叉验数远端 peerCounts 得到 sourceTokenCount，必须等于本地 recvCounts 对应项。
15
expert 末尾同步同一 expert 的所有 source worker 完成后 `SyncAll`，再进入下一个 expertIdx；UB 继续复用 copyBuffer。
16
通知 AIC全部专家都搬完后调用 SignalAicDataReady，事件号为 kAicDataReadyEventId。
17
release barrier只有所有 rank 都读完 peer window 才结束当前 epoch，否则下一轮可能覆盖仍被读取的 payload。

5. 两类搬运：发布与拉取

CopyInitialWindowPayload

先把 token 数乘 hiddenSize 变为 BF16 元素数。主 payload 由所有 AIV 分工；counts 只有 task0 写。countNum 最多 128，32B 小批写入能明确标量到 MTE3 的依赖。

CopyExpertFromSource

它从远端 context 的指定窗口读取，并写到本地 recvBuffer。实际搬运元素数为 sourceTokenCount × K。

数据路径是 peer GM → UB → local GM。单个 TBuf 配合 MTE2↔MTE3 硬事件，比这里早期使用的双深度 TQue 更直接。

6. 为什么既有 SyncAll，又有 peer flag，还有 cross-core flag

机制同步范围用途
`SyncAll<true>`本 rank 内 AIV tasks本卡所有 worker 的阶段同步
window epoch slots不同 rankpublish/release barrier
CATLASS CrossCoreFlag配对 AIV → AIC完整接收区就绪后允许 GEMM

kControlRegionBytes 固定为 16 MiB，windowBytes 决定控制区尾地址；requiredBytes 用来拒绝装不下的窗口。

7. ProcessAic：数据完整后逐 expert 计算

18
等待 AIVAIC 等 kAicDataReadyEventId，不再依赖 user workspace 的逐 expert ready。
19
构建单 expert 元数据BuildExpertMetaForIndex 计算 recvTokenBase 和 tokenCount。
20
运行主 GEMMA 取 recvBuffer，B 取 gmmweight，C 写 gmmy。零 token 专家不发起 GEMM。
21
可选共享 MM主专家循环后，如已提供 mmx、mmweight 和 mmy，再执行共享 GEMM。

CATLASS 文件不在本页完整源码面板中，但调用语义是 BF16 A/B/C、FP32 accumulator、四种预编译 tile。完整工程教程请配套阅读 Markdown 文档。

8. 这份最终代码背后的稳定性修复

  1. 搬运中间态由 TQue 改成单 copyBuffer，显式 MTE2/MTE3 事件。
  2. counts 不再把 tiling 内字段二次包装为 GM tensor；task0 标量装入 flagBuffer 后写窗口。
  3. context、TPipe 和 AIV buffers 只在 AIV 分支初始化，AIC 不碰 peer-window 资源。
  4. 早期逐 expert ready 改为所有通信完成后一次 SignalAicDataReady，先稳定正确性。
  5. publish/release 都带 epoch，避免第二轮误吃第一轮 flag。

9. 如何使用完整源码面板

点击右下角“源代码”可打开 540 行完整 `allto_allv_grouped_mat_mul_aiv_mode.h`。点击本文任意变量后：

  • 绿色按钮跳到声明；
  • 蓝色按钮可在所有使用点之间循环；
  • 键盘左右键切换当前高亮位置，Esc 关闭；
  • 建议从 Run → ProcessAiv → CopyExpertFromSource → ProcessAic 顺序阅读。

附录 B：读代码时的四条不变量

  1. 所有 counts 都必须非负，任何 offset 加法都不能溢出。
  2. 远端源偏移按 destination-major；本地目标偏移按 expert-major。
  3. AIC 看到 data-ready 时，完整 recvBuffer 必须已对 AIC 可见。
  4. 任一 rank 复用窗口前，所有 peer 必须完成 release barrier。
