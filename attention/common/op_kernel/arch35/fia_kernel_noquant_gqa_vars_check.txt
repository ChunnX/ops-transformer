## 四、constInfo 在 constInfo 中的字段初始化跟踪
================================================================================
constInfo 是 FlashAttentionNoQuantGqaKernel 的成员变量(L85), 非引用,默认构造。
在 Init(L134) 中调用 InitConstInfo() 完成全字段初始化。
InitConstInfo 将 tilingData 中的全部 Fia*Params 逐字段拷贝到 constInfo。
constInfo 作为引用传递给 cubeBlock、vecFaBlock、vecFdBlock 的构造函数(L116)。
Init() 中 InitConstInfo(L134)先于 InitVecBlock(L149)和 InitCubeBlock(L155)调用,顺序安全。

所有 constInfo 字段初始化来源详见 fia_block_vec_noquant_gqa_vars_check.txt 第四节。

## 五、特殊分析：无内联默认值的成员变量初始化安全分析
================================================================================
以下4个成员变量声明时无内联默认值, 需确认使用前已初始化:

[L102] curS2Start (uint32_t, ★无默认)
  首次使用路径: FlashAttention(L403) → while loop → GetTaskDealMode(L428)
  → isFirstTask=true(L474) → CalcCurS2StartEnd*(L509/511) 设置 curS2Start
  → 返回 CREATE_TASK → FlashAttention → CreateTask(L431) → CalcParams(L689)
  → L748: info.isFirstS2Loop = ((loop==0)||(s2Cur==curS2Start)) ← 此时已赋值
  结论: SAFE (isFirstTask=true 确保首次调用必然经过赋值路径)

[L104] prevBIdx (uint32_t, ★无默认)
  首次使用路径: FlashAttention → GetTaskDealMode(L477):
    if (isFirstTask || prevBIdx != bIdx)
  isFirstTask=true → 短路求值, prevBIdx 不被读取 → 进入if体 → L478 prevBIdx = bIdx 赋值
  后续调用: prevBIdx已在上一轮赋值, 比较合法
  结论: SAFE (短路求值保护首次读取; 赋值后值被持久化)

[L105] prevBN2Idx (uint32_t, ★无默认)
  首次使用路径: FlashAttention(L413)在while之前: prevBN2Idx = bN2Cur (赋值)
  首次读取路径: GetTaskDealMode(L507): if (isFirstTask || bN2Cur != prevBN2Idx || ...)
  isFirstTask=true → 短路求值, prevBN2Idx 不被读取
  结论: SAFE (先赋值L413,后条件读取L507; 短路求值保护)

[L106] prevGS1Idx (uint32_t, ★无默认)
  与 prevBN2Idx 相同: L414赋值, L507短路求值保护
  结论: SAFE
