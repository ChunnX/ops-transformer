# 新算子适配方案

> 解决问题: 四个算子的 NPU 调用模式(两阶段/单阶段)、量化算法(MXFP8/HIF8/hifloat8)、输出结构各不相同, 框架如何用一个接口范式涵盖。

---

## 一、适配的本质: 什么是变的, 什么是不变的

### 不变的(框架核心提供)

- 流程编排: gen → cpu → npu → gpu → compare → prof
- 用例管理: 加载、笛卡尔积、ID匹配
- 精度比对: 两方/三方、失败分析、连续性检测
- 性能测试: msprof编排、产物解析、baseline回归
- 可靠性: try/except、增量CSV、pt持久化
- 配置管理: YAML、dtype阈值

### 变的(新算子必须适配的)

| 适配点 | 非量化FA | 全量化FA | MQSMLA | QSFA |
|--------|----------|----------|--------|------|
| 轴参数定义 | B/N1/N2/S1/S2/D... | B/N_q/N_kv/D/actual_seq... | B/S1/S2/N1/N2/D/K... | B/S1/S2/N1/N2/D/K... |
| tensor构造 | InputSpec+layout映射 | 手写+MXFP8量化 | 手写+HIF8量化 | 手写+hifloat8量化 |
| NPU调用模式 | 两阶段(metadata+kernel) | 单阶段 | 两阶段 | 单阶段 |
| NPU算子名 | flash_attn_metadata + flash_attn | npu_fused_infer_attention_score_v2 | mixed_quant_sparse_flash_mla_metadata + ... | npu_kv_quant_sparse_flash_attention |
| GPU调用 | 三路径(paged/varlen/fixed) | 无 | 无 | 无 |
| 量化算法 | 无 | MXFP8(per-token-group) | HIF8(5档精度) | hifloat8(SSR/TA/Hybrid) |
| 输出结构 | out + lse | atten_out + lse_out | out + lse | attention_out |
| 精度阈值 | fp16/bf16差异化 | 同左 | 同左+FP8特殊 | 同左+hifloat8特殊 |

## 二、核心思路: 分离数据契约与调用契约

gen_data 产出一个 inputs 字典(数据契约), cpu/npu/gpu 各自接收同一份 inputs(调用契约), meta/attn 拆分是 npu 内部行为。

```
case_loader.py
    baseparam(轴参数字典)
         │
         ▼
gen_data.py (算子适配)
    baseparam → inputs: dict    ← 数据契约: 所有物理排布tensor + 标量超参
         │                        CPU/NPU/GPU 共用, 完全一致
         ├──→ cpu.py    inputs → outputs: dict    ← CPU golden
         ├──→ npu.py    inputs → outputs: dict    ← NPU(内部自行处理metadata两阶段)
         └──→ gpu.py    inputs → outputs: dict    ← GPU(可选)
                    │
                    ▼
              compare.py
    cpu_out vs npu_out (vs gpu_out)  → 按key遍历比对
```

## 三、适配接口定义

新算子适配只需实现 5 个方法:

```python
class OperatorAdapter(Protocol):
    name: str

    # 1. 参数定义: 告诉框架这个算子有哪些轴参数、默认值
    param_names: list[str]
    param_defaults: dict

    # 2. 参数推导: 从少量必需参数推导全部参数(如cu_seqlens→seqused)
    def normalize_params(self, params: dict) -> dict: ...

    # 3. 数据生成: 轴参数 → 物理排布tensor + 标量超参 (含量化, 如果需要)
    def gen_inputs(self, params: dict) -> dict: ...

    # 4a. CPU golden: inputs → outputs (数学参考实现)
    def cpu_compute(self, inputs: dict) -> dict: ...

    # 4b. NPU调用: inputs → outputs (内部处理单阶段/两阶段/graph_path)
    def npu_compute(self, inputs: dict, graph_path: int = 0) -> dict: ...

    # 4c. GPU调用: inputs → outputs (可选)
    def gpu_compute(self, inputs: dict) -> dict: ...
```

## 四、三个关键设计决策

### 决策1: meta/attn 拆分下沉到 npu_compute 内部

```
gen_data 产出: inputs = {"q": tensor, "k": tensor, "v": tensor,
                          "cu_seqlens_q": list, "softmax_scale": float, ...}

npu_compute 内部(非量化FA):
    meta_dict = {k: inputs[k] for k in META_KEYS}      # 内部拆分
    kernel_dict = {k: inputs[k] for k in KERNEL_KEYS}
    metadata = flash_attn_metadata(**meta_dict)
    return {"out": out, "lse": lse}

npu_compute 内部(全量化FA):
    return {"atten_out": out, "lse_out": lse}           # 不拆分, 直接调
```

框架核心不感知 meta/attn, gen_data 也不产出 meta/attn。

### 决策2: 量化是 gen_inputs 的内部逻辑

```
gen_inputs(全量化FA):
    q_fp16 = torch.rand(...)
    q_fp8, dequant_scale = mxfp8_quant(q_fp16)          # 量化在内部
    return {"q": q_fp8, "dequant_scale_q": dequant_scale, ...}

gen_inputs(非量化FA):
    q = torch.rand(...)                                  # 不需要量化
    return {"q": q, ...}
```

量化算法(MXFP8/HIF8/hifloat8)作为独立模块(`quant.py`), 被 `gen_inputs` 调用。框架核心不感知量化。

### 决策3: outputs 字典统一 key 约定

```python
# 所有算子的 outputs 字典使用统一 key:
outputs = {
    "out": tensor,   # 主输出(必选)
    "lse": tensor,   # LSE输出(可选, 无则不放入)
}

# compare 遍历 outputs.keys() 逐一比对:
for key in cpu_out.keys():
    result = check_result(cpu_out[key], npu_out[key], dtype, tolerance)
```

新算子如果有多输出, 约定 key 名即可。compare 不关心输出语义, 只按 key 比对。

---

## 五、关键约束

1. `gen_inputs` 产出的 `inputs` 字典, `cpu_compute` 和 `npu_compute` 接收时**完全一致**(超参数、tensor、排布)
2. `outputs` 字典只包含需要比对的 tensor(如 `{"out": tensor, "lse": tensor}`), metadata 等中间产物不放入
3. `compare` 按 key 遍历 outputs 字典, 对每个 key 做两方/三方比对
4. `npu_compute` 内部自行决定: 是否调 metadata 算子、如何从 inputs 中提取 metadata 入参、如何拆分 meta/kernel 字典 — 这是 NPU 调用细节, 不泄露到框架层

## 六、新算子适配完整步骤

| 步骤 | 内容 | 框架支持 |
|------|------|----------|
| 1 | 定义轴参数(`param_names` + `param_defaults`) | case_loader 自动笛卡尔积展开 |
| 2 | 实现 `normalize_params`(参数推导链) | 框架在 gen 前自动调用 |
| 3 | 实现 `gen_inputs`(轴→tensor, 含量化) | 框架自动存 input.pt |
| 4 | 实现 `cpu_compute`(数学参考) | 框架自动存 cpu.pt |
| 5 | 实现 `npu_compute`(含 metadata 两阶段处理) | 框架自动存 npu.pt + graph_path 配置 |
| 6 | (可选)实现 `gpu_compute` | 框架自动存 gpu.pt |
| 7 | (可选)定义用例集(`testcase/xxx.py`) | 字典/CSV/Excel 三种形式 |
| 8 | (可选)覆盖 `get_tolerance` | 默认从 ops-precision-standard 取 |

**框架核心无需修改一行代码即可接入新算子。**

## 七、与既有框架的对比

| 既有框架问题 | 本方案解决方式 |
|-------------|---------------|
| MQSMLA: CPU用BNSD, NPU用PA排布, 两套tensor并存 | gen_inputs产出物理排布tensor, CPU/NPU共用同一份inputs |
| 非量化FA: NPU内部再调build_flash_attn_params重新构造, CPU不调用 | meta/attn拆分下沉到npu_compute内部, gen_inputs只产一份inputs |
| 全量化FA: CPU收FP32 scale, NPU收e8m0打包scale | gen_inputs产出NPU格式tensor, CPU内部自行反量化 |
| MQSMLA: metadata_input/op_input键重复不干净 | inputs是扁平字典, 拆分由npu_compute内部自行管理 |
| 四框架: outputs key不统一(out/lse vs atten_out/lse_out) | 约定统一key: out + lse(可选) |
