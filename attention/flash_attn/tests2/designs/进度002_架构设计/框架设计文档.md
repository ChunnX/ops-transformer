### 顶层文件职责

| 文件 | 职责 | 内容 |
|------|------|------|
| `conftest.py` (~50行) | pytest hooks | `pytest_addoption`(所有CLI参数) + `pytest_generate_tests`(委托test.py加载cases) |
| `test.py` (~150行) | 纯入口(薄层委托) | `main()`(argparse+for+reporter) + `test_op()`(fixture+run_case+assert) + session fixtures(stages/reporter) + hookwrapper + `if __name__=="__main__"` |
| `orchestrator.py` (~250行) | 引擎+报告 | `run_case()`(stages控制+pt管理+device转换+ThreadPoolExecutor) + `Reporter`类(CSV增量flush+终端表格) + `make_failure_result` + helpers(_pt_path/_save_pt/_load_pt) |
| `compare.py` (~114行) | 精度判定 | `compare_outputs`(纯函数, torch.isclose+fail_ratio, 不打印) |
| `precision_analyze.py` (~123行) | 失败诊断 | `analyze_failure`(失败点位打印+高级分析, 独立) |
| `csv_parser.py` (~10行) | CSV转换工具 | `parse_csv`(CSV→paramset字典, 独立工具) |
| `pytest.ini` (~6行) | marker静态注册 | `markers = STC/RDV/PROF/WHITEBOX/REDLINE` (参考FIA/MQSMLA/QSFA, 不用pythonpath, 靠rootdir自动插入) |

设计原则: 顶层文件数冻结为6个.py + 2个配置, 不再往其他路径移动。test.py保持纯入口语义(薄层委托), 引擎细节(reporter/run_case/helpers)内聚于orchestrator.py, 保证可独立单元测试。

用法:
- CLI: `python test.py --stages gen,cpu,npu,compare`
- pytest: `pytest test.py --stages gen,cpu,npu,compare`

pytest硬约束: `pytest_addoption`和`pytest_generate_tests`必须在conftest.py中。marker注册沿用既有框架通用做法(静态pytest.ini)。

### 接口与实现模式

core/`__init__.py` 定义ABC基类, core/下各模块定义具体Backend类直接继承:

```python
# core/__init__.py — ABC基类 + 门面函数
from abc import ABC, abstractmethod

class GenDataBase(ABC):
    @abstractmethod
    def gen_inputs(self, params: dict) -> dict: ...
    @abstractmethod
    def normalize_params(self, params: dict) -> dict: ...

class CpuBase(ABC):
    @abstractmethod
    def cpu_compute(self, inputs: dict) -> dict: ...

class NpuBase(ABC):
    @abstractmethod
    def npu_compute(self, inputs: dict, graph_path: int = 0) -> dict: ...

class GpuBase(ABC):
    @abstractmethod
    def gpu_compute(self, inputs: dict) -> dict: ...

def forward(inputs: dict, device: str = "npu", **kwargs) -> dict:
    from core.gen_data import GenDataBackend
    from core.cpu import CpuBackend
    from core.npu import NpuBackend
    if device == "cpu":
        return CpuBackend().cpu_compute(inputs)
    elif device == "npu":
        return NpuBackend().npu_compute(inputs, **kwargs)
    elif device == "gpu":
        from core.gpu import GpuBackend
        return GpuBackend().gpu_compute(inputs)
    raise ValueError(f"Unsupported device: {device}")
```

```python
# core/cpu.py (示例, gen_data/npu/gpu同理)
from core import CpuBase

class CpuBackend(CpuBase):
    def cpu_compute(self, inputs: dict) -> dict:
        ...  # golden实现
        return {"out": out, "lse": lse}
```

命名约定(移植非量化FA Backend命名):

| core/ 文件 | 基类(在`__init__.py`) | 具体类 | 实例化方式 |
|-----------|------|------------|--------|
| gen_data.py | GenDataBase(ABC) | GenDataBackend | `GenDataBackend()` |
| cpu.py | CpuBase(ABC) | CpuBackend | `CpuBackend()` |
| npu.py | NpuBase(ABC) | NpuBackend | `NpuBackend()` |
| gpu.py | GpuBase(ABC) | GpuBackend | `GpuBackend()` |

orchestrator 调用:

```python
from core.gen_data import GenDataBackend
from core.cpu import CpuBackend
from core.npu import NpuBackend

gen = GenDataBackend()
cpu = CpuBackend()
npu = NpuBackend()

# gen阶段: load_network_pt 独立于stages, 优先于gen_inputs
if config.get("load_network_pt"):
    inputs = gen.load_network_inputs(config["load_network_pt"])
else:
    inputs = gen.gen_inputs(params)

cpu_out = cpu.cpu_compute(inputs)

# npu阶段: ThreadPoolExecutor崩溃隔离 + retry
with ThreadPoolExecutor(max_workers=1) as executor:
    for attempt in range(max_retries + 1):
        future = executor.submit(npu.npu_compute, dev_inputs, graph_path)
        npu_out = future.result()
```

量化与反量化是Backend内部实现细节(量化在gen_inputs内, 反量化在cpu_compute内), core/quant.py被同目录gen_data.py/cpu.py直接import。

## 三、核心架构

### 数据流

```
baseparam(轴参数) → gen_inputs → inputs(一个字典, CPU/NPU/GPU共用, 完全一致)
外部pt(--load-network-pt) → load_network_inputs ↗
                                    ├──→ cpu_compute  → outputs dict
                                    ├──→ npu_compute  → outputs dict (ThreadPoolExecutor隔离)
                                    └──→ gpu_compute  → outputs dict(可选)
                                              ↓
                                    compare(只做判定, 按key遍历outputs逐个比对)
                                              ↓
                                    reporter(CSV增量flush+终端表格)
                                    precision_analyze(失败点位打印+高级分析)
```

### 编排机制

移植全量化FA已验证的模式: stages set + if/else 阶段控制:
- `--stages` 解析为 set (如 `{"gen","cpu","npu","compare"}`)
- `run_case()` 内按固定自然顺序(gen→cpu→npu→gpu→compare)检查每个阶段是否在 set 中, 在则执行, 不在则从pt加载
- prof 阶段在 set 中则调用, 命中 `raise NotImplementedError`
- 每阶段产出后默认存pt, 下阶段优先从内存取, 无则从pt加载

### 双入口

- **pytest 入口**(主): `pytest test.py` @parametrize 批量 + session fixture 注入 stages + reporter + marker 三层分层; run_case从orchestrator.py导入
- **CLI 入口**(辅): `python test.py`, argparse 单 case/调试/golden 独立, for 循环 + try/except + reporter; run_case从orchestrator.py导入
- 两入口共享 `run_case()`(orchestrator.py) 和 session fixtures(test.py), 参数语义一致

## 四、模块设计

### A1. 编排器

| # | 定稿方案 |
|---|---------|
| 1 | `run_case(stages: set[str], params: dict, reporter: Reporter, *, max_retries: int = 0) -> dict`; 位置: orchestrator.py(根目录); 移植全量化FA模式: stages set + if/else阶段控制, 固定自然顺序gen→cpu→npu→gpu→compare |
| 2 | 内存优先, 默认存pt; 连续阶段内存传递, 跳过阶段从pt加载; 可配置关闭存pt |
| 3 | 每阶段 if 在set中则执行, 否则从pt加载; pt不存在则报错 |
| 4 | 8阶段固定自然顺序; 5精度阶段有实现, 3 prof阶段虚函数; stages set控制哪些执行 |
| 5 | 双入口共享编排器: pytest(parametrize+pytest.fail) + CLI(for+try/except+reporter) |
| 6 | pt路径构造(orchestrator.py内部): `_pt_path(case_set, case_id, stage) -> Path("data") / case_set / case_id / f"{stage}.pt"` |
| 7 | npu_compute崩溃隔离: orchestrator.py内用`ThreadPoolExecutor(max_workers=1)`包裹npu_compute调用, 异常被try/except捕获后record到reporter继续下一case |
| 8 | gen阶段: 若config含`load_network_pt`路径则调`gen.load_network_inputs(load_network_pt)`, 否则调`gen.gen_inputs(params)`; `--load-network-pt`独立于`--stages`, 优先于gen阶段 |

### B3. cpu/npu/gpu compute

| # | 定稿方案 |
|---|---------|
| 1 | core/gen_data.py,cpu.py,npu.py,gpu.py 为具体Backend类(继承__init__.py中ABC); 量化在Backend内部; 直接实例化, 无工厂方法 |

### B4. compare

| # | 定稿方案 |
|---|---------|
| 1 | 两方: torch.isclose+fail_ratio; 返回dict{passed,max_abs,mean_abs,fail_cnt,total,fail_ratio}; 只做判定, 不打印; 向量化比对 |
| 2 | 阈值: compare.py硬编码默认值(fp16/bf16两档) + 算子可提供get_tolerance覆盖; get_tolerance放在core/__init__.py中, compare.py通过getattr探测 |
| 3 | 大case并行(仅CPU): 默认单进程向量化; 配置chunk_size>0时启用torch.multiprocessing+share_memory_零拷贝分块; 配置项: compare.chunk_size + compare.num_workers |
| 4 | 按outputs key逐个比对(out/lse分别), 失败时触发precision_analyze |
| 5 | 结果交reporter存CSV增量flush |
| 6 | FP8/特殊dtype处理由算子提供(如uint8重解释), 通过`dtype_handler: Callable[[Tensor], Tensor] = None`回调注入compare; 框架核心只处理fp16/bf16/fp32 |
| 7 | torch向量化(非numpy) |
| 8 | 三方比对作为可选扩展, 不入框架核心 |
| 9 | 导入整网pt: GenDataBase基类增加load_network_inputs(pt_path)->dict可选方法, 从外部整网pt加载inputs替代gen_inputs; 设计目标(8) |

## 五、新算子适配

### core/ 接口与实现

ABC基类定义在 `core/__init__.py`, 具体Backend类在core/各模块:

```python
# core/__init__.py — ABC基类定义
class GenDataBase(ABC):
    @abstractmethod
    def gen_inputs(self, params: dict) -> dict: ...
    @abstractmethod
    def normalize_params(self, params: dict) -> dict: ...
    def load_network_inputs(self, pt_path: str) -> dict: ...  # 可选, 导入整网pt(设计目标8)

class CpuBase(ABC):
    @abstractmethod
    def cpu_compute(self, inputs: dict) -> dict: ...

class NpuBase(ABC):
    @abstractmethod
    def npu_compute(self, inputs: dict, graph_path: int = 0) -> dict: ...

class GpuBase(ABC):
    @abstractmethod
    def gpu_compute(self, inputs: dict) -> dict: ...

def forward(inputs: dict, device: str = "npu", **kwargs) -> dict: ...
```

```python
# core/gen_data.py — 具体实现
from core import GenDataBase
class GenDataBackend(GenDataBase): ...

# core/cpu.py — 具体实现
from core import CpuBase
class CpuBackend(CpuBase): ...
```

量化与反量化是Backend内部实现细节, core/quant.py被同目录gen_data.py/cpu.py直接import。

### forward() 门面函数

core/__init__.py 提供forward()门面, 供用户直接调用:

```python
# core/__init__.py
def forward(inputs: dict, device: str = "npu", **kwargs) -> dict:
    from core.gen_data import GenDataBackend
    from core.cpu import CpuBackend
    from core.npu import NpuBackend
    if device == "cpu":
        return CpuBackend().cpu_compute(inputs)
    elif device == "npu":
        return NpuBackend().npu_compute(inputs, **kwargs)
    elif device == "gpu":
        from core.gpu import GpuBackend
        return GpuBackend().gpu_compute(inputs)
```

用户可直接调 `core.forward(inputs, device="npu", graph_path=7)`, 也可通过orchestrator走 `cpu_compute`/`npu_compute`。forward()不改Backend接口, 仅是便捷封装。

### 三个关键约束

1. **inputs 完全一致**: gen_inputs 产出的 inputs 字典, cpu_compute 和 npu_compute 接收时完全一致(超参数、tensor、排布)
2. **outputs 统一 key**: outputs 只含需比对的 tensor(如 `{"out": tensor, "lse": tensor}`), metadata 等中间产物不放入
3. **meta/attn 拆分是 npu 内部行为**: npu_compute 自行决定是否调 metadata 算子、如何拆分, 不泄露到框架层
