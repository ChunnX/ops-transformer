## 三、核心架构

### 数据流

```
baseparam(轴参数) → gen_inputs → inputs(一个字典, CPU/NPU/GPU共用, 完全一致)
                                    ├──→ cpu_compute  → outputs dict
                                    ├──→ npu_compute  → outputs dict
                                    └──→ gpu_compute  → outputs dict(可选)
                                              ↓
                                    compare(按key遍历outputs逐个比对)
                                              ↓
                                    reporter(CSV增量flush) + analyze(失败分析)
```

### 编排机制

阶段注册表 + 管道执行 + CaseContext 数据容器:
- **STAGE_REGISTRY**: 8 个阶段注册(gen/cpu/npu/gpu/compare/npuprof/npuprofop/gpuprof), prof 为虚函数
- **管道执行**: 按 `stages` 列表顺序逐个执行, 编排器不硬编码顺序
- **CaseContext**: 持有 inputs/outputs/result, 阶段间通过它传递; `ctx.xxx or load_pt(...)` 自动解决数据依赖

### 双入口

- **pytest 入口**(主): `@parametrize` 批量 + conftest session fixture 注入 stages/config + marker 三层分层
- **CLI 入口**(辅): argparse 单 case/调试/golden 独立, for 循环 + try/except + reporter
- 两入口共享 `run_case()` 和 `STAGE_REGISTRY`, 参数语义一致

### A2. 入口脚本

| # | 定稿方案 |
|---|---------|

### A3. 配置管理

| # | 定稿方案 |
|---|---------|
| 1 | 两层: 算子级{op}_paramset.py(PARAM_NAMES+DEFAULTS+SKIP_CASES) + 用例级字典覆盖; 框架级配置(device_id/graph_path/种子等)放入DEFAULTS |

### B1. case_loader

| # | 定稿方案 |
|---|---------|
| 1 | 字典+笛卡尔积为主; CSV/Excel为导入源(tools/excel_convert.py转换), 不作运行时格式 |
| 2 | 算子级定义PARAM_NAMES/DEFAULTS; case_loader统一展开: 笛卡尔积+DEFAULTS填充+SKIP_CASES过滤 |
| 3 | 随机测试: gen_inputs内seed控制tensor值随机; 不引入自定义random语法 |
| 4 | ID匹配三模式: 精确+前缀+后缀, 移植非量化FA resolve_case_ids |
| 5 | CSV/Excel列名=PARAM_NAMES |

### B2. gen_data → inputs

| # | 定稿方案 |
|---|---------|
| 1 | inputs key与NPU算子参数名一致; 标量超参(layout_q/softmax_scale)也放入inputs |
| 2 | 算子gen_inputs可选用InputSpec工具(声明式tensor+layout映射)或自由实现; 特殊token解析/5种生成方法/layout_override等FA特定能力由算子自行决定是否使用 |
| 3 | seed作为param, 默认值在DEFAULTS; gen_inputs内torch.Generator+manual_seed, 多tensor共享generator |
| 4 | inputs含tensor+标量, 统一一个字典; layout作为标量放入, CPU/NPU各自解读 |
| 5 | gen_inputs按params中的layout产出物理排布tensor; layout标量放入inputs |
| 6 | normalize_params→gen_inputs顺序: 先推导参数, 再轴→tensor |

### B3. cpu/npu/gpu compute

| # | 定稿方案 |
|---|---------|
| 1 | 算子实现OperatorAdapter, 直接import注册; --op选择对应adapter |
| 2 | graph_path作为npu_compute参数, 编排器从config传入; 算子npu_compute内自行处理graph_path 0/3/5/6/7的CompilerConfig配置 |
| 3 | GPU可选: gpu_compute签名统一, 实现由算子负责; 未实现则is_available返回False |
| 4 | outputs: out(必选)+算子自定义可选key(如lse); Dict{"out","lse"} |
| 5 | compute抛异常不捕获, 编排器统一try/except |
| 6 | 编排器统一device转换: `v.to(device) if isinstance(v,Tensor) else v`; compute内部不散布.npu() |
| 7 | clear_cache: 编排器每case后调用torch.npu.empty_cache()/torch.cuda.empty_cache() |

### B4. compare

| # | 定稿方案 |
|---|---------|
| 1 | 两方: torch.isclose+fail_ratio; 返回dict{passed,max_abs,mean_abs,fail_cnt,total,fail_ratio}; 向量化比对, 不分块并行 |
| 2 | 阈值: compare.py硬编码默认值(fp16/bf16两档) + 算子级get_tolerance覆盖 |
| 3 | 按outputs key逐个比对(out/lse分别), 失败时触发B6分析 |
| 4 | 结果存CSV增量flush |
| 5 | FP8/特殊dtype处理由算子adapter提供(如uint8重解释), 通过回调注入compare; 框架核心只处理fp16/bf16/fp32 |
| 6 | torch向量化(非numpy) |
| 7 | 三方比对作为tools/可选扩展, 不入框架核心 |

### B5. 精度比对后处理

| # | 定稿方案 |
|---|---------|
| 1 | CSV表头: case,dtype,key,pass,max_abs,mean_abs,fail_ratio,error |
| 2 | 增量flush: csv.DictWriter+append+每case flush, O(n) |
| 3 | 终端表格: Unicode box drawing; 中间报告print_interim(--report-interval) + 最终汇总print_final |
| 4 | Reporter.record(name,result,error,dtype); 失败时直接构造NaN占位dict |
| 5 | 汇总: 终端汇总表(pass/fail/total) + 汇总CSV |
| 6 | check_results: 按outputs key逐一检查passed, 失败时pytest.fail含key+pass率 |

### B6. 精度比对分析

| # | 定稿方案 |
|---|---------|
| 1 | 框架核心: 失败点位打印(默认前10, --verbose-diff全量) + Max-RE前3 + max_abs/mean_abs/fail_ratio统计 |
| 2 | 触发: --fail-analysis控制, 默认失败时触发; try/except防崩溃 |
| 3 | 报告: txt文件存于data/用例集名/用例名/fail_analysis.txt + 终端打印 |
| 4 | 高级分析(维度分析+连续性+可视化)作为tools/可选工具脚本, 不入框架核心; 非量化FA的5维度分析+热力图可移植为tools/analyze_advanced.py + tools/visualize.py |

## 五、新算子适配

### OperatorAdapter 接口

新算子适配只需实现以下方法:

```python
class OperatorAdapter(Protocol):
    name: str
    param_names: list[str]
    param_defaults: dict

    def normalize_params(self, params: dict) -> dict: ...
    def gen_inputs(self, params: dict) -> dict: ...
    def cpu_compute(self, inputs: dict) -> dict: ...
    def npu_compute(self, inputs: dict, graph_path: int = 0) -> dict: ...
    def gpu_compute(self, inputs: dict) -> dict: ...  # 可选
    def get_tolerance(self, dtype: str) -> tuple: ...  # 可选, 默认从compare.py取
```

### 三个关键约束

1. **inputs 完全一致**: `gen_inputs` 产出的 inputs 字典, `cpu_compute` 和 `npu_compute` 接收时完全一致(超参数、tensor、排布)
2. **outputs 统一 key**: outputs 只含需比对的 tensor(如 `{"out": tensor, "lse": tensor}`), metadata 等中间产物不放入
3. **meta/attn 拆分是 npu 内部行为**: npu_compute 自行决定是否调 metadata 算子、如何拆分, 不泄露到框架层

### 适配步骤

| 步骤 | 内容 | 框架支持 |
|------|------|----------|
| 1 | 定义轴参数(param_names + param_defaults) | case_loader 自动笛卡尔积展开 |
| 2 | 实现 normalize_params(参数推导链) | 框架在 gen 前自动调用 |
| 3 | 实现 gen_inputs(轴→tensor, 含量化) | 框架自动存 input.pt |
| 4 | 实现 cpu_compute(数学参考) | 框架自动存 cpu.pt |
| 5 | 实现 npu_compute(含graph_path配置) | 框架自动存 npu.pt |
| 6 | (可选)实现 gpu_compute | 框架自动存 gpu.pt |
| 7 | (可选)定义用例集(testcase/xxx.py) | 字典/CSV/Excel 三种形式 |
| 8 | (可选)覆盖 get_tolerance | 默认从 compare.py 取 |

**框架核心无需修改即可接入新算子。**

## 六、框架核心 vs 算子适配 vs 可选工具

| 层级 | 职责 | 内容 |
|------|------|------|
| **框架核心**(core/) | 通用骨架 | 编排器, case_loader, config, reporter, compare(两方), analyze(基础), orchestrator |
| **算子适配**(operators/) | 算子特定 | paramset, OperatorAdapter(gen_inputs+cpu/npu/gpu_compute+normalize_params+get_tolerance), InputSpec工具, 量化算法, FP8处理, graph_path配置 |
| **可选工具**(tools/) | 低频/特定 | Excel互转, 高级分析(维度+连续性), 可视化(热力图), 三方比对(Result类) |

> 原则: 框架核心只包含对所有算子通用的能力。算子特定的逻辑(FA的InputSpec特殊token、FP8 uint8重解释、5维度分析等)由OperatorAdapter实现或作为tools/工具脚本。

## 七、pt 文件管理

### 目录结构

```
data/{用例集名}/{用例名}/
    ├── input.pt      # gen阶段产出(inputs字典)
    ├── cpu.pt        # cpu阶段产出(outputs字典)
    ├── npu.pt        # npu阶段产出(outputs字典)
    ├── gpu.pt        # gpu阶段产出(outputs字典, 可选)
    └── fail_analysis.txt  # B6失败分析报告(失败时生成)
```

### 存储约定

- 默认存pt(设计目标7), 可通过config.save_pt关闭
- pt内容: torch.save(dict) 序列化, 加载时 `torch.load(path, map_location="cpu", weights_only=False)`
- 阶段跳过时从pt加载: `ctx.xxx or load_pt(path)`, pt不存在则报错
- --keep-pt控制中间产物保留(默认保留)
