### test_{op}.py — 薄适配层

每个算子一个test文件, 不含业务逻辑, 仅连接pytest与orchestrator:

```python
# test_flash_attn.py
from core.case_loader import load_cases
from core.orchestrator import run_case

CASES, CASE_IDS = load_cases("flash_attn")

@pytest.mark.parametrize("params", CASES, ids=CASE_IDS)
def test_flash_attn(params, stages, reporter):
    result = run_case(stages, "flash_attn", params, reporter)
    if not result["passed"]:
        pytest.fail(result["fail_msg"])
```

不同运行模式(single/batch)和不同NPU调用模式(ci/graph)通过stages+graph_path控制, test文件无感:
- single vs batch → `--stages` 不同值, orchestrator自动处理pt加载
- ci vs graph → `--graph-path` 不同值, npu_compute内部处理
- 不同数据量(ci小/perf大) → paramset按marker分层(CASE_SETS), case_loader按当前marker加载

### core/ 的两层职责

| 类别 | 文件 | 说明 |
|------|------|------|
| **框架骨架**(不变) | orchestrator.py, case_loader.py, compare.py, reporter.py | 所有算子通用, 换算子不修改; reporter.py为Reporter类(移植FA) |
| **基类+工厂**(不变) | gen_data.py, cpu.py, npu.py, gpu.py | ABC纯接口 + load(op_name)动态加载ops/{op}/Backend; 换算子不修改 |

> 量化与反量化是Backend内部实现细节: 量化在GenDataBackend.gen_inputs()内调用, 反量化在CpuBackend.cpu_compute()内调用。core/不感知量化, 不需要量化与反量化.py。ops/{op}/quant.py被同目录的gen_data.py/cpu.py直接import。

### 基类模式

core/ 的 gen_data.py/cpu.py/npu.py/gpu.py 是纯接口基类(ABC) + load()工厂方法:

```python
# core/cpu.py (示例, 其余三个同理)
class CpuBase(ABC):
    @abstractmethod
    def cpu_compute(self, inputs: dict) -> dict: ...

def load(op_name: str) -> CpuBase:
    mod = importlib.import_module(f"ops.{op_name}.cpu")
    return mod.CpuBackend()
```

ops/{op}/ 下的实现继承基类:

```python
# ops/flash_attn/cpu.py
from core.cpu import CpuBase
class CpuBackend(CpuBase):
    def cpu_compute(self, inputs: dict) -> dict:
        ...  # golden实现
        return {"out": out, "lse": lse}
```

命名约定(移植非量化FA Backend命名):

| core/ 文件 | 基类 | ops/ 实现类 | load() |
|-----------|------|------------|--------|
| gen_data.py | GenDataBase(ABC) | GenDataBackend | mod.GenDataBackend() |
| cpu.py | CpuBase(ABC) | CpuBackend | mod.CpuBackend() |
| npu.py | NpuBase(ABC) | NpuBackend | mod.NpuBackend() |
| gpu.py | GpuBase(ABC) | GpuBackend | mod.GpuBackend() |

orchestrator 调用:

```python
gen = core.gen_data.load(op_name)
cpu = core.cpu.load(op_name)
npu = core.npu.load(op_name)

# gen阶段: load_pt or gen_inputs
if config.get("load_pt"):
    inputs = gen.load_inputs(config["load_pt"])
else:
    inputs = gen.gen_inputs(params)

cpu_out = cpu.cpu_compute(inputs)

# npu阶段: ThreadPoolExecutor崩溃隔离 + retry
with ThreadPoolExecutor(max_workers=1) as executor:
    for attempt in range(max_retries + 1):
        future = executor.submit(npu.npu_compute, dev_inputs, graph_path)
        npu_out = future.result()
```

量化与反量化是Backend内部实现细节(量化在gen_inputs内, 反量化在cpu_compute内), core/不感知, 无需量化与反量化.py。ops/{op}/quant.py被同目录gen_data.py/cpu.py直接import。

## 三、核心架构

### 数据流

```
baseparam(轴参数) → gen_inputs → inputs(一个字典, CPU/NPU/GPU共用, 完全一致)
外部pt(--load-pt) → load_inputs ↗
                                    ├──→ cpu_compute  → outputs dict
                                    ├──→ npu_compute  → outputs dict (ThreadPoolExecutor隔离)
                                    └──→ gpu_compute  → outputs dict(可选)
                                              ↓
                                    compare(只做判定, 按key遍历outputs逐个比对)
                                              ↓
                                    reporter(CSV增量flush+终端表格)
                                    precision_analyze(失败点位打印+高级分析)
```

### 编排机制

移植全量化FA已验证的模式: stages set + if/else 阶段控制:
- `--stages` 解析为 set (如 `{"gen","cpu","npu","compare"}`)
- `run_case()` 内按固定自然顺序(gen→cpu→npu→gpu→compare)检查每个阶段是否在 set 中, 在则执行, 不在则从pt加载
- prof 阶段在 set 中则调用, 命中 `raise NotImplementedError`
- 每阶段产出后默认存pt, 下阶段优先从内存取, 无则从pt加载

### 双入口

- **pytest 入口**(主): `test_{op}.py` @parametrize 批量 + conftest session fixture 注入 stages + reporter + marker 三层分层
- **CLI 入口**(辅): run.py, argparse 单 case/调试/golden 独立, for 循环 + try/except + reporter
- 两入口共享 `run_case()`, 参数语义一致, Reporter类定义共享

## 五、新算子适配

### core/ 基类接口

```python
# core/gen_data.py
class GenDataBase(ABC):
    @abstractmethod
    def gen_inputs(self, params: dict) -> dict: ...
    @abstractmethod
    def normalize_params(self, params: dict) -> dict: ...
    def load_inputs(self, pt_path: str) -> dict: ...  # 可选, 导入整网pt(设计目标8)

# core/cpu.py
class CpuBase(ABC):
    @abstractmethod
    def cpu_compute(self, inputs: dict) -> dict: ...

# core/npu.py
class NpuBase(ABC):
    @abstractmethod
    def npu_compute(self, inputs: dict, graph_path: int = 0) -> dict: ...

# core/gpu.py
class GpuBase(ABC):
    @abstractmethod
    def gpu_compute(self, inputs: dict) -> dict: ...
```

每个基类提供 `load(op_name)` 工厂方法: `importlib.import_module(f"ops.{op_name}.{module}")` 加载并返回 `mod.XxxBackend()` 实例。

量化与反量化是Backend内部实现细节, core/不感知, 无需量化与反量化.py。

### ops/{op}/ 实现约定

```
ops/{op_name}/
    ├── __init__.py     # 仅 from .gen_data import GenDataBackend 等(约5行)
    ├── paramset.py     # PARAM_NAMES, DEFAULTS, CASE_SETS(按marker分层), SKIP_CASES(按marker分层)
    ├── gen_data.py     # class GenDataBackend(GenDataBase): gen_inputs, normalize_params
    ├── cpu.py          # class CpuBackend(CpuBase): cpu_compute
    ├── npu.py          # class NpuBackend(NpuBase): npu_compute
    ├── gpu.py          # class GpuBackend(GpuBase): gpu_compute (可选)
    └── quant.py        # 量化与反量化 (无基类, 算子自由定义, 可选; 被gen_data.py/cpu.py内部import)
```

### 三个关键约束

1. **inputs 完全一致**: gen_inputs 产出的 inputs 字典, cpu_compute 和 npu_compute 接收时完全一致(超参数、tensor、排布)
2. **outputs 统一 key**: outputs 只含需比对的 tensor(如 `{"out": tensor, "lse": tensor}`), metadata 等中间产物不放入
3. **meta/attn 拆分是 npu 内部行为**: npu_compute 自行决定是否调 metadata 算子、如何拆分, 不泄露到框架层

### 适配步骤

| 步骤 | 内容 | 框架支持 |
|------|------|----------|
| 1 | 创建 ops/{op}/paramset.py 定义轴参数+CASE_SETS(按marker分层) | case_loader 自动笛卡尔积展开 |
| 2 | 实现 ops/{op}/gen_data.py 中 GenDataBackend | 框架在 gen 前自动调用 normalize_params |
| 3 | 实现 gen_inputs(轴→tensor, 含量化) | 框架自动存 input.pt |
| 4 | 实现 ops/{op}/cpu.py 中 CpuBackend | 框架自动存 cpu.pt |
| 5 | 实现 ops/{op}/npu.py 中 NpuBackend | 框架自动存 npu.pt |
| 6 | (可选)实现 ops/{op}/gpu.py 中 GpuBackend | 框架自动存 gpu.pt |
| 7 | (可选)实现 ops/{op}/quant.py 量化函数 | gen_data.py/cpu.py 内部 import |
| 8 | (可选)定义用例集(testcase/xxx.py) | 字典形式 |
| 9 | (可选)实现get_tolerance | 放ops/{op}/__init__.py, compare.py通过getattr探测, 默认从compare.py取 |
| 10 | (可选)实现load_inputs | 放ops/{op}/gen_data.py, 从外部pt加载inputs替代gen_inputs(设计目标8) |

**框架核心无需修改即可接入新算子。**

## 六、pt 文件管理

### 目录结构

```
data/{用例集名}/{用例名}/
    ├── input.pt      # gen阶段产出(inputs字典)
    ├── cpu.pt        # cpu阶段产出(outputs字典)
    ├── npu.pt        # npu阶段产出(outputs字典)
    ├── gpu.pt        # gpu阶段产出(outputs字典, 可选)
    └── fail_analysis.txt  # precision_analyze失败分析报告(失败时生成)
```

### 存储约定

- 默认存pt(设计目标7), 可通过配置关闭
- pt内容: torch.save(dict) 序列化, 加载时 `torch.load(path, map_location="cpu", weights_only=False)`
- 阶段跳过时从pt加载, pt不存在则报错
- --keep-pt控制中间产物保留(默认保留)
