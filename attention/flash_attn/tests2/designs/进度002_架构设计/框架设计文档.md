## 二、目录结构

```
pytest/
├── README.md
├── 入口脚本.py                     # CLI入口(用例组合, 任务分发, 路由)
├── conftest.py                     # pytest入口(addoption+fixture+marker)
├── pytest.ini                      # marker定义
├── core/
│   ├── orchestrator.py             # 编排器(stages set + if/else阶段控制)
│   ├── case_loader.py              # 用例加载+配置merge(框架骨架)
│   ├── gen_data.py                 # dispatch → ops/{op}/gen_inputs
│   ├── cpu.py                      # dispatch → ops/{op}/cpu_compute
│   ├── npu.py                      # dispatch → ops/{op}/npu_compute
│   ├── gpu.py                      # dispatch → ops/{op}/gpu_compute
│   ├── compare.py                  # 精度比对(只做判定返回dict, 不打印)
│   ├── 精度比对后处理.py            # 结果收集+CSV增量flush+终端表格(框架骨架)
│   └── 量化与反量化.py              # dispatch → ops/{op}/quantize
├── ops/
│   └── {op_name}/
│       ├── __init__.py             # gen_inputs, cpu_compute, npu_compute, gpu_compute, quantize, normalize_params
│       └── paramset.py             # PARAM_NAMES, DEFAULTS, SKIP_CASES
├── data/
│   └── {用例集名}/{用例名}/
│       ├── input.pt
│       ├── cpu.pt
│       ├── npu.pt
│       ├── gpu.pt
│       └── fail_analysis.txt
├── testcase/
│   └── {用例集}.py
├── csv/
│   ├── result_{timestamp}.csv
│   └── csv_parser.py               # CSV解析脚本+表头定义
├── precision_analyze.py            # 失败点位打印+高级分析(维度+连续性+可视化)
└── prof/
    ├── npuprof/                    # NPU性能采集(虚函数)
    ├── npuprofop/                  # NPU单算子性能(虚函数)
    ├── gpuprof/                    # GPU性能(虚函数)
    ├── l2_flush/                   # L2刷新(虚函数)
    └── 性能产物解析/               # 性能产物解析(虚函数)
```

### core/ 的两层职责

| 类别 | 文件 | 说明 |
|------|------|------|
| **框架骨架**(不变) | orchestrator.py, case_loader.py, compare.py, 精度比对后处理.py | 所有算子通用, 换算子不修改 |
| **dispatch层**(约10行/文件) | gen_data.py, cpu.py, npu.py, gpu.py, 量化与反量化.py | importlib动态加载ops/{op}/, 转发调用; 换算子不修改 |

### dispatch机制

core/ 中的 dispatch 文件在 orchestrator 启动时通过 `init(op_name)` 加载对应 ops/{op}/ 模块, 之后直接调用。case_loader 直接 `importlib.import_module(f"ops.{op_name}.paramset")` 加载参数定义。

## 三、核心架构

### 数据流

```
baseparam(轴参数) → gen_inputs → inputs(一个字典, CPU/NPU/GPU共用, 完全一致)
                                    ├──→ cpu_compute  → outputs dict
                                    ├──→ npu_compute  → outputs dict
                                    └──→ gpu_compute  → outputs dict(可选)
                                              ↓
                                    compare(只做判定, 按key遍历outputs逐个比对)
                                              ↓
                                    精度比对后处理(CSV增量flush+终端表格)
                                    precision_analyze(失败点位打印+高级分析)
```

### 编排机制

移植全量化FA已验证的模式: stages set + if/else 阶段控制:
- `--stages` 解析为 set (如 `{"gen","cpu","npu","compare"}`)
- `run_case()` 内按固定自然顺序(gen→cpu→npu→gpu→compare)检查每个阶段是否在 set 中, 在则执行, 不在则从pt加载
- prof 阶段在 set 中则调用, 命中 `raise NotImplementedError`
- 每阶段产出后默认存pt, 下阶段优先从内存取, 无则从pt加载

### 双入口

- **pytest 入口**(主): `@parametrize` 批量 + conftest session fixture 注入 stages + marker 三层分层
- **CLI 入口**(辅): 入口脚本.py, argparse 单 case/调试/golden 独立, for 循环 + try/except + 精度比对后处理
- 两入口共享 `run_case()`, 参数语义一致

| # | 定稿方案 |

| 3 | 每阶段 if 在set中则执行, 否则从pt加载; pt不存在则报错 |

|---|---------|

### B3. cpu/npu/gpu compute

| # | 定稿方案 |
|---|---------|
| 1 | core/gen_data.py,cpu.py,npu.py,gpu.py,量化与反量化.py 为dispatch层, 转发到ops/{op}/__init__.py; --op选择对应算子 |

### B4. compare

| # | 定稿方案 |
|---|---------|
| 1 | 两方: torch.isclose+fail_ratio; 返回dict{passed,max_abs,mean_abs,fail_cnt,total,fail_ratio}; 只做判定, 不打印; 向量化比对 |
| 2 | 阈值: compare.py硬编码默认值(fp16/bf16两档) + 算子可提供get_tolerance覆盖 |
| 3 | 按outputs key逐个比对(out/lse分别), 失败时触发precision_analyze |
| 4 | 结果交精度比对后处理存CSV增量flush |
| 5 | FP8/特殊dtype处理由算子提供(如uint8重解释), 通过回调注入compare; 框架核心只处理fp16/bf16/fp32 |
| 6 | torch向量化(非numpy) |
| 7 | 三方比对作为可选扩展, 不入框架核心 |

### B5. 精度比对后处理

| # | 定稿方案 |
|---|---------|
| 1 | CSV表头: case,dtype,key,pass,max_abs,mean_abs,fail_ratio,error; 表头定义在csv/csv_parser.py |
| 2 | 增量flush: csv.DictWriter+append+每case flush, O(n) |
| 3 | 终端表格: Unicode box drawing; 中间报告print_interim(--report-interval) + 最终汇总print_final |
| 4 | record(name,result,error,dtype); 失败时直接构造NaN占位dict |
| 5 | 汇总: 终端汇总表(pass/fail/total) + 汇总CSV |
| 6 | check_results: 按outputs key逐一检查passed, 失败时pytest.fail含key+pass率 |

### B6. 精度比对分析(precision_analyze.py)

| # | 定稿方案 |
|---|---------|
| 1 | 失败点位打印(默认前10, --verbose-diff全量) + Max-RE前3 + 前10后10预览; compare.py只做判定不打印, 打印全在此 |
| 2 | 触发: --fail-analysis控制, 默认失败时触发; try/except防崩溃 |
| 3 | 报告: txt文件存于data/用例集名/用例名/fail_analysis.txt + 终端打印 |
| 4 | 高级分析(维度分析+连续性+可视化)在此文件中, 按需调用; 非量化FA的5维度分析+热力图可移植至此 |

## 五、新算子适配

### ops/{op}/__init__.py 约定接口

新算子适配只需在 `ops/{op_name}/` 下实现:

```python
# ops/{op_name}/__init__.py

def normalize_params(params: dict) -> dict: ...
def gen_inputs(params: dict) -> dict: ...
def cpu_compute(inputs: dict) -> dict: ...
def npu_compute(inputs: dict, graph_path: int = 0) -> dict: ...
def gpu_compute(inputs: dict) -> dict: ...  # 可选
def quantize(*args, **kwargs): ...  # 可选, 量化与反量化.py dispatch到此
def get_tolerance(dtype: str) -> tuple: ...  # 可选, 默认从compare.py取
```

### ops/{op}/paramset.py 约定

```python
PARAM_NAMES = ["B", "N1", "S1", "D", ...]
PARAM_DEFAULTS = {"graph_path": [0], "device_id": [0], "seed": [42], ...}
SKIP_CASES = set()  # 可选
```

### 三个关键约束

1. **inputs 完全一致**: gen_inputs 产出的 inputs 字典, cpu_compute 和 npu_compute 接收时完全一致(超参数、tensor、排布)
2. **outputs 统一 key**: outputs 只含需比对的 tensor(如 `{"out": tensor, "lse": tensor}`), metadata 等中间产物不放入
3. **meta/attn 拆分是 npu 内部行为**: npu_compute 自行决定是否调 metadata 算子、如何拆分, 不泄露到框架层

### 适配步骤

| 步骤 | 内容 | 框架支持 |
|------|------|----------|
| 1 | 创建 ops/{op}/paramset.py 定义轴参数 | case_loader 自动笛卡尔积展开 |
| 2 | 实现 ops/{op}/__init__.py 中 normalize_params | 框架在 gen 前自动调用 |
| 3 | 实现 gen_inputs(轴→tensor, 含量化) | 框架自动存 input.pt |
| 4 | 实现 cpu_compute(数学参考) | 框架自动存 cpu.pt |
| 5 | 实现 npu_compute(含graph_path配置) | 框架自动存 npu.pt |
| 6 | (可选)实现 gpu_compute | 框架自动存 gpu.pt |
| 7 | (可选)定义用例集(testcase/xxx.py) | 字典形式 |
| 8 | (可选)实现 get_tolerance | 默认从 compare.py 取 |

**框架核心无需修改即可接入新算子。**

## 六、pt 文件管理

### 目录结构

```
data/{用例集名}/{用例名}/
    ├── input.pt      # gen阶段产出(inputs字典)
    ├── cpu.pt        # cpu阶段产出(outputs字典)
    ├── npu.pt        # npu阶段产出(outputs字典)
    ├── gpu.pt        # gpu阶段产出(outputs字典, 可选)
    └── fail_analysis.txt  # precision_analyze失败分析报告(失败时生成)
```

### 存储约定

- 默认存pt(设计目标7), 可通过配置关闭
- pt内容: torch.save(dict) 序列化, 加载时 `torch.load(path, map_location="cpu", weights_only=False)`
- 阶段跳过时从pt加载, pt不存在则报错
- --keep-pt控制中间产物保留(默认保留)
