## 三、核心架构

### 数据流

```
baseparam(轴参数) → gen_inputs → inputs(一个字典, CPU/NPU/GPU共用, 完全一致)
                                    ├──→ cpu_compute  → outputs dict
                                    ├──→ npu_compute  → outputs dict
                                    └──→ gpu_compute  → outputs dict(可选)
                                              ↓
                                    compare(按key遍历outputs逐个比对)
                                              ↓
                                    reporter(CSV增量flush) + analyze(失败分析)
```

### 编排机制

阶段注册表 + 管道执行 + CaseContext 数据容器:
- **STAGE_REGISTRY**: 8 个阶段注册(gen/cpu/npu/gpu/compare/npuprof/npuprofop/gpuprof), prof 为虚函数
- **管道执行**: 按 `stages` 列表顺序逐个执行, 编排器不硬编码顺序
- **CaseContext**: 持有 inputs/outputs/result, 阶段间通过它传递; `ctx.xxx or load_pt(...)` 自动解决数据依赖

### 双入口

- **pytest 入口**(主): `@parametrize` 批量 + conftest session fixture 注入 stages/config + marker 三层分层
- **CLI 入口**(辅): argparse 单 case/调试/golden 独立, for 循环 + try/except + reporter
- 两入口共享 `run_case()` 和 `STAGE_REGISTRY`, 参数语义一致

## 五、新算子适配

### OperatorAdapter 接口

新算子适配只需实现以下方法:

```python
class OperatorAdapter(Protocol):
    name: str
    param_names: list[str]
    param_defaults: dict

    def normalize_params(self, params: dict) -> dict: ...
    def gen_inputs(self, params: dict) -> dict: ...
    def cpu_compute(self, inputs: dict) -> dict: ...
    def npu_compute(self, inputs: dict, graph_path: int = 0) -> dict: ...
    def gpu_compute(self, inputs: dict) -> dict: ...  # 可选
```

### 三个关键约束

1. **inputs 完全一致**: `gen_inputs` 产出的 inputs 字典, `cpu_compute` 和 `npu_compute` 接收时完全一致(超参数、tensor、排布)
2. **outputs 统一 key**: outputs 只含需比对的 tensor(如 `{"out": tensor, "lse": tensor}`), metadata 等中间产物不放入
3. **meta/attn 拆分是 npu 内部行为**: npu_compute 自行决定是否调 metadata 算子、如何拆分, 不泄露到框架层

### 适配步骤

| 步骤 | 内容 | 框架支持 |
|------|------|----------|
| 1 | 定义轴参数(param_names + param_defaults) | case_loader 自动笛卡尔积展开 |
| 2 | 实现 normalize_params(参数推导链) | 框架在 gen 前自动调用 |
| 3 | 实现 gen_inputs(轴→tensor, 含量化) | 框架自动存 input.pt |
| 4 | 实现 cpu_compute(数学参考) | 框架自动存 cpu.pt |
| 5 | 实现 npu_compute(含 metadata 两阶段处理) | 框架自动存 npu.pt + graph_path 配置 |
| 6 | (可选)实现 gpu_compute | 框架自动存 gpu.pt |
| 7 | (可选)定义用例集(testcase/xxx.py) | 字典/CSV/Excel 三种形式 |
| 8 | (可选)覆盖 get_tolerance | 默认从 config.yaml 取 |

**框架核心无需修改即可接入新算子。**

## 六、pt 文件管理

### 目录结构

```
data/{用例集名}/{用例名}/
    ├── input.pt      # gen阶段产出(inputs字典)
    ├── cpu.pt        # cpu阶段产出(outputs字典)
    ├── npu.pt        # npu阶段产出(outputs字典)
    ├── gpu.pt        # gpu阶段产出(outputs字典, 可选)
    └── fail_analysis.txt  # B6失败分析报告(失败时生成)
```

### 存储约定

- 默认存pt(设计目标7), 可通过config.save_pt关闭
- pt内容: torch.save(dict) 序列化, 加载时 `torch.load(path, map_location="cpu", weights_only=False)`
- 阶段跳过时从pt加载: `ctx.xxx or load_pt(path)`, pt不存在则报错
- --keep-pt控制中间产物保留(默认保留)
