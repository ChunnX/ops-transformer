# 既有框架探索报告

> 本报告基于对 4 个既有 FA 测试框架的深度分析，提取各维度最优方案作为新框架设计的移植来源。

---

## 一、框架总览

| 框架 | 路径 | 规模 | 定位 |
|------|------|------|------|
| 非量化FA | `attention/flash_attn/tests/pytests` | ~9500行 | 脚本式，Backend多态，功能最全面 |
| 全量化FA | `attention/fused_infer_attention_score/tests/pytest` | ~8000行 | pytest集成，四阶段解耦，工程化最成熟 |
| MQSMLA | `attention/mixed_quant_sparse_flash_mla/tests/pytest` | ~3400行 | Excel驱动，pt契约，HIF8量化 |

## 四、各维度最优方案与移植来源

### 4.1 阶段路由

**最优方案**：`gen→cpu→npu→compare` 四阶段 + `--golden-mode` 组合控制

**移植来源**：全量化FA `test_runner.py:51-107`

```python
# 通过 --golden-mode all/gen,cpu,npu,compare 任意组合
_VALID_MODES = {"all", "gen", "cpu", "npu", "compare"}
def _parse_golden_mode(raw):
    parts = {m.strip() for m in raw.split(",") if m.strip()}
    if "all" in parts:
        return {"gen", "cpu", "npu", "compare"}
    return parts
```

**优势**：四阶段可独立运行或任意组合，配合 .pt 缓存实现跨机器协作和快速调试。

### 4.2 用例定义与加载

**最优方案**：字典 + `PARAM_NAMES` 固定顺序 + `DEFAULTS` 默认值 + 笛卡尔积 + ID 多模式匹配

**移植来源**：
- 参数展开：全量化FA `fia_fullquant_mxfp8_paramset_common.py:36-49`
- ID 匹配：非量化FA `case_loader.py:103-120`（精确/后缀/前缀三模式）

```python
PARAM_NAMES = ["B", "N_q", "N_kv", "D", "actual_seq_q", ...]
TEST_PARAMS_DEFAULTS = {"data_range_q": [1.0], "graph_path": [0], "device_id": [0], ...}

def expand_paramset_to_cases(test_params):
    for name, params in test_params.items():
        expanded = dict(params)
        for key, default_vals in TEST_PARAMS_DEFAULTS.items():
            if key not in expanded:
                expanded[key] = default_vals
        for combo in itertools.product(*[expanded[n] for n in PARAM_NAMES]):
            case = {"name": name, **dict(zip(PARAM_NAMES, combo))}
            cases.append(case)
    return cases
```

### 4.3 数据生成

**最优方案**：`InputSpec` 建造者 + 声明式 tensor + layout 映射 + `when` 条件

**移植来源**：非量化FA `core/data.py:120-228`

```python
flash_attn_inputs = (
    InputSpec("flash_attn")
    .tensor("q", layout={"BNSD": "B,N1,S1,D", "TND": "total_s1,N1,D"},
            method="uniform", low=-5.0, high=5.0, range_key="q_range",
            when=lambda p: "q_range" in p)
    .tensor("k", layout={...}, layout_override="layout_kv")
)
```

**优势**：新增 layout 只需加一行映射；`when` lambda 支持条件生成；`layout_override` 处理 PA 场景。

### 4.4 Backend 抽象

**最优方案**：`Backend ABC` 策略模式 + 统一 `compute()` 接口

**移植来源**：非量化FA `core/backends/base.py:8-28`

```python
class Backend(ABC):
    @abstractmethod
    def is_available(self) -> bool: ...
    @abstractmethod
    def compute(self, inputs, params): ...
    def clear_cache(self): ...
```

## 五、共同短板（新框架需补齐）

| 短板 | 现状 | 新框架目标 |
|------|------|-----------|
| 配置全硬编码 | 阈值/数据范围/device_id 散落各处 | 统一 YAML 配置文件，按 dtype/芯片差异化 |
| 无重试机制 | NPU 偶发错误直接判失败 | 可配置重试次数 + 指数退避 |
| 无大case并行比对 | 比对均为单线程串行 | 配置化并行加速（分块比对） |
| 无GPU性能采集 | 仅非量化FA有GPU精度对比 | GPU prof 支持 |
| 无UT/ST分层 | 均为端到端测试 | UT(纯函数)/ST(算子级)/集成测试三层 |
| 无子进程隔离(精度测试) | 单进程内逐case跑，状态污染累积 | 子进程隔离 + 设备状态重置 |
| 无结构化日志 | print/print_log | 结构化 JSON 日志 + 性能指标输出 |
| 无随机种子固化(MQSMLA) | random.randint 不可复现 | 统一种子管理 |
| HIF8量化逐元素Python循环 | 大tensor极慢 | 向量化或C扩展 |
| 结果存储O(n²) | 每条读全表+concat+写全表 | 内存累积+一次性flush 或 CSV追加 |

## 七、总结

四框架各有所长：**非量化FA** 在 Backend 抽象、GPU 封装、三方比对、失败分析、性能产物解析方面最全面；**全量化FA** 在四阶段解耦、golden CLI、NPU 路径配置化、msprof 自动编排方面最成熟；**MQSMLA** 的 pt 契约和 conftest 失败信息定制有独到价值；**QSFA** 的 cs 格式适配器和 Excel 双源管理值得借鉴。

新框架应以全量化FA的四阶段架构为骨架，融合非量化FA的 Backend/GPU/比对/分析能力，补齐配置驱动、重试、并行比对、UT/ST分层等工程化短板。
