# 并行执行设计

> 基于实际依赖图分析, 将串行流水线改为 DAG 并行执行, 并支持跨 case 并行。

---

## 一、现状分析

### 1.1 当前串行模型

```
gen → cpu → npu → gpu → compare → prof*
```

`run_case()` 内按固定顺序逐个执行阶段。8 阶段全部串行。

### 1.2 实际依赖图

```
gen ──┬── cpu ────┐
      ├── npu ────┼── compare → prof*
      └── gpu ────┘

cpu/npu/gpu 三者: 同一份 inputs 入参(只读), 各自独立产出, 各自独立设备, 零数据依赖
```

### 1.3 跨 case 依赖

每个 case 完全独立: 各自 params → inputs → outputs, 各自 pt 文件, 无共享状态。仅 NPU 设备需要串行化访问。

---

## 二、设计 1: 单 case 内 compute 并行

### 2.1 执行模型

```
串行: gen + cpu_time + npu_time + gpu_time + compare_time
并行: gen + max(cpu_time, npu_time, gpu_time) + compare_time
```

### 2.2 run_case 改造

```python
def run_case(stages: set, params: dict, reporter: Reporter, *,
             max_retries: int = 0, load_pt: str = None, graph_path: int = 0,
             chunk_size: int = 0, num_workers: int = 0, verbose_diff: bool = False,
             fail_analysis: bool = True, keep_pt: bool = True) -> dict:

    case_set = params.get("case_set", "")
    case_id = params.get("case_id", params.get("name", ""))
    result = {"passed": True, "fail_msg": ""}

    try:
        # ═══════════ gen 阶段 (串行, 产出 inputs) ═══════════
        gen = GenDataBackend()
        if "gen" in stages:
            if load_pt:
                inputs = gen.load_inputs(load_pt)
            else:
                inputs = gen.gen_inputs(gen.normalize_params(params))
            if keep_pt:
                _save_pt(inputs, _pt_path(case_set, case_id, "input"))
        else:
            inputs = _load_pt(_pt_path(case_set, case_id, "input"))

        # ═══════════ compute 阶段 (并行) ═══════════
        cpu = CpuBackend()
        npu = NpuBackend()

        tasks = {}
        with ThreadPoolExecutor(max_workers=3) as pool:
            if "cpu" in stages or "compare" in stages:
                tasks["cpu"] = pool.submit(
                    _compute_or_load, "cpu", inputs, stages, case_set, case_id, keep_pt,
                    cpu.cpu_compute, inputs)
            if "npu" in stages or "compare" in stages:
                tasks["npu"] = pool.submit(
                    _compute_or_load, "npu", inputs, stages, case_set, case_id, keep_pt,
                    _npu_compute_fn, inputs, npu, graph_path, max_retries)
            if "gpu" in stages:
                tasks["gpu"] = pool.submit(
                    _compute_or_load, "gpu", inputs, stages, case_set, case_id, keep_pt,
                    _gpu_compute_fn, inputs)

            outputs = {}
            for name, future in as_completed(tasks):
                try:
                    outputs[name] = future.result()
                except Exception:
                    outputs[name] = {"_error": traceback.format_exc()}

        cpu_out = outputs.get("cpu")
        npu_out = outputs.get("npu")

        # ═══════════ compare 阶段 (串行, 等待 cpu+npu) ═══════════
        if "compare" in stages and cpu_out is not None and npu_out is not None:
            if isinstance(cpu_out, dict) and "_error" not in cpu_out \
               and isinstance(npu_out, dict) and "_error" not in npu_out:
                result = compare_outputs(cpu_out, npu_out, chunk_size=chunk_size,
                                         num_workers=num_workers)
                result["fail_msg"] = "" if result.get("passed", False) else "compare failed"
                if not result.get("passed", False) and fail_analysis:
                    print(analyze_failure(cpu_out, npu_out, result,
                                          case_dir=result_dir, verbose=verbose_diff))
            else:
                result["passed"] = False
                result["fail_msg"] = "compute 阶段异常, 跳过 compare"
            reporter.record(case_id, result, dtype=dtype)

        # ═══════════ prof 阶段 (串行) ═══════════
        _run_prof_stages(stages, case_id, str(Path("result") / case_id))

        # cleanup
        if "npu" in stages:
            torch.npu.empty_cache()
        if "gpu" in stages:
            torch.cuda.empty_cache()

        return result

    except Exception as e:
        traceback.print_exc()
        fail = make_failure_result(str(e))
        reporter.record(case_id, fail, error=str(e), dtype=dtype)
        return fail
```

### 2.3 统一 compute 执行器

```python
def _compute_or_load(stage_name: str, inputs: dict, stages: set,
                     case_set: str, case_id: str, keep_pt: bool,
                     compute_fn, *args):
    """统一的 compute 阶段: stages 中则执行并保存 pt, 否则从 pt 加载."""
    if stage_name in stages:
        output = compute_fn(*args)
        if keep_pt:
            _save_pt(output, _pt_path(case_set, case_id, stage_name))
        return output
    # 不在 stages 中 → 从 pt 加载
    pt = _pt_path(case_set, case_id, stage_name)
    return _load_pt(pt) if pt.exists() else None


def _npu_compute_fn(inputs: dict, npu: NpuBackend, graph_path: int, max_retries: int):
    """NPU compute 含 ThreadPoolExecutor 崩溃隔离 + 重试."""
    dev_inputs = _to_device(inputs, "npu")
    with ThreadPoolExecutor(max_workers=1) as executor:
        for attempt in range(max_retries + 1):
            try:
                future = executor.submit(npu.npu_compute, dev_inputs, graph_path)
                return future.result()
            except Exception:
                if attempt < max_retries:
                    continue
                raise


def _gpu_compute_fn(inputs: dict):
    """GPU compute."""
    from core.gpu import GpuBackend
    gpu = GpuBackend()
    dev_inputs = _to_device(inputs, "cuda")
    return gpu.gpu_compute(dev_inputs)
```

### 2.4 线程安全分析

| 共享资源 | 模式 | 冲突 |
|----------|------|------|
| `inputs` dict | 三线程只读 | 无 |
| `cpu.pt / npu.pt / gpu.pt` | 各自写不同文件 | 无 |
| `reporter.record()` | 仅 compare 阶段调 | 无 |
| `CpuBackend / NpuBackend / GpuBackend` | 各自独立实例 | 无 |
| `torch.npu.empty_cache()` | npu 线程内 | 无 |

### 2.5 错误处理

- 单个 compute 失败 → `_compute_or_load` 抛异常 → `as_completed` 捕获 → 存入 `{"_error": ...}`
- compare 阶段检测到 `_error` → 跳过比对, 记录失败
- 其他 compute 不受影响 → 继续执行 (ThreadPoolExecutor 不取消其他 future)

## 三、设计 2: 跨 case 并行

### 3.1 执行模型

```
串行: Case1 全流程 → Case2 全流程 → Case3 全流程 → ...
并行: Case1 ─┐
      Case2 ─┼─ 同时跑, NPU 互斥锁串行化设备访问
      Case3 ─┘
```

### 3.2 新增参数

| 参数 | 默认 | 说明 |
|------|------|------|
| `--parallel` | 1 | 并行 case 数, 1=串行(向后兼容), 0=自动(CPU核数) |
| `--npu-devices` | 0 | NPU 设备列表, 逗号分隔, 如 `0,1,2,3` |

```
--parallel 1  → 当前行为, 逐 case 串行
--parallel 4  → 4 case 并发, 共享 1 个 NPU 锁
--parallel 4 --npu-devices 0,1 → 4 case 并发, 轮询分发到 npu:0 / npu:1
```

### 3.3 实现

#### 3.3.1 NPU 互斥锁

```python
# orchestrator.py
import threading

_npu_locks: dict[int, threading.Lock] = {}

def _get_npu_lock(device_id: int) -> threading.Lock:
    if device_id not in _npu_locks:
        _npu_locks[device_id] = threading.Lock()
    return _npu_locks[device_id]


def _npu_compute_fn(inputs: dict, npu: NpuBackend, graph_path: int,
                    max_retries: int, device_id: int):
    """NPU compute — 设备级互斥."""
    lock = _get_npu_lock(device_id)
    with lock:
        dev_inputs = _to_device(inputs, "npu")
        with ThreadPoolExecutor(max_workers=1) as executor:
            for attempt in range(max_retries + 1):
                try:
                    future = executor.submit(npu.npu_compute, dev_inputs, graph_path)
                    return future.result()
                except Exception:
                    if attempt < max_retries:
                        continue
                    raise
```

#### 3.3.2 Reporter 线程安全

```python
class Reporter:
    def __init__(self):
        ...
        self._lock = threading.Lock()   # ← 新增

    def record(self, name, result, error=None, dtype=""):
        with self._lock:                # ← 加锁
            if error:
                result["error"] = error
            self._results[name] = result
            self._dtypes[name] = dtype
            if self._csv_writer:
                for key, m in result.items():
                    if not isinstance(m, dict):
                        continue
                    self._csv_writer.writerow({...})
                self._csv_file.flush()
```

#### 3.3.3 CLI 并行入口

```python
# test.py
def main():
    ...
    stages = _parse_stages(args.stages)
    cases, case_ids = _collect_cases(args.case_set, args.case_id)

    if not cases:
        print("[ERROR] 没有可运行的 case")
        sys.exit(1)

    reporter = _make_reporter()

    parallel = args.parallel if args.parallel > 0 else os.cpu_count() or 4

    if parallel == 1:
        # 串行路径 — 向后兼容
        for i, (params, case_id) in enumerate(zip(cases, case_ids)):
            _run_single_case(stages, params, case_id, reporter, args, len(cases), i)
    else:
        # 并行路径
        _run_cases_parallel(stages, cases, case_ids, reporter, args, parallel)

    fail_cnt = reporter.print_final()
    sys.exit(0 if fail_cnt == 0 else 1)


def _run_single_case(stages, params, case_id, reporter, args, total, index):
    """单个 case 执行 (供串行路径)."""
    print(f"\n{'='*66}\n  Case: {case_id}\n{'='*66}")
    try:
        run_case(stages, params, reporter,
                 max_retries=args.max_retries, load_pt=args.load_pt,
                 graph_path=args.graph_path, chunk_size=args.chunk_size,
                 num_workers=args.num_workers, verbose_diff=args.verbose_diff,
                 fail_analysis=args.fail_analysis, keep_pt=args.keep_pt)
    except Exception as e:
        err = f"{e}\n{traceback.format_exc()}"
        print(f"[ERROR] {case_id} 运行异常: {e}")
        fail = make_failure_result(str(e))
        reporter.record(case_id, fail, error=err, dtype=params.get("dtype", ""))


def _run_cases_parallel(stages, cases, case_ids, reporter, args, max_workers):
    """并行执行多个 case."""
    from concurrent.futures import as_completed

    with ThreadPoolExecutor(max_workers=max_workers) as pool:
        futures = {}
        for params, case_id in zip(cases, case_ids):
            f = pool.submit(_run_single_case, stages, params, case_id,
                           reporter, args, len(cases), 0)
            futures[f] = case_id

        for f in as_completed(futures):
            case_id = futures[f]
            try:
                f.result()
            except Exception as e:
                print(f"[ERROR] {case_id} 线程异常: {e}")
```

## 四、pytest 入口适配

pytest 入口不需要额外改造 — pytest-xdist (`pytest -n 4`) 已实现跨 case 进程级并行, 且每个 worker 进程独享 NPU 设备, 无需互斥锁。

新参数通过 `conftest.py` 的 `pytest_addoption` 注册:

```python
def pytest_addoption(parser):
    ...
    parser.addoption("--parallel", default=1, type=int, help="并行 case 数")
    parser.addoption("--npu-devices", default="0", help="NPU 设备列表")
```

pytest 模式下 `--parallel` 对 `@parametrize` 生成的 case 列表生效 (非 pytest-xdist 场景)。

## 五、数据流更新

```
                    ┌── _compute_or_load("cpu") ──┐
gen → inputs ──────┼── _compute_or_load("npu") ──┼── compare → reporter → prof*
                    └── _compute_or_load("gpu") ──┘
                         ↑ ThreadPoolExecutor(max_workers=3)

跨 case:
  Case1: gen → {cpu,npu,gpu} → compare
  Case2: gen → {cpu,npu,gpu} → compare    ← 同时, npu 互斥锁排队
  Case3: gen → {cpu,npu,gpu} → compare
```

## 六、向后兼容

| 场景 | 行为 |
|------|------|
| `--parallel 1` (默认) | 单 case 内 compute 并行, 跨 case 串行 |
| 不传 `--parallel` | 默认 1, 与旧行为一致 |
| stages 不含 cpu/npu/gpu 中的某些 | 只对 stages 中含的阶段并行 |
| stages 只有 gen,compare (pt 加载模式) | compute 并行组为空, 直接 compare |
| pytest @parametrize | 单 case 内 compute 并行, 跨 case 依赖 pytest-xdist |

## 七、预期收益

| 场景 | 串行耗时 | 并行后 | 加速比 |
|------|----------|--------|--------|
| 单 case (cpu+npu) | cpu 30s + npu 120s = 150s | max(30,120) = 120s | 1.25× |
| 单 case (cpu+npu+gpu) | 30+120+5 = 155s | max(30,120,5) = 120s | 1.29× |
| 4 case ci (--parallel 4) | 4×150 = 600s | ~170s | 3.5× |
| 4 case + 2 NPU 卡 | 600s | ~90s | 6.7× |
