# 并行执行设计

> 基于实际依赖图分析, 将串行流水线改为 DAG 并行执行, 并支持跨 case 并行。

---

## 一、依赖图分析

### 1.1 串行模型（当前）

```
gen → cpu → npu → gpu → compare → prof*
```

### 1.2 实际 DAG

```
         l2_flush (仅 profiling 时)
              ↓
gen ──┬── cpu ───────────────┐
      ├── npu (·npuprof) ────┼── compare
      └── gpu (·gpuprof) ────┘
```

- cpu / npu / gpu: 同份 inputs 入参 (只读), 各自独立产出, 各自独立设备, 零数据依赖
- npuprof / npuprofop / gpuprof: 不是独立节点, 是 npu / gpu 的修饰符 (profiler 外壳)
- l2_flush: gen 之后、profiled compute 之前的前置节点

### 1.3 prof 归约

```
npuprof   ≡  npu_compute + msprof wrapper + 产物解析
npuprofop ≡  npu_compute + msprofop wrapper + 产物解析
gpuprof   ≡  gpu_compute + nsys wrapper + 产物解析
```

**stages 归一化**: prof 阶段进入 run_case 前一步归一化。`npuprof` ∈ stages → 归约为 `npu` compute + profiling flag。并行组槽位始终 `{cpu, npu, gpu}` 三个, 不因 profiling 增加。

```python
_PROF_MODES = {"npuprof", "npuprofop", "gpuprof"}

_normalize_stages({"gen","cpu","npuprof","compare"})
  → compute={"gen","cpu","npu","compare"}, profiling={"npuprof"}

_normalize_stages({"gen","npu","compare"})
  → compute={"gen","npu","compare"}, profiling=∅
```

`compute` 控制哪些阶段在并行组; `profiling` 作为参数传入 npu/gpu compute 函数, 决定是否套 profiler 外壳。

## 二、设计 1: 单 case 内 compute 并行

### 2.1 执行模型

```
串行: gen + cpu_time + npu_time + gpu_time + compare_time
并行: gen + max(cpu_time, npu_time, gpu_time) + compare_time
```

### 2.2 核心改动

- `run_case()` 入口调用 `_normalize_stages(stages)` → `(compute_stages, profiling)`
- gen 串行产出 inputs (不变)
- `{cpu, npu, gpu}` 通过 `ThreadPoolExecutor(max_workers=3)` 并发提交
- cpu 使用 `_compute_or_load()` (pt 存取统一)
- npu / gpu 感知 profiling flag, 套 profiler 外壳
- `as_completed()` 收集结果, 单 compute 失败不影响其他
- compare 等待 cpu + npu 完成后串行执行 (不变)

### 2.3 线程安全

| 共享资源 | 模式 | 冲突 |
|----------|------|------|
| `inputs` dict | 三线程只读 | 无 |
| `cpu.pt / npu.pt / gpu.pt` | 各自写不同文件 | 无 |
| `reporter.record()` | 仅 compare 阶段调用 | 无 |
| Backend 实例 | 各自独立 | 无 |

### 2.4 错误处理

- 单个 compute 失败 → 存入 `{"_error": ...}`, 其他 compute 继续
- compare 检测到 `_error` → 跳过比对, 记录失败

## 三、设计 2: 跨 case 并行

### 3.1 执行模型

```
串行: Case1 → Case2 → Case3 → ...
并行: Case1 ─┐
      Case2 ─┼─ 同时跑, NPU 互斥锁串行化设备访问
      Case3 ─┘
```

### 3.2 新增参数

| 参数 | 默认 | 说明 |
|------|------|------|
| `--parallel` | 1 | 并行 case 数。1=串行 (向后兼容), 0=自动 |
| `--npu-devices` | 0 | NPU 设备列表, 逗号分隔, 如 `0,1,2,3` |

```
--parallel 1                       → 逐 case 串行 (当前行为)
--parallel 4                       → 4 case 并发, 共享 1 个 NPU 锁
--parallel 4 --npu-devices 0,1     → 4 case 并发, 轮询分发到 2 个 NPU
```

### 3.3 关键机制

- **NPU 互斥锁**: `threading.Lock` 按 device_id 索引。npu_compute 在锁内执行, 异常自动释放
- **Reporter 线程安全**: `record()` + `flush()` 加锁, 多 case 并发写入同一 CSV
- **pytest 入口**: 不需要额外改造 — pytest-xdist 已提供进程级并行, 每个 worker 独享 NPU

### 3.4 多 NPU 分发

npu 设备 ID 轮询: `device_id = npu_devices[case_index % len(npu_devices)]`

每个设备独立 Lock, 多卡无竞争。

## 四、向后兼容

| 场景 | 行为 |
|------|------|
| `--parallel 1` (默认) | 单 case 内 compute 并行, 跨 case 串行 |
| 不传 `--parallel` | 默认 1, 行为不变 |
| stages 只有 gen,compare (pt 加载) | compute 并行组为空, 直接 compare |
| pytest @parametrize | 单 case 内 compute 并行, 跨 case 依赖 pytest-xdist |

## 五、预期收益

| 场景 | 串行 | 并行后 | 加速 |
|------|------|--------|------|
| 单 case (cpu+npu) | cpu 30s + npu 120s = 150s | max(30,120) = 120s | 1.25× |
| 单 case (cpu+npu+gpu) | 30+120+5 = 155s | max(30,120,5) = 120s | 1.29× |
| 4 case ci (--parallel 4) | 4×150 = 600s | ~170s | 3.5× |
| 4 case + 2 NPU 卡 | 600s | ~90s | 6.7× |

## 六、验收标准

### 6.1 功能正确性 — 并行结果与串行一致

| # | 验收项 | 验证方法 |
|---|--------|----------|
| F1 | 同一 case, `--parallel 1` 与 `--parallel 4` 的 compare 结果相同 | 跑 ci 全部 case, diff 两次的 CSV |
| F2 | 同一 case, 串行 pt 与并行 pt 逐 bit 一致 | `torch.equal(cpu_serial, cpu_parallel)` |
| F3 | `npuprof` 归约后 npu compute 结果与非 prof 模式一致 | 同 case 跑 `npu` vs `npuprof`, compare 通过 |
| F4 | `_normalize_stages` 六个边界用例输出正确 | 单元测试覆盖 |
| F5 | CLI 和 pytest 双入口并行行为一致 | 分别跑 `python test.py --parallel 4` 和 `pytest test.py` |

### 6.2 竞争条件 — 并发无数据损坏

| # | 验收项 | 验证方法 |
|---|--------|----------|
| R1 | 多 case 并发写同一 CSV, 行数 = 串行行数, 无缺行/错行 | 4 case × 2 key = 至少 8 行, diff CSV |
| R2 | 多 case 并发写各自 pt 文件, 文件完整可加载 | `torch.load` 所有 pt 无异常 |
| R3 | `_save_pt` 并发写不同 stage 文件 (`cpu.pt`/`npu.pt`/`gpu.pt`) 无交错 | 三线程同 case 并行跑, 三个 pt 各自可加载 |
| R4 | `Reporter._results` dict 无并发丢失 — `print_final()` 的通过+失败 = 总 case 数 | 跑 N 个 case, 断言 `pass+fail == N` |

### 6.3 死锁 — 无永久阻塞

| # | 验收项 | 验证方法 |
|---|--------|----------|
| D1 | NPU lock 异常时自动释放 — npu compute 抛异常后下一 case 能继续 | Mock npu_compute 抛 RuntimeError, 验证锁已释放 |
| D2 | Reporter lock 异常时自动释放 — record 中途崩溃不阻塞其他线程 | Mock csv write 抛异常, 验证后续 record 正常 |
| D3 | `ThreadPoolExecutor` 超时自动退出 — 不使用 `pool.shutdown(wait=True)` 无限等 | 单 case 并行组应在合理时间内完成 (CI 已限时) |
| D4 | 无循环锁依赖 — NPU lock 和 Reporter lock **不同时持锁** | 代码审查: npu compute 内不调 reporter |

### 6.4 压力测试

| # | 验收项 | 验证方法 |
|---|--------|----------|
| S1 | `--parallel 4` 跑 ci 全部 case, 10 次无 hang | 脚本循环 |
| S2 | `--parallel 0` (自动) 不因核数过多创建过量线程 | 断言 `max_workers ≤ 8` |
| S3 | 单 case 内 compute 并行 + 跨 case 并行叠加, 无异常 | `--parallel 4` + cpu/npu/gpu 全开 |

### 6.5 `_normalize_stages` 边界用例

| 输入 | 期望 compute | 期望 profiling |
|------|-------------|---------------|
| `{"gen","cpu","npu","compare"}` | 同输入 | `∅` |
| `{"npuprof"}` | `{"npu"}` | `{"npuprof"}` |
| `{"npu","npuprof"}` | `{"npu"}` | `{"npuprof"}` |
| `{"gen","cpu","npuprof","compare"}` | `{"gen","cpu","npu","compare"}` | `{"npuprof"}` |
| `{"gpuprof"}` | `{"gpu"}` | `{"gpuprof"}` |
| `{"l2_flush","npuprof"}` | `{"npu"}` | `{"npuprof"}` |
