## 1. 整体架构

FlashAttentionScore 算子的拦截逻辑分为四个层次，从用户调用到最终 Kernel 执行，逐层校验和分发：

```
用户调用 aclnnFlashAttentionScoreV{1-5}
         │
         ▼
┌─────────────────────────────────┐
│  ACLNN API 层拦截 (~123个拦截点) │  ← 参数校验、格式检查、布局分析、预处理
└─────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────┐
│  InferShape 层拦截 (~20个拦截点) │  ← 输出形状推导、数据类型推导
└─────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────┐
│  Tiling 层拦截 (~15个拦截点)     │  ← 模板选择、空输入处理、架构分发
└─────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────┐
│  Kernel 层拦截 (编译期分发)      │  ← if constexpr 模板分发
└─────────────────────────────────┘
         │
         ▼
    执行计算
```

## 2. ACLNN API 层拦截

**代码位置**: `op_api/aclnn_flash_attention_score.cpp`

API 层是用户调用的第一道防线，负责所有参数的合法性检查和必要的预处理转换。

### 2.1 空指针检查

**函数**: `CheckFaParam()` (约第 908-941 行)

对必需输入和可选输入进行空指针校验：

| 检查项 | 错误码 | 说明 |

| `key == nullptr` | `ACLNN_ERR_PARAM_NULLPTR` | key 不能为空 |
| `value == nullptr` | `ACLNN_ERR_PARAM_NULLPTR` | value 不能为空 |
| `inputLayout == nullptr` | `ACLNN_ERR_PARAM_NULLPTR` | 布局参数不能为空 |
| `executor == nullptr` | `ACLNN_ERR_PARAM_NULLPTR` | 执行器不能为空 |
| `workspaceSize == nullptr` | `ACLNN_ERR_PARAM_NULLPTR` | workspace 大小指针不能为空 |
| `softmaxMaxOut == nullptr` | `ACLNN_ERR_PARAM_NULLPTR` | softmaxMax 输出不能为空 |
| `softmaxSumOut == nullptr` | `ACLNN_ERR_PARAM_NULLPTR` | softmaxSum 输出不能为空 |
| `attentionOutOut == nullptr` | `ACLNN_ERR_PARAM_NULLPTR` | attentionOut 输出不能为空 |

### 2.2 布局兼容性检查

**函数**: `AnalysisAxis()` (第 172-220 行)

**支持的布局类型** (5 种):

| 布局 | 维度数 | Query 形状 | Key/Value 形状 |
|------|--------|------------|----------------|
| `BSH` | 3D | (B, S1, N1*D) | (B, S2, N2*D) |
| `BSND` | 4D | (B, S1, N1, D) | (B, S2, N2, D) |
| `SBH` | 3D | (S1, B, N1*D) | (S2, B, N2*D) |
| `BNSD` | 4D | (B, N1, S1, D) | (B, N2, S2, D) |
| `TND` | 3D | (T, N1, D) | (T, N2, D) |

**拦截点**:
- 布局与维度数不匹配 → `ACLNN_ERR_PARAM_INVALID`
- qD ≠ kD → `ACLNN_ERR_PARAM_INVALID`
- kD < vD → `ACLNN_ERR_PARAM_INVALID`

```cpp
// 代码片段 (第 205-218 行)
if (shapeInfo.axes.d != shapeInfo.axes.dk) {
    OP_LOGE(ACLNN_ERR_PARAM_INVALID, "qD and kD should be same, but got qD=%ld kD=%ld",
        shapeInfo.axes.d, shapeInfo.axes.dk);
    return ACLNN_ERR_PARAM_INVALID;
}
if (shapeInfo.axes.d < shapeInfo.axes.dv) {
    OP_LOGE(ACLNN_ERR_PARAM_INVALID, "only support kD >= vD, but got kD=%ld vD=%ld",
        shapeInfo.axes.d, shapeInfo.axes.dv);
    return ACLNN_ERR_PARAM_INVALID;
}
```

### 2.3 数据类型一致性检查

**函数**: `InputDtypeCheck()` (第 391-446 行)

| 拦截点 | 条件 | 说明 |
|--------|------|------|
| Q/K/V dtype 不一致 | `qDtype != kDtype || kDtype != vDtype` | Query、Key、Value 数据类型必须相同 |
| 硬件限制 | `StrideLimited() && dtype not in [FP16, BF16, FP32]` | DAV_2201 架构仅支持 FP16/BF16/FP32 |
| PSE type 2/3 dtype 错误 | `pseType == 2或3 && pseDtype != FP32` | PSE alibi 场景下 PSE 必须为 FP32 |
| PSE dtype 与输出不一致 | `pseDtype != outDtype` | PSE 数据类型需与输出一致 |
| Sink dtype 错误 | `sinkDtype != FP32` | Sink 必须为 FP32 |

**量化场景检查** `InputDtypeCheckQuant()` (第 448-469 行):
- Q/K/V dtype 一致性
- 硬件限制 (FP16/BF16/FP32)

### 2.4 格式检查

**函数**: `CheckFormat()` (第 471-521 行)

所有输入和输出 **不能为 NZ (Fractal) 格式**：

```cpp
bool formatValid = query->GetStorageFormat() != op::Format::FORMAT_FRACTAL_NZ &&
                   key->GetStorageFormat() != op::Format::FORMAT_FRACTAL_NZ &&
                   value->GetStorageFormat() != op::Format::FORMAT_FRACTAL_NZ &&
                   softmaxMaxOut->GetStorageFormat() != op::Format::FORMAT_FRACTAL_NZ &&
                   softmaxSumOut->GetStorageFormat() != op::Format::FORMAT_FRACTAL_NZ &&
                   attentionOutOut->GetStorageFormat() != op::Format::FORMAT_FRACTAL_NZ;
```

可选输入 (queryRope, keyRope, realShift, dropMask, paddingMask, attenMask, sink) 同样不能为 NZ 格式。

### 2.5 Head 维度检查

**函数**: `AnalysisInput()` (第 523-616 行)

| 拦截点 | 条件 | 常量值 |
|--------|------|--------|
| headNum ≤ 0 | `headNum <= 0` | - |
| Head 维度 > 768 | `shapeInfo.axes.d > HEAD_DIM_MAX` | `HEAD_DIM_MAX = 768` |
| VarLen seq len 超限 | seq len > `MAX_VAR_LEN_SEQ_LEN` | `MAX_VAR_LEN_SEQ_LEN = 20000` |

### 2.6 Padding 决策

**函数**: `IsNeedPad()` (第 312-358 行)

Padding 决策逻辑：

```
BNSD/TND 布局 && N1==N2 && 不需要转置
    ├── d == 72 或 d == 88 → 不 pad (padNum = 0)
    ├── dv == 72 或 dv == 88 → 不 pad (padNumv = 0)
    └── 其他情况 → 需要 pad

TND 布局特殊逻辑:
    ├── d >= 96 → 需要 pad
    ├── sKvLenMax <= 1024 && sQLenSum < 160*1024 → 不 pad
    └── 其他情况 → 需要 pad
```

### 2.7 SameAB 能力判断

**函数**: `IsCapableSameAB()` (第 360-372 行)

判断是否可以使用 SameAB 模板优化：

```cpp
// 不支持 FP32
if (query->GetDataType() == DT_FLOAT) return false;

// 条件1: d 不是 16 的倍数或 d==96，且 s2 >= 512
if (((d + padNum) % 16 != 0 || d == 96) && s2 >= 512) return true;

// 条件2: s2 > 1024 且 128 < d < 196
if (s2 > 1024 && d > 128 && d < 196) return true;

return false;
```

### 2.8 MLA 支持判断

**函数**: `isSupportMLA()` (第 374-389 行)

```cpp
// TND 模板支持 MLA
if (inputLayout == TND) return true;
// SameAB 模板支持 MLA
if (IsCapableSameAB(shapeInfo, query)) return true;
// S1S2 模板支持 MLA (s2 > 1024)
if (shapeInfo.axes.s2 > 1024) return true;
return false;
```

### 2.9 Multi-Input (RoPE) 支持判断

**函数**: `isSupportMultiInput()` (约第 943-1005 行)

queryRope/keyRope 仅在以下条件下支持：
- 数据类型为 BF16
- attenMask 存在
- 无 PSE
- 无 dropMask
- keepProb = 1
- TND 布局
- 不需要 pad/transpose/reshape

### 2.10 布局转换拦截

**函数**: `SetShapeInfoForBshBsnd()` (第 222-250 行) 和 `SetShapeInfoForSbh()` (第 252-277 行)

当 stride 超过硬件限制时，自动触发转置和 reshape：

| 布局 | 触发条件 | 转换操作 |
|------|----------|----------|
| BSH/BSND | `alignedH1Size > MAX_STRIDE_S1 (65535)` | 转置为 BNSD 布局 |
| SBH | `B * alignedH1Size > MAX_STRIDE_S1 (65535)` | 转置为 BNSD 布局 |

### 2.11 连续性检查和预处理

**函数**: `Contiguous()` (第 634-714 行) 和 `PreprocessQKV()` (第 751-845 行)

| 操作 | 说明 |
|------|------|
| `l0op::Contiguous()` | 确保所有输入 tensor 内存连续 |
| `l0op::Reshape()` | 根据 `shapeInfo.needReshape` 进行 reshape |
| `l0op::Pad()` | 根据 `shapeInfo.needPad` 进行 padding |
| `l0op::Transpose()` | 根据 `shapeInfo.needTranspose` 进行转置 |

### 2.12 空 Tensor 提前返回

在每个 `*GetWorkspaceSize` 函数中，如果三个输出都为空，则提前返回：

```cpp
if (softmaxMaxOut->GetStorageShape().GetShapeSize() == 0 &&
    softmaxSumOut->GetStorageShape().GetShapeSize() == 0 &&
    attentionOutOut->GetStorageShape().GetShapeSize() == 0) {
    *workspaceSize = 0;
    return ACLNN_SUCCESS;
}
```

### 2.13 ACLNN 两段式接口

所有 ACLNN 接口遵循 **GetWorkspaceSize + Execute** 两段式模式：

```cpp
// 第一阶段：获取 workspace 大小并构建计算图
aclnnFlashAttentionScoreV4GetWorkspaceSize(
    query, key, value, ...,  // 所有输入
    &workspaceSize,          // 输出：workspace 大小
    &executor);              // 输出：携带计算图的执行器

// 第二阶段：执行计算图
aclnnFlashAttentionScoreV4(
    workspace, workspaceSize,
    executor, stream);
```

## 4. Tiling 层拦截

**代码位置**: `op_host/flash_attention_score_tiling.cpp` (入口) + `op_host/arch32/flash_attention_score_tiling_general.cpp` (arch32 模板) + `op_host/arch35/` (arch35 模板)

Tiling 层是算子编译期的核心拦截层，负责模板选择和切分策略。

### 4.1 参数检查

**函数**: `CheckParams()` (第 74-119 行)

| 布局 | 检查项 |
|------|--------|
| BSH | query.dim(0) == key.dim(0) (batch 一致) |
| SBH | query.dim(1) == key.dim(1) (batch 一致) |
| TND | query.dim(2) == key.dim(2) (D 维度一致) |
| BNSD/BSND | query.dim(0) == key.dim(0) (batch 一致) |
| BNSD/BSND | query.dim(3) == key.dim(3) (D 维度一致) |
| 所有 3D 布局 | key.dim(2) >= value.dim(2) (kD >= vD) |
| 所有 4D 布局 | key.dim(3) >= value.dim(3) (kD >= vD) |

### 4.2 空输入拦截

根据 NPU 架构分为两条路径：

#### Arch32 (DAV_2201): `IsEmptyInput()` (第 278-343 行)

**触发条件**: `(querySize == 0 || keySize == 0) && (attentionOutSize != 0 || softmaxSumSize != 0)`

处理逻辑：
1. 计算 coreNum、formerNum、tailNum
2. 计算每个核处理的数据量（主核/尾核/最后一个核）
3. 设置 tiling key 为 `FA_EMPTY_TILING_KEY = 1`
4. 预留 100MB workspace

#### Arch35 (DAV_3510): `IsEmptyInputRegbase()` (第 212-276 行)

**触发条件**: `(querySize == 0 || keySize == 0 || valueSize == 0) && (attentionOutSize != 0 || softmaxSumSize != 0)`

处理逻辑与 arch32 类似，但增加了 value 的空输入检查。

### 4.3 架构分发

**函数**: `TilingFlashAttentionScore()` (第 345-372 行)

```cpp
ASCENDC_EXTERN_C ge::graphStatus TilingFlashAttentionScore(gert::TilingContext *context) {
    // 1. 参数检查
    if (CheckParams(context) != ge::GRAPH_SUCCESS) {
        return ge::GRAPH_FAILED;
    }

    // 2. 获取平台信息
    auto platformInfoPtr = context->GetPlatformInfo();
    auto ascendcPlatform = platform_ascendc::PlatformAscendC(platformInfoPtr);

    // 3. 架构分发
    if (ascendcPlatform.GetCurNpuArch() == NpuArch::DAV_3510) {
        // Arch35: Regbase 路径
        if (IsEmptyInputRegbase(context)) {
            return ge::GRAPH_SUCCESS;
        }
    } else {
        // Arch32: General 路径
        if (IsEmptyInput(context)) {
            return ge::GRAPH_SUCCESS;
        }
    }

    // 4. 模板分发
    auto resultCode = TilingRegistryArch::GetInstance().DoTilingImpl(context);
    return resultCode;
}
```

### 4.5 模板能力匹配 (Arch32 - DAV_2201)

**代码位置**: `op_host/arch32/flash_attention_score_tiling_general.cpp`

模板通过 `IsCapable()` 和 `IsTemplateMatched()` 方法进行能力判断，框架按优先级依次尝试：

| 模板 | 优先级 | IsCapable() 条件 | 说明 |
|------|--------|------------------|------|
| `FlashAttentionScoreTilingDropMask` | 90 | DropMask 专用条件 | DropMask 场景 |
| `FlashAttentionVarLenScoreTiling` | 94 | TND 布局 | 变长序列场景 |
| `FlashAttentionScoreTilingS1s2Bn2gs1SameAB` | 95 | `IsCapableSameAB()` 返回 true | SameAB 优化模板 |
| `FlashAttentionScoreTilingS1s2Bn2gs1` | 96 | `s2Size > 1024` | S1S2 通用模板 |
| `FlashAttentionScoreTilingS1Bn2gs1` | 97 | `128 < s2Size <= 1024` | S1 中等序列模板 |
| `FlashAttentionScoreTilingB` | 98 | `s2Size <= 128` | B 小序列模板 |

**SameAB 模板详细条件** (第 3619-3650 行):

```cpp
bool IsCapable() override {
    // 不支持 FP32
    if (dataType == DT_FLOAT) return false;
    // 条件1: d 不是 16 的倍数或 d==96，且 s2 >= 512
    if (((d + padNum) % 16 != 0 || d == 96) && s2 >= 512) return true;
    // 条件2: s2 > 1024 且 128 < d < 196
    if (s2 > 1024 && d > 128 && d < 196) return true;
    // 条件3: d==64 且 s2%64!=0 且 2048 < s2 < 18432
    if (d == 64 && s2 % 64 != 0 && s2 > 2048 && s2 < 18432) return true;
    return false;
}
```

**S1S2 模板特殊 Shape 优化** (第 3209 行):

```cpp
bool IsSpecialShape() {
```

### 4.8 Tiling Key 编码

#### Arch32 TilingKey (32-bit)

```cpp
struct TilingKey {
    uint32_t splitS1 : 1;   // 是否切分 S1
    uint32_t splitS2 : 1;   // 是否切分 S2
    uint32_t splitD : 1;    // 是否切分 D
```

## 5. Kernel 层拦截

**代码位置**: `op_kernel/flash_attention_score.cpp`

Kernel 层使用 **编译期 `if constexpr`** 进行模板分发，根据 TilingKey 中的参数选择具体的 Kernel 实现。

### 5.1 Kernel 模板参数

```cpp
template<uint8_t KernelTypeKey, uint8_t UB0, uint8_t UB1, uint8_t Block, uint8_t ImplMode,
    uint8_t DataType, uint8_t Layout, uint8_t Bmm1Format, uint8_t Bmm2Source, uint8_t Sparse,
    uint8_t BigDoubleBuffer, bool HasDropOut, bool HasAttenMask, bool HasPse, bool EnableL1Reuse,
    bool HasRope, uint8_t MatmulPolicyType, uint8_t S1TemplateType, uint8_t S2TemplateType,
    uint8_t dTemplateSize>
__global__ __aicore__ void flash_attention_score(...)
```

### 5.2 Kernel 分发逻辑

| 条件 | 模板 | 数据类型分发 | 代码行 |
|------|------|-------------|--------|
| `KernelTypeKey == 1` | EmptyTensor | FP16 / FP32 / BF16 | 397-417 |
| `UB0==3 && UB1==9 && Block==9 && Layout==4` | TND SameAB (VarLen) | FP16 / BF16 / FP32 | 420-455 |
| `UB0==3 && UB1==4 && Block==9 && Layout==4` | TND Normal (VarLen) | FP16 / BF16 / FP32 | 458-475 |
| `UB0==3 && UB1==9 && Block==9 && Layout!=4` | SameAB | FP16 / BF16 / FP32 | 478-511 |
| `UB0==3 && UB1==4 && Block==9 && Layout!=4` | S1S2 | FP16 / BF16 / FP32 | 514-549 |
| `UB0==3 && UB1==5 && Block==9` | S1 | FP16 / BF16 / FP32 | 552-635 |
| `UB0==9 && UB1==9 && Block==0` | B | FP16 / BF16 / FP32 | 638-694 |

### 5.3 数据类型分发

在每个模板分支内部，进一步按 `DataType` 分发：

| DataType 值 | 数据类型 | 说明 |
|-------------|----------|------|
| 1 | `float` (FP32) | 全精度 |
| 2 | `bfloat16_t` (BF16) | 在部分架构 (3003/3113) 上被 `#if` 排除 |
| 3 | `half` (FP16) | 半精度 |

### 5.4 Matmul 格式分发

在模板内部，根据 `Bmm1Format` 选择 ND 或 NZ 格式的 matmul 实现：

| Bmm1Format | 实现宏 | 说明 |
|------------|--------|------|
| 0 (ND) | `INVOKE_FA_GENERAL_OP_IMPL` | 标准 ND 格式 matmul |
| 1 (NZ) | `INVOKE_FA_GENERAL_OP_IMPL_BMM1NZ` | NZ (Fractal) 格式 matmul |

### 5.5 Matmul Policy 分发

| MatmulPolicyType | 实现宏 | 说明 |
|------------------|--------|------|
| 0 (NORMAL) | `INVOKE_FA_GENERAL_OP_IMPL` | 普通 matmul 策略 |
| 1 (UNSPLITK) | `INVOKE_FA_GENERAL_OP_IMPL_WITH_MMPOLICY` | 不切分 K 维度的 matmul 策略 |

### 5.6 DropMask 预处理

在 VECTOR 实现路径中，如果 `tilingData->inputParams.needDropMaskOp` 为 true，则先执行 DropMask adapter：

```cpp
if (tilingData->inputParams.needDropMaskOp) {
    FlashAttentionScoreDropMaskAdapter dropMaskAdapter;
    dropMaskAdapter.Init(dropMask, user, tilingData, &tPipe);
    dropMaskAdapter.Process();
    tPipe.Reset();
    // ... 然后执行主 kernel
}
```

### 5.7 架构条件编译

BF16 类型在特定架构上被排除：

```cpp
#if !(defined(__NPU_ARCH__) && (__NPU_ARCH__ == 3003 || __NPU_ARCH__ == 3113))
// BF16 实现
#endif
```

### 6.3 关键拦截设计原则

| 原则 | 说明 | 示例 |
|------|------|------|
| **防御性拦截** | 防止无效输入导致崩溃 | 空指针检查、数组越界检查 |
| **兼容性拦截** | 确保输入在硬件支持范围内 | 硬件架构检查、数据类型支持检查 |
| **优化性拦截** | 为不同 shape 选择最优策略 | 模板能力匹配、特殊 shape 优化 |
| **转换性拦截** | 自动转换不兼容的输入格式 | 布局转换、连续性转换、Padding 转换 |
| **提前返回** | 无效输入快速失败 | 空 Tensor 提前返回、空输入快速路径 |

### 6.4 错误处理机制

| 错误类型 | 错误码 | 处理方式 |
|----------|--------|---------|
| 空指针 | `ACLNN_ERR_PARAM_NULLPTR` | 记录日志 + 返回错误码 |
| 参数无效 | `ACLNN_ERR_PARAM_INVALID` | 记录日志 + 返回错误码 |
| 图推导失败 | `GRAPH_FAILED` | 记录日志 + 返回失败状态 |
| 内部创建失败 | `ACLNN_ERR_INNER_CREATE_EXECUTOR` | 记录日志 + 返回错误码 |

所有错误均通过 `OP_LOGE` / `OP_LOGW` / `OP_LOGI` / `OP_LOGD` 记录日志，便于问题定位。
