## 1. 整体设计哲学差异

| 维度 | FlashAttentionScore (训练) | FusedInferAttentionScore (推理) |
|------|---------------------------|-------------------------------|
| **验证策略** | **前置拦截** — ~123 个检查集中在 API 层，在图构建前快速失败 | **延迟拦截** — API 层仅 ~12 个检查，~1500+ 检查延迟到 Tiling 阶段的 Checker 系统 |
| **模板策略** | **优先级注册** — 6~10 个模板通过 `IsCapable()` 竞争匹配 | **扁平 Key 分发** — ~180+ 预注册 Key，直接匹配 |
| **复杂度** | 简单：布局少、类型少、专注训练正确性 | 复杂：14 种布局、7+ 数据类型、量化、PA、MLA、GQA、FlashDecode |
| **代码组织** | 单体 API 文件（123 个检查集中在一个文件） | 模块化：按功能拆分 checker 文件（mask、PA、sparse 等） |
| **可扩展性** | 新增模板 → 注册并设置优先级 | 新增场景 → `REGISTER_TILING_DATA_CLASS` + `TILING_KEY_IS` 匹配 |

## 2. 架构支持对比

### 相同点

- 两者都支持 **DAV_3510** (Ascend950) 架构
- 都使用 `platform_ascendc::PlatformAscendC` 获取平台信息
- 都通过 `GetCurNpuArch()` 进行架构判断

### 不同点

| 项目 | 支持架构 | 架构分发方式 | 架构专用代码 |
|------|---------|-------------|-------------|
| **FlashAttentionScore** | DAV_2201 (arch32) + DAV_3510 (arch35) | `op_host/flash_attention_score_tiling.cpp:358` — `if (arch == DAV_3510)` 分支到 Regbase vs General 路径 | `op_host/arch32/` (1 文件) + `op_host/arch35/` (4 文件: basic, dropmask, varlen, regbase) |
| **FusedInferAttentionScore** | ASCEND310P + ASCEND910B + DAV_3510 | `op_host/fused_infer_attention_score_tiling_info_parser.cpp:189-213` — `GetNpuInfo()` 验证 SoC 是否为 310P/910B/3510 之一 | `op_host/arch32/` (checkers) + `op_host/arch35/` (tiling_v4) — Checker 系统仅 arch32 |

**关键差异**:
- FlashAttentionScore 采用**双架构并行**设计，每个架构有独立的模板注册和 TilingData
- FusedInferAttentionScore 采用**统一 Tiling 路径 + SoC 验证**，Checker 系统仅在 arch32 生效

## 3. ACLNN API 层对比

### 相同点

- 都提供 V1~V5 共 5 个版本的接口
- 都使用两段式接口模式 (`GetWorkspaceSize` + `Execute`)
- 都有 SoftmaxLse 的占位 tensor 处理逻辑
- 都调用 Inner 接口进行实际的路由

### 不同点

| 对比项 | FlashAttentionScore | FusedInferAttentionScore |
|--------|---------------------|-------------------------|
| **API 文件组织** | 单文件 `aclnn_flash_attention_score.cpp` | 5 个独立文件 (`_v2.cpp`, `_v3.cpp`, `_v4.cpp`, `_v5.cpp`, `_inner.cpp`) |
| **架构拦截** | **无** — 接受所有架构 | V1~V4 **拒绝 DAV_3510**（分别在各自文件第 33/76/118/88 行）；V5 是唯一支持 Ascend950 的版本 |
| **废弃警告** | **无** | V1~V4 首次调用输出 `OP_LOGW` 废弃警告（计划 2026 年 12 月废弃） |
| **拦截点数量** | **~123 个** | **~12 个** |
| **空指针检查** | `CheckFaParam()` — 18 项检查 | 无集中空指针检查，延迟到 Checker |
| **数据类型检查** | `InputDtypeCheck()` — Q/K/V dtype 一致、硬件限制、PSE dtype、Sink dtype | 无 API 层 dtype 检查，延迟到 Checker 系统 |
| **格式检查** | `CheckFormat()` — 所有输入输出不能为 NZ 格式 | 无 API 层格式检查，延迟到 Checker（仅支持 ND/NCHW/NHWC/NCDHW） |
| **布局分析** | `AnalysisAxis()` — 分析 stride，决定是否转置/reshape | 无 API 层布局分析，延迟到 InferShape/Tiling |
| **Padding 决策** | `IsNeedPad()` — 根据 d、布局、seq len 决定是否 pad | 无 API 层 padding 决策 |
| **预处理** | `Contiguous()` + `PreprocessQKV()` (Reshape/Pad/Transpose) — 重度数据变换 | `FusedInferAttentionScoreProcessSoftmaxLse()` 创建 addr=0xff 占位 tensor；`TensorPreProcess()` 转换 INT32→INT4 |
| **空 Tensor 提前返回** | 每个 `*GetWorkspaceSize` 中：3 个输出都为 size 0 则立即返回 | 无 API 层提前返回 |
| **FakeArray** | 无 | V5 版本为 5 个 `aclIntArray` 创建 fake tensor |

**关键差异**: FlashAttentionScore 在 API 层做**重度验证**（dtype、format、layout、padding、stride、MLA、RoPE 全部在此检查），而 FusedInferAttentionScore 的 API 层**轻量**，大部分验证延迟到 Checker 系统。

## 4. InferShape 层对比

### 相同点

- 都检查 context、shape、attrs 等基本参数非空（~10 项）
- 都进行布局合法性验证
- 都推导 `softmaxMax/Sum` 输出为 FP32
- 都根据布局推导 `attentionOut` 形状

### 不同点

| 对比项 | FlashAttentionScore | FusedInferAttentionScore |
|--------|---------------------|-------------------------|
| **文件行数** | 199 行 | 428 行 |
| **支持的布局** | **5 种**: BSH、BSND、SBH、BNSD、TND | **14 种**: BSH、BSND、BNSD、TND、NTD、BNSD_BSND、BSH_BNSD、BSND_BNSD、NTD_TND、BSH_NBSD、BSND_NBSD、BNSD_NBSD、TND_NTD、NSD |
| **混合布局** | **不支持** | **支持**: `BNSD_BSND`（输入 BNSD → 输出 BSND）、`BSH_BNSD`、`*_NBSD` 等 |
| **Page Attention 检测** | **不支持** | `isPageAttention = (blockTable == nullptr) ? false : true`（第 307 行） |
| **未知维度处理** | **不支持** | `FIA_UNKNOWN_DIMS = -2` — 传播未知维度到输出（第 338-345 行） |
| **numHeads 检查** | 不检查 | `*numHeadsPtr == 0` → 失败（第 328 行） |
| **GQA 支持** | 无 | 有 `numKeyValueHeads` 属性，支持 GQA 场景 |
| **LSE 输出** | 固定输出 `softmaxMax` + `softmaxSum` | **条件输出**: 仅当 `softmaxLseFlag==true` 时输出 `softmaxLse` |
| **输出形状推导** | `softmaxMax`: (B,N,S,8) 或 FP8: (B,N,S,1) 或 TND: (T,N,8) | `attentionOut`: 7 种布局分支推导；`softmaxLse`: {t,n1,1} (TND/NTD) 或 {b,n1,s1,1} (其他) |
| **Dtype 推导** | FP8 输入 → 输出 BF16；否则 → 输入 dtype | 默认 → query dtype；`quantScale2` 存在 → INT8；query 为 INT8/FP8 → queryRope dtype；`DT_FLOAT8_E5M2` 明确不支持 |
| **InputsDataDependency** | 未注册 | 注册 `{5, 6, 15, 16, 23}` |

**关键差异**: FusedInferAttentionScore 的 InferShape 层更复杂，支持 14 种布局（含混合布局）、PA 检测、未知维度传播、条件 LSE 输出、GQA 和量化 dtype 处理。

## 5. Tiling 层对比

### 相同点

- 都使用 `IMPL_OP_OPTILING` 宏注册 Tiling 入口
- 都有空 Tensor 检测和处理逻辑
- 都有 SoC/架构验证
- 都通过 TilingKey 进行 Kernel 分发

### 不同点

| 对比项 | FlashAttentionScore | FusedInferAttentionScore |
|--------|---------------------|-------------------------|
| **Tiling 入口** | `TilingFlashAttentionScore()` | `DoOpTilingFusedInferAttentionScore()` |
| **TilingPlacement** | 未指定 | `TILING_ON_HOST \| TILING_ON_AICPU` |
| **TilingData 类型** | **2 种**: `FlashAttentionScoreTilingData` (arch32) + `FlashAttentionScoreEmptyInputTilingDataRegbase` (arch35) | **~180+ 种** — 通过 Key 前缀区分：`5...` (Split-Fuse IFA)、`51...` (FlashDecode)、`52...` (Decoding)、`100...` (PFA)、`103/104/105...` (MLA/GQA v3)、`15...` (全量化)、`200...` (PFA Base)、`300...` (ATB)、`400...` (MLA 通用)、`13/14/27/30` (空 Tensor) |
| **TilingKey 设计** | **32-bit 结构体** (splitS1:1, splitS2:1, splitD:1, dtype:2, layoutType:2, sparseType:2, reserved:23) + **64-bit 模板 Key** (`ASCENDC_TPL_ARGS_DECL`，arch32 有 22 个模板参数，arch35 有 16 个) | **64-bit 整数常量** — `FAI_FLAG_TILING=5e18`、`PFA_FLAG_TILING=1e18`、`FIA_FLAG_TILING=1e17`；编码 dtype(Q/KV/Out)、缓存模式、Mask 类型、LSE 模式、布局、Sink、FlashDecode、Decoding |
| **空输入处理** | Arch32: `IsEmptyInput()` — 检查 `querySize==0 \|\| keySize==0`；Arch35: `IsEmptyInputRegbase()` — 增加 `valueSize==0` 检查；都设置 `FA_EMPTY_TILING_KEY=1`，预留 100MB workspace | `GetEmptyTensorFlag()` — `queryShapeSize==0 && attenOutShapeSize==0` → 空标志；不一致的空/非空 → `GRAPH_FAILED` |
| **模板匹配方式** | **优先级竞争**: DropMask(90) > VarLen(94) > SameAB(95) > S1S2(96) > S1(97) > B(98)，每个模板有 `IsCapable()` + `IsTemplateMatched()` | **无优先级系统** — 直接通过 `TILING_KEY_IS` 宏匹配 (~100+ 次)，`#elif TILING_KEY_VAR == ...` 链分发 |
| **Tiling 准备** | `TilingPrepareForFlashAttentionScore()` 填充 aivNum, aicNum, socVersion, npuArch, ubSize, l1Size, l0cSize, l2CacheSize | `ConvertContextToParamsPFA()` + `ConvertOptionalInputsIFA()` — 大量的上下文到参数转换 |
| **量化模式检测** | 无 | `GetQuantMode()` — `inputQType != inputKvType` → ANTI_QUANT；FP16/BF16 → NO_QUANT；其他 → FULL_QUANT |
| **RoPE 模式检测** | 无 | `GetRopeMode()` — DAV_3510 特殊处理：`qkHeadDim < vHeadDim` → 失败；`qkHeadDim > vHeadDim` → ROPE_COMBINE 或失败；`qkHeadDim == vHeadDim` → ROPE_SPLIT 或 NO_ROPE |

**关键差异**: FlashAttentionScore 使用**模板注册 + 优先级竞争**模式，而 FusedInferAttentionScore 使用**扁平 Key 直接匹配**模式，后者模板数量多一个数量级（180+ vs 6~10）。

## 6. Checker 系统对比

### 相同点

- 都进行数据类型合法性校验
- 都进行格式合法性校验
- 都检查必需参数存在性

### 不同点

| 对比项 | FlashAttentionScore | FusedInferAttentionScore |
|--------|---------------------|-------------------------|
| **独立 Checker 系统** | **无** | **有 — 模块化设计，~1500+ 拦截点** |
| **验证方式** | 内联在 API/Tiling 层中 | 独立的 Checker 子系统，按功能模块拆分 |
| **检查链** | 无固定检查链 | **4 级检查链**: `CheckSinglePara()` → `CheckParaExistence()` → `CheckFeature()` → `CheckMultiParaConsistency()` |
| **空 Tensor 跳过** | 不适用 | `if (fiaInfo_.emptyTensorFlag) return GRAPH_SUCCESS` — 跳过所有检查 |
| **Dtype 支持映射** | 硬编码在 `InputDtypeCheck()` 中 | 集中在 `DTYPE_SUPPORT_MAP`（`fused_infer_attention_score_tiling_constants.h:166-191`） |
| **Format 支持集合** | API 层拒绝 NZ 格式 | `FORMAT_SUPPORT_SET = {ND, NCHW, NHWC, NCDHW}` |

#### FusedInferAttentionScore 独有的 Checker 模块

| Checker 模块 | 文件 | 主要拦截内容 |
|-------------|------|-------------|
| **数据类型/量化模式分发** | `fused_infer_attention_score_tiling_check_existence.cpp` | MLA Noquant/Antiquant/Fullquant + GQA Noquant/Antiquant/Fullquant 的 dtype 组合验证 |
| **参数存在性** | `fused_infer_attention_score_tiling_check_existence.cpp` | 6 种模式下各自的 must-exist 和 must-not-exist 参数列表 |
| **SparseMode** | `fused_infer_attention_score_tiling_check_feature.cpp` | Sparse9 (Tree) 约束：必须 ROPE_SPLIT、无左 padding、无 PSE、无 prefix、无 INT8 输出、s2≥s1 |
| **Mask** | `fused_infer_attention_score_tiling_check_feature.cpp` | 根据 sparseMode 验证 mask 维度；无 RoPE 布局仅支持 2D mask |
| **后量化** | `fused_infer_attention_score_tiling_check_feature.cpp` | 不支持 RoPE、布局限制为 BSH/BSND/BNSD/BNSD_BSND |
| **左 Padding** | `fused_infer_attention_score_tiling_check_feature.cpp` | 布局限制、无 RoPE、无 TensorList、无 PA、无 prefix |
| **PSE** | `fused_infer_attention_score_tiling_check_feature.cpp` | 布局限制、无 RoPE |
| **Learnable Sink** | `fused_infer_attention_score_tiling_check_feature.cpp` | 1D tensor、dim==n1、dtype==BF16 |
| **布局** | `fused_infer_attention_score_tiling_check_feature.cpp` | 按 RoPE 模式和 headDim 全面验证 |
| **HeadDim** | `fused_infer_attention_score_tiling_check_feature.cpp` | vHeadDim≤512、ropeHeadDim==64、PA NZ 需 16 字节对齐 |
| **GQA Prefix** | `fused_infer_attention_score_tiling_check_feature.cpp` | 布局限制、无 RoPE、无 PA、无 TensorList with qs>1 |
| **KV Shape 一致性** | `fused_infer_attention_score_tiling_check_consistency.cpp` | 连续 batch / TensorList / Page Attention 三种场景的 shape 校验 |
| **BlockTable** | `fused_infer_attention_score_tiling_check_consistency.cpp` | TND 布局下 blockTable dim0 必须等于 batchSize |
| **后量化一致性** | `fused_infer_attention_score_tiling_check_consistency.cpp` | 输出必须 INT8、scale2/offset2 dtype 和 shape 一致、query 必须 FP16/BF16 |
| **Mask Checker** | `op_host/checkers/mask_checker.cpp` | AttentionMask dtype 必须 int8/uint8/bool；SparseMode 仅支持 0/1/2/3/4/9；IFAMLA 约束 |
| **PA Checker** | `op_host/checkers/paged_attention_checker.cpp` | BlockTable dtype=INT32、shape 2D、blockSize>0、需 queryPaddingSize+kvPaddingSize |

**关键差异**: FlashAttentionScore **没有独立的 Checker 系统**，所有验证内联在 API/Tiling 层中；FusedInferAttentionScore 有**完整的模块化 Checker 子系统**，按功能拆分为 15+ 个专用 checker，支持 MLA/GQA × Noquant/Antiquant/Fullquant 的矩阵式验证。

## 7. Kernel 层对比

### 相同点

- 都使用 `extern "C" __global__ __aicore__` 定义 Kernel 入口
- 都通过 TilingKey 进行分发
- 都使用模板实例化具体的注意力计算逻辑
- 都有数据类型分发（FP16 / BF16）

### 不同点

| 对比项 | FlashAttentionScore | FusedInferAttentionScore |
|--------|---------------------|-------------------------|
| **Kernel 文件** | `op_kernel/flash_attention_score.cpp` (697 行) | `op_kernel/fused_infer_attention_score.cpp` (668 行) + `fused_infer_attention_score_v3.cpp` + `flash_attention_interface.cpp` |
| **Kernel 签名** | **22 个模板参数**: `KernelTypeKey, UB0, UB1, Block, ImplMode, DataType, Layout, Bmm1Format, Bmm2Source, Sparse, BigDoubleBuffer, HasDropOut, HasAttenMask, HasPse, EnableL1Reuse, HasRope, MatmulPolicyType, S1TemplateType, S2TemplateType, dTemplateSize` | **无模板参数** — 32 个 `__gm__ uint8_t*` 原始指针；通过 tiling key 在运行时分发 |
| **一级分发** | `if constexpr (KernelTypeKey == 1)` → EmptyTensor | `if (TILING_KEY_VAR >= FAI_FLAG_TILING)` → Split-Fuse 路径 |
| **二级分发** | `if constexpr (UB0==3 && UB1==9 && Block==9 && Layout==4)` 等组合 | `TILING_KEY_IS` 宏匹配 (~100+ 次) |
| **三级分发** | `#elif TILING_KEY_VAR == ...` → `INVOKE_FA_GENERAL_OP_IMPL*` 宏 | `#elif TILING_KEY_VAR == ...` → `SplitFuse::FAInfer<...>` 模板实例化 |
| **FAInfer 模板参数** | 不适用 | **9 个**: `InputDtypeQ, InputDtypeKv, IntermCalcPrec, PagedCacheFlag, IS_FD, maskCategory, inLayout, lseMode, sinkMode` |
| **Mask 类型** | 通过 `HasAttenMask` bool 控制 | `MaskType::NO_MASK=0, MASK_CAUSAL=1, MASK_SPEC=2, MASK_SWA=4, FULL_MASK=5` |
| **DropMask 处理** | `needDropMaskOp` → 先运行 `FlashAttentionScoreDropMaskAdapter` | 无 DropMask；使用 `attenMask` + mask category |
| **FlashDecode** | **不支持** | **支持** — `_FD` 后缀 tiling key，`IS_FD=true` 模板参数 |
| **Decoding 优化** | **不支持** | **专用** — `FAInferDecoding` 类，优化 `pagedCacheFlag==true && qSeqlen==1 && NO_MASK && !lseFlag` |
| **APT Kernel** | **无** | **有** — `fused_infer_attention_score_apt.cpp`，13 个模板参数；`quantMode >= FullQuantTiling` → PFA vs IFA 路径 |
| **V3 Kernel (MLA/GQA)** | **无** | **有** — `fused_infer_attention_score_v3.cpp`，`#ifdef FIA_ENABLE_MLA` 条件编译 |
| **`if constexpr` 内部** | 按 `DataType`、`Bmm1Format`、`MatmulPolicyType` 分发 | 按 `IS_FD`、`INPUT_LAYOUT==TND`、`!PAGED_CACHE_FLAG`、`MASK_TYPE` 分发 |
| **架构条件编译** | `#if !(__NPU_ARCH__ == 3003 \|\| __NPU_ARCH__ == 3113)` 排除 BF16 | 主 Kernel 无架构 `#if`；通过 tiling key 区分 |

**关键差异**: FlashAttentionScore 使用**编译期模板分发**（22 个模板参数 + `if constexpr` 分支），而 FusedInferAttentionScore 使用**运行时 Tiling Key 分发**（扁平 `#elif` 链 → 模板实例化），并额外包含 FlashDecode、Decoding、MLA/GQA v3 路径。

## 8. 数据类型支持对比

### 相同点

- 都支持 FP16、BF16
- `softmaxMax/Sum` 输出固定为 FP32
- 都有 FP8 相关的特殊处理

### 不同点

| Tensor | FlashAttentionScore | FusedInferAttentionScore |
|--------|---------------------|-------------------------|
| **Query** | FP16, BF16, **FP32** | FP16, BF16, **INT8** |
| **Key** | 同 Query | FP16, BF16, INT8, **INT4, HIFLOAT8, FLOAT8_E4M3FN, FLOAT4_E2M1** |
| **Value** | 同 Query | FP16, BF16, INT8, **INT4, HIFLOAT8, FLOAT8_E4M3FN, FLOAT4_E2M1** |
| **Output** | 同输入 (FP8→BF16) | FP16, BF16, **INT8** |
| **PSE** | FP32 (alibi)，必须匹配输出 dtype | FP16, BF16 |
| **Sink** | FP32 | BF16 (learnableSink) |
| **量化支持** | 仅 FP8 (HIFLOAT8/FLOAT8_E4M3FN/FLOAT8_E5M2) — 输出转 BF16 | **全量化链路**: INT4, INT8, FP8；3 种模式 (NO_QUANT/ANTI_QUANT/FULL_QUANT)；多种反量化模式 (per-channel/per-token/per-tensor-head/per-token-head/per-token-pa/per-token-head-pa/per-token-group/per-block) |
| **不支持的 dtype** | 无明确排除 | `DT_FLOAT8_E5M2` 明确不支持 |

**关键差异**: FlashAttentionScore 面向**训练场景**，数据类型以 FP16/BF16/FP32 为主，FP8 仅用于 attention score 计算；FusedInferAttentionScore 面向**推理场景**，拥有完整的量化管线（INT4/INT8/FP8），支持反量化、反量化 scale/offset、learnable sink 等推理优化特性。

---

## 9. 布局支持对比

### 相同点

- 都支持 BSH、BSND、BNSD、TND 四种基础布局
- 都在 InferShape 层验证布局合法性
- 都根据布局推导输出形状

### 不同点

| 对比项 | FlashAttentionScore | FusedInferAttentionScore |
|--------|---------------------|-------------------------|
| **布局总数** | **5 种**: BSH, BSND, SBH, BNSD, TND | **14 种**: BSH, BSND, BNSD, TND, NTD, BNSD_BSND, BSH_BNSD, BSND_BNSD, NTD_TND, BSH_NBSD, BSND_NBSD, BNSD_NBSD, TND_NTD, NSD |
| **SBH 布局** | **支持** | **不支持** |
| **NTD 布局** | **不支持** | **支持** |
| **NSD 布局** | **不支持** | **支持** |
| **混合布局** | **不支持** | **支持**: `BNSD_BSND`（输入 BNSD → 输出 BSND）、`BSH_BNSD`、`BSND_BNSD`、`NTD_TND`、`TND_NTD`、`*_NBSD` 系列 |
| **NBSD 格式** | **不支持** | **支持** (新格式) |
| **布局转换** | 自动：BSH/SBH → BNSD，当 stride 超过 `MAX_STRIDE_S1=65535` | 无自动转换；布局在 InferShape 层验证 |
| **Kernel 层布局** | `LayOutTypeEnum` 5 个值 (BSH=0, BSND=1, SBH=2, BNSD=3, TND=4) | 仅 2 个值 (`BSND=0, TND=1`)；高层 tiling 处理 14 种 |

**关键差异**: FusedInferAttentionScore 支持 14 种布局（含混合布局和 NBSD 新格式），支持跨布局 I/O（如输入 BNSD 输出 BSND），但不做自动布局转换；FlashAttentionScore 仅 5 种布局，但有自动 stride-based 布局转换。

## 10. 特殊功能对比

### 相同点

- 都支持 RoPE（但实现方式不同）
- 都支持 MLA（但支持程度不同）
- 都支持 PSE（位置编码）
- 都支持 attenMask

### 不同点

| 功能 | FlashAttentionScore | FusedInferAttentionScore |
|------|---------------------|-------------------------|
| **Page Attention** | **不支持** | **支持** — `blockTable` 输入、`PAGEDCACHE` tiling key 变体、PA 专用 shape 推导、PA Checker |
| **RoPE** | 简单 `HasRope` bool；`isSupportMultiInput()` 限制为 BF16+TND+noPSE+noDropMask+keepProb=1+noPad | **3 种模式**: ROPE_SPLIT / ROPE_COMBINE / NO_ROPE；DAV_3510 特殊处理：`qkHeadDim < vHeadDim` → 失败；`qkHeadDim > vHeadDim` → ROPE_COMBINE 或失败 |
| **MLA** | `isSupportMLA()` — TND 模板 + SameAB 模板 + S1S2(s2>1024) 支持 MLA | **完整 MLA 支持**: MLA v3 tiling keys (`103/104/105...`)、`MLAGeneralTilingData`、`FiaKernelNonQuantMla`、MLA 专用 dtype/shape 检查、`MLA_QKD_SIZE=192`、`MLA_VD_SIZE=128` |
| **SparseMode** | 2-bit 字段 (0-3) | **6 种模式**: 0 (无 mask)、1 (全 mask)、2 (左上因果)、3 (右下因果)、4 (带状)、**9 (树状)**；Tree 模式有大量约束 |
| **FlashDecode** | **不支持** | **支持** — `_FD` 后缀 tiling key、`IS_FD=true` 模板参数、workspace sizing + tensor setup + task loop 差异化 |
| **Decoding 优化** | **不支持** | **专用优化** — `FAInferDecoding` 类、`BS1GN2` 任务分解（vs `BN2S1GS2`）、优化 `qSeqlen==1` 场景 |
| **Learnable Sink** | 基础支持 (FP32) | **完整支持** — 1D tensor、dim==n1、dtype==BF16、`SinkMode::ENABLE/DISABLE` 模板参数、epilogue 集成 |
| **GQA Prefix** | **不支持** | **支持** — `keySharedPrefix`/`valueSharedPrefix` 输入、prefix tiling key、GQA prefix checker |
| **左 Padding** | **不支持** | **支持** — `queryPaddingSize`/`kvPaddingSize` 输入，有约束条件 |
| **后量化** | **不支持** | **支持** — 输出 INT8、scale2/offset2、query 必须 FP16/BF16、无 RoPE、布局限制 |
| **TensorList** | **不支持** | **支持** — KV 作为 TensorList 用于增量注意力、累计 S 验证、batch-per-tensor 检查 |
| **DropMask** | **支持** — `FlashAttentionScoreDropMaskAdapter` | **不支持**；使用 `attenMask` + mask category |
| **SameAB 优化** | **支持** — `IsCapableSameAB()` 复杂条件判断 | **不支持** |

**关键差异**: FlashAttentionScore 面向训练，功能相对简单（DropMask、基础 RoPE、基础 MLA、SameAB 优化）；FusedInferAttentionScore 面向推理，功能丰富（Page Attention、FlashDecode、Decoding、完整 MLA/GQA、SparseMode 9、后量化、TensorList、Prefix、左 Padding、Learnable Sink）。

## 11. 约束条件对比

### 相同点

- 都要求 query/key 的 D 维度一致（RoPE 场景除外）
- 都对 head 数量有合法性检查
- 都对序列长度有上限约束
- 都检查 PSE dtype 合法性

### 不同点

| 约束项 | FlashAttentionScore | FusedInferAttentionScore |
|--------|---------------------|-------------------------|
| **Head dim 上限** | `HEAD_DIM_MAX = 768` | `vHeadDim <= 512`，`ropeHeadDim == 64` |
| **VarLen seq len 上限** | `MAX_VAR_LEN_SEQ_LEN = 20000` | `T_LIMIT = 1048576`，`S_LIMIT = 20971520` (20M) |
| **Shape 上限 (arch35)** | 未显式定义 | `B_LIMIT=65536, N1_LIMIT=256, N2_LIMIT=256, G_LIMIT=64, D_LIMIT=512, H_LIMIT=65535` |
| **D 对齐** | d==72 或 d==88 → 不 pad (BNSD/TND)；d>=96 (TND) → 需 pad | PA NZ 格式需 16 字节对齐 |
| **kD vs vD** | `kD >= vD` 在 API + Tiling + InferShape 三层强制 | 通过 valueD 推导处理；无显式 kD>=vD 检查 |
| **qD vs kD** | `qD == kD` 必须（RoPE 场景允许不同） | `qkHeadDim` vs `vHeadDim` vs `ropeHeadDim` — 更细粒度 |
| **Batch 一致性** | query.dim(0) == key.dim(0) (BSH/BSND/BNSD) | 更严格：tensorlist batch 验证、累计 KV S 检查 |
| **BlockSize** | 不适用 | `BLOCK_SIZE_MAX=512` (非量化: 1024)，必须 >0，PA 对齐到 16/128 |
| **Inner precise** | 不适用 | `INNER_PRECISE_LIMIT=4`，HIGH_PRECISION=0，HIGH_PERFORMANCE=1 |
| **SameAB 能力** | `IsCapableSameAB()` — d、s2、padNum 的复杂条件 | 不适用 |
| **PSE 约束** | PSE type 2/3 → 必须 FP32；dtype 必须匹配输出 | PSE dtype: FP16/BF16；启用 PSE 时不支持 RoPE |
| **SparseMode 约束** | 2-bit 字段，无额外约束 | Sparse9 (Tree) 有 6 项约束：必须 ROPE_SPLIT、无左 padding、无 PSE、无 prefix、无 INT8 输出、s2≥s1 |
| **量化约束** | 无 | INT8 输出时 D 需 32 对齐；INT4 时 D 需 64 对齐；FP16/BF16 时 D 需 16 对齐 |
| **Q_S > 1 约束** | 不适用 | B≤65536；INT8 且 D 非 32 对齐时 B≤128；FP16/BF16 且 D 非 16 对齐时 B≤128；N≤256；D≤512 |
| **Q_S == 1 约束** | 不适用 | B≤65536；N≤256；D≤512；不支持 INT8 输入 |

**关键差异**: FlashAttentionScore 的约束以**形状为中心**（维度限制、对齐要求、padding 决策）；FusedInferAttentionScore 的约束以**功能为中心**（模式兼容性、sparse+mask 组合、量化+布局限制）。

## 12. 总结

### 核心差异一览

| 维度 | FlashAttentionScore | FusedInferAttentionScore |
|------|---------------------|-------------------------|
| **场景定位** | 训练 | 推理（增量 + 全量） |
| **验证策略** | 前置拦截（API 层 ~123 个检查） | 延迟拦截（API 层 ~12 个 + Checker ~1500+ 个） |
| **模板策略** | 优先级注册（6~10 个模板竞争） | 扁平 Key 分发（~180+ 预注册 Key） |
| **布局数量** | 5 种 | 14 种（含混合布局） |
| **数据类型** | FP16/BF16/FP32 + FP8 | FP16/BF16/INT8/INT4/FP8（全量化链路） |
| **Checker 系统** | 无 | 有（15+ 个模块化 checker） |
| **Page Attention** | 不支持 | 支持 |
| **FlashDecode** | 不支持 | 支持 |
| **Decoding 优化** | 不支持 | 支持 |
| **SparseMode** | 4 种 (0-3) | 6 种 (0/1/2/3/4/9) |
| **MLA 支持** | 基础 | 完整（v3） |
| **量化模式** | 无 | 3 种 (NO_QUANT/ANTI_QUANT/FULL_QUANT) |

### 设计哲学总结

**FlashAttentionScore** 采用**"快速失败"**策略：在 API 层尽可能多地做验证，确保无效输入在图构建前就被拒绝。代码组织相对集中，适合训练场景对正确性的严格要求。

**FusedInferAttentionScore** 采用**"分层验证 + 模块化"**策略：API 层仅做最基本的版本路由和预处理，将复杂验证延迟到 Tiling 阶段的 Checker 系统。Checker 系统按功能模块拆分，便于维护和扩展，适合推理场景的多样化需求（量化、PA、FlashDecode、Decoding 等）。
