# D=256 设计方案（PyPTO FlashAttnGrad）

范围：`D, Dv ∈ (192, 256]`。64 / 128 / 192 与 BN2 现有路径不改。

对照实现：本仓 `attention/flash_attention_score_grad` arch35
（`SetSplitAxis`、`flash_attention_score_grad_kernel.h` 的 `Process()`、
`flash_attention_score_grad_block_cube.h`）。

---

## 1. 目标与原则

- 精度：现有 `check_result`（ratio 0.005，max abs 0.1）。
- **分核**跟 GS1S2；**主循环**跟 AscendC `D>128` 的 `Process()` 1-ahead，
不跟小 D 的 `ProcessPreloadTwoTimes`。
- 不把 D=256 放进 `template==1` / `flash_attn_grad_bn2`：那条是一核一头、
v5/v6 直出，和 GS1S2 多核切 S 冲突。
- 片上放得下优先于和 192 档共用同一套 lag。

---

## 2. 路由与契约


| 项                    | 取值                                                          |
| -------------------- | ----------------------------------------------------------- |
| tilingkey `template` | **0（BN2GS1S2）**                                             |
| `d_align`            | 现有 2 bit 空余值 **3 = 256**（不扩位）                               |
| `dv_align`           | 仍 1 bit：0=128，1=256。Dv∈(128, 256] 按 256 分配，`valid_shape` 裁列 |
| Host `SelectDBucket` | `d≤64→64`，`d≤128→128`，`d≤192→192`，`d≤256→256`               |
| `MAX_HEAD_DIM`       | 256（`flash_attn_grad` + `flash_attn_metadata` 的 grad 检查）    |
| BN2                  | `BN2_MAX_D` 仍 **128**，不编 `BN2×256`                          |
| TND                  | 与 D=192 相同：**不编**                                           |
| mask                 | 0 / 3 / 4；`swizzle+mask` 与 192 一样不编                         |
| Dv≤D                 | 继续检查（写越界防护）                                                 |
| 确定性                  | 继续拒绝                                                        |


分核：`fusedOuter = b·n2·g·s1Outer·s2Outer`，`CUBE_BASEM/N = 128`，
metadata / `SetBlockDim` / swizzle 判据沿用 GS1S2。短 S、GQA、长 S 都走这一套，
不因为 D=256 改成一核一头。

---



## 3. 主循环（和 BN2 函数的关系）

挂在 `flash_attn_grad_bn2gs1s2` 里，按 `d_align` 分叉：

- **64 / 128 / 192**：现有 `PRELOAD_TIMES=3`，cube 领先 2 拍，drain 2 轮。
- **256**：抄 BN2 的 **1-ahead**：`runInfos[2]`，`taskId % 2`，`taskId>0` 才做
MM3/4/5 与 V1…，末尾 drain **1** 轮。

计算仍调 GS1S2 的 `iterate_mm_*` / `process_vec*` / `flush_dkv` /
`next_work_gidx`，**不调** `iterate_mm_*_bn2`。

对齐 AscendC：

```
Process()                    // D>128：runInfos[2]
  mm2 + mm1                  // 当前 task
  ComputeDqkvBn2gs1s2(prev)  // 上一 task 的 V2… + MM5/3/4
```

数据流不变：`MM2→V2/V4`，`MM1→V1/V3`，`MM5→MM3→MM4`。
pre / post、fp32 workspace、dq atomic 仍是 GS1S2。

Q/dO 只 lag **1** 拍：`q_l1.previous()` 给 MM4，不再要 3 槽 N-2 视图。

---



## 4. Cube / 片上



### D 切分（编译期表）

- `D_NCHUNKS[256] = 2`，`128+128`（C0=16 对齐）。
- C1/C2：第二块 `matmul_acc` 进同一 acc。
- C3：两块列不相交，各 atomic 出 dq workspace。
- 真实 D=193…255：第二块 `valid_shape` 裁到 `d-128`。



### L1

- `D_PHYS_W[256] = 256`，整头 `pl.load`，再 `pl.move(..., [0, dOff])` 切列
（少改 C1–C3）。
- Q/dO **各 2 槽**（1-ahead）。不做 AscendC 的 `IS_L1_PRELOAD`（拷下一 task 的 Q/dO）。
- 预算：`2+2`×64KB + K + K_ND + V + dS/P ≈ 512KB。



### L0A / L0B

- 按最宽分块 128 列声明：`[128,128] fp16 = 32KB` × 2 = 64KB，双缓冲刚好满。



### L0C（首版）

- **dK/dV 不驻留**：每 task 每 chunk 算完 atomic 出 workspace（C3 同款）。
- acc 可双缓冲 + 一块 scratch。整头 256 列两块同时驻留要 320KB，放不下。

192 的 96+96 + 双块 L0C 驻留不动。

---



## 5. Vector

- 新 VF：`softmax_grad_front_row256_vf`（128+128 两趟，不和 192 写进同一个 VF）。
- `v1w = 256`：y/dy `64×256×2`，主图 UB 放得下。
- pre/post 1D 切块复用 192 的 `PRE_ELEMS` / `POST_ELEMS`。

---



## 6. 改动面

- Host：`MAX_HEAD_DIM`、`SelectDBucket`、`DAlignBits(256→3)`、
dv 在 `d=256` 时 256→bit1。
- Kernel：`fag_tiling.is_valid`、`fag_common` 分块表、`fag_mem` / `fag_buffers`
256 档、`fag_kernel` 1-ahead 分叉、`fag_block_cube` C4/C5 非驻留、
`fag_vector_api` / `fag_block_vec`。
- metadata grad 上限 256；测试 `HEAD_DIM_MAX`；文档 `D<=256`。
- **不改** `flash_attn_grad_bn2` 的分核与直出路径。

---



## 7. 实施顺序

1. 契约：host + metadata + tilingkey，现有 675 例 key 不变。
2. `describe_layout(256)` / `audit_mutex(256)` 不超容量。
3. GS1S2 内 1-ahead + 128+128 + VF256。
4. 冒烟：D=193 / 200 / 240 / 256；Dv=128 / 192 / 256；mask 0/3/4；
  BSND / BNSD；GQA；S 尾块。
5. 回归 `fag_test_case_kernel.xlsx` enable True+1（675）。
6. 再谈 L0C 只驻留 Dv、L1 按列两次 load。

首版验收按「GS1S2 + 1-ahead + 总是 128 切 D + 不驻留 dkv」。
不要用 AscendC 短 S 走 BN2 的耗时当对拍基线。
若要和短 S 也对齐分核，那是下一阶段（放宽 BN2 的 D），不在本方案里。

## 8. 与当前 AscendC 的不一致



### 8.1 本方案相对 AscendC D=256 的刻意差异

这些是讨论后选定的，不是漏实现。

| --- | ---------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- | ---------------------------------------------------------------------------------- |
| A1  | **模板选择**         | `BN2_MAX_D=512`。D=256 且 S1/S2≤128 且 MHA → **BN2**；S∈(128, 640] 且 D==Dv 且过 BN 门 → **BN2 MultiBlk**；否则 GS1S2           | D∈(192, 256] **一律 GS1S2**                         | 短 S / 中 S 的 D=256：ASC 一核一头、无 s1o×s2o；我们多核切 S、走 workspace atomic。同 shape 分核图不同，性能会偏 |

### 8.2 对齐 AscendC D=256 的部分（避免误判成差异）

- GS1S2 长 S / GQA：两边都是 `b·n2·g·s1o·s2o`，s1/s2 base 128。
- D>128 **不用** `ProcessPreloadTwoTimes`（`IS_PRELOAD_TWO_TIMES` 只到 128）。
本方案 256 用 1-ahead，这里与 ASC 一致。
- `IS_L1_PRELOAD` 对 D=256 为假：我们也不做 next-Q 预取。
- 整头 dK+dV 不驻留 L0C：公式上 ASC 也是 false。
- dq/dk/dv 经 fp32 workspace + atomic（`IS_*_WRITE_UB=false` 的 GS1S2）。
- 阶段顺序：MM2→V2/V4，MM1→V3，MM5→MM3→MM4。
- D 切块粒度 128（在「总是切」的前提下与 `SPLIT_BASE_D` 一致）。



### 8.3 原有 PyPTO ↔ AscendC 差异（256 会继承，不是本需求新引入）


| 点              | 说明                                                                                                    |
| -------------- | ----------------------------------------------------------------------------------------------------- |
| D≤128 主循环      | 我们 GS1S2 已是 `PRELOAD_TIMES=3`；ASC 同条件才 `ProcessPreloadTwoTimes`。256 不走这条。                             |
| **D=192 主循环**  | 我们仍是 +2；ASC 192 已是 1-ahead。本需求不改 192。                                                                 |
| D=192 L0C      | 我们 96+96 双块驻留；ASC 整头公式也不驻留，另有 192/Dv=128 特例。                                                          |
| MM4/MM5 转置     | ASC `isLeftTranspose`；我们 vector 侧 NZ / `ds_t` / `p_t`。                                                |
| K 的双视图         | 我们 `tensor_k` 与 `tensor_k_nt` 分开推 layout。                                                             |
| sink / seqused | 接口有，kernel 基本未用；ASC 有 sink 计算。                                                                        |
| dtype / layout | 我们 fp16/bf16、BSND/BNSD（TND 仅 D≤128 档）；ASC 还有 fp32/fp8、BSH/SBH。                                        |
| 注释债            | `fag_kernel.py` 仍写「实现的是 Process 两槽、PreloadTwoTimes 未做」，但 64/128/192 实际是 3 槽。256 才会真正补上两槽 `Process()`。 |




### 8.4 同 shape 时最容易看到的行为差

1. `B, N, S=128, D=256`**（MHA）**：ASC → BN2 单块；我们 → GS1S2（一核也可能只拿到 1 个 128×128 tile），但走 workspace / 1-ahead GS1S2，不是 v5/v6 直出。
2. `S=512, D=256`**（MHA、BN 够大）**：ASC → BN2 MultiBlk；我们仍 GS1S2。
3. `S=64, D=256`：ASC 可能不切 D；我们仍 128+128（第二块 valid 成 128，多一次空/短 K 轴）。
4. **长 S + GQA + D=256**：模板两边都是 GS1S2，差在 L0C（我们不驻留 Dv）和 L1（我们整头 load）。
