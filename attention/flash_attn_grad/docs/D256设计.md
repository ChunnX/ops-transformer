# 上篇：D=256（已落地）

范围：`D, Dv ∈ (192, 256]`。64 / 128 / 192 与 BN2 现有路径不改。

---

## 1. 目标与原则

- 精度：现有 `check_result`（ratio 0.005，max abs 0.1）。
- **分核**跟 GS1S2；**主循环**跟 AscendC `D>128` 的 `Process()` 1-ahead，
不跟小 D 的 `ProcessPreloadTwoTimes`。
- 不把 D=256 放进 `template==1`：那条是一核一头、v5/v6 直出，和 GS1S2
多核切 S 冲突。流水复用 `flash_attn_grad_preload2` 函数（后续对标 Process
else），分核仍是 GS1S2。
- 片上放得下优先于和 192 档共用同一套 lag。

---

## 2. 路由与契约


| 项                    | 取值                                                          |
| -------------------- | ----------------------------------------------------------- |
| tilingkey `template` | **0（BN2GS1S2）**                                             |
| `d_align`            | 现有 2 bit 空余值 **3 = 256**（不扩位）                               |
| `dv_align`           | 2 bit，取值与 `d_align` 相同。一般 `d_align==dv_align`；仅 D=192 且 Dv=128 时为 128 |
| Host `SelectDBucket` | `d≤64→64`，`d≤128→128`，`d≤192→192`，`d≤256→256`               |
| `MAX_HEAD_DIM`       | 256（`flash_attn_grad` + `flash_attn_metadata` 的 grad 检查）    |
| BN2                  | `BN2_MAX_D` 仍 **128**，不编 `BN2×256`                          |
| TND                  | 与 D=192 相同：**不编**                                           |
| mask                 | 0 / 3 / 4；`swizzle+mask` 与 192 一样不编                         |
| D 与 Dv              | 必须相等；唯一例外 D=192 且 Dv=128                                      |
| 确定性                  | 继续拒绝                                                        |


分核：`fusedOuter = b·n2·g·s1Outer·s2Outer`，`CUBE_BASEM/N = 128`，
metadata / `SetBlockDim` / swizzle 判据沿用 GS1S2。短 S、GQA、长 S 都走这一套，
不因为 D=256 改成一核一头。

## 3. 主循环（和 BN2 函数的关系）

分核仍是 GS1S2（`template=0`）。入口：仅 `Tmpl.BN2GS1S2` 且 D≤192 走
`flash_attn_grad_preload3`；其余走 `flash_attn_grad_preload2`
（后续对标 ASC `Process()` else）：

- **64 / 128 / 192**：`flash_attn_grad_preload3` 的
`PRELOAD_TIMES=3`，cube 领先 2 拍，drain 2 轮。
- **256**：入口分发到 `flash_attn_grad_preload2`，与 `Tmpl.BN2` **共用同一套
1-ahead while**，只在视图 / pre/post / matmul·vec / 同步顺序不同处分支。
`runInfos[2]`，`taskId % 2`，`taskId>0` 才做 MM3/4/5 与 V1…，末尾 drain
**1** 轮。pre/post 按场景：D=256 清 workspace 再 scale+cast；`template==1`
直出不跑这套。

计算仍调 GS1S2 的 `iterate_mm_*` / `process_vec*` / `next_work_gidx`，
**不调** `iterate_mm_*_bn2`。`template==1` 的分核与直出不变。

对齐 AscendC：

```
Process()                    // D>128：runInfos[2]
  mm2 + mm1                  // 当前 task
  ComputeDqkvBn2gs1s2(prev)  // 上一 task 的 V2… + MM5/3/4
```

数据流不变：`MM2→V2/V4`，`MM1→V1/V3`，`MM5→MM3→MM4`。
fp32 workspace、dq atomic 仍是 GS1S2 算法；pre/post 在
`flash_attn_grad_preload2` 里仅 D=256 场景执行。

Q/dO 只 lag **1** 拍：`q_l1.previous()` 给 MM4，不再要 3 槽 N-2 视图。

## 4. Cube / 片上



### D 切分（编译期表）

- `D_NCHUNKS[256] = 2`，`128+128`（C0=16 对齐）。
- C1/C2：第二块 `matmul_acc` 进同一 acc。
- C3：两块列不相交，各 atomic 出 dq workspace。
- 真实 D=193…255：第二块 `valid_shape` 裁到 `d-128`。



### L1

- `D_PHYS_W[256] = 256`，整头 `pl.load`，再 `pl.move(..., [0, dOff])` 切列
（少改 C1–C3）。
- Q/dO **各 2 槽**（1-ahead）。不做 AscendC 的 `IS_L1_PRELOAD`（拷下一 task 的 Q/dO）。
- 预算：`2+2`×64KB + K + K_ND + V + dS/P ≈ 512KB。



### L0A / L0B

- 按最宽分块 128 列声明：`[128,128] fp16 = 32KB` × 2 = 64KB，双缓冲刚好满。



### L0C（首版）

- **dK/dV 不驻留**：每 task 每 chunk 算完 atomic 出 workspace（C3 同款）。
- acc 可双缓冲 + 一块 scratch。整头 256 列两块同时驻留要 320KB，放不下。

192 的 96+96 + 双块 L0C 驻留不动。

- pre/post 1D 切块复用 192 的 `PRE_ELEMS` / `POST_ELEMS`。

## 7. 实施顺序

1. 契约：host + metadata + tilingkey，现有 675 例 key 不变。
2. `describe_layout(256)` / `audit_mutex(256)` 不超容量。
3. `flash_attn_grad_preload2` 接 D=256 的 1-ahead + pre/post；128+128 + VF256。
4. 冒烟：D=Dv=193 / 200 / 240 / 256；以及 D=192,Dv=128；mask 0/3/4；
  BSND / BNSD；GQA；S 尾块。其余 D≠Dv 应被 host 拒绝。
5. 回归 `fag_test_case_kernel.xlsx` enable True+1（675）。
6. 再谈 L0C 只驻留 Dv、L1 按列两次 load。

首版验收按「GS1S2 + 1-ahead + 总是 128 切 D + 不驻留 dkv」。
不要用 AscendC 短 S 走 BN2 的耗时当对拍基线。
若要和短 S 也对齐分核，那是下一阶段（放宽 BN2 的 D），不在本方案里。

### 8.2 对齐 AscendC D=256 的部分（避免误判成差异）

- GS1S2 长 S / GQA：两边都是 `b·n2·g·s1o·s2o`，s1/s2 base 128。
- D>128 **不用** `ProcessPreloadTwoTimes`（`IS_PRELOAD_TWO_TIMES` 只到 128）。
本方案 256 用 1-ahead，这里与 ASC 一致。
- `IS_L1_PRELOAD` 对 D=256 为假：我们也不做 next-Q 预取。
- 整头 dK+dV 不驻留 L0C：公式上 ASC 也是 false。
- dq/dk/dv 经 fp32 workspace + atomic（`IS_*_WRITE_UB=false` 的 GS1S2）。
- 阶段顺序：MM2→V2/V4，MM1→V3，MM5→MM3→MM4。
- D 切块粒度 128（在「总是切」的前提下与 `SPLIT_BASE_D` 一致）。



### 8.3 原有 PyPTO ↔ AscendC 差异（256 会继承，不是本需求新引入）


| 点              | 说明                                                                                                    |
| -------------- | ----------------------------------------------------------------------------------------------------- |
| D≤128 主循环      | 我们 GS1S2 已是 `PRELOAD_TIMES=3`；ASC 同条件才 `ProcessPreloadTwoTimes`。256 不走这条。                             |
| **D=192 主循环**  | 我们仍是 +2；ASC 192 已是 1-ahead。本需求不改 192。                                                                 |
| D=192 L0C      | 我们 96+96 双块驻留；ASC 整头公式也不驻留，另有 192/Dv=128 特例。                                                          |
| MM4/MM5 转置     | ASC `isLeftTranspose`；我们 vector 侧 NZ / `ds_t` / `p_t`。                                                |
| K 的双视图         | 我们 `tensor_k` 与 `tensor_k_nt` 分开推 layout。                                                             |
| sink / seqused | 接口有，kernel 基本未用；ASC 有 sink 计算。                                                                        |
| dtype / layout | 我们 fp16/bf16、BSND/BNSD（TND 仅 D≤128 档）；ASC 还有 fp32/fp8、BSH/SBH。                                        |
| 注释债            | `fag_kernel.py` 仍写「实现的是 Process 两槽、PreloadTwoTimes 未做」，但 64/128/192 实际是 3 槽。256 才会真正补上两槽 `Process()`。 |




### 8.4 同 shape 时最容易看到的行为差

1. `B, N, S=128, D=256`**（MHA）**：ASC → BN2 单块；我们 → GS1S2（一核也可能只拿到 1 个 128×128 tile），但走 workspace / 1-ahead GS1S2，不是 v5/v6 直出。
2. `S=512, D=256`**（MHA、BN 够大）**：ASC → BN2 MultiBlk；我们仍 GS1S2。
3. `S=64, D=256`：ASC 可能不切 D；我们仍 128+128（第二块 valid 成 128，多一次空/短 K 轴）。
4. **长 S + GQA + D=256**：模板两边都是 GS1S2，差在 L0C（我们不驻留 Dv）和 L1（我们整头 load）。

# 下篇：D>256（≤768，方案）

范围：`D, Dv ∈ (256, 768]`。上篇 D=256 与 64 / 128 / 192 / BN2 **行为不改**。
本篇只扩上限、加 **768 一档**；`256 < D ≤ 768` 都路由到这一档（与 ASC
`GetDTemplateType` 相同）。不设 512 档。

## 9. 目标与原则

- 算法、分核、主循环跟上篇：GS1S2 + `flash_attn_grad_preload2` 1-ahead +
C4/C5 不驻留、atomic 出 workspace。
- **片上放得下优先于整头常驻**。现网 L1 同时铺 Q/dO/K/K_nd/V/dS/P；
`D_PHYS_W` 若跟到 768，一张图会超 512KB（见 §12）。
- 不把大 D 放进 `template==1`，也不放宽 `BN2_MAX_D`。ASC 的 `BN2_MAX_D=512`
对 D=384/512 短 S 可走 BN2，我们继续一律 GS1S2（上篇 A1 的同一条）。
- **档位跟 ASC**：`256 < D ≤ 768` 一律 `d_align=768`，不设 384 / 512
编译档。真实 D 用 `dSize` / `valid_shape` 裁。代价是 D=384 也会按 6 块
展开，后几块 `dW=0` 跳过计算（`next()` 仍按档固定推进）。
- D==Dv 契约不动；不新增 `D≠Dv`。

## 10. AscendC 大 D 在做什么

host `GetDTemplateType`：D∈(256, 768] **一律** `dTemplateType=768`，
没有 384 / 512 kernel 模板。`d` / `d1` 用 tiling 运行值。

| 项 | D=256（ASC） | D=384 / 512（ASC） | D=768（ASC） |
| -- | ------------ | ------------------ | ------------ |
| 模板桶 | 256 | **768** | **768** |
| 分核 | BN2 / MultiBlk / BN2S2 / GS1S2 | 同左（`d≤512`） | **只能 GS1S2** |
| 主循环 | `Process()` 1-ahead | 同左 | 同左 |
| `IS_L1_PRELOAD` / `REUSE` | false / **true** | **false / false** | **false / false** |
| L1 | 专用 q/k/dy/v，跨 S2 复用 | `commonL1Buf` ping-pong，每 mm 现搬 | 同左 |
| C1/C2 | 整头进 L1；D>128 走 `MatmulKMutex`（L0 切 K=128） | 整头 `dSize` 进 L1，同样 K-mutex | 同左；一槽 `128×768×2=192KB`，DB=384KB |
| C3/C4/C5 | `SPLIT_BASE_D=128`；S1/S2>64 才切 | **总是切**；`SPLIT_BASE_D=512` | 同左；`nLoops=2`（512+256） |
| `IS_DKV_RESIDENT_L0C` | false | false | false |
| `IS_DV_RESIDENT_L0C` | true（GS1S2/BN2S2） | **false** | **false** |
| V1 | 整宽 VF≤256 | 运行期按 `dAlignToBlock` 选 VF 384/512/640/768；`sfmgMaxLoopSize=64×128/768` **切行** | 同左 |
| 写出 | GS1S2：fp32 workspace + atomic | 同左 | 同左 |

C3 切 D 时（`!IS_L1_REUSE`）每个 512 列窗口从 GM 再搬 K，再 `MatmulNMutex`
（L0 N 向仍按 128）。fp16 的 `DQ_L0_SPLIT_K` / `DKV_L0_SPLIT_K` 都是 128。

确定性旧路径 `DETER_OLD` 且模板 768 时 `SPLIT_BASE_D=256`。我们继续拒确定性，
不跟这条。

## 11. 路由与契约


| 项 | 取值 |
| -- | --- |
| tilingkey `template` | **0（BN2GS1S2）** |
| `d_align` | 扩到 **3 bit**。取值 `64/128/192/256/768` → 编码 `0/1/2/3/4`（5–7 不用） |
| `dv_align` | 同宽 3 bit；大 D **必须** `d_align==dv_align==768` |

| BN2 | `BN2_MAX_D` 仍 **128**，不编 BN2×768 |
| TND | 与 192/256 相同：**不编** |
| mask | 0 / 3 / 4；`swizzle+mask` **不编** |
| D 与 Dv | 必须相等；唯一例外仍是 D=192 且 Dv=128 |
| 确定性 | 继续拒绝 |
| dtype / layout | 仍 fp16/bf16、BSND/BNSD |


`is_valid`：`d_align==768` 时与 256 同一套剪枝
（`layout==0` 且 `(mask_mode==0 or swizzle==0)`，且 `dv_align==768`）。

分核公式与 metadata / `SetBlockDim` / swizzle 判据沿用 GS1S2，不因大 D
改成一核一头。

入口已有 `d_align<=192 → preload3 else preload2`，768 自然进
preload2，**不必改分发条件**；pre/post 从「仅 256」扩成「`d_align>=256`」。

## 12. 片上为什么不能整头常驻

L1 512KB，现网同时铺 Q(2) + dO(2) + K + K_nd + V + dS + P。
一槽 `128 × W × 2`：

| `D_PHYS_W` | 一槽 | Q+dO 两槽各 2 | 再加上 K+K_nd+V+dS+P | 结论 |
| ---------- | ---- | ------------- | -------------------- | ---- |
| 256（现网） | 64KB | 256KB | 256KB，合计 **512KB** | 刚好 |
| 768 | 192KB | 768KB（或单槽各 1 仍 384KB） | 不够 | **超** |

L0A/L0B 64KB：最宽分块必须停在 **128 列**（`[128,128] fp16=32KB` ×2）。
ASC 整头进 L1 之后，L0 仍按 128 切（`MatmulKMutex` / `MatmulNMutex`）。

L0C 256KB：`128×512×4=256KB` 一块就满。大 D 不能驻留 dK/dV，继续上篇
store 路径。

UB 主图从 `0x21000` 起只剩约 **124KB**。`y+dy` 按 `64 × dv_align × 2`：

| 分配宽 | y+dy | 结论 |
| ------ | ---- | ---- |
| 256（现网） | 64KB | 放下 |
| 768 | 192KB | **超** |

所以大 D **不能**再把 `d_align` 当成 L1/UB 物理宽。这和 `d_align=64` 时
`D_PHYS_W=128` 是同一类：档位是逻辑桶，物理宽另表。

ASC 的解法是丢掉 `IS_L1_REUSE`，只用 `commonL1Buf` 一次装一个整头操作数
（768 时 192KB×2=384KB），C1/C2 整头、C3–C5 按 512 列再搬；V1 按行切开。
我们首版不搬这套 L1 图（改动面大于「256 再开几个窗」），见 §13。

## 13. Cube / 片上（首版）

### 物理约定

| 项 | `d_align=768`（`256 < D ≤ 768` 共用） |
| -- | ------------------------------------- |

| D 窗 | 编译期 **3** 窗；运行期 `ceil(dSize/256)`，空窗 `dW=0` |

| 展开块数 `D_NCHUNKS[768]` | **6** |
| `D_CHUNK_MAXW` / L0 | **128** |
| L0C C4/C5 | 不驻留，`tensor_out=workspace` |
| Q/dO 槽 | 仍 2（task 级 1-ahead） |

真实 D 用 `valid_shape` 裁（例如 D=384 → 6 块里只有前 3 块 `dW>0`；
D=640 → 前 5 块有效；D=768 → 6 块满）。`next()` 次数按 768 档固定，
不随 `dSize` 变。

`d_align=64` 已证明「档位 ≠ 物理宽」。768 档的 `d_align` 只决定
展开次数、host 桶和 VF 趟数，**不**再当 `pl.load` 的整头列数。

### 分块从「最多 2」改成 Python 展开循环

现网 `if D_NCHUNKS>1` 只写得下第二块；再叠 OFF2/W2… 会撞
「Array tuple assignment … has no C++ name」。改成 trace 期
`for i in range(D_NCHUNKS[d_align])`（Python `range`，会展开）：

```
dOff = i * 128
dW   = min(128, dSize - dOff)     # 运行期裁尾
left.next() / right.next()        # 必须在 if dW>0 之外，游标次数按档固定
```

C1/C2：`i==0` 用 `matmul`，其后 `matmul_acc`（D 在 K 轴）。
C3/C4/C5：各块列不相交，每块 atomic 出对应列。

### L1 按窗从 GM 再装

一窗 256 列，和现网 256 的 `pl.load` 同宽。窗与窗之间 Q/K/V/dO **重读 GM**
（`pl.load` 第 4 维加 `winOff`）。

C1/C2 跨窗累加到同一 acc，算完才是完整 S / dP。
C3–C5 各窗写不相交的 dq/dk/dv 列。

C4 不能再假设 `q_l1.previous()` 里是**整头** Q：槽里只有上一 task 的
**最后一窗**。首版 C4/C5 **每窗从 GM 再搬** Q/dO。这与 ASC
`IS_L1_REUSE=false` 时 C3–C5 每块重搬是同一类取舍；D=256 的
`previous()` 复用只留在单窗（256）路径。

`describe_layout(768)` 应与 256 **同字节图**（物理宽相同），只是
kernel 按窗循环多次 `pl.load`。`audit_mutex` 号也不应涨。

### 下一阶段（不在首版）

对齐 ASC C1/C2：丢掉同时常驻的 K/V 专用槽，改 ping-pong `commonL1`
（一槽 `128×d_align`），整头 load + L0 128 切 K。C3–C5 可把窗宽从 256
抬到 512（L1 一窗 128KB，L0 仍 128）。那是少 GM、多改 `fag_mem` /
`fag_buffers` 的性能项，首版正确性不依赖它。

## 14. Vector

- **不要**按 `64×768` 开 y/dy（主图放不下，§12）。
- 工作列宽钉在 **256**（复用现网 y/dy / VF256 分配）。`v1w` 大 D 档 = 256，
不是 `dv_align`。
- V1 按列开窗：768 档固定 **3 趟** VF256；每趟 `colOff=256*k`，
reduce 累加到同一 `sfmg`。`dvSize<=256` 时后两趟 mask 为 0；
`dvSize<=512` 时第三趟为 0。
- 不新开 VF384/512/640/768，也不跟 ASC 按 `sfmgMaxLoopSize` 切行
（64 行 × 256 列现网已放下）。ASC 切行是因为编译期 VF 的 `srcN` 是整头。
- pre/post 仍 1D 切元素，复用 256 的 `PRE_ELEMS` / `POST_ELEMS`。
workspace 字节随 `qSize/kSize/vSize` 涨，host 现有公式不用改形态。

## 15. tilingkey 扩位

现网（上篇，2 bit，**不扩**）：

```
bit[7:6] d_align     0=64, 1=128, 2=192, 3=256
bit[9:8] dv_align    同上
bit10    is_bn2_multiblk
bit11    bn2_need_zero
```

大 D 只再表示 **768**（不设 512）。`d_align` 在 kernel 里当档位键
（`D_NCHUNKS[d_align]`、`if dv_align==256`），继续走「取值即档位」：

```
bit[8:6]  d_align    0=64, 1=128, 2=192, 3=256, 4=768
bit[11:9] dv_align   同上
bit12     is_bn2_multiblk
bit13     bn2_need_zero
```

`AlignBits` / `EncodeTilingKey` / `FlashAttnGradTilingKey` 一起改。
`Tmpl` 仍是普通 int，不改成 IntEnum。

**675 例 key 数值会变**（`d_align` 吃掉原 `dv_align` 的 bit8，BN2 两位后移）。
64/128/192/256 的**语义编码仍是 0/1/2/3**，回归按新编码重编，不能拿旧
key 对拍。BN2 组合只在 D≤128 出现，逻辑不变。

备选（首版不采用）：bit0–11 不动，bit[13:12] 另加 `d_large`。675 key
数值可不变，但 kernel 处处要写
`width = d_large if d_large else d_align`，和「取值即档位」对着干，容易漏。

## 17. 实施顺序

1. 契约：host + metadata + 3 bit tilingkey。先让 D≤256 用新编码编过、
675 例 `is_valid` 仍成立（数值变、组合不变）。
2. `_TIERS` 加 768，`describe_layout` / `audit_mutex` 与 256 同图。
3. cube 展开循环替换「最多 2 块」特写；256 档应 bit-exact 保持。
4. preload2 接 768：按窗 `pl.load`，C4/C5 store；V1 三趟 VF256。
5. 冒烟：D=Dv=257 / 384 / 512 / 640 / 768（同一 768 档）；再加 D=256、
D=192/Dv=128 防回归。mask 0/3/4；BSND / BNSD；GQA；S 尾块。
其余 D≠Dv、D>768 应被拒。
6. 回归 xlsx enable True+1（675，**新 key**）。
7. 再谈 §13 的 commonL1 整头 C1/C2、窗宽 512。

首版验收：「GS1S2 + 1-ahead + 物理窗 256 + 窗内 128 切 + 不驻留 dkv +
V1 复用 VF256」。不要用 ASC 短 S 走 BN2、或 ASC 整头 C1/C2 的耗时当
对拍基线。

## 18. 与当前 AscendC 的不一致（D>256）

上篇 A1–A11（BN2 / BN2S2 / TND / D≠Dv / 确定性 / swizzle+mask）对大 D
**全部继承**。下面只列本篇新引入的。


| # | 点 | AscendC 现在 | 本方案 | 影响 |
| - | -- | ------------ | ------ | ---- |
| B1 | **模板桶** | 257–768 一个 768 | **同样只设 768** | 档位对齐；我们展开固定 6×128，ASC C3 按 `SPLIT_BASE_D=512` |
| B2 | **tilingkey** | `DTemplateNum=768` + `IsDNoEqual` | 3 bit `d_align`/`dv_align` | 675 key 数值重编 |
| B3 | **C1/C2 L1** | 整头进 `commonL1Buf`，L0 `MatmulKMutex` | 首版 **256 列一窗**，跨窗重读 GM，L0 仍 128 | 大 D 的 S/dP 多几次 GM；正确性不差 |
| B4 | **C3–C5 切宽** | `SPLIT_BASE_D=512`，`nLoops=ceil(D/512)` | 固定 6×128，空块 `dW=0` | D=384：ASC mm3 一刀 384；我们 3 块有效 + 3 块空。D=768：ASC 512+256；我们 6×128 |
| B5 | **C4 Q 复用** | `IS_L1_REUSE=false`，每块重搬 | 首版每窗重搬（256 单窗路径仍 `previous()`） | 与 ASC 大 D 同类；比我们自己的 D=256 多 GM |
| B6 | **V1** | 整宽 VF + **切行**（768 约 10 行/趟） | **64 行 × 256 列**，切列多趟 VF256 | UB 策略不同；reduce 趟数我们按 256 列计 |
| B7 | **Dv 独立 / 768 档** | `d1` 可到 768 且可 `d1≠d` | 大 D 必须 D==Dv | ASC 的 GQA-D 我们拒 |
| B8 | **BN2 × D≤512** | 短 S 可 BN2 | 仍只 GS1S2 | 同 A1，D=384/512 短 S 分核图不同 |


### 18.1 对齐 AscendC 的部分（避免误判成差异）

- D>128 走 `Process()` 1-ahead，不走 `ProcessPreloadTwoTimes`。
- 大 D：`IS_DKV_RESIDENT_L0C=false`，`IS_DV_RESIDENT_L0C=false`；我们也不驻留。
- GS1S2 长 S / GQA：`b·n2·g·s1o·s2o`，base 128。
- L0 最宽 128（ASC 的 K/N mutex 粒度与我们 `_mm_*_chunk` 相同）。
- dq/dk/dv 经 fp32 workspace + atomic。
- 阶段顺序：MM2→V2/V4，MM1→V1/V3，MM5→MM3→MM4。
- `IS_L1_PRELOAD` 对模板 768 为假：我们也不做 next-task Q 预取。


### 18.2 同 shape 时最容易看到的行为差

1. `S=128, D=384`（MHA）：ASC 可 BN2；我们 GS1S2。两边都是 768 档。
ASC C1/C2 整头一次、C3 一刀 384；我们三窗展开里只有前两窗（3 块）有效。
2. `S=128, D=512`（MHA）：同上，ASC 仍可能 BN2；C3 `nLoops=1`（刚好 512）。
我们 4 块有效 + 2 块空。
3. `S` 很长、`D=768`：两边都是 GS1S2 1-ahead、不驻留 L0C、同一 768 档。
差在我们 C1/C2 三窗重读、C3 六块 128；ASC 整头 C1/C2 + C3 两块 512。
4. `D=640`：两边 768 档；我们 5 块有效；ASC C3 的 512+128。
5. 任意 `D≠Dv`（除 192/128）：我们 host 拒，ASC 能跑。
