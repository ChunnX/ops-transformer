A5 FIA MXFullQuant 特殊 BAND 模式改动说明

面向 arch35/fia_kernel_fullquant_mx.h 的 DN + BAND + global/local sparse 实现梳理

global window = KV 前 4 列 local window = 原 BAND pre/next 语义 S2 union 调度 gap 跳过 global-only tile 收缩

1. 功能目标

当前特殊 BAND 模式是在原有 sparseMode == BAND 的 local window 基础上，额外把 KV 的前 4 个 token 作为 global window 纳入 attention 计算。最终有效 S2 范围可以理解为： 

valid_s2 = local_band_s2_range UNION global_prefix_s2_range

global_prefix_s2_range = [0, min(4, actual_seq_kv))
local_band_s2_range    = 原 BAND 根据 preTokens / nextTokens 算出的范围
当前实现边界： global 前 4 列是在 local BAND 行有效的基础上叠加的。若当前 S1 block 的 local BAND 已整体判空， kernel 会直接跳过该 S1 block，不会单独用 global prefix 把整行重新激活。这一点与当前 actual_seq_q=4096, actual_seq_kv=2048 场景的修复保持一致。

2. 触发条件与行为变化

触发条件

USE_DN && HAS_MASK && sparseMode == BAND

判断函数在 IsBandGlobalLocalSparse()。

global 固定大小

BAND_GLOBAL_WINDOW_SIZE = 4U

kernel 和 vector 侧各有一个同名常量。

local 窗口来源

继续使用原 BAND 的 preTokens / nextTokens。

例如最近 1024 通常配置 preTokens=1023、nextTokens=0。

项目 原普通 BAND 当前特殊 BAND
S2 有效范围 单段 local BAND 范围 local BAND 范围 + KV 前 4 列 global 范围
S2 调度 连续 [curS2Start, curS2End) 支持 global段 + local段，中间 gap 直接跳过
global-only 块 不存在 只计算前 4 列，避免整块 512 列被计算
mask 行为 由原 BAND pre/next 共同裁剪 block0 内会恢复 global 前 4 列为可见
整行无效 local 范围为空则跳过 当前仍以 local 有效性作为 S1 block 是否参与的前提

5. Host 分核实现

当前 host 侧在 SplitCore() 中为 BAND prefill 增加了简单分核路径：按有效 S1G 行均分， 不做 S2 方向拆分。每个 core 的结束元数据写入 bN2End/mEnd/s2End，其中 s2End[i] = 0U 表示不在 host 侧做 S2 tail 裁剪，S2 的真实 sparse 范围由 kernel 侧按行计算。 

// split_core_v2.cpp
if (mode == SparseMode::BAND && s1Size0 >= param.mBaseSize) {
    ...
    auto s2Range = CalcS2Range(s1GIdx, baseInfo, param, bCache);
    if (s2Range.second > s2Range.first) {
        validStart = s1GIdx;
        break;
    }
    ...
    result.s2End[i] = 0U;
}
为什么 host 不拆 S2： 特殊 BAND 的 S2 是两段 union，host 元数据只有一个 s2End，不适合直接表达两段区间。 当前方案把 S2 两段调度放在 kernel 内部处理，host 只负责把 S1G 行范围分给 core。

5.1 Host 有效行切分图

host 的 BAND 简单分核仍然以 local BAND 是否有效作为“这行是否值得分核”的判断标准。它先从 s1GIdx=0 开始调用 CalcS2Range()，找到第一个 s2End > s2Start 的行，记为 validStart。后续只把 [validStart, s1GBaseNum) 这些有效行均分给 core。

6. Kernel S2 Range 计算

6.1 原 BAND local 范围

在 CalcCurS2StartEndWithSparse() 中，先按原 BAND 计算 local 范围： 

s2FirstToken = s1FirstToken - preTokenLeftUp;
s2LastToken  = s1LastToken  + nextTokenLeftUp;

localS2RangeValid = !(s2FirstToken >= actSeqLensKv ||
                      s2LastToken < 0 ||
                      s2LastToken < s2FirstToken);

当前实现如果 localS2RangeValid == false，会直接设置 curS2Start=0、 curS2End=0 并返回。这保证了 S1 > S2 场景中前面整行无效的 Q block 不会被 global prefix 误激活。

6.2 叠加 global 前缀

当 local 有效且命中特殊 BAND 条件时，kernel 额外构造 global 范围： 

globalTokenEnd = min(4, actSeqLensKv);
globalS2Start  = 0;
globalS2End    = ceil(globalTokenEnd / s2BaseSize);

local 和 global 都会经过 core 边界裁剪： 

ClipSparseS2Range(globalS2Start, globalS2End, clipStart, clipEnd);
ClipSparseS2Range(localS2Start,  localS2End,  clipStart, clipEnd);
S2 轴
global 前 4 列 gap，调度跳过 local BAND 窗口

6.3 公式和区间图解

特殊 BAND 的核心不是重新定义一个新的 sparseMode，而是在原 BAND local 区间的计算结果上追加一个 global prefix 区间。下面用公式和图形把这两个区间的来源拆开。

local BAND 区间

preLeftUp  = actQ - actKV + preTokens
nextLeftUp = actKV - actQ + nextTokens

s2FirstToken = s1FirstToken - preLeftUp
s2LastToken  = s1LastToken  + nextLeftUp

若 s2FirstToken >= actKV、s2LastToken < 0 或 s2LastToken < s2FirstToken，当前 S1 block 的 local BAND 为空。

global prefix 区间

globalTokenStart = 0
globalTokenEnd   = min(4, actKV)

globalS2Start = 0
globalS2End   = ceil(globalTokenEnd / s2BaseSize)

当前代码中，global prefix 只在 local BAND 有效时叠加。local 为空时该 S1 block 直接跳过。

判断点 代码结果 设计意图
localS2RangeValid == false curS2Start=0; curS2End=0; return; 整行 local 无效时跳过计算，避免 Q>KV 前置无效行产生非 0 输出。
localS2RangeValid == true 计算 local block 区间，并可继续叠加 global。 保留原 BAND 的有效行语义。
actKV > 0 && BAND_GLOBAL_WINDOW_SIZE > 0 构造 [0, ceil(4 / s2BaseSize))。 把 KV 前 4 列作为 global window。
global/local 均被 core 边界裁空 curS2Start=0; curS2End=0; return; 当前 core 在该行没有有效 S2 任务。

7. Scheduler 如何跳过 gap

新增了三组调度状态：

变量 含义
globalS2Start/globalS2End global 前缀所在的 S2 block 区间。
localS2Start/localS2End 原 BAND local window 所在的 S2 block 区间。
nextS2Start 当前 s2Cur 落在 gap 时，下一次应该跳到的有效 S2 block。

在 GetTaskDealMode() 中，如果 s2Cur 不在 global/local 任一段内， 会返回 NOT_START，并把 nextS2Start 设置为下一段起点： 

if (IsBandGlobalLocalSparse() && !IsCurS2InSparseRange(s2Cur)) {
    nextS2Start = GetNextSparseS2Start(s2Cur);
    return TASK_DEAL_MODE::NOT_START;
}

随后 UpdateAxisInfo() 使用 nextS2Start 更新 s2Cur，实现 gap 跳过： 

if (taskDealMode == TASK_DEAL_MODE::NOT_START) {
    s2Cur = nextS2Start;
    return;
}

8. RunInfo 新增标记与 global-only 收缩

RunInfoX 新增 isBandGlobalOnlyS2Loop，表示当前 S2 block 只属于 global 段， 不属于 local 段。 

bool isBandGlobalOnlyS2Loop = false;

在 CalcParams() 中，如果当前任务是 global-only，则把本轮 S2 实际处理长度收缩到 min(4, actS2Size)： 

if (info.isBandGlobalOnlyS2Loop) {
    uint32_t globalTokenEnd = Min(BAND_GLOBAL_WINDOW_SIZE, static_cast<uint32_t>(info.actS2Size));
    info.actSingleLoopS2Size = globalTokenEnd - info.s2Idx;
}
效果： BMM1 拷 K、BMM2 拷 V、Vec softmax 都依赖 runInfo.actSingleLoopS2Size。 因此 global-only 的 block0 不会计算整个 512 列，只处理真实 global 的 4 列。

8.1 RunInfo 生命周期

RunInfoX 是 scheduler 到 cube/vector 的任务描述。特殊 BAND 没有新增一套任务类型， 而是在现有 RunInfoX 中补了一个标记，并复用原有坐标字段来约束数据搬运、mask 和 softmax。

1. scheduler 确定任务坐标

bN2Cur/gS1Cur/s2Cur 来自 core 起止边界和 S2 内层循环。

2. range 生成两段 sparse

global/local/cur/next 几组 S2 区间在当前行缓存。

3. CalcParams 写入 RunInfo

把 block 坐标转成 token 偏移，并判断是否 global-only。

4. consume 后续模块消费

BMM 用坐标搬 K/V，Vec 用标记修 mask，RowInvalid 用 left-up 边界清行。

bIdx/n2Idx/realN2Idx

由 bN2Cur 拆出来，定位 batch、N2、真实 N2。它决定读取哪一个 batch 的 actSeqLensQ/KV，也决定 K/V tensor-list 切 batch 时是否要换基地址。

gS1Idx/s1Idx

gS1Idx = gS1Cur * mBaseSize，是带 G 后的 M 方向起点； s1Idx 是真实 Q token 起点。local BAND 的 token 窗口就是以它为基准推导。

s2Idx

s2Idx = s2Cur * s2BaseSize，直接控制 BMM1 拷 K、BMM2 拷 V 的列偏移。 对 global-only 来说，它必须落在 block0，随后长度被收缩到 4。

actS1Size/actS2Size

当前 batch 的真实 Q/KV 长度。它们参与 local range 越界判断、S1/S2 tail 裁剪，以及 min(4, actS2Size) 的 global 长度保护。

actMSize

当前 S1G tile 在 M 方向的真实处理长度。尾块不满 mBaseSize 时会缩短， 后续 Vec 的 M 方向循环和 RowInvalid 都依赖它。

actSingleLoopS2Size

当前 S2 tile 的真实列数。普通 tile 是 s2BaseSize 或 KV tail； global-only tile 被改成 globalTokenEnd - s2Idx。

isFirstS2Loop/isLastS2Loop

控制 softmax streaming 的初始化和收尾。gap 被跳过时不会产生任务，所以 global 段之后的 local 段仍然接在同一行的 softmax 累积链路上。

isS2SplitCore

表示是否处在 S2 跨 core 切分场景。当前 BAND 简单分核把 s2End=0， S2 sparse 主要由 kernel 内部 range 管理。

preTokensLeftUp/nextTokensLeftUp

由 GetPreNextTokenLeftUp() 计算。local BAND、RowInvalid、DN mask 的 pre/next 方向判断都要用它。

RunInfo 字段 写入位置 特殊 BAND 中的关键影响
isBandGlobalOnlyS2Loop CalcParams() global block 与 local block 不重叠时置 true，触发 S2 长度收缩和 mask 跳过。
actSingleLoopS2Size CalcParams() global-only 时只让前 4 列进入 BMM/Vec，避免 block0 的剩余列被误算。
preTokensLeftUp/nextTokensLeftUp CalcParams() 传给 vector 侧做 mask/RowInvalid，保证 global 只解除 pre-left 屏蔽，不解除 next/causal 整行无效。

9. Vector Mask 与 RowInvalid

9.1 global-only tile

对 global-only tile，vector mask copy 直接标记为跳过 mask： 

if (runInfo.isBandGlobalOnlyS2Loop) {
    isSkipMask = true;
    return;
}

因为此时实际只计算 global 前 4 列，旧 BAND pre-mask 不应该再把它们遮掉。

9.2 block0 混合 global/local

当 block0 同时含 global 和 local 时，旧 BAND mask merge 后，前 4 列会被恢复为可见： 

if (constInfo.sparseMode == static_cast<uint32_t>(BAND) &&
    runInfo.s2Idx == 0U && subLoop == 0U && isSkipMaskForNext) {
    uint32_t globalKeepSize = Min(BAND_GLOBAL_WINDOW_SIZE, maskInfo.s2dealNum) *
                              (maskInfo.gs1dealNum >> 1);
    Duplicate(attenMaskUb, static_cast<uint8_t>(1U), globalKeepSize);
}

9.3 RowInvalid

RowInvalid() 中，DN + BAND 下把 s1LastValidToken 放宽到 actS1Size，避免 pre/local-left 边界把已经有 global 可看的行清掉。 但 s1FirstValidToken 仍由 nextTokensLeftUp 控制，因此 next/causal 方向的整行无效仍然保留。 

s1FirstValidToken = min(max(-nextTokensLeftUp, 0), actS1Size);
s1LastValidToken  = min(max(preTokensLeftUp + actS2Size, 0), actS1Size);

if (USE_DN && sparseMode == BAND && actS2Size > 0) {
    s1LastValidToken = actS1Size;
}

9.4 Mask 处理决策图

vector 侧的改动可以按下面三种 tile 来理解。核心原则是：global 前 4 列要可见，但不能把 padding、 next/causal 方向的整行无效也恢复出来。

global-only tile

isBandGlobalOnlyS2Loop == true

直接跳过 atten mask copy。因为这一轮真实 S2 长度已经被收缩到前 4 列，再套旧 BAND pre-mask 会把本来要保留的 global 列屏蔽掉。

block0 混合 tile

s2Idx == 0 && local overlaps block0

先走原 DN/BAND mask merge，再用 Duplicate(..., 1, globalKeepSize) 把前 4 列恢复为 keep。

local-only tile

s2Idx in local range only

完全沿用原 BAND mask 和 softmax 更新逻辑；global 改动不影响该 tile 的 mask 语义。

保护点 代码位置 为什么需要
local 为空直接跳过 CalcCurS2StartEndWithSparse() 避免 actual_seq_q > actual_seq_kv 前置无效行被 global 前 4 列激活。
global-only 缩列 CalcParams() 避免 block0 里除前 4 token 外的列参与 BMM/softmax。
RowInvalid 保留 next 边界 RowInvalid() global 只修复 pre-left，不改变 next/causal 和 padding 的无效行判断。

10. Golden 与测试侧对齐

Python golden 中新增 GLOBAL_WINDOW_SIZE = 4，并在 BAND mask 构造时，让 global 前缀绕过 pre_mask： 

if sparse_mode == 4:
    delta = k_lens_acl - q_lens_acl
    next_mask = k_range > (q_range + delta + next_tokens)
    pre_mask  = k_range < (q_range + delta - pre_tokens)
    if global_window_size > 0:
        global_keep = k_range < global_window_size
        pre_mask = pre_mask & (~global_keep)
    return next_mask | pre_mask | q_padding_mask | k_padding_mask

run_batch_test.py 中 case 可显式设置 global_window_size；若未设置， 继承 golden 模块默认值。

12. 当前实现的注意点

普通 BAND 影响： 当前触发条件是 USE_DN && HAS_MASK && sparseMode == BAND，没有单独的运行时开关。 因此 DN + mask + BAND 默认都会走特殊 BAND 逻辑。若后续需要同时保留普通 BAND，建议在 tiling/constInfo 中增加 bandGlobalWindowSize，只有大于 0 时才启用本逻辑。
global 的激活边界： 当前代码中 local BAND 范围为空时会直接跳过当前 S1 block。也就是说 global 前 4 列不会作为独立兜底窗口 去激活 local 已判空的整行。这是当前通过 Q > KV 无效行 case 的关键策略。
性能侧收益： host 不拆 S2，kernel 内部跳 gap；global-only tile 只算 4 列。这避免了把 [globalEnd, localStart) 中间空洞全部跑一遍。
