# `block_sparse_attention` benchmark

`benchmark.py` is a head-to-head latency benchmark for the
`attention/block_sparse_attention` kernel against an `npu_fusion_attention` dense
reference. All workload generators (`gen_pfa_inputs`, `create_attention_mask`,
`sabi_to_block_sparse_mask`, frame/sparsity policy, timing harness) live in
the sibling `util.py` so this directory ships as a fully self-contained
feature — no cross-tree imports, no `sys.path` patching.

The output table format matches BSA's `benchmark.py` line-by-line so results
are directly comparable when both are run on the same workload.

## What the table measures

- **Workload**: `B=1, H=3, S_q=S_kv=118 806, D=128`, BF16, BNSD layout. Random
  Q/K/V tensors; per-row block-level sparsity pattern generated by the
  `blocks_optimized_batched` policy with `FrameWidths(29,1,29,1)` by default
  (matches BSA's standard test config).
- **Each row**: a different sparsity level (fraction of KV blocks dropped per
  Q tile). The frame forces a minimum density, so high sparsities can become
  infeasible — those rows print `INFEASIBLE`.
- **Timing**: `N_REPEATS=10`, `N_WARMUP=2` runs per sparsity, latency averaged
  with `torch.npu.Event`.
- **Correctness column** (`Outputs_equal`): only computed at sparsity 0 by
  default (force-dense reference path). Set `RUN_REFERENCE = True` in the
  script to enable per-sparsity correctness comparison; the full dense
  `[B, H, S, S]` reference mask costs ~42 GB and OOMs at this S — see
  `attention/block_sparse_attention/tests/pytest/` (`test_attn.py`, `test_lse.py`,
  `test_joint.py`) for a smaller-S pytest correctness suite.

## Prerequisites

1. The `block_sparse_attention` kernel + aclnn library must be built and
   installed into `$ASCEND_OPP_PATH/vendors/custom_transformer/op_api/`:
   ```bash
   bash build.sh --make_clean -j96 --pkg --soc=ascend910b --ops=block_sparse_attention
   ./build/cann-ops-transformer-custom_linux-aarch64.run
   ```
2. The `npu_ops_transformer` torch extension must be built + installed
   (it provides the JIT-compiled Python entry point
   `npu_ops_transformer.ops.block_sparse_attention`):
   ```bash
   cd torch_extension
   python3 -m pip install -r requirements.txt
   python3 -m build --wheel -n
   python3 -m pip install dist/*.whl --force-reinstall --no-deps
   ```
   First `import npu_ops_transformer` triggers a one-time ninja JIT compile
   of the C++ wrapper (`ops/csrc/block_sparse_attention.cpp`). See
   [`torch_extension/README.md`](../../../torch_extension/README.md) for full
   build instructions.

## Running

```bash
cd attention/block_sparse_attention/benchmark

# Default — KV block size 128, BSA-default frame
ASCEND_RT_VISIBLE_DEVICES=5 python benchmark.py

# Override KV block size (Q block stays 128); token-matched frame for fair comparison
ASCEND_RT_VISIBLE_DEVICES=5 BSA_BLOCK_SIZE_KV=512 BSA_FRAME=8,1,29,1 python benchmark.py
```

Defaults — shape (`B`/`H`/`S`/`D`), sparsity sweep, `FRAME`, `BLOCK_SIZE_Q`,
`BLOCK_SIZE_KV`, dtype, layout — are defined at the top of `util.py`
in this directory. To change them, edit `util.py` (or override at
the env-var level — see the "Environment variables" section below).

### Run 2 — `block_shape=[128, 512]` (coarser KV granularity, token-matched frame)

KV block size = 512 means each frame "column" covers 4× more KV tokens than at
128×128. To keep the LEFT-frame coverage roughly token-matched
(`29*128 = 3712` vs `8*512 = 4096`), the frame is set to
`FrameWidths(8, 1, 29, 1)` for this run via the `BSA_FRAME` env var.
(`top_rows`/`bottom_rows` are Q-axis blocks at fixed 128, so they don't
scale.) This also brings the minimum forced density down enough to make

## File layout (autonomous, no cross-tree imports)

| File | Purpose |
|---|---|
| `benchmark.py` | The benchmark entry point. Builds the per-row sparse pattern, converts sabi → int8 block mask, times `npu_ops_transformer.ops.block_sparse_attention(…)` over the sparsity sweep, prints the table. |
| `util.py` | All shared helpers — `FrameWidths`, constants (`B_VALS, H_VALS, S_VALS, D_VALS, SPARSITY_VALS, BLOCK_SIZE_Q, BLOCK_SIZE_KV, FRAME, …`), pattern generators (`generate_sparse_blocks_by_row{,_per_head}`, `make_block_mask{,_per_head}`), reference implementations (`ref_attention_fp32`, `ref_attention_launcher`), timing harness (`_run_timed`, `_check_correctness`), and the sabi→int8 mask converter (`sabi_to_block_sparse_mask`). |
| `README.md` | This file. |

The `tests/pytest/` sibling directory imports from this `util.py` via a
local `sys.path.insert(0, ../benchmark)` — that's the only intra-package
path manipulation. **Nothing imports from `experimental/`.**

## What this shows

1. **block_sparse_attention beats BSA at every sparsity**, with the biggest
   wins at the high-sparsity priority window (0.5–0.9): **1.5×–1.8×** faster.
2. **KV block granularity (128 vs 512) has near-zero effect on latency** for
   block_sparse_attention. The two runs are within ~1% across the board.
   The kernel's compute time is proportional to the count of KEPT tokens, not
   to the block count — `block_shape` only determines mask resolution and the
   gather stride in `BlockMmadQK::operator()` ([block_mmad_qk.hpp:177-227](../op_kernel/attn_infra/gemm/block/block_mmad_qk.hpp#L177-L227)).
3. **Why no 128×512 speedup like BSA had?** BSA was reportedly 1.89× faster
   at 128×512 vs 128×128 (an open TODO in BSA's own documentation). That
   speedup was specific to BSA's matmul-library cube tiling (128×128 cube
   tile vs 128×512 cube tile). The
   CATLASS template stack in `block_sparse_attention` decouples the
   sparsity-granularity from the cube-tile shape: `L1TileShape::N` and
   `L0TileShape::N` are fixed (CATLASS template params), and gather
   bookkeeping just iterates more or fewer mask cells. So changing
   block granularity doesn't shrink/grow the cube work.
4. **Frame scaling matters with block granularity.** With the BSA default
   `FrameWidths(29,1,29,1)` at 128×512 (232 kv blocks total), the frame
   forces ≥24% density and sparsity > 0.76 becomes infeasible. Scaling LEFT
   frame to `8` blocks (the token-matched value) drops min density to
   ~7%, restoring sparsity 0.9. The `BSA_FRAME` env var (`left,right,top,bottom`)
   controls this — top/bottom are Q-axis (fixed 128) and don't scale.

## Environment variables

- `ASCEND_RT_VISIBLE_DEVICES` — pick the NPU (commonly `5` on this machine).
- `BSA_BLOCK_SIZE_KV` — override `BLOCK_SIZE_KV` (default `128`). Affects
  both the mask shape passed to the kernel and the `block_shape` value.
  `BLOCK_SIZE_Q` is currently NOT overridable (the mask generator hardcodes
  it to 128).
- `BSA_FRAME` — override `FrameWidths` as `left,right,top,bottom` (block
  units, e.g. `BSA_FRAME=8,1,29,1`). Default is `FrameWidths(29,1,29,1)`.
  Useful for keeping token-coverage matched across different `BSA_BLOCK_SIZE_KV`
  runs, and for avoiding infeasibility at high sparsity + coarse KV granularity.

## Notes on the comparison

- `block_sparse_attention` is called with `atten_mask=None`. The kernel does
  not support fine-grained intra-block masking on CANN 8.5.0-beta.1, so the
  block-level mask is the only sparsity vehicle. BSA's `bsa_atten_mask`
  (per-position bool) is NOT forwarded.
- At `sparsity = 0`, `block_sparse_attention` receives an all-ones mask
  (dense). The reference is forced to dense mode too. Both produce true dense
  attention, so the correctness column reads `yes`.
- At `sparsity > 0`, the correctness column reads `N/A` because
  `RUN_REFERENCE = False` (the dense reference mask would be ~42 GB at this
  S). For correctness verification at a smaller S (24 000), run the pytest
  suite in `../test/` (`test_attn.py` for attention output vs PFA,
  `test_lse.py` for LSE vs FIAS / Python float32 reference, `test_joint.py`
  for both outputs from a single kernel call).

## Re-running these exact tables

```bash
# Set up env
export ASCEND_RT_VISIBLE_DEVICES=5

# 128x128 row (default frame FrameWidths(29,1,29,1))
python benchmark.py

# 128x512 row with token-matched frame FrameWidths(8,1,29,1)
BSA_BLOCK_SIZE_KV=512 BSA_FRAME=8,1,29,1 python benchmark.py
```

The published numbers will vary by a few percent per re-run due to NPU
clock/scheduling variance; the relative ordering across sparsities is stable.
