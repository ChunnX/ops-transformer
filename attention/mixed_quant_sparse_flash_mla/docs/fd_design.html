1. Flash Decode 原理与数学推导

1.1 标准注意力公式

对于查询向量 q ∈ ℝd 和键/值序列 K ∈ ℝs₂×d, V ∈ ℝs₂×d, 注意力输出为:

O = softmax( qKT / √d ) · V

展开元素级别，令 sk = q · kk / √d 表示位置 k 的缩放点积分数:

O = Σk=0..s₂-1 exp(sk − m) · vk / Σk=0..s₂-1 exp(sk − m)

其中 m = maxk sk 为全局最大分数，用于数值稳定性（加减常数在分子分母间抵消）。

1.2 Online Flash Softmax (单核迭代)

当 KV 序列分块迭代处理时（如 FlashAttention），softmax 统计量需增量累积。第 j 次迭代产生:

  • m(j): 已见分数的运行最大值
  • ℓ(j): Σ exp(sk − m(j)) 的运行求和
  • O(j): Σ exp(sk − m(j)) · vk 的运行加权求和
1
更新全局最大值: m(j) = max(m(j-1), m̃j)
2
计算修正因子: α = exp(m(j-1) − m(j)), 当 m(j) > m(j-1) 时 α < 1, 无溢出风险
3
更新运行求和: ℓ(j) = α · ℓ(j-1) + Σk∈tile_j exp(sk − m(j))
4
更新运行输出: O(j) = α · O(j-1) + Σk∈tile_j exp(sk − m(j)) · vk
5
最终归一化: Ofinal = O(J) / ℓ(J)

正确性证明: 处理所有 tile 后, m(J) = m (全局最大), ℓ(J) = Σ exp(sk − m), O(J) = Σ exp(sk − m) · vk, 因此 O(J)/ℓ(J) = softmax(qKT/√d) · V。

1.3 Flash Decode: 多核分解推导

这是 FD 的核心推导。当 s₂ 被切分到 N 个核并行计算时, 如何从各核的 partial 结果恢复全局注意力输出。

Split 定义

核 i 处理 KV 范围 Ri = [starti, endi), 步长 128。各 split 互不重叠且覆盖完整序列。

各核 Partial 计算

partial_maxi = maxk∈Ri sk
partial_sumi = Σk∈Ri exp(sk − partial_maxi)
partial_Oi = Σk∈Ri exp(sk − partial_maxi) · vk   未归一化

关键: partial_Oi 是未归一化的加权求和 — 不除以 partial_sumi。各核使用自己的局部最大值作为参考点。

全局规约推导

3.1
定义全局最大值:
global_max = maxi partial_maxi = maxk=0..s₂-1 sk = m
3.2
推导修正因子: 对 k ∈ Ri:
exp(sk − global_max) = exp(sk − partial_maxi) · exp(partial_maxi − global_max)
定义 correctioni = exp(partial_maxi − global_max)
3.3
推导全局求和:
global_sum = Σi correctioni · partial_sumi
global_sum = Σi=0..N-1 exp(partial_maxi − global_max) · partial_sumi
3.4
推导全局输出:
global_O = Σi correctioni · partial_Oi
global_O = Σi=0..N-1 exp(partial_maxi − global_max) · partial_Oi
3.5
最终归一化:
final_O = global_O / global_sum

等价性验证: 由构造可得 final_O = softmax(qKT/√d) · V, 与完整序列计算结果数学等价（除浮点舍入误差）。

1.4 LSE (Log-Sum-Exp) 输出

LSE 用于下游自回归推理（如 KV cache 合并）。定义:

lse = log Σk=0..s₂-1 exp(sk)

从全局规约结果推导:

lse = log[ exp(global_max) · Σ exp(sk − global_max) ]
= global_max + log( Σ exp(sk − global_max) )
= global_max + log(global_sum)
lse = global_max + log(global_sum)

注: 分数 sk 已包含 softmax_scale（vec1 中 Muls 已应用），因此 partial_max/sum/O 均反映缩放后的分数，无需额外缩放修正。

1.5 数值稳定性分析

修正因子边界

对任意 split i: partial_maxi ≤ global_max, 因此:

0 < correctioni = exp(partial_maxi − global_max) ≤ 1

无溢出保证

  • correctioni · partial_sumi 和 correctioni · partial_Oi 均 ≤ 原始 partial 值
  • 全局规约仅涉及 ≤1 的乘法和加法 — 无指数增长
  • 包含全局最大值的 split: correction = 1；远离全局最大的 split: correction 可能趋近 0，天然剪枝低分位置

FP32 精度保障

  • partial_sum/partial_O 在 FP32 累积（vec1/vec2 阶段）
  • correction 在 FP32 计算: exp(partial_max − global_max), 参数 ≤ 0, 结果 ∈ (0, 1]
  • 全局规约在 FP32 累积，最终除法后可选 Cast 到输出 dtype

2. 当前算子现状分析

2.1 当前流水线流程

task[N]Bmm1: Q·KT → UB (Fixpipe)V0: KV 反量化 FP8→BF16, 输出到 L1 (或 GM)

3. FD 改造方案设计

3.1 总览与对比

FA (当前)

  • 单核覆盖 所有 s₂ 循环
  • Online softmax 跨 s₂ 迭代累积
  • Vec2: FlashUpdateLast + LastDiv + 直接输出
  • 输出直接写 attentionOutGm
  • LSE: 未输出

FD (改造后)

  • 多核各覆盖 一个 s₂ split (128 tokens)
  • Partial online softmax; 全局跨核规约
  • Vec2: FlashUpdateLastNoDiv + 拷出 partial O
  • 规约核写入 attentionOutGm
  • LSE: global_max + log(global_sum)

3.2 多核切分策略

s₂ 维度 (kvSeqLen) 被切分为 N = ceil(kvSeqLen / 128) 个 split, 每个 AIV 核组处理一个 split, 通过 FD metadata 传入计算范围。

切分示例 (kvSeqLen=640, batch=2, head=128):

// kvSeqLen=640 → N = ceil(640/128) = 5 splits
// (b=0, h=0): 5 splits → 5 AIV cores (core 0..4), core 0 是规约核
// (b=0, h=1): 5 splits → 5 AIV cores (core 5..9), core 5 是规约核
// 总计: batch * n2 * g * N AIV 核; 上限 72 核

3.3 Vec1 修改: 拷出 max+sum 到 GM

MODIFIED ProcessVec1 — 在最后一个 s₂ 循环后, 拷出 partial softmax 状态到 GM workspace:

1
现有 softmax 流程完全保留 (ProcessVec1Vf, SFAUpdateExpSumAndExpMax, DataCopy to L1)
2
新增: 最后 s₂ 循环 (s2LoopCount == s2LoopLimit) 后:
• DataCopy(lseWorkspaceGm + maxOffset, softmaxMaxBuf, s1LocalSize)
• DataCopy(lseWorkspaceGm + sumOffset, softmaxSumBuf, s1LocalSize)
3
Workspace 布局: 每个 split 存储 [max (s₁ fp32)] + [sum (s₁ fp32)], 偏移由 FD metadata 的 workspaceIdx 决定

3.4 Vec2 修改: 拷出 partial O + 规约

MODIFIED ProcessVec2 — 分为两个阶段:

阶段 1: Partial 计算 (所有 FD 核)

  • 中间迭代: 不变 (FlashUpdateNew — 含修正但无除法)
  • 最后迭代: NEW 使用 FlashUpdateLastNoDiv — 跳过 LastDiv, 保留 partial O 未归一化
  • 拷出 partial O 到 GM: DataCopyPad(partialOWorkspaceGm + oOffset, vec2ResUb, ...)

阶段 2: 规约 (仅规约核)

  • 全局 barrier: GM polling (非 CrossCoreSetFlag — 该 API 仅支持核组内 AIC↔AIV 配对同步)
  • 规约核读取所有 partial max+sum+O, 计算全局结果
  • 非规约核: barrier 后直接退出

3.5 规约阶段详细设计

NEW ProcessFdReduction — 仅规约核执行:

1
找到全局最大值: global_max = max(partial_max₀, ..., partial_maxN-1)
从 lseWorkspaceGm 逐 split 读入, 用 Max API 做元素级 max
2
计算修正因子和全局求和:
correctioni = exp(partial_maxi − global_max)
global_sum = Σ correctioni · partial_sumi
使用 Sub+Exp+Mul+Add 基础矢量 API
3
累积修正后的 partial O:
global_O = Σ correctioni · partial_Oi
correction 从 [s₁] 广播到 [s₁, d] — 使用 DIST_BRC_B32 VF 加载模式
4
归一化: final_O = global_O / global_sum, 使用 LastDivNew (global_sum 广播到 d 维度)
5
输出: Cast(bf16) → attentionOutGm; lse = global_max + log(global_sum) → softmaxLseGm

3.8 跨核同步设计

重要: CrossCoreSetFlag/CrossCoreWaitFlag 仅支持核组内 AIC↔AIV 配对同步, 不能跨核组全局 barrier。FD 需要跨核组同步, 必须使用GM polling 机制。

两级同步

L1
计算-规约 Barrier (GM polling):
• 各计算核完成 partial 计算后, 在 fdCompletionGm 写入完成标志 (uint32 值 = 1)
• 规约核 polling fdCompletionGm 的对应位置, 等所有 numSplits 个标志就绪
• fdCompletionGm 布局: [numSplits] uint32 值, 由 FD metadata 的 completionOffset 索引
• 优势: 简单可靠, 无需额外硬件同步 API; 劣势: polling 有微小延迟
L2
规约-输出: 规约核独占写入各自的 attentionOutGm 区域, 无需额外同步
每个 (b,h) 的输出到独立内存区域, 无重叠

AIC-AIV 协调

FD 模式下 AIC 侧最小修改: 每个 AIC 核处理其分配的 s₂ split (而非完整 s₂)。现有 CrossCoreSetFlag<0, PIPE_MTE3>(15) 模式复用 (这是核组内配对同步, 不受全局 barrier 限制)。AIC 完成 Bmm1/Bmm2 后退出。

3.9 边界情况处理

边界情况处理策略
尾部 split (s₂RealSize < 128)复用现有 ComputeBmm1Tail 逻辑; FD metadata 中的 s2LoopLimit 限制迭代次数
单 split (kvSeqLen ≤ 128)FD 退化为 FA: 单核既是计算核又是规约核, 直接 LastDiv + 输出, 跳过 GM workspace 和规约
空核 (coreEnable = 0)未分配的核跳过所有处理 (同当前 FA)
多 s₁ block per 核FD metadata 的 mStart/mNum 允许单核处理多个 s₁ block; 每个 block 独立写 workspace
混合 batch 长度不同 batch 元素的 kvSeqLen 不同 → 不同 N_splits; workspaceNum 字段处理差异

4. 各阶段伪代码

4.1 ProcessVec1 (FD 修改)

void ProcessVec1(...) {
    // ========== 现有 softmax 流程 (完全不变) ==========
    bmm1ResBuf.WaitCrossCore();
    // ProcessVec1Vf: Muls(scale) + SoftmaxFlashV2 + Cast + ND2NZ
    // SFAUpdateExpSumAndExpMax
    // DataCopy softmax P to L1
    bmm1ResBuf.SetCrossCore();

    // ========== NEW: FD - 写 partial max/sum 到 GM workspace ==========
    if constexpr (isFd) {
        if (runInfo.s2LoopCount == runInfo.s2LoopLimit) {
            // 重新读取最新的 sum/max (已被 SFAUpdateExpSumAndExpMax 更新)
            LocalTensor<float> finalSumUb = softmaxSumBuf[...].Get<float>();
            LocalTensor<float> finalMaxUb = softmaxMaxBuf[...].Get<float>();

            // 偏移计算:
            //   每个 split 存储 [max(halfMRealSize fp32)] + [sum(halfMRealSize fp32)]
            //   maxOffset = fdWorkspaceIdx * 2 * halfMRealSizeAligned
            //   sumOffset = maxOffset + halfMRealSizeAligned
            int64_t halfMAligned = runInfo.halfMRealSize; // 1 fp32 per row, 32 rows per subBlock
            int64_t maxOffset = runInfo.fdWorkspaceIdx * 2 * halfMAligned;
            int64_t sumOffset = maxOffset + halfMAligned;
            int64_t s1LocalSize = runInfo.halfMRealSize; // 每行 1 个 fp32 值

            DataCopy(lseWorkspaceGm + maxOffset, finalMaxUb, s1LocalSize);
            DataCopy(lseWorkspaceGm + sumOffset, finalSumUb, s1LocalSize);
        }
    }
}

关键点: 现有 softmax 流程零修改, FD 逻辑纯粹是追加的。

4.2 ProcessVec2 (FD 修改)

void ProcessVec2(...) {
    bmm2ResBuf.WaitCrossCore();
    LocalTensor<T> vec2ResUb = stage2OutBuf.Get<T>();
    LocalTensor<T> mmRes = bmm2ResBuf.GetTensor<T>();
    int64_t vec2CalcSize = runInfo.vec2MRealSize * dTemplateAlign64;

    // ========== 中间迭代 (不变) ==========
    if (runInfo.s2LoopCount == 0) {
        DataCopy(vec2ResUb, mmRes, vec2CalcSize); // 首次: 直接存 bmm2 结果
    } else if (runInfo.s2LoopCount < runInfo.s2LoopLimit) {
        // 中间: FlashUpdateNew — 含修正但无除法
        FlashUpdateNew<T, Q_T, OUTPUT_T, dTemplateAlign64>(
            vec2ResUb, mmRes, vec2ResUb, expUb, ...);
    }

    // ========== 最后迭代: FD 分支 ==========
    else { // s2LoopCount == s2LoopLimit
        if constexpr (!isFd) {
            // ---- NON-FD: 原始行为 ----
            FlashUpdateLastNew(vec2ResUb, mmRes, vec2ResUb, expUb, sumUb, ...);
            // 含除法: O = (prev*expMax + cur) / softmaxSum
            CopyOutAttentionOut(runInfo, constInfo, vec2ResUb, ...);
        } else {
            // ---- FD: 无除法, 写 partial O 到 workspace ----
            FlashUpdateLastNoDiv<T, Q_T, OUTPUT_T, dTemplateAlign64>(
                vec2ResUb, mmRes, vec2ResUb, expUb, ...);
            // 无除法: O_partial = prev*expMax + cur (保留未归一化)

            // 拷出 partial O 到 GM workspace
            int64_t oOffset = runInfo.fdWorkspaceIdx * s1BaseSize * dTemplateAlign64;
            DataCopyPad(partialOWorkspaceGm + oOffset, vec2ResUb, oCopyParams);
        }
    }

    bmm2ResBuf.SetCrossCore();
}

4.3 ProcessFdReduction (新增规约阶段)

void ProcessFdReduction(RunInfo &runInfo, ConstInfo &constInfo) {
    if constexpr (!isFd) return;

    // ========== 角色检查 ==========
    if (!runInfo.isReductionCore) {
        SetFlag<HardEvent::V_MTE3>(vToMte3Id); // 确保 GM 写完成
        WaitFlag<HardEvent::V_MTE3>(vToMte3Id);
        // 在 GM workspace 的完成标志区写入本核完成信号
        DataCopy(fdCompletionGm + runInfo.fdCompletionOffset, completionFlagValue, 1);
        return; // 非规约核退出
    }

    // ========== 全局 Barrier (GM polling) ==========
    // CrossCoreSetFlag/CrossCoreWaitFlag 是核组内 AIC↔AIV 配对同步, 不能跨核组全局 barrier。
    // FD 全局 barrier 使用 GM 完成标志 + polling:
    //   1. 各计算核完成 partial 计算后, 在 fdCompletionGm 写入标志 (如 1)
    //   2. 规约核 polling fdCompletionGm, 等所有 numSplits 个标志就绪
    for (uint32_t i = 0; i < numSplits; i++) {
        // Polling: 读取 fdCompletionGm[completionBase + i], 等值为 1
        PollGmCompletion(fdCompletionGm + completionBase + i); // GM polling barrier
    }

    // ========== 单 split 边界: 直接除法输出 ==========
    if (numSplits == 1) {
        LastDivNew(vec2ResUb, vec2ResUb, sumUb, ...); // 等价 FA 模式
        CopyOutAttentionOut(...);
        ComputeLseOutputVF(lseUb, sumUb, maxUb, ...);
        DataCopy(softmaxLseGm + lseOffset, lseUb, ...);
        return;
    }

    // ========== Step 1: 找全局最大值 ==========
    DataCopy(globalMaxUb, lseWorkspaceGm + 0, s1LocalSize); // 初始化为 split 0
    for (splitIdx = 1; splitIdx < numSplits; splitIdx++) {
                DataCopy(partialMaxUb, lseWorkspaceGm + splitIdx*2*halfMAligned, s1LocalSize);
        Max(globalMaxUb, globalMaxUb, partialMaxUb, s1LocalSize); // 元素级 max
    }

    // ========== Step 2: 修正因子 + 全局求和 ==========
    Duplicate(globalSumUb, (T)0.0, s1LocalSize);
    for (splitIdx = 0; splitIdx < numSplits; splitIdx++) {
        DataCopy(partialMaxUb, lseWorkspaceGm + splitIdx*2*halfMAligned, ...);
        DataCopy(partialSumUb, lseWorkspaceGm + splitIdx*2*halfMAligned + halfMAligned, ...);
        Sub(correctionUb, partialMaxUb, globalMaxUb, ...);     // partialMax - globalMax
        Exp(correctionUb, correctionUb, ...);                  // exp(correction) ∈ (0,1]
        Mul(correctionSumUb, correctionUb, partialSumUb, ...); // correction * partialSum
        Add(globalSumUb, globalSumUb, correctionSumUb, ...);  // globalSum += ...
    }

    // ========== Step 3: 累积修正后的 partial O ==========
    Duplicate(finalOUb, (T)0.0, vec2CalcSize);
    for (splitIdx = 0; splitIdx < numSplits; splitIdx++) {
        // 重算 correction (同 Step 2)
        Sub(correctionUb, partialMaxUb, globalMaxUb, ...);
        Exp(correctionUb, correctionUb, ...);
        // 读 partial O from GM
        DataCopyPad(partialOUb, partialOWorkspaceGm + splitIdx*oSizePerSplit, ...);
        // correction 广播 [s₁] → [s₁, d]: 使用 DIST_BRC_B32 VF 加载
        // finalO += correction * partialO (新增 FdReduceAccum_VF 自定义函数)
        // 注意: ReduceFinalRes_VF 的签名和语义不同, 不能直接复用
        FdReduceAccum_VF(finalOUb, correctionUb, partialOUb, m, d);
    }

    // ========== Step 4: 除以 global_sum (广播) ==========
    LastDivNew(finalOUb, finalOUb, globalSumFloatUb, ...); // globalSum 广播到 d 维度

    // ========== Step 5: Cast + 写 attentionOutGm ==========
    Cast(attenOutBf16, finalOUb, CAST_ROUND, ...);
    DataCopyPad(attentionOutGm + attentionOutOffset, attenOutBf16, ...);

    // ========== Step 6: 计算 + 写 LSE ==========
    // lse = globalMax + log(globalSum)
    ComputeLseOutputVF(lseUb, globalSumUb, globalMaxUb, ...);
    DataCopy(softmaxLseGm + lseOffset, lseUb, ...);
}

4.4 FlashUpdateLastNoDiv (新增 VF 函数)

NEW 与 FlashUpdateLastBasicVF 结构相同, 但移除 Div 步骤:

template<typename T, typename INPUT_T, typename OUTPUT_T, uint16_t srcD>
__simd_vf__ inline void FlashUpdateLastNoDivVF(
    __ubuf__ float* dstUb, __ubuf__ float* curUb,
    __ubuf__ float* preUb, __ubuf__ float* expMaxUb,
    const uint16_t m, const uint16_t d)
{
    // dstTensor = preTensor * expMaxTensor + curTensor
    // NOTE: NO Div by expSumTensor (关键差异)
    for (uint16_t i = 0; i < m; ++i) {
        LoadAlign<T, DIST_BRC_B32>(vreg_exp_max, expMaxUb + i*reduceSize);
        for (uint16_t j = 0; j < dLoops; ++j) {
            LoadAlign(vreg_input_pre, preUb + i*d + j*floatRepSize);
            LoadAlign(vreg_input_cur, curUb + i*d + j*floatRepSize);
            Mul(vreg_mul, vreg_exp_max, vreg_input_pre, preg_all);  // prev * expCorrection
            Add(vreg_add, vreg_mul, vreg_input_cur, preg_all);  // + current (NO Div)
            StoreAlign(dstUb + i*d + j*floatRepSize, vreg_add, preg_all);
        }
    }
}

实质: FlashUpdateLastNoDiv 计算 dst = prev × expCorrection + cur, 与 FlashUpdateNew 数学等价。独立命名是为了语义清晰和未来扩展。

4.5 FdReduceAccum_VF (新增自定义规约累积函数)

NEW 注意: 现有 ReduceFinalRes_VF 的签名和语义与 FD 规约需求不同 (它使用 DIST_BLK 而非 DIST_BRC_B32), 因此需要新增自定义 VF 函数:

template<typename T>
__simd_vf__ inline void FdReduceAccumVF(
    __ubuf__ float* dstUb,     // final_O (累积目标)
    __ubuf__ float* corrUb,     // correction [s₁] (每行一个 fp32)
    __ubuf__ float* partialOUb, // partial_O [s₁×d]
    const uint16_t m,      // halfMRealSize (有效行数)
    const uint16_t d)      // dTemplateAlign64 (列数)
{
    // finalO += correction * partialO (correction 广播 [s₁] → [s₁,d])
    for (uint16_t i = 0; i < m; ++i) {
        // 关键: 使用 DIST_BRC_B32 广播每行的 correction 值到所有 d 列
        LoadAlign<T, DIST_BRC_B32>(vreg_corr, corrUb + i*reduceSize);
        for (uint16_t j = 0; j < dLoops; ++j) {
            LoadAlign(vreg_finalO, dstUb + i*d + j*floatRepSize);
            LoadAlign(vreg_partialO, partialOUb + i*d + j*floatRepSize);
            Mul(vreg_mul, vreg_corr, vreg_partialO, preg_all); // correction * partialO
            Add(vreg_finalO, vreg_finalO, vreg_mul, preg_all); // finalO += ...
            StoreAlign(dstUb + i*d + j*floatRepSize, vreg_finalO, preg_all);
        }
    }
}

与 ReduceFinalRes_VF 的差异: ReduceFinalRes_VF 使用 DIST_BLK 加载 lse (block 模式), 而 FD 规约需要 DIST_BRC_B32 加载 correction (单值广播模式)。这是关键区别, 不可直接复用。
