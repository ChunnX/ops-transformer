## 第一轮 Host 分块公式（round17）

定义 `align_a(x)=ceil(x/a)*a`，`U(x)=align_256(x)`，`B=min(硬件UB,248*1024)`，`K=4D`。
所有分块、推进配额、尾块由 tiling 下发；kernel 不进行容量搜索。

### Cube 与四算子 wave

保留现有 Cube 规划：wave Mtile=128；目标 M=3072 的非wave Mtile=192。
`C=min(AIC,AIV/2)`，wave `mGrid=min(floor(C/4),ceil(M/128))`，
初选 `kGrid=min(floor(C/mGrid),ceil(K/256))`，
`partialK=min(align_256(ceil(K/kGrid)),1024)`，
`splitK=align_partialK(ceil(K/kGrid))`，最后再取 `kGrid=ceil(K/splitK)`。
`rowsPerWave=mGrid*Mtile`；L1/L0仍受真实容量、双槽和对齐约束。
本实验 wave L1K=128、baseK=64；非wave L1K=128、baseK=32；FP32 MMAD K步长32。

wave 启用条件：至少4个可用 Cube 核；存在合法 CubePlan；Mtile能被2*kGrid整除；
最后一批完整；至少两批；最短 K 分片至少两个完整 L1 tile；同时存活 UB≤B。
不匹配特定 M、D 或32核。其他情况退回已有阶段屏障调度。

每个 AIV 产生 `R=Mtile/(2*kGrid)` 行，最短 K 分片有 `L` 个完整 tile。
从 tile 1 开始，`quota=ceil(R/(L-1))`，`ticks=ceil(R/quota)`，
`stride=floor((L-1)/ticks)`；每次推进最多 quota 行。
于是 `1+(ticks-1)*stride<L`，下一 wave 前行已全部产生。
这里必须使用最短 K 分片：D2560 的最后分片只有8个 tile，不能按24个 tile规划。

|D|四算子 splitK/lastK|四算子 quota/stride|五算子 splitK|
|---:|---:|---:|---:|
|2560|3072/1024|3/1|5120|
|5120|5120/5120|1/2|10240|
|6144|6144/6144|1/2|12288|
|7168|7168/7168|1/3|14336|

四个目标 D 均使用 mGrid=8、kGrid=4、三批wave；五算子为 mGrid=16、kGrid=2。
partialK 均为1024。D2560 的 K 分片不均衡是离散分块，不是5120特判。

### UB 预算与 projection

四算子 wave producer：`P4=26D+1536` 字节（本实验 D 对齐下的简化式）。
projection 的两个低精度输入槽只需要 `r*L1K` 元素，原来的 `max(K,r*L1K)` 多分配
没有实际读取用途；缩小后 `Pproj=U(4r)+U(4rL1K)+2U(2rL1K)`。
wave r=64，Pproj=64.25 KiB；非wave r=96，Pproj=96.5 KiB。

### 五算子容量策略对照

候选A保留两份 producer 输入，gamma2 放不下时分块。
除gamma2外预算 `Pbase=26D+1280`；枚举最小块数 n，
`G=align_64(ceil(K/n))`，使 `Pbase+U(4G)≤B`。
D2560/5120 的gamma整行常驻；D6144/7168 每行加载两块gamma。
Post仍对完整K累积平方和，只求一次invRms，各gamma块共用该值。

候选B用容量选择输入槽数，优先常驻完整gamma2。
`P5(S)=22D+10SD+1280`，选择满足 `P5(S)≤B` 的最大 `S∈{1,2}`。
D2560/5120用双槽；D6144/7168用单槽。单槽在当前行MTE3完成后加载下一行，
不会在计算读完前覆盖residual。数学计算仍共用原来的RMSMid函数。

### Epilogue

令 `p=K/1024`，`g=kGrid`，候选行数 `r≤min(projectionRows,48)`，`ra=align_8(r)`。
精确预算为：

`E(r)=U(8D)+2U(2D)+U(4D)+768+U(96ra)+U(4g*ra)+U(4*(p*r*32+64))`。

从最大行数开始按8行减小，选择 `E(r)≤B` 的最大合法批量；小M保留实际行数。
前三个目标D取48行，D7168取32行。四算子 E 为106.25/206.25/246.25/228.50 KiB，
五算子为106.00/206.00/246.00/228.25 KiB。各阶段由Destroy分隔生命周期，不能把所有阶段相加。

## partialK 与 mhc_pre 对齐，以及更简单的分核公式（round21/22）

这里的 `K=n*D`，当前接口 `n=4`。`g` 是核间 K 分工数，与输入 n 没有绑定关系。
`singleCoreK` 是一核负责的总 K 范围，`partialK` 是一次 Cube 累加后交给 Vector 归并的范围，
`L1K/baseK` 则是核内搬运和计算块，三者不能混用。

### 累加条件（已与 mhc_pre 对齐）

给定候选 K 分核数 g，先计算 `S0=alignUp(ceil(K/g),256)`：

- S0<2048：`singleCoreK=S0`，每核只输出一个 partial，最后一核按真实尾块长度累加。
- S0>=2048：`partialK=1024`，`singleCoreK=1024*ceil(ceil(K/1024)/g)`。
- 实际 K 核数为 `ceil(K/singleCoreK)`；尾核长度由 Host 下发。
- 只有分段累加路径要求 L1K 整除1024；小分片允许最后一个 L1 搬运块有尾块。

这与 mhc_pre 的 CalculateMkTiling 判断和分片调整顺序一致，并不表示两者 M/K 分核策略完全相同。
例如1280/1536/1792现在各自产生一个 partial，而2048产生两个1024 partial。
round21只修改该条件：Host7980组通过，上板64组全部通过且重复逐位一致。

### wave 分核候选（round22）

保留两个全局流水预算：每个 AIV 每批生成 R=16 行，projection 每块 B=8192 元素。
它们是此前实验选定的全局参数，不声称由硬件容量唯一推导，也不按 D 查表。
L1K 对齐 A=128，由此得 `gMax=B/(R*A)=4`；这个4来自搬运预算，与 n 无关。
当前支持的 D 为256倍数，因此 K 是1024倍数。令 `P=K/1024`、`C=min(AIC,AIV/2)`：

```text
g      = gcd(P, C, gMax)
Mtile  = 2*R*g
L1Kcap = B/(R*g)
```

对足够大的 M，`mGrid=C/g`。于是每批处理 `mGrid*Mtile=2*R*C` 行，
每个 AIV 的 projection 块为 `(Mtile/2)*L1Kcap=B`，两者均不随 D 改变。
D 的变化通过 P 决定 K 分工与每核循环次数，不增加经验区间。
小 M 仍由实际 M 块数限制核数；完整批、同步进度和 UB 容量检查不通过时使用现有非 wave 路径。

L1K 在该上限内再受 L1 A/B 双缓冲容量约束、按128向下对齐，并遵守上述 partial 边界。
baseK 则取 L0A、L0B、L1K 三者容量上限的最小值，按32向下对齐。
所有循环次数、尾块和同步推进参数仍在 Host 计算，kernel 计算模块不变。

### round24：比较最忙核的工作量，相同则优先大 M 块

保留全局 R=16、B=8192、L1K按128对齐，以及Mtile至少64的效率约束。
由此候选g为2/4，而不是输入n决定的固定4路。对每个g：

```text
P = ceil(K/1024)
W(g) = g * ceil(P/g)
g = W(2) < W(4) ? 2 : 4
Mtile = 32*g
L1Kcap = 512/g
```

理由：最忙核的分片长为 `1024*ceil(P/g)`，Mtile为32*g，所以其M×K工作量
与W(g)成正比。W不是实际全核总计算量，也不是加权性能评分；它只比较最忙核的工作量。
相同W时保留更大的Mtile，以减少round22/23已经测到的小M计算开销。

|P|W(2)|W(4)|选择g|
|---:|---:|---:|---:|
|10|10|12|2|
|11|12|12|4|
|13|14|16|2|
|15|16|16|4|
|20|20|20|4|

因此代码只需比较两个向上对齐值，不枚举D、没有经验区间，也不需要校准权重。
可用核数通过公约数约束g；若无法保持至少两路，则退回原非wave路径。
L1/L0容量、partial边界、完整wave和UB检查仍然生效，核内循环和尾块都由Host下发。
该方案仍是当前wave结构的简洁规划规则，不声称为任意M/D或五算子找到了全局最优。

## 整批、尾批、小T顺序修复与T8192对照（round43–48，2026-09-27）
