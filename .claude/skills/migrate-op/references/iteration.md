# 经验沉淀

迁移成功后只沉淀经过本次验证且能解释根因的规则。

## 沉淀前复盘

写入经验前，先完整回忆本次踩坑和解决过程：

- 最早失败的阶段、日志关键词和可复现现象
- 当时做过的判断、排除过的方向和排除依据
- 根因是什么，证据来自哪段代码、日志或产物
- 最终修改为什么直接解决根因
- 是否存在只绕过问题的做法；若最终方案不能解释根因，不沉淀为通用规则

## 写入条件

一条经验同时满足：

- 有明确失败症状或迁移场景
- 有对应的根因修复
- 修改后编译或精度验证通过
- 对未来算子有复用价值
- 能讲清问题根因，而不是只记录“换一种方式规避后通过”

## 写法

记录到最相关的文件：

- 框架路径、产物、运行环境：`framework-contract.md`
- 导入、本地化、host/kernel/CMake 模式：`copy-first-migration.md`
- pybind、module、输入、CSV：`validation.md`
- 失败症状和修复：`troubleshooting.md`

每条经验使用短句：

```text
症状/场景 -> 根因 -> 判断方法 -> 根因修复 -> 验证结果
```

保留日志路径或错误关键词，说明为什么这是根因修复。避免写成没有证据的通用结论，也不要把临时绕法包装成经验。

## 暂不沉淀

- 只在单个算子中成立的临时绕法或未解释根因的规避
- 未通过编译或精度验证的猜测
- 会改变计算语义的修改
- 可以从 CANN 文档或框架源码直接推出的常识
