# Iterate Skills

对退化的 skill 进行多维度并行审查与迭代重构。

## 何时使用

- Skill 经过多轮补丁式修改，结构已混乱
- 内容存在冗余、重复或相互矛盾的指令
- 整体可读性下降，难以快速定位关键信息

## 意见严重等级

每条审查意见必须标注严重等级：

| 等级 | 含义 | 示例 |
|------|------|------|
| 🔴 高 | 影响 skill 正确执行，或存在根本性设计问题 | 触发条件错误、核心步骤缺失、职责边界混乱 |
| 🟡 中 | 影响使用质量，但不阻断执行 | 指令模糊、结构层次不清、示例不足 |
| 🟢 低 | 表达或风格层面的优化 | 措辞冗余、段落顺序微调、语言不够流畅 |

## 收敛条件

满足以下任一条件时停止迭代：

- **自然收敛**：本轮三个 agent 提出的意见全部为 🟢 低等级
- **轮次上限**：已完成第 4 轮迭代

## 工作流程

### 第一步：读取原始 skill

完整读取待重构的 SKILL.md，不做任何修改，作为第一轮审查的输入。

### 第二步：并行审查（每轮执行）

三个 agent 同时对当前版本进行审查，每条意见标注等级（🔴 高 / 🟡 中 / 🟢 低）：

**Agent 1 — 设计哲学审查**
- Skill 的核心职责是否始终清晰？有无范围蔓延（scope creep）？
- 触发条件是否准确——该触发时触发，不该触发时不触发？
- Skill 边界是否合理，有无承担不属于它的职责？

**Agent 2 — 内容质量审查**
- 指令是否明确可执行？有无歧义或永远不会被执行到的死指令？
- 边界情况、异常处理、错误输入是否有所覆盖？
- 是否有清晰的成功标准，让使用者知道 skill 是否正确执行？

**Agent 3 — 文档结构审查**
- 结构层次是否清晰，信息能否被快速定位？
- 有无重复表达同一意思的段落或指令？
- 语言是否流畅自然，无补丁式拼接痕迹？

### 第三步：判断是否收敛

检查本轮所有意见的等级：

- **全部为 🟢 低** → 收敛，跳至第五步
- **存在 🟡 中或 🔴 高，且未达第 4 轮** → 进入第四步
- **已是第 4 轮** → 强制结束，跳至第五步，并注明哪些问题未能解决

### 第四步：合并修改并进入下一轮

汇总三个 agent 的意见，按优先级处理：
- 🔴 高：必须修复
- 🟡 中：尽量修复，若与其他修改冲突以 Agent 1（设计哲学）为准
- 🟢 低：酌情处理

修改完成后，以新版本作为输入，返回第二步。

### 第五步：输出与确认

展示最终版本，并附上每轮的意见摘要（轮次 / 意见数量 / 等级分布），让用户了解迭代过程。将新旧版本的关键差异呈现给用户确认后，再写入文件。
