# Vibe Coding Philosophy — Agent-Driven Workflow

> 本工作流的方法论与核心理念。定义 agent 如何利用文件系统实现可靠、一致、零信息丢失的跨会话开发。

## 问题

AI agent 在复杂代码库上工作时：

1. **上下文有限** — LLM 上下文窗口有上限
2. **上下文临时** — 新会话没有前次记忆
3. **总结会丢信息** — 压缩必然丢失细节
4. **偏差会累积** — 小偏离在多次会话后放大

没有结构化记忆系统，agent 会：重复已完成的工作、遗漏前次关键上下文、偏离用户原始意图、产生与已有决策矛盾的方案。

## 解决方案：文件驱动的状态架构

```
AGENTS.md（入口）
    │
    ├── .workflow/                    ← 跨会话记忆与任务状态
    │   ├── GOAL.md                   ← 方向（要去哪）
    │   ├── PLAN.md                   ← 路径（怎么去）
    │   ├── NEXT_STEPS.md             ← 用户任务索引（概要+状态+链接）
    │   ├── CHECKLIST.md              ← 质量标准（如何验证）
    │   ├── CHANGELIST.md             ← 历史（改了什么、为什么）
    │   ├── reference/                ← 参考文档
    │   │   ├── vibe-coding-philosophy.md  ← 本文件
    │   │   └── next_steps/           ← 详细任务说明（NEXT_STEPS.md 索引）
    │   └── raw/                      ← 原始数据（不可修改）
    │       ├── INDEX.md              ← 文档索引（检索入口）
    │       ├── spec/                 ← 需求规格说明书
    │       └── reference/            ← 参考文档（走读、分析、设计等）
    │
    └── *                             ← 项目源码
```

## 设计原则

### 1. 信息必须持久化

**有价值的信息必须写入文件，不依赖上下文记忆。**

- 上下文是临时的，文件是持久的
- 发现重要信息 → 立即写入
- 不要假设"下次会话能推断出来"

### 2. 原始信息必须原样保留

**用户原始输入、想法、设计意图必须未压缩、未改写地保存。**

- 存储在 `.workflow/raw/`
- 保持原始语言（中文存中文，英文存英文）
- 不翻译、不改写、不"优化表达"
- raw/ 是 **truth source**，其他文件是衍生物

### 3. 文件即记忆

| 文件 | 记忆类型 | 变更频率 |
|------|---------|---------|
| `GOAL.md` | 长期目标记忆 | 很少变更 |
| `PLAN.md` | 实现路径记忆 | 按阶段变更 |
| `NEXT_STEPS.md` | 用户意图记忆 | 用户更新时 |
| `CHECKLIST.md` | 质量标准记忆 | 随时间增长 |
| `CHANGELIST.md` | 历史变更记忆 | 追加式 |
| `raw/` | 原始意图记忆 | 追加式，不可修改 |

### 4. 自引用原则

**"信息必须持久化"这条原则本身也必须被持久化。**

本文件的存在就是这个原则的体现。不被记录的原则无法被遵循。

### 5. 渐进式披露

**知识应从宏观到微观、从概念到细节组织。**

- 新 agent/开发者先看概览，再深入细节
- 直接跳到细节会导致管中窥豹
- 渐进式披露降低认知负荷

## Agent 角色模型

### 主 Agent（编排者）

- **角色**: 项目管理者
- **职责**: 读取全局状态 → 制定计划 → 分发任务 → 验证结果 → 更新状态
- **不做**: 不亲自实现具体代码（除非极简任务）
- **核心产出**: PLAN.md 的任务编排、CHANGELIST.md 的变更记录

### Subagent（执行者）

- **角色**: 具体任务实施者（开发、测试、评审等）
- **职责**: 接收精准上下文 → 完成具体任务 → 产出回写
- **优势**: 独立上下文，最小化信息噪声，提高任务可靠性
- **核心产出**: 代码变更、测试结果、评审报告

### 协作机制

```
用户 ←→ 主 Agent ←→ .workflow/ 文件 ←→ Subagent
         (编排)      (通信层)          (执行)
```

1. 主 agent 将任务拆解后分发给 subagent
2. Subagent 在独立上下文中完成任务
3. 完成后通过文件（CHANGELIST、PLAN 等）同步状态
4. 新会话/新 agent 通过读取文件了解全局状态

## 会话工作流

### 启动新会话

1. 读 `AGENTS.md` → 了解工作流方法论
2. 读 `GOAL.md` → 了解总体目标
3. 读 `PLAN.md` → 了解当前阶段计划
4. 读 `NEXT_STEPS.md` → 了解用户下一步指示
5. 如有歧义 → 读 `raw/` 原始文档

### 工作期间

1. 做重大决策前 → 检查 `CHECKLIST.md`
2. 发现新信息 → 写入对应文件
3. 原始意图不明确 → 查阅 `raw/`

### 完成工作后

1. 按 `CHECKLIST.md` 验证
2. 追加 `CHANGELIST.md`
3. 更新 `PLAN.md` 和 `NEXT_STEPS.md` 状态
4. 更新 `GOAL.md` 进度（如有变化）

## 为什么这套方法有效

1. **消除上下文丢失** — 重要信息都在磁盘上
2. **保持意图保真** — raw/ 防止偏离原始愿景
3. **提供决策框架** — GOAL → PLAN → NEXT_STEPS 给出清晰方向
4. **支持质量控制** — CHECKLIST 充当独立审查者
5. **确保连续性** — 新会话精确接续前次工作
6. **最小化上下文** — 每个 subagent 只拿到完成任务所需的精准信息
