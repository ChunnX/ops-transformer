**方式**：删除 `ToVector(shape)` 辅助函数（先拷贝 shape 到 vector 再遍历），改为直接按 `shape.GetDimNum()` 遍历打印：
```cpp
// 旧: auto v = ToVector(shape); if (v.size() > 0) { for(i<v.size()-1) oss<<v[i]<<", "; oss<<v[v.size()-1]; }
// 新: const size_t dimCount = shape.GetDimNum();
```

**正确性解析**: ✅ 等价。两者输出均为 `"d0, d1, ..., dn-1"`，空 shape 均输出空串；新版还规避了旧版 `v.size() - 1` 在 size_t 下的下溢隐患（有 `>0` 保护所以旧版也未出错）。已确认 6 个文件中 `ToVector` 无残留调用者（仅 MQSMLA check.h:89 遗留一条死声明，无实现无调用，不参与链接）。

## 三、边缘风险点（非功能性问题，记录在案）

1. **日志文本微变**：0928_2 MQSMLA tiling.cpp `GetAttrParaInfo` 中报错日志 `"attrs got from ge is nullptr"` → `"mqsmlaAttrs got from ge is nullptr"`。仅影响日志可读性/一致性比对，无功能影响。
2. **`unlikely()` 提示丢失**：表驱动重构把 `OP_CHECK_IF` 展开为手写 `if`，丢失编译器分支预测提示。无功能影响，校验路径非热点。
3. **遗留死声明**：mixed_quant_sparse_flash_mla_check.h:89 的 `ToVector` 声明已无实现无调用，建议后续清理。
4. **函数改名导致的接口变化**：`CheckRequiredParaExistence` → `Check{Li,Qli,Liv2,Qliv2}RequiredParameters`、`GetTypeSize`→`SFAGetTypeSize` 等均为类内/文件内 static 函数，调用方已同步，无外部接口影响。
5. **微等价改写抽查**（691 处 `i++`→`++i`、`empty()`、`back()` 等）：对整型/迭代器下标场景语义完全等价，抽查未发现越界或符号差异场景。

## 四、结论

1. 四仓降重中**真正的代码逻辑重构共 8 类**（2.1–2.7 及散布的微等价改写），全部位于 **op_host / op_api 侧**（tiling 校验、日志辅助、aclnn 包装）。
2. **kernel 侧（op_kernel）未发现任何逻辑变化**——包括最初高度怀疑的 get_kv_phy_addr_vf.h、vector1.h、csa_block 系列大块改动，经指令序列级验证均为纯改名。
3. 已识别的重构经逐处解析**均语义等价**，风险集中在「错误分支行为需实机回归兜底」：表驱动校验重构（2.2/2.3）与 ToStringRaw 重写（2.1）建议在编包后覆盖一轮入参校验类 ST 用例。
4. 加注释/改变量名两类改动未发现风险（token 级映射验证全覆盖）。

## 附：验证手段说明

- **函数级 token 流映射对齐**：对新旧同名函数体提取 token 序列，按位置学习「新标识符→旧标识符」映射（支持任意前缀剥离），映射应用后序列需完全一致，否则进入人工清单。
- **指令序列验证**（kernel 关键函数）：对每条 `Reg::`/`DataCopy`/同步指令按 token 精确对齐，任何一条指令的操作数映射错乱（如 pingpong 双缓冲 `_1/_2` 交叉）都会表现为映射冲突而被发现。
- **控制流/字面量不变性**：等价改写下 if/for/while/return/break/continue 计数与数字、字符串字面量多重集应保持不变（微等价改写如 `v[size-1]`→`back()` 的例外已人工覆盖）。
