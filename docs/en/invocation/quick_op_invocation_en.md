After the open-source third-party software is ready, you can use the following compilation methods as required:

 *  **custom operator package:**
    
    The package generated by the compilation of some operators is called the custom operator package. The package is mounted to the CANN package without changing the original package content. The priority of the generated user-defined operator package is higher than that of the original CANN package. This package supports the invoking of AI Core operators in aclnnn and graph mode.
 *  **ops-transformer package:**
    
    The ops-transformer package generated by compiling the entire project is called the ops-transformer package, which can completely replace the corresponding part of the CANN package. This package supports calling AI Core operators in aclnnn and graph modes.
 *  **Ops-transformer static library:**
    
    > Note: If you need to perform secondary release based on this project and have requirements on the size of the software package, you are advised to use the static library to compile the software package. The static library can link your application development program and retain only the operators required by the service to minimize software deployment.
    
    Indicates that the entire project is compiled as a static library file, including the libcann_transformer_static.a and aclnn interface header file. This package supports only ACLN invoking AI Core operators.

### Networked Compilation ###

#### custom operator package ####

1.  **Compiling the custom operator Package**
    
    Go to the root directory of the project and run the following compilation command:
    
    ```
    bash build.sh --pkg --soc=${soc_version} [--vendor_name=${vendor_name}] [--ops=${op_list}]
    #The FlashAttentionScore operator is used as an example.
    #bash build.sh --pkg --soc=ascend910b --ops=flash_attention_score
    #Compile the operator in the experimental contribution directory.
    #bash build.sh --pkg --experimental --soc=ascend910b --ops=${experimental_op}
    ```
    
     *  \--soc: $\{soc_version\} indicates the NPU model. For the Atlas A2 series, use the ascend910b (default), for the Atlas A3 series, use the ascend910_93, and use the ascend950 for the Ascend 950PR/Asscend 950DT.
     *  \--vendor_name (Optional): $\{vendor_name\} indicates the name of the built custom operator package. The default name is custom.
     *  \--ops (optional): $\{op_list\} indicates the operator to be compiled. If this parameter is not specified, all operators are compiled by default. The format is "apply_rotary_pos_emb,rope_quant_kvcache, ...". Use commas (,) to separate multiple operators.
     *  \--experimental (optional): Compile the operator in the experimental contribution directory. $\{experimental_op\} indicates the directory name of the new operator.
    
    If neither $\{vendor_name\} nor $\{op_list\} is transferred, the ops-transformer package is compiled. If the custom operator packages of all operators are compiled, $\{vendor_name\} must be transferred. If the following information is displayed, the compilation is successful:
    
    ```
    Self-extractable archive "cann-ops-transformer-${vendor_name}_linux-${arch}.run" successfully created.
    ```
    
    After the compilation is successful, the run package is stored in the build_out directory of the project root directory.
2.  **Installing the custom operator Package**
    
    ```
    ./cann-ops-transformer-${vendor_name}_linux-${arch}.run
    ```
    
    The installation path of the custom operator package is`${ASCEND_HOME_PATH}/opp/vendors`, $\{ASCEND_HOME_PATH\} is configured through the environment variable, indicating the installation path of the CANN toolkit package. Generally, the path is $\{install_path\}/cann.
    
    > Note: If the installation directory of the operator package is specified by the --install-path parameter during operator package deployment, you need to run the source $\{install-path\}/vendors/$\{vendor_name\}/bin/set_env.bash command before using custom operator. In the set_env.bash script, add the installation path of the customized operator package to the ASCEND_CUSTOM_OPP_PATH environment variable so that the customized operator takes effect in the current environment.
3.  **(Optional) Deleting the custom operator Package**
    
    Note that the custom operator package cannot be uninstalled. To uninstall the package, delete the $\{vendor_name\} directory in vendors/ and the $\{vendor_name\} configuration item corresponding to load_priority in vendors/config.ini.

#### ops-transformer package ####

1.  **Compiling the ops-transformer Package**
    
    Go to the root directory of the project and run the following compilation command:
    
    ```
    #Compile all operators except the experimental contribution directory.
    bash build.sh --pkg --soc=${soc_version}
    #Compile all operators in the experimental contribution directory.
    #bash build.sh --pkg --experimental --soc=${soc_version}
    ```
    
     *  \--soc: $\{soc_version\} indicates the NPU model. For the Atlas A2 series, use ascend910b (default), for the Atlas A3 series, use ascend910_93, and use ascend950 for the Ascend 950PR/Asscend 950DT.
     *  \--experimental (optional): indicates that the operator in the experimental contribution directory is compiled.
    
    If the following information is displayed, the compilation is successful:
    
    ```
    Self-extractable archive "cann-${soc_name}-ops-transformer_${cann_version}_linux-${arch}.run" successfully created.
    ```
    
    In the preceding command, $\{soc_name\} indicates the NPU model name, that is, $\{soc_version\} indicates the remaining content after ascend is deleted. After the compilation is successful, the run package is stored in the build_out directory.
2.  **Installing the ops-transformer Package**
    
    ```
    #Installation Commands
    ./cann-${soc_name}-ops-transformer_${cann_version}_linux-${arch}.run --full --install-path=${install_path}
    ```
    
    $\{install_path\}: specifies the installation path, which must be the same as the installation path of the toolkit package. By default, the toolkit is installed in`/usr/local/Ascend`The catalog.
3.  **(Optional) Uninstalling the ops-transformer Package**
    
    ```
    #Uninstall Command
    ./${install_path}/cann/share/info/ops_transformer/script/uninstall.sh
    ```

#### Ops-transformer static library ####

> Note: The static library supports only Atlas A2 and Atlas A3 series products. Currently, experimental operators do not support static libraries.

1.  **Compiling the Ops-Transformer Static Library**
    
    Go to the root directory of the project and run the following compilation command:
    
    ```
    bash build.sh --pkg --static --soc=${soc_version}
    ```
    
    $\{soc_version\} indicates the NPU model. For the Atlas A2 series, use the default value ascend910b. For the Atlas A3 series, use the default value ascend910_93. If the following information is displayed, the compilation and compression are successful:
    
    ```
    [SUCCESS] Build static lib success!
    Successfully created compressed package: ${repo_path}/build_out/cann-${soc_name}-ops-transformer-static_${cann_version}_linux-${arch}.tar.gz
    ```
    
    In the preceding command, $\{repo_path\} indicates the root directory of the project, and $\{soc_name\} indicates the NPU model name, that is, $\{soc_version\} indicates the remaining content after ascend is deleted. After the compilation is successful, the package is stored in the build_out directory.
2.  **Decompress the ops-transformer static library.**
    
    Go to the build_out directory and run the following decompression command:
    
    ```
    tar -zxvf ./cann-${soc_name}-ops-transformer-static_${cann_version}_linux-${arch}.tar.gz -C ${static_lib_path}
    ```
    
    $\{static_lib_path\} indicates the decompression path of the static library. The directory structure after the decompression is as follows:
    
    ```
    ├── cann-${soc_name}-ops-transformer-static_${cann_version}_linux-${arch}
    │   ├── lib64
    │   │   ├── libcann_transformer_static.a        #Static library file
    │   └── include
    |       ├── ...                                 #Header file of the aclnn interface
    ```

### Compilation without network connection ###

If the source code is compiled in an environment that is not connected to the Internet, prepare the required third-party software in advance and compile the source code. The process is as follows:

1.  **Check whether the basic environment is complete.**
    
    Please make sure you have pressed [Environment Deployment]() Build the basic environment, including installing the CANN package and downloading the source code.
    
     *  In a networked environment, go to[Home page of this project](https://gitcode.com/cann/ops-transformer)	, through the`下载ZIP`or the`clone`Click to download the source code as instructed.
     *  Connect to the offline environment and upload the source code to the specified directory. If the source code package is downloaded, decompress it first.
2.  **Downloading Third-Party Software Dependencies**
    
    Download the third-party software in advance in the networked environment. Currently, the following methods are available. Select the methods as required:
    
     *  Method 1: According to[Third-Party Software Dependency](#third-party-software-dependency)	Manually download the provided form. If you download the form from another address, ensure that the version number is the same.
     *  Method 2: Pass the[third_lib_download.py](../../../scripts/tools/third_lib_download.py)	One-click download of the script, which is in this project`scripts/tools/`Directory, download the script, and run the following command:
        
        ```
        python ${scripts_dir}/third_lib_download.py
        ```
    
    $\{scripts_dir\} indicates the path for storing the script. By default, the downloaded third-party software package is stored in the directory where the current script is stored.
3.  **Compiling an Operator Package**
    
    Upload the downloaded third-party software to the offline environment and store it in`third_party`Directory or customized directory. The former is recommended. Its compilation commands are the same as those in the networked compilation scenario.
    
     *  **third_party directory (recommended)**
        
        Please create in the root directory of the project.`third_party`Directory (If the directory exists, you do not need to create it.) Copy the third-party software to the directory. In this case, the compilation command is the same as the networked compilation command. For details, see.[Networked Compilation](#networked-compilation)	.
     *  **Customizing directories**
        
        Create a new file anywhere in the offline environment`${cann_3rd_lib_path}`Directory. Copy the third-party software to the directory. Ensure that you have the permission to access the directory.
        
        ```
        mkdir -p ${cann_3rd_lib_path}
        ```
        
        In this case, the compilation command needs to be added on the basis of the networked compilation command.`--cann_3rd_lib_path=${cann_3rd_lib_path}`This parameter specifies the path of the third-party software. Assume that the storage path is`/path/cann_3rd_lib_path`The commands for different compilation modes are as follows:
        
         *  custom operator package
            
            ```
            bash build.sh --pkg --soc=${soc_version} [--vendor_name=${vendor_name}] [--ops=${op_list}] --cann_3rd_lib_path=${cann_3rd_lib_path}
            #The FlashAttentionScore operator is used as an example.
            #bash build.sh --pkg --soc=ascend910b --ops=flash_attention_score --cann_3rd_lib_path=/path/cann_3rd_lib_path
            ```
         *  ops-transformer package
            
            ```
            bash build.sh --pkg --soc=${soc_version} --cann_3rd_lib_path=${cann_3rd_lib_path}
            #bash build.sh --pkg --soc=ascend910b --cann_3rd_lib_path=/path/cann_3rd_lib_path
            ```
         *  Ops-transformer static library
            
            ```
            bash build.sh --pkg --static --soc=${soc_version} --cann_3rd_lib_path=${cann_3rd_lib_path}
            #bash build.sh --pkg --static --soc=ascend910b --cann_3rd_lib_path=/path/cann_3rd_lib_path
            ```
4.  **Installing or Uninstalling Operator Packages**
    
    The operator package compilation result is the same in the scenario where the network is not connected to the network and the operator package is stored in the build_out directory of the project root directory by default. The installation and uninstallation commands are the same. For details, see.[Networked Compilation](#networked-compilation)	.

## Local authentication ##

Run the build.sh script in the root directory of the project to execute the operator and UT test cases. Currently, the operator can be invoked in API mode (aclnn interface) or graph mode. Aclnn is recommended.

### Execution Operator Example ###

> **Note: For details about the example of the simulation operator used by the Ascend 950PR, see.**[Simulation Guide](../debug/op_debug_prof_en.md#method-2-for-ascend-950pr)	.

 *  Execute the operator example based on the custom operator package. After the package is installed, run the following command:
    
    ```
    bash build.sh --run_example ${op} ${mode} ${pkg_mode} [--vendor_name=${vendor_name}] [--soc=${soc_version}]
    #FlashAttentionScore example is used as an example.
    #bash build.sh --run_example flash_attention_score eager cust --vendor_name=custom
    ```
    
     *  $\{op\}: indicates the operator to be executed. The operator name is an underscore (_) in lowercase, for example, flash_attention_score.
     *  $\{mode\}: indicates the execution mode. Currently, the following options are supported: eager (invoking by aclnn) and graph (invoking by graph mode).
     *  $\{pkg_mode\}: package mode. Currently, only cust, that is, custom operator packages, is supported.
     *  (Optional) $\{vendor_name\}: The value must be the same as that of the built custom operator package. The default value is custom.
     *  $\{soc_version\} (Optional): NPU model. The default value is ascend910b. When set to "ascend950", the sample file in the "arch35" directory will run.
    
    Note: When $\{mode\} is set to graph, $\{pkg_mode\} and $\{vendor_name\} are not specified.
 *  Execute the operator example based on the ops-transformer package. After the installation, run the following command:
    
    ```
    bash build.sh --run_example ${op} ${mode} [--soc=${soc_version}]
    #FlashAttentionScore example is used as an example.
    #bash build.sh --run_example flash_attention_score eager
    ```
    
     *  $\{op\}: indicates the operator to be executed. The operator name is an underscore (_) in lowercase, for example, flash_attention_score.
     *  $\{mode\}: operator execution mode. Currently, the operator execution mode can be eager (invoked by aclnn) or graph (invoked by graph mode).
     *  $\{soc_version\} (Optional): NPU model. The default value is ascend910b. When set to "ascend950", the sample files in the "arch35" directory will run.
 *  The following is an example of operator execution based on the ops-transformer static library:
    
    1.  **Prerequisite**
        
        The ops-transformer static library depends on the ops-legacy and ops-math static libraries. Prepare the static libraries, decompress them, and move all lib64 and include directories to the $\{static_lib_path\} directory.
        
        > Description: ops-legacy static library`cann-${soc_name}-ops-legacy-static_${cann_version}_linux-${arch}.tar.gz`You need to click[Download link](https://ascend.devcloud.huaweicloud.com/artifactory/cann-run-release/software/master)	Obtain the ops-transformer and ops-math static libraries. Currently, no software packages are provided. Use local compilation to generate the software packages.
    2.  **Creating the run.sh script**
        
        Operator to be executed`examples\test_aclnn_${op_name}.cpp`Create the run.sh file in the same directory.
        
        The following uses the FlashAttentionScore operator as an example to describe how to execute test_aclnn_flash_attention_score.cpp:
        
        ```
        #Environment variables take effect.
        if [ -n "$ASCEND_INSTALL_PATH" ]; then
            _ASCEND_INSTALL_PATH=$ASCEND_INSTALL_PATH
        elif [ -n "$ASCEND_HOME_PATH" ]; then
            _ASCEND_INSTALL_PATH=$ASCEND_HOME_PATH
        else
            _ASCEND_INSTALL_PATH="/usr/local/Ascend/cann"
        fi
        
        source ${_ASCEND_INSTALL_PATH}/bin/setenv.bash
        
        #Compiling an executable file
        g++ test_aclnn_flash_attention_score.cpp -I ${static_lib_path}/include -L ${static_lib_path}/lib64 -L ${ASCEND_HOME_PATH}/lib64 -Wl,--allow-multiple-definition \
        -Wl,--start-group -lcann_transformer_static -lcann_math_static -lcann_legacy_static -Wl,--end-group -lgraph -lmetadef \
        -lascendalog -lregister -lopp_registry -lops_base -lascendcl -ltiling_api -lplatform -ldl -lnnopbase -lgraph_base \
        -lc_sec -lunified_dlog -lruntime -lhccl_fwk -o test_aclnn_flash_attention_score   #Replace it with the actual executable name of the operator.
        
        #Executing the procedure
        ./test_aclnn_flash_attention_score
        ```
        
        $\{static_lib_path\} indicates the unified path for storing the static library. $\{ASCEND_HOME_PATH\} indicates the installation path of the CANN toolkit package. Generally, the path is $\{install_path\}/cann. Replace the final executable file name with the actual executable file name of the operator. In the preceding information, lcann_transformer_static, lcann_math_static, and lcann_legacy_static indicate the static library files on which the operator depends. Obtain the static library files from $\{static_lib_path\}. lgraph and lmetadef indicate the underlying library files on which operators depend. You can obtain the files from the CANN toolkit package.
    3.  **Run the run.sh script.**
        
        ```
        bash run.sh
        ```

### Execute the UT operator. ###

> Note: The execution of UT cases depends on the Googletest unit test framework. For details, see.[Googletest official website](https://google.github.io/googletest/advanced.html#running-a-subset-of-the-tests)	.

```
#Install the test-related requirements.txt dependency in the root directory.
pip3 install -r tests/requirements.txt
#Method 1: Compile and execute the UT test case for the specified operator and the corresponding function.
bash build.sh -u --[opapi|ophost|opkernel] --ops=flash_attention_score
#Method 2: Compile and execute all UT test cases.
#bash build.sh -u
#Method 3: Compile all UT test cases but do not execute them.
#bash build.sh -u --noexec
#Method 4: Compile and execute the UT test cases of the corresponding function.
#bash build.sh -u --[opapi|ophost|opkernel]
#Method 5: Compile the UT test cases of the corresponding function but do not execute them. (Select one method.)
#bash build.sh -u --noexec --[opapi|ophost|opkernel]
#Method 6: When executing UT test cases, specify the SOC for compilation.
#bash build.sh -u --[opapi|ophost|opkernel] [--soc=${soc_version}]
```

To check whether the ophost function is normal, run the following command:

```
bash build.sh -u --ophost
```

If the following information is displayed, the execution is successful:

```
Global Environment TearDown
[==========] ${n} tests from ${m} test suites ran. (${x} ms total)
[  PASSED  ] ${n} tests.
[100%] Built target transformer_op_host_ut
```

$\{n\} indicates that n test cases are executed, $\{m\} indicates m tests, and $\{x\} indicates the time taken to execute the test cases, in milliseconds.
