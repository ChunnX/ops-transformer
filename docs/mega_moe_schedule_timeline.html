A. expert-major: 同一个 expert 的 waves 先在多个 group 上并行。4096 n 下是 CG0: E0.W0/E0.W2, CG1: E0.W1/E0.W3, 然后进入 E1。 这个顺序接近当前 demo 的奇偶 wave 思路。
B. load-balanced wave queue: 把 16 个 wave task 放入队列后分配给 group。 均匀 token 时这里用 wave-major 队列轮询展示。token 不均匀时, 按估计 wave cost 降序, 再用 longest-processing-time/list scheduling 放到当前累计 cost 最低的 group。

场景与时间轴

groupNum 采用基础策略 min(4, floor(aic / gmm1Tiles))。 GMM1 的 tile 下界决定能开多少组, GMM2 的 tile/core 决定 G2 阶段在每个 wave 中拉多长。

为什么不是 tile 级表

主问题是 group 调度。
这里要比较的是 16 个 wave task 如何填入 group 队列, 以及 GMM1、SwiGLU、GMM2、Combine 是否能重叠。 展开到 tile 级会把核心关系淹没。
tile 映射可以由公式推导。
GMM1: core = groupStart + tileN % groupSize。 GMM2: core = groupStart + tileId % groupSize。 每个 phase block 的 hover title 都带了该场景的 tile 数和 per-core 上界。
设计分析更关心瓶颈。
4096 n 时 36 AIC 不能多开一组, 但降低 GMM2 平均 tile/core。 h=7068/7168 是 GMM2-heavy。n=2048 时 GMM1 下界降到 8, 可开 4 组。
