# ops-transformer 项目功能与架构分析报告

## 一、项目概述

**ops-transformer** 是华为昇腾 CANN（Compute Architecture for Neural Networks）算子库中专门面向 Transformer 大模型计算的进阶算子库。该项目为 Atlas NPU 提供高性能的 transformer 类算子实现，覆盖 Attention、MoE、MC2（通算融合）等关键场景。

**项目定位**：作为 CANN 算子生态的重要组成部分，位于底层算子库与上层框架之间，为大规模模型推理和训练提供核心计算能力支撑。

**支持的硬件平台**：
- Atlas A2/A3 系列（ascend910b, ascend910_93）
- Atlas 950PR/950DT/KirinX90 系列（ascend950, kirinx90, kirin9030）
- mc62cm12a 等芯片

---

## 二、核心功能模块

### 1. Attention 算子模块（attention/）
**功能定位**：实现各类注意力计算，是 Transformer 模型的核心组件

**主要算子（约40+个）**：

| 算子类型 | 代表算子 | 功能说明 |
|---------|---------|---------|
| Flash Attention | flash_attention_score, fused_infer_attention_score | 高效自注意力计算，支持训练/推理 |
| 稀疏注意力 | sparse_flash_attention, kv_quant_sparse_flash_attention | 大序列长度场景优化 |
| 增量推理 | incre_flash_attention, prompt_flash_attention | 推理场景 KV Cache 管理 |
| NSA系列 | nsa_compress, nsa_selected_attention | Native Sparse Attention 实现 |
| KV Cache管理 | scatter_pa_cache, gather_pa_kv_cache | PagedAttention 缓存操作 |
| MLA预处理 | mla_preprocess, mla_prolog | Multi-Head Latent Attention 支持 |

### 2. MoE 算子模块（moe/）
**功能定位**：支持混合专家模型的路由与计算

**主要算子（约30+个）**：
- **路由计算**：moe_gating_top_k_softmax, moe_init_routing
- **Token重排**：moe_token_permute, moe_token_unpermute
- **结果合并**：moe_finalize_routing
- **梯度计算**：mo*_grad 系列反向传播算子

### 3. MC2 模块（mc2/）
**功能定位**：通信与计算融合，实现分布式训练/推理的高效计算

**主要算子**：
- **通信融合**：matmul_all_reduce, all_gather_matmul, allto_all_matmul
- **MoE分布式**：moe_distribute_dispatch, moe_distribute_combine
- **混合融合**：matmul_all_reduce_add_rms_norm（MM+通信+归一化融合）

### 4. GMM 模块（gmm/）
**功能定位**：分组矩阵乘法，支持 MoE 专家并行计算

**主要算子**：
- grouped_matmul, grouped_matmul_add
- grouped_matmul_swiglu_quant（融合量化+SwiGLU激活）
- grouped_matmul_finalize_routing

### 5. FFN 模块（ffn/）
**功能定位**：前馈神经网络计算

**主要算子**：
- ffn（支持 MoE FFN）
- swin_attention_ffn, swin_transformer_ln_qkv

### 6. Position Embedding 模块（posembedding/）
**功能定位**：旋转位置编码及相关预处理

**主要算子**：
- apply_rotary_pos_emb, rotary_position_embedding
- qkv_rms_norm_rope_cache（融合 RMSNorm+RoPE+KV Cache）
- rope_quant_kvcache（融合量化）

### 7. MHC 模块（mhc/）
**功能定位**：混合超连接架构支持

**主要算子**：
- mhc_pre, mhc_post, mhc_res（残差连接）
- mhc_sinkhorn（Sinkhorn-Knopp 算法）

## 三、架构设计

### 3.1 项目结构层次

```
ops-transformer/
├── cmake/                    # 编译系统配置
├── common/                   # 公共头文件与工具代码
│   ├── inc/                  # 公共头文件
│   └── src/                  # 公共实现（含 framework ONNX插件）
├── attention/                # Attention类算子
├── moe/                      # MoE类算子
├── mc2/                      # 通信计算融合算子
├── gmm/                      # 分组矩阵乘算子
├── ffn/                      # FFN算子
├── posembedding/             # 位置编码算子
├── mhc/                      # MHC架构算子
├── experimental/             # 用户自定义算子扩展区
├── torch_extension/          # PyTorch扩展接口
├── examples/                 # 算子开发与调用示例
├── docs/                     # 文档中心
├── tests/                    # 测试用例
└── scripts/                  # 构建脚本
```

### 3.2 单算子工程结构（标准模式）

每个算子目录遵循统一的工程模板：

```
${op_name}/
├── op_host/                  # Host侧实现
│   ├── ${op_name}_def.cpp    # 算子信息定义（原型）
│   ├── ${op_name}_tiling.cpp # Tiling策略实现
│   ├── ${op_name}_infershape.cpp # Shape推导
│   └── config/               # SOC配置文件
├── op_kernel/                # Device侧 Kernel实现
│   ├── ${op_name}.cpp        # Kernel主入口
│   ├── ${op_name}.h          # Kernel头文件
│   └── arch32/arch35/arch38  # 多架构适配
├── op_api/                   # aclnn接口实现（可选自动生成）
├── op_graph/                 # 图模式融合规则
│   ├── fusion_pass/          # 融合Pass
│   └── ${op_name}_graph_infer.cpp
├── examples/                 # 调用示例
│   ├── test_aclnn_${op_name}.cpp
│   └── test_geir_${op_name}.cpp
├── tests/                    # UT/ST测试
└── docs/                     # API文档
```

### 3.3 编译架构（CMake）

**构建系统**：CMake + 自定义构建脚本

**关键编译选项**：
- `ASCEND_COMPUTE_UNIT`：目标SOC类型
- `BUILD_OPEN_PROJECT`：开源项目构建模式
- `ENABLE_AICPU`：启用AI CPU算子
- `ENABLE_TILING_SINK`：Tiling下沉优化
- `ENABLE_EXPERIMENTAL`：启用实验性模块

**编译流程**：
1. CMake配置 → 依赖检查
2. 算子原型生成 → opbuild工具处理
3. Kernel编译 → 多架构适配
4. 打包部署 → vendor包生成

## 四、技术特性

### 4.1 多调用模式支持

| 调用方式 | 说明 | 适用场景 |
|---------|------|---------|
| aclnn API | C语言Host侧接口 | 单算子调用、灵活集成 |
| 图模式 | ONNX/GEIR构图 | 模型整网部署 |
| PyTorch Extension | torch_extension模块 | PyTorch框架集成 |
| <<<>>> | 简易Kernel Launch | 快速开发原型 |

### 4.2 性能优化技术

- **Tiling策略**：数据分块并行计算
- **算子融合**：减少内存访问，降低通信开销
- **量化支持**：INT8/FP8量化计算
- **多架构适配**：arch32/arch35/arch38 多代NPU优化

### 4.3 开发者支持

- **experimental目录**：用户自定义算子开发区
- **NpuOpsTransformerExt模板**：PyTorch集成模板工程
- **CANN Simulator**：仿真调试支持
- **完整文档体系**：开发指南、API列表、示例代码

## 六、依赖关系

**上游依赖**：
- CANN 软件包（ASCEND_HOME_PATH）
- Ascend 驱动
- 第三方库：Eigen、Abseil-cpp、Protobuf、GTest

## 七、总结

ops-transformer 是一个面向 Transformer 大模型的专业算子库，具备以下特点：

1. **功能全面**：覆盖 Attention/MoE/MC2 等核心场景，100+算子
2. **架构清晰**：标准化算子工程模板，分层模块设计
3. **性能优化**：融合算子、量化支持、多架构适配
4. **生态完善**：多种调用模式、完整文档、开发者扩展机制
5. **持续迭代**：活跃更新，持续支持新算子和新硬件
