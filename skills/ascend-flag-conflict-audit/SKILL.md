# Ascend flagId 冲突审查

先确认目标硬件、CANN 版本、实际编译宏、kernel 入口和参与核数。不要按 mode 或 AIC/AIV
自行假设独立命名空间。910B/CANN 9.1 的 Wait 最终只有 flagId；其他平台需重新验证实现。

## 扫描与收敛

运行 `scripts/scan_flags.py <kernel 文件或目录> [配置头文件] [-D NAME=整数]`。
工具只读源文件，以 JSON 输出 Set/Wait 站点、可解析 ID、跨 mode **Set** 复用候选及未知项。
它是保守词法扫描，不是 C++ 语义分析器：数组索引取所有候选值，条件编译分支和同名符号
可能合并；不解析完整调用图，不跟随系统 include，也不能证明无冲突。

源码扫描不通过不能直接改 ID，扫描无告警也不能宣布安全。继续核对：

- 对每个候选记录生产者/消费者、mode、pipe、flag 表达式、核范围、任务/块索引、
  动态次数、生命周期、前后依赖。特别区分按 KV 块奇偶与按 task 奇偶选 ID。
- 以 **Set 的协议**识别跨 mode 复用。Wait 的默认模板 mode 可能为 0，而实际用于消费
  mode 2 通知；不能因此把每个这种配对误报为独立协议冲突。
- 同 ID 若有严格完成确认，可以安全分时使用；AIV 已发 Set 不等于远端已消费。
  同一核源码顺序也不等于不同管线的完成顺序。不要用延迟或负载均衡代替协议修复。
- 查看 SyncAll、Matmul/KFC、wrapper、保留 ID 和自动插入的同步。此仓库案例中
  CANN MIX 的 `clearWorkspace` 额外发 mode 2 flag 15；不可把 15 普遍视为空闲。

## 二进制与复现

对实际加载 ELF 做 hash 标识、反汇编，核对 Set 消息、Wait 操作数、隐式同步和循环。
记录符号起点、节内偏移；日志 `current - pc start` 是符号内偏移，不能直接等同 `.text` 偏移。
如果工具无法解码，明确证据不足，不能从源码假装得到了机器码。

需要硬件验证且用户已授权时，在空闲的指定设备上使用独立安装包、新进程及有限 timeout；
只改变目标 ID 做 A/B 对照，保留原 kernel，失败后退出 context。不自动重置设备、杀其他
用户进程或把普通异常当成复现。遇到非预期结果停止并保存现场。

结论分开写：源码候选 → 实测超时/对照 → PC 对应 → 候选计数器机制。
没有全核/计数器轨迹，不声称抓到了某条通知的错误消费；有限通过不证明永远安全。

本仓库实例及图见 `docs/klloss_sync/README.md`（相对仓库根目录）。复用技能到其他仓库时，
无需携带本案例；上面的约束与扫描脚本应足以完成初步审查。
